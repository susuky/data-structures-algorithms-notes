    1. 從輸入與輸出合約開始

    拿到問題先寫出資料範圍與輸出定義。例如「找最大值」仍有空集合怎麼辦、是否允許修改輸入、同分選哪一個等歧義。實作前確定這些條件，往往比提早選資料結構更有效。本文以 n 表示元素個數；若還有 m 個查詢，就保留 n 與 m 兩個變數，除非題目真的保證它們相等。

    1. 輸入：有序嗎？有負數、重複值、空值嗎？資料是一次拿到，還是持續到達？
    2. 輸出：要存在性、個數、索引、實際內容，還是所有答案？「任何一組」和「最早一組」是不同合約。
    3. 限制：能改原陣列嗎？是否要求保留順序？額外記憶體與時間的取捨是什麼？
    4. 基準解：先有一定正確的小規模方法，之後用它檢查優化版本。

    一個常見陷阱是把回傳索引改成回傳數值，或先排序後忘了索引已經改變。演算法就算很快，只要違反合約，仍然不是解答。

    2. Big O 描述成長，不是秒數

    令 T(n) 是某種明確操作的次數。T(n) = O(f(n)) 表示當 n 夠大時，存在固定常數 C，使 T(n) ≤ C × f(n)。它是漸近上界；Θ(f(n)) 表示上下界同階，Ω(f(n)) 是下界。面試常把「O(n)」當作緊的量級描述，但嚴格說 O(n²) 也能包含線性函式，所以分析時應盡量給出有資訊量的界。

    3n + 20 是 Θ(n)，n² + 5n 是 Θ(n²)。去掉低階項不表示它們在實際機器上不存在，而是我們關注輸入放大後的趨勢。O(1) 也不代表只做一次；做固定 10,000 次仍是常數。兩個 O(n) 程式可能有不同執行時間，實測則還受到 Python 版本、資料分布與硬體影響。

    圖中的數字是成長模型的值，並非某段 Python 的測速結果。對數的底數只差常數倍，因此通常寫 O(log n)。

    還要說清楚是哪一種情況：線性搜尋第一格就命中是最佳 O(1)，完全找不到是最壞 O(n)；平均時間需要明確的輸入分布假設。攤銷則是在一串操作中分攤偶發的大成本，並不是假設幸運輸入。list.append 的單次擴容可能搬移很多參照，但連續追加的平均攤銷成本通常是 O(1)。

    3. 逐步範例：巢狀迴圈不靠外觀判定

    自編題意：輸入非負整數 n，回傳所有符合 0 ≤ j < i < n 的位置對數量；只回傳個數，不列出位置對。n 為負數時拋 ValueError。

    以下程式計算所有 j < i 的位置對，只累加個數，不建立答案清單。外層第 i 輪執行 i 次內層，因此總次數為 0 + 1 + … + (n − 1) = n(n − 1)/2。

    def count_position_pairs(n: int) -> int:
    """計算 0 <= j < i < n 的位置對數，不儲存所有位置對。"""
    if n < 0:
        raise ValueError("n 必須非負")
    pairs = 0
    for i in range(n):
        for j in range(i):
            pairs += 1
    return pairs

    不變量：外層開始第 i 輪時，pairs 已等於所有第二個位置小於 i 的有效配對數。內層把以 i 為第二個位置的配對恰好加入一次，所以終止時沒有漏算或重算。這是一個「先描述已完成部分，再證明本輪擴張」的標準證明方式。

    時間 Θ(n²)，輔助空間 O(1)。如果改成把每一對加入 list，時間仍為 Θ(n²)，但輸出空間變成 Θ(n²)。兩個相鄰的線性迴圈是 O(n + n) = O(n)，不同變數的巢狀掃描可能是 O(nm)；不能只憑兩個 for 就判定為 O(n²)。

    4. Python 常用操作的成本

    常用動作通常成本注意事項
    list 索引、len(list)O(1)list 裝的是物件參照；不是把所有物件內容擠在相鄰格子
    list.append、尾端 pop()追加攤銷 O(1)；尾端刪除通常 O(1)不要把單次最壞成本與一串操作的成本混用
    list.pop(0)、前端 insertO(n)後續元素參照需要移位；佇列通常改用 deque
    x in listO(n)假設每次相等比較 O(1)
    list[l:r]、複製 listO(k)，k 為複製長度同時需要 O(k) 新參照空間，屬淺複製
    dict / set 查找平均 O(1)假設良好雜湊分布與短鍵；最壞可線性，詳見第 03 章
    sorted(items)最壞 O(n log n)建立新 list；比較與 key 計算若昂貴需另加成本
    ''.join(parts)O(片段數 + 總字元數)結果字串也佔空間；逐次串接應保守估計複製成本

    上表是常見 CPython 容器在基本操作成本固定時的演算法模型，不是所有 Python 實作、資料型別都必須保證的即時延遲。Python 的整數可變長；兩個有 b 位元的巨大整數相加不能一直視為 O(1)。字串比較也可能掃過共同前綴。估算成本時，也要確認每行程式呼叫的操作實際做了哪些工作。

    容易忽略的空間還包括：排序暫存、集合中的鍵、切片、遞迴呼叫堆疊，以及 generator 尚未釋放的狀態。說「原地」也不自動等於 O(1) 空間，例如某些原地排序仍需輔助工作區。

    5. 遞迴：縮小問題，也保留回來的位置

    自編題意：輸入整數清單 nums，分別用線性掃描與遞迴回傳元素總和；空清單回傳 0，兩個版本都不修改輸入。

    一個可靠的遞迴函式必須具備：清楚的參數含義、直接可解的基本情況、嚴格縮小的子問題，以及把子答案合成答案的規則。呼叫者會停在原地等待子呼叫回傳，尚未完成的呼叫記錄存於堆疊。Python 不應假設尾端遞迴會被自動消除；長鏈狀遞迴可能遇到深度限制。

    下面兩種方法都把整數加總。線性版的迴圈不變量是「total 等於目前已讀元素總和」。遞迴版的函式合約是「total(lo, hi) 回傳 nums[lo:hi] 的和」，但實作只傳邊界，不真的切片。

    def linear_total(nums: list[int]) -> int:
    total = 0
    for value in nums:
        total += value
    return total


def recursive_total(nums: list[int]) -> int:
    """以半開區間分治；不建立 nums 的切片。"""
    def total(lo: int, hi: int) -> int:
        if lo == hi:
            return 0
        if hi - lo == 1:
            return nums[lo]
        mid = (lo + hi) // 2
        left = total(lo, mid)
        right = total(mid, hi)
        return left + right

    return total(0, len(nums))

    階段正在等待的呼叫得到的子結果

    正確性：長度 0 與 1 直接正確。若所有更短區間都算對，左右子區間互斥且剛好覆蓋原區間，相加便得到原答案。長度大於 1 時，兩個子區間都更短，因此一定到達基本情況。這是對區間長度的歸納證明。

    遞迴版總呼叫數為 Θ(n)，時間 Θ(n)；對 n ≥ 1，輔助堆疊為 O(log n)，不是 O(n)，因為完整呼叫樹不會同時留在堆疊上。空輸入則是 O(1)。線性版同樣 Θ(n) 時間、O(1) 額外空間，實際上通常更簡單。這裡用分治加總示範遞迴的分析方式，實際加總時不必特地改用遞迴。

    若每一層改成切出左右兩半，該層總複製量為 O(n)，共有 O(log n) 層，總時間便增至 O(n log n)。在深度優先、子清單適時釋放的典型實作下，最大同時存活的切片容量是 O(n)，不是把所有歷史切片都相加的 O(n log n)。

    6. 自編練習與解答

    練習 1：count_position_pairs(5) 回傳什麼？若只需要個數，如何把兩層迴圈改成常數次算術？新的時間分析有什麼前提？

    參考解答

    回傳 10。對非負 n，回傳 n * (n − 1) // 2 即可。在固定字長算術模型下是 O(1) 時間、O(1) 輔助空間；若 n 有任意多位元，乘法成本要依位數分析，不能宣稱與所有輸入大小都無關。

    練習 2：以下函式對 n = 13 會做幾輪？為何不是 O(n)？n = 0 又如何？

    def halving_steps(n: int) -> int:
    if n < 0:
        raise ValueError("n 必須非負")
    steps = 0
    while n > 0:
        n //= 2
        steps += 1
    return steps
    參考解答

    狀態為 13 → 6 → 3 → 1 → 0，共 4 輪。n > 0 時輪數為 floor(log₂ n) + 1，因此在固定成本整數模型下是 Θ(log n) 時間、O(1) 空間。n = 0 不進入迴圈，回傳 0。每次嚴格縮小非負 n 是終止理由。

    練習 3：要把 k 個文字片段接成一個總長 L 的字串，為什麼反覆 result = result + part 不是可靠的線性成本寫法？

    參考解答

    字串不可變，應保守估計每次串接都可能複製目前內容；若每個片段長度固定，累計可能達 Θ(k²)。某些實作會優化特定情況，不能把優化當成演算法保證。使用 join 可清楚表達一次建構結果，時間 O(k + L)，結果空間 O(L)，實際編碼寬度視字元而定。

    return "".join(tokens)

    練習 4：有人說「這個遞迴有 n 個葉節點，所以堆疊空間是 O(n)」。請用本章加總程式反駁，並說出什麼遞迴真的需要線性堆疊。

    參考解答

    堆疊計算的是尚未返回的一條呼叫路徑。平衡二分深度只有 O(log n)。若每次只把問題從 n 減成 n − 1，且父呼叫要等待子呼叫，最深可累積 n 層，才是 O(n) 堆疊。總工作量與同時存活空間是不同問題。

    02｜陣列與字串：用邊界減少重複掃描

    本章的範例數據與練習敘述為自編。相關 LeetCode 題目列在對應段落旁，標為「相近題型」或「延伸練習」；規格不同處會另行說明。可先依本章題意完成，再開連結練習。

    陣列題最常見的浪費，是對重疊區間重複掃描。雙指標把可排除的候選丟掉，滑動視窗把相鄰區間的共同資訊留住，前綴和則先算好各個前綴的總和，再以相減回答區間查詢。這三種方法各有適用前提，不能只因題目提到「連續」就套同一個模板。

    本章目標：能證明指標為什麼可以前進、辨認負數何時破壞視窗條件，並用半開區間避免索引錯位。範例的加減、索引與整數比較採固定成本模型。所有「區間」預設連續；子序列可以跳過元素，兩者不同。

    1. 先約定索引與區間

    長度 n 的 Python list，合法索引是 0 到 n − 1；負索引是語言的便利功能，卻可能掩蓋越界的邏輯錯誤。list 可修改，字串不可修改。Python str 的索引依 Unicode 碼位，不等於使用者眼中的完整字形；組合重音與某些 emoji 可能包含多個碼位。若題目關心「看起來一個字」，需要另外定義文字分割方式。

    本章以 [left, right) 表示含左、不含右的半開區間。長度直接是 right − left；空區間可寫成 [i,i)；相鄰的 [a,b) 與 [b,c) 合起來剛好是 [a,c)。注意：程式中兩端夾逼的 two_sum_sorted 使用兩個包含端點的索引，回傳也是元素索引；其餘回傳區間的函式會明寫半開區間，不能混用。

    Python 的 nums[left:right] 會建立新 list，長度 k 就需 O(k) 時間與空間。維護一對邊界則只需 O(1) 空間。想驗證目前視窗，可以在小測試中印出切片；正式迴圈若每輪都切片或重新 sum，就可能把線性演算法變回平方級。

    2. 左右夾逼：用排序證明整批排除

    相近題型：LeetCode 167 · Two Sum II - Input Array Is Sorted。原題也在已排序陣列中找兩數和，但索引從 1 開始且保證恰有一組解。本章索引從 0 開始，允許無解並回傳 None；找到任意一組即可。

    問題：給定已依非遞減順序排序的整數陣列，找兩個不同位置使其和為 target；任意一組即可，無解回傳 None。用 left 指向最小、right 指向最大。若兩者和太小，連目前最大的搭檔都不夠，left 不可能和剩餘任何元素成功，因此可以丟掉；太大則對稱地丟掉 right。

    def two_sum_sorted(nums: list[int], target: int):
    """前置條件：nums 已依非遞減順序排序。回傳兩個不同索引或 None。"""
    left, right = 0, len(nums) - 1
    while left < right:
        current = nums[left] + nums[right]
        if current == target:
            return left, right
        if current < target:
            left += 1
        else:
            right -= 1
    return None

    逐步範例 A：nums = [−6, −2, 1, 5, 9]，target = 6。

    left、right相加動作與理由
    0、4−6 + 9 = 3太小，排除 left = 0
    1、4−2 + 9 = 7太大，排除 right = 4
    1、3−2 + 5 = 3太小，排除 left = 1
    2、31 + 5 = 6回傳 (2,3)

    不變量：如果答案存在，至少有一組完整位於目前的 [left,right] 中。每次排除端點都有上述大小關係支持，所以不會丟掉全部答案。停止於 left ≥ right，表示已沒有兩個不同位置。每輪至少縮短一格，故必定終止。

    已排序前提下，時間 O(n)、額外空間 O(1)。負數與重複值都允許。若輸入未排序，不能直接套用；先排序需 O(n log n)，若還要原始索引，就要保留值與索引的配對。第 03 章會用雜湊解未排序版本。

    3. 同向雙指標：讀取與寫入分開

    相近題型：LeetCode 27 · Remove Element。原題只要求回傳保留元素個數，並把它們放在陣列前端，允許改變順序。本章另要求保留相對順序，使用讀寫指標做穩定壓縮。

    問題：原地刪去所有 unwanted，保留其他元素的相對順序，回傳有效長度。read 逐一讀原位置，write 指向下一個可寫位置；遇到要保留的值才寫入並前進。此合約不要求真的縮短 list，因此尾端的舊值不算答案。

    def remove_value(nums: list[int], unwanted: int) -> int:
    """原地穩定壓縮；僅前 write 個元素是有效輸出。"""
    write = 0
    for read in range(len(nums)):
        if nums[read] != unwanted:
            nums[write] = nums[read]
            write += 1
    return write

    不變量：每輪開始時，nums[:write] 等於原輸入中 read 之前所有應保留的元素，且 write ≤ read。這個不等式保證寫入不會破壞尚未讀取的區域。例如 [5,2,5,8] 刪除 5，最後前兩格是 [2,8]，回傳 2，尾端可能仍有殘值。

    時間 O(n)，額外空間 O(1)。若題目要求縮短容器，可另做 del nums[write:]，但要把那一步的工作量算入。直接在 for 迴圈中 remove 元素會移位，也容易跳過相鄰重複值；讀寫指標分別標記「已完成、待處理」的邊界，方便檢查寫入是否安全。

    4. 可變視窗：把單調性寫成前提

    相近題型：LeetCode 1208 · Get Equal Substrings Within Budget。原題把兩個等長字串各位置的字元碼差絕對值當成成本，求總成本不超過 maxCost 的最長連續子字串長度。本章直接提供非負成本陣列，回傳區間邊界，並額外指定平手取最早。

    問題：每天消耗量都是非負整數，找總消耗不超過 budget 的最長連續時段。回傳半開區間，平手選最早；空輸入或沒有非空合法時段回傳 (0,0)。右端加入一天後若超過預算，左端持續移出，直到再次合法。非負性確保：往右加入不會降低總和，從左移出不會增加總和。

    def longest_budget_window(nums: list[int], budget: int) -> tuple[int, int]:
    """回傳最長合法半開區間；同長時取最早者。僅接受非負整數。"""
    if budget < 0 or any(value < 0 for value in nums):
        raise ValueError("budget 與元素必須非負")
    left = 0
    total = 0
    best = (0, 0)
    for right, value in enumerate(nums):
        total += value
        while total > budget:
            total -= nums[left]
            left += 1
        if right + 1 - left > best[1] - best[0]:
            best = (left, right + 1)
    return best

    逐步範例 B：nums = [2,1,3,1,1,2]，budget = 5。表格記錄縮完後的狀態；right 是本輪剛加入的元素索引。

    right加入後總和移出left、剩餘總和目前最優區間
    02無0、2[0,1)
    13無0、3[0,2)
    2621、4[0,2)，平手不更新
    35無1、5[1,4)
    4612、5[1,4)
    5733、4[1,4)

    不變量：縮完後 total 等於 nums[left:right+1] 的總和且不超標；所有比 left 更早的起點對目前右端都已知不合法。當某個左端因超標被丟掉，未來再加非負數也無法讓從它開始的區間重新合法。因此目前視窗是以這個右端結尾的最長合法候選，逐輪比較便得到全域最長。

    雖然 for 內有 while，left 與 right 都只前進、各最多 n 次，所以總時間 O(n)，空間 O(1)。前面的非負檢查另掃一次，也仍為 O(n)。只保存邊界，沒有複製最長區間；若最終要回傳內容，另計輸出長度。

    負數反例：[4,−3,2]，budget = 3。若套同一規則，讀到 4 就將它丟掉，最後只找到長度 2；但整段總和是 3，正解長度 3。負數讓已超標區間可能重新合法，破壞了永久排除的證明。本函式會拒絕負數；混合正負數的精確區間和可改看前綴和與第 03 章的雜湊。

    滑動視窗不一定依賴數值非負；例如「不重複字元」可以用集合或計數維護。這些視窗方法都需要確認：擴張造成的違規，能藉單向收縮修復，而且已丟棄的邊界不必回頭。使用前，要先證明這些條件成立。

    5. 前綴和：把一段相加換成兩點相減

    相近題型：LeetCode 303 · Range Sum Query - Immutable。原題對固定陣列反覆查詢區間總和，sumRange 的左右端點都包含在內。本章使用半開區間。把原題 sumRange(left,right) 的輸入交給本章 range_sum 時，右端點要往後移一格。

    若資料固定卻有許多區間加總查詢，預先建 P，令 P[0] = 0，P[i+1] = P[i] + nums[i]。P[i] 表示前 i 個元素的總和，因此 nums[left:right] 的總和恰好是 P[right] − P[left]。負數不會破壞此等式；需要的是加法與減法，而不是單調性。

    def build_prefix(nums: list[int]) -> list[int]:
    prefix = [0]
    for value in nums:
        prefix.append(prefix[-1] + value)
    return prefix


def range_sum(prefix: list[int], left: int, right: int) -> int:
    if not 0 <= left <= right < len(prefix):
        raise ValueError("區間必須符合 0 <= left <= right <= n")
    return prefix[right] - prefix[left]

    逐步範例 C：輸入 [3,−2,5,1]。

    讀入元素目前前綴新增意義
    尚未讀入[0]前 0 個元素總和
    3[0,3]P[1] = 3
    −2[0,3,1]P[2] = 1
    5[0,3,1,6]P[3] = 6
    1[0,3,1,6,7]P[4] = 7

    查 [1,4) 得 7 − 3 = 4；查整段 [0,4) 得 7；查空段 [2,2) 得 0。統一公式不需替 left = 0 寫特例。

    不變量：建立到第 i 個邊界時，prefix[i] 正好是原陣列 [0,i) 的和。查詢時共同前綴相消，即得到目標區間。建表 O(n) 時間與空間，m 次查詢 O(m)，合計 O(n + m)。原資料若更新，舊前綴會失效；別把「靜態快速查詢」誤認成「動態更新也快速」。

    前綴最大值不能像總和一樣相減：左邊曾出現的最大值，並沒有一個減法可以從全段最大值中移除。決定保存哪種摘要前，先確認能否用它還原所需的區間資訊。二維前綴和則再用容斥扣除重疊，但仍應先把一維的邊界模型練熟。

    6. 自編練習與解答

    延伸練習：LeetCode 643 · Maximum Average Subarray I。原題求固定長度區間的最大平均值；下方自編練習求最大總和。長度固定時，找到最大總和後除以 k，就得到原題要求的平均值。

    練習 1：固定長度時段。給定可含負數的日收益，求長度恰好為 k 的最大連續總和。k 不合法時拋出 ValueError。為什麼這裡負數沒有問題？

    參考解答

    固定視窗每次移出一個、移入一個，不做「超標就永久排除起點」的推論，所以不需要非負性。初始 best 必須是第一個視窗的和，不能設為 0，否則全負數會出錯。時間 O(n)、額外空間 O(1)；用 generator 建第一個和，避免切片。

    def max_fixed_window_sum(nums: list[int], k: int) -> int:
    if not 1 <= k <= len(nums):
        raise ValueError("k 必須介於 1 與陣列長度之間")
    current = sum(nums[i] for i in range(k))
    best = current
    for right in range(k, len(nums)):
        current += nums[right] - nums[right - k]
        best = max(best, current)
    return best

    例如 [−5,−2,−4]，k = 2，兩段為 −7 與 −6，應回傳 −6。

    延伸練習：LeetCode 209 · Minimum Size Subarray Sum。原題要求正整數陣列中，總和至少 target 的最短連續區間長度，無解回傳 0。下方練習沿用這個目標，但允許元素為零，並檢查不合法輸入。

    練習 2：最短達標時段。元素非負、target > 0，求總和至少 target 的最短非空連續長度；無解回傳 0。與最長不超標的更新時機有何不同？

    參考解答

    目前一旦達標，就先記錄候選，再縮左端，嘗試更短答案；縮到不達標才等待下一個元素。若等縮完才記錄，留下的反而是不合法視窗。每個右端的合法候選在收縮時被檢查；已經記錄並丟掉的左端，未來只會形成更長區間，不可能改進最短答案。

    def min_length_at_least(nums: list[int], target: int) -> int:
    """最短非空區間：元素非負、target > 0；無解回傳 0。"""
    if target <= 0 or any(value < 0 for value in nums):
        raise ValueError("target 必須為正，元素必須非負")
    left, total = 0, 0
    best = len(nums) + 1
    for right, value in enumerate(nums):
        total += value
        while total >= target:
            best = min(best, right - left + 1)
            total -= nums[left]
            left += 1
    return 0 if best == len(nums) + 1 else best

    [2,1,3,1]、target = 4 的答案是 2。時間 O(n)、空間 O(1)。允許零，但 target 必須為正，避免空區間與收縮條件混淆。

    延伸練習：LeetCode 303 · Range Sum Query - Immutable。這題自編練習專門處理原題的包含式端點，與本章半開區間之間的轉換。

    練習 3：查詢索引轉換。原始陣列 [3,−2,5,1] 的查詢介面使用「包含左右端點」的 [1,3]。如何呼叫 range_sum？若 left = right 又如何？

    參考解答

    先建 prefix，再呼叫 range_sum(prefix, 1, 4)，答案 4。包含式 [i,i] 是單一元素，必須轉成半開 [i,i+1)，而不是 [i,i)。最好在介面邊界只轉換一次，內部統一使用同一區間約定。

    延伸練習：LeetCode 27 · Remove Element。這題用自編輸入練習原地移除；本章仍比原題多要求保留順序。

    練習 4：原地壓縮。對 [7,7,1,7,2] 刪除 7，請手算每一輪 read、write，並說明為什麼不用把被刪元素挪到尾端。

    參考解答

    處理各位置後的 write 依序是 0、0、1、1、2；前兩格最後為 [1,2]。合約只承諾前 write 格有效，尾端沒有規定。多做交換或尾端整理只會增加不必要工作，甚至破壞穩定性。

    如果演算法不停問「這個值先前出現過嗎？」「出現幾次？」「最早在哪裡？」，反覆掃描歷史就會浪費時間。雜湊表把某種鍵映射到位置，讓集合 set 和字典 dict 能在通常情況下快速回答這些問題。選擇鍵與值時，要先想清楚後面的查詢需要哪些資訊，單靠記住 API 還不夠。

    本章目標：從存在性逐步走到計數與索引；用前綴雜湊處理含負數的精確區間和；理解複合鍵、相等性與查詢／更新順序。所有平均線性分析都假設雜湊分布良好，且整數鍵的雜湊與比較可視為 O(1)。

    1. 雜湊值、碰撞與相等性

    概念上，雜湊函式把鍵映射成整數，再由容器定位可能的儲存區域。不同鍵可能有相同雜湊值，叫作碰撞；正確的容器還要比較鍵是否相等，不能只看雜湊值。因此自己寫「把 hash(x) 放進 set 就當作存了 x」可能產生假陽性，應直接把 x 存入集合。

    平均查找、插入、刪除通常 O(1)，但碰撞嚴重時一次操作最壞可達 O(n)，整串 n 次操作最壞可到 O(n²)。擴容也會有偶發成本，插入的常數分析帶有攤銷觀點。若鍵本身很長，計算雜湊和相等比較的成本還要算入；即使用了雜湊表，長字串或大 tuple 的鍵仍有這些處理成本。

    Python dict 保留插入順序，但不是依鍵排序；set 不應被當成有可依賴的排序。需要可重現的排序輸出時，請明確排序並計算其成本。雜湊表是一種查找結構，不是有序索引。

    2. 只問是否出現，就用集合

    相近題型：LeetCode 217 · Contains Duplicate。原題只回傳是否有重複值的布林結果。本章改為回傳掃描時第一個重複的值，無重複則回傳 None，所以還需要明確定義掃描順序。

    問題：依序掃描整數，回傳第一個「在掃描當下成為重複」的值；若沒有則回傳 None。例如 [8,3,8,3] 的答案是 8，而不是值最小的重複元素。這個輸出定義讓掃描順序成為題目的一部分。

    def first_repeated(nums: list[int]):
    """回傳掃描時首先重複出現的整數；無重複回傳 None。"""
    seen = set()
    for value in nums:
        if value in seen:
            return value
        seen.add(value)
    return None

    不變量：處理目前元素之前，seen 恰好包含所有已處理的值。先查詢、再加入；命中表示已有較早位置持有相同值。第一次命中就是最早重複事件。若先加入再查，每個元素都會看見自己。時間平均 O(n)，額外空間 O(u)，u 是不同值的個數，最壞 u ≤ n。

    本函式只接受整數，因此用 None 表示不存在沒有歧義；若輸入本身可以包含 None，就應改回傳索引、額外的 found 旗標，或使用獨特 sentinel。設計回傳值也屬於演算法合約。

    3. 問出現幾次，就保存頻率

    延伸練習：LeetCode 1512 · Number of Good Pairs。原題同樣計算值相等、且較小索引在前的索引對個數。本章使用自編數據說明頻率累加，也允許空輸入。

    問題：計算值相同的索引對 (i,j)，其中 i < j。當讀到 value，之前已有 c 個同值元素，就恰好新增 c 對，不必把先前的位置全部保存。頻率已足以回答這個計數問題，因此可以用它取代逐一檢查先前位置的工作。

    def count_equal_pairs(nums: list[int]) -> int:
    freq = {}
    pairs = 0
    for value in nums:
        old_count = freq.get(value, 0)
        pairs += old_count
        freq[value] = old_count + 1
    return pairs

    逐步範例 A：輸入 [4,4,7,4,7]。

    目前值更新前次數新增配對累計 pairs更新後頻率
    4000{4:1}
    4111{4:2}
    7001{4:2,7:1}
    4223{4:3,7:1}
    7114{4:3,7:2}

    正確性：每一對只會在較晚位置到達時被計入，且較早的同值位置都由頻率表完整代表。因此每對剛好算一次。時間平均 O(n)，空間 O(u)。事後也可對各值頻率 c 累加 c(c−1)/2，但逐一處理的寫法更適合串流，也直接說明了計數來源。

    Python 可用 dict.get(key, 0)、collections.Counter 或 defaultdict(int)。get 讀不到鍵時不會寫入；defaultdict 的索引讀取缺失鍵則會建立預設值。選 API 時要確認它是否會改變字典內容，尤其是在用「字典有多少鍵」表示不同種類數時。

    4. 問先前在哪裡，就保存索引

    自編題意：輸入未排序整數陣列 nums 與 target，回傳兩個不同位置的零起算索引，使對應數值相加為 target；無解回傳 None。若有多組，回傳掃描中最先完成的那組，搭檔相同時保留最早索引。

    相近題型：LeetCode 1 · Two Sum。原題保證恰有一組答案；本章允許無解或多解，因此多定義了回傳 None 與平手選擇的規則。

    未排序的兩數和不再能依大小移動左右指標。但對目前值 x，要找的搭檔一定是 target − x。將前面數值的最早索引存入字典，就能直接查其補數。

    def two_sum_any(nums: list[int], target: int):
    first_index = {}
    for index, value in enumerate(nums):
        complement = target - value
        if complement in first_index:
            return first_index[complement], index
        first_index.setdefault(value, index)
    return None

    輸入 [9,2,9]、target = 18：第一個 9 還沒有搭檔，記 {9:0}；讀到 2 也無搭檔，記 {9:0,2:1}；最後的 9 查到先前的 9，回傳 (0,2)。輸入 [9] 則不會用自己配自己，因為查詢發生在加入目前位置之前。

    不變量：每次查詢時，first_index 僅含目前位置之前出現的值；setdefault 保留最早索引。演算法回傳掃描中最先找到的那組，亦即最早可完成的右端點，並不保證所有答案中字典序最小的索引對。若合約要求別種平手規則，需要額外設計。時間平均 O(n)，空間 O(n)。

    5. 前綴雜湊：把區間條件改寫成歷史查詢

    延伸練習：LeetCode 560 · Subarray Sum Equals K。原題的 k 就是本章的 target，要求回傳符合總和的非空連續區間個數。下方保留自編範例與完整追蹤，不必開原題也能推導。

    問題：陣列可含正數、零與負數，計算總和恰好等於 target 的非空連續區間個數。第 02 章定義 P[j] 為前 j 個元素之和，故 [i,j) 的和為 P[j] − P[i]。把等式移項：P[j] − P[i] = target，等價於 P[i] = P[j] − target。

    於是每遇到一個新右邊界 j，只需知道之前有幾個前綴值等於 P[j] − target。因為不同邊界可能具有相同前綴值，這裡必須用次數，不能只用集合。這個方法也適用於負數，因為代數等式不要求前綴單調。

    def count_subarrays_sum(nums: list[int], target: int) -> int:
    freq = {0: 1}
    prefix = 0
    answer = 0
    for value in nums:
        prefix += value
        answer += freq.get(prefix - target, 0)
        freq[prefix] = freq.get(prefix, 0) + 1
    return answer

    逐步範例 B：nums = [2,−1,2,1,−2]，target = 2。起始 freq = {0:1}。

    四個區間是 [0,1)、[2,3)、[1,4)、[0,5)。最後前綴值 2 的次數才更新成 2；它代表兩個不同邊界，不應被合併成一個「存在」。

    不變量：處理右邊界 j 的查詢之前，freq 精確記錄 P[0] 到 P[j−1] 的出現次數；answer 已包含所有右邊界小於 j 的合法非空區間。查到的每一個舊邊界 i 都滿足 i < j，因此新增區間非空，而且每個區間只在自己的右邊界被計入。接著加入 P[j]，不變量延續到下一輪。

    兩個不可省略的細節：初始 {0:1} 代表「尚未讀入元素」的前綴邊界，讓從索引 0 開始的區間也能被算到。順序必須先查、再加入目前前綴；若 target = 0 而先加入，就把 P[j] 和自己配對，錯算空區間。

    時間平均 O(n)，額外空間 O(n)，不需要真的保存整個 prefix 陣列。答案可能是 n(n+1)/2，因此別把答案大小誤認成只有 O(n)。Python int 可容納大計數，但若改用固定位元語言，要檢查溢位；若以位元成本分析，也要計入大整數算術。

    6. 同樣的鍵，不同問題需要不同值

    自編題意：輸入可含負數的整數陣列與 target，找總和恰好等於 target 的最長非空連續區間，回傳半開邊界；同長取最早，無解回傳 (0,0)。

    相近題型：LeetCode 325 · Maximum Size Subarray Sum Equals k。原題頁目前標示需 Premium 才能閱讀；這裡的自編題意、範例與解答可直接閱讀，不依賴付費頁面。

    如果改問「總和恰好等於 target 的最長區間」，頻率不再有用；對固定右端點，越早的相符左端點會產生越長區間，所以只保存每個前綴值的第一次出現位置。後來相同的前綴不應覆蓋它。

    def longest_subarray_sum(nums: list[int], target: int) -> tuple[int, int]:
    """回傳最長非空符合區間，同長取最早；無解回傳 (0, 0)。"""
    first_position = {0: 0}
    prefix = 0
    best = (0, 0)
    for end, value in enumerate(nums, start=1):
        prefix += value
        needed = prefix - target
        if needed in first_position:
            start = first_position[needed]
            if end - start > best[1] - best[0]:
                best = (start, end)
        first_position.setdefault(prefix, end)
    return best

    例如 [1,−1,1] 的前綴邊界依序為 0、1、0、1，target = 1。若把前綴 0 的最早位置 0 改寫成 2，最後只能得到 [2,3) 長度 1，而漏掉 [0,3) 長度 3。這個例子說明了保留最早位置才能找到最長區間，選擇更新方式時必須守住這項條件。時間平均 O(n)，空間 O(n)。

    真正要回答的問題表中保存什麼
    是否曾出現set 中的鍵
    能形成多少組鍵 → 出現次數
    找最長區間鍵 → 最早位置
    找最短非空區間常需鍵 → 最近位置，且先查後更新

    「最短」那一列是精確區間和的設計方向，仍需檢查空區間與平手合約，不能機械替換所有問題的儲存策略。選擇狀態時，要檢查保存的資訊是否足以回答後續查詢，避免合併仍需區分的情況。

    7. 複合鍵：讓相同結構得到同一個表示

    鍵不一定是單一數字。格子座標可用 (row,col)，有時間維度的狀態可用 (row,col,time)。若方向會影響下一步，方向也要放入鍵；省略一個影響未來的維度，就會把不同狀態錯當成相同。反過來，不相關的資訊也不必加入，否則應被合併的狀態無法合併。

    相近題型：LeetCode 49 · Group Anagrams。原題將能互相重排的單字分組，允許任意輸出順序。本章另保留組內輸入順序，以及各組首次出現的順序。

    自編輸入輸出：輸入只含小寫英文字母的單字清單，回傳分組後的清單；空輸入回傳 []，空字串也可分組。例如 ["arc", "car", "arr"] 回傳 [["arc", "car"], ["arr"]。遇到字母表以外的字元則拋 ValueError。

    另一個例子是字母重排分組：兩個詞若每個字母的次數都相同，就放同組。對固定 a 到 z 的字母表，可用長度 26 的次數 tuple 作為鍵。列表本身可變且不可雜湊，轉成 tuple 才能當鍵；但 tuple 若內含 list，仍不可雜湊。不是所有「外觀不可變」的容器都保證可用。

    def group_anagrams(words: list[str]) -> list[list[str]]:
    """只接受 a 到 z；保留各組輸入順序及分組首次出現順序。"""
    groups = {}
    for word in words:
        counts = [0] * 26
        for char in word:
            if not "a" <= char <= "z":
                raise ValueError("只接受小寫英文字母 a 到 z")
            counts[ord(char) - ord("a")] += 1
        key = tuple(counts)
        groups.setdefault(key, []).append(word)
    return list(groups.values())

    設 W 為單字數、L 為總字元數、G 為組數、A 為字母表大小。建立計數及鍵的時間平均 O(L + WA)，鍵的保存空間 O(GA)，分組存放單字參照還需 O(W)。此處 A = 26 為固定常數，所以可簡寫為平均 O(L + W) 時間、O(G + W) 空間。這段程式只保存輸入字串的參照，不重新複製所有文字。

    若支援任意 Unicode，就不能用固定 26 格。可把排序後的碼位序列作為鍵，單字長度 k 時建鍵 O(k log k)，或用字元計數後排序的鍵值對；大小寫、重音正規化是否等同也要由需求決定。不要默默刪掉未知字元。本函式對不在 a 到 z 的字元直接報錯。

    別用沒定義編碼規則的字串拼接代替 tuple。例如把兩段文字用「|」相接，('a|b','c') 和 ('a','b|c') 都可能變成 'a|b|c'。直接使用二元 tuple 能保留邊界。可作鍵的自訂物件還必須維持雜湊與相等性一致，且存入容器期間不能任意改變影響鍵身分的內容。

    8. 自編練習與解答

    延伸練習：LeetCode 560 · Subarray Sum Equals K。這題用全零自編輸入檢查重複前綴的計數，目標仍是非空區間個數。

    練習 1：零的壓力測試。[0,0,0] 中總和為 0 的非空區間有幾個？逐步列出 freq[0] 與 answer。改用 set 會少算多少？

    參考解答

    起始 freq[0] = 1。三次查詢分別新增 1、2、3 個區間，answer 依序 1、3、6；更新後頻率依序 2、3、4。若每輪集合查到就只加 1，只會得到 3，少算 3。相同值的不同前綴邊界對應不同區間，不能去重。

    練習 2：集合還是字典？資料是使用者編號串流。需求 A：判斷是否曾出現重複；需求 B：回傳每個編號的總次數；需求 C：發現重複時回報最早一次的位置。各該保存什麼？

    參考解答

    A 用 seen 集合即可；B 用編號到次數的字典；C 用編號到最早索引的字典，首次見到才設定。三者的平均處理時間都是 O(n)，但保存的語意不同。若 A 只要布林值，第一次重複就能提前停止；B 則必須讀完整段。

    延伸練習：LeetCode 325 · Maximum Size Subarray Sum Equals k。這題是本章最長區間函式的自編除錯練習，題意與反例已列在下方；原題頁需 Premium。

    練習 3：錯誤的最長區間。把 longest_subarray_sum 迴圈末尾的 first_position.setdefault(prefix, end) 改成 first_position[prefix] = end，為什麼 [1,−1,1]、target = 1 會失敗？請說出被破壞的不變量。

    參考解答

    第二個邊界的前綴為 0，覆蓋了原本邊界 0 的紀錄；第三個邊界查詢時只能找到位置 2。表中保存的是「最近位置」而非「最早位置」，無法支持最長性的推論。setdefault 或只在鍵不存在時賦值才能保留所需資訊。

    練習 4：不只位置相同。機器人移動規則取決於目前格子以及已使用的折返次數。visited 只用 (row,col) 是否足夠？

    參考解答

    不夠。即使同一格，剩餘可折返額度不同，未來可行動作也可能不同。至少要用 (row,col,used) 或其他能完整代表剩餘能力的等價狀態。判斷需要哪些維度時，要看它們是否影響後續可行的動作，不能只因題目有座標就省略其他狀態。第 06 與 13 章會延續狀態設計。

    9. 測試與章末決策

    本章測試對元素取自 {−1,0,2}、長度 0 至 6 的 1,093 組陣列，驗證重複事件、相等配對、未排序兩數和、精確區間計數與最長區間；區間答案以暴力枚舉對照。另測全零、空字串分組、不合法字母表，以及自訂不同物件刻意回傳相同雜湊值時，集合仍能依相等性區分。這些邊界測試用來檢查保存的狀態是否符合各題的查詢需求。

    • 只需存在性時，set 已足夠；需要數量或位置時，用 dict 並明確定義值。
    • 題目關心「之前」，就通常先查詢，再加入目前元素，避免與自己配對。
    • 區間和先寫 P[j] − P[i] = target，再決定保存頻率、最早或最近邊界。
    • 複合鍵應保存影響未來的所有維度，也要保留欄位邊界。
    • 報告平均／攤銷假設、鍵的建構成本、最壞碰撞風險與輸出空間。

    陣列用位置找元素；鏈結串列用「下一個是誰」把節點串起來。每次修改連結前，先說清楚哪些節點已處理、哪些尚未處理，以及通往剩餘資料的入口有沒有保住。本章會用這些關係檢查反轉、刪除、合併與快慢指標的每一步。

    本章的預設條件：除環偵測外，輸入都是有限、無環的單向串列；head 可為 None。範例原地重接節點，會改變呼叫者持有的結構。n 表示節點數；節點值的比較視為 O(1)。若其他程式還持有中間節點的參照，必須先討論修改權限。

    1. 節點、參照與操作成本

    節點包含 value 與 next。head 是指向第一個節點的參照，None 代表沒有節點。兩個節點可以剛好裝著相同的值，卻仍是不同物件。因此「是否走回同一節點」應用 is 比較身分，而不是比較 value。Python 變數賦值通常複製參照；寫 cur = cur.next 只移動游標，不會移動或複製節點。

    單向串列與 Python list 的差異
    操作單向串列Python list
    讀第 i 個元素O(i)，最壞 O(n)O(1)
    頭部插入O(1)O(n)，需搬動參照
    已知前驅後插入／刪除O(1)通常 O(n)
    尋找某個值O(n)O(n)
    尾部插入有 tail 為 O(1)，否則 O(n)攤銷 O(1)

    「鏈結串列刪除是 O(1)」少了一個重要前提：你已持有前驅節點。如果只有目標值，就仍要先 O(n) 尋找。Python 節點通常還有物件與參照的記憶體負擔，快取區域性也比連續陣列差；不能只看插入的大 O 就斷言它在實際程式中一定更快。

    from dataclasses import dataclass
from typing import Optional

@dataclass(eq=False)
class Node:
    value: int
    next: Optional["Node"] = None

def from_values(values):
    dummy = Node(0)
    tail = dummy
    for value in values:
        tail.next = Node(value)
        tail = tail.next
    return dummy.next

def to_values(head):
    """僅用於有限、無環串列；測試工具不算進解法的額外空間。"""
    result = []
    while head is not None:
        result.append(head.value)
        head = head.next
    return result

    eq=False 讓 dataclass 保留物件身分語意，避免遞迴比較整條 next 鏈。from_values 與 to_values 是建構、觀察範例的工具；後者會配置 O(n) 輸出空間，而且不可用來列印未知是否有環的串列。

    2. 反轉：保住尚未處理的入口

    自編題意：給定無環單向串列的 head，原地反轉所有 next，回傳新的頭節點；空串列回傳 None。下方的 6 → 2 → 9 反轉後為 9 → 2 → 6。

    延伸練習：LeetCode 206 · Reverse Linked List。原題同樣要求反轉單向串列並回傳新頭節點。下方使用自編節點值，追蹤每次改線時保存的入口。

    每次迴圈開始，prev 指向已反轉的前段，cur 指向尚未處理的後段。兩段互不重疊，而且合起來恰好是全部原節點。下一步必須先保存 cur.next，再把 cur.next 指回 prev。若先改 next，原本的後段就可能再也找不到。

    def reverse(head):
    prev, cur = None, head
    while cur is not None:
        following = cur.next
        cur.next = prev
        prev, cur = cur, following
    return prev

    逐步例一：6 → 2 → 9

    時刻prev 指向的鏈cur 指向的鏈這輪保存的 following
    開始None6 → 2 → 9尚未保存
    處理 6 後6 → None2 → 92
    處理 2 後2 → 6 → None99
    處理 9 後9 → 2 → 6 → NoneNoneNone

    正確性分三段說：初始化時已反轉段為空，不變量成立；每輪把 cur 的首節點搬到 prev 前方，保留其餘後段，因此不變量繼續成立；終止時 cur 為 None，全部節點都在 prev 中，順序恰好與原本相反。每輪未處理節點數減一，所以有限無環串列必定終止。

    時間 O(n)，演算法額外空間 O(1)。遞迴反轉也可行，但 Python 會消耗 O(n) 呼叫堆疊，且長串列可能超過遞迴深度限制。這裡的 O(1) 不包含既有 n 個節點。

    反轉回傳的是新 head。呼叫時要寫 head = reverse(head)；舊 head 已變成尾端。若串列有環，以上終止與兩段不重疊的推理失效，不能直接套用。

    3. 快慢指標：中點與環

    延伸練習：LeetCode 876 · Middle of the Linked List。原題回傳中點節點，偶數長度取第二個中點。本章使用相同規則，另定義空串列回傳 None。

    找中點時，slow 每輪走一步，fast 每輪走兩步；走了 t 輪後，slow 在第 t 個索引，fast 已走 2t 步或離開串列。先檢查 fast，再檢查 fast.next，才能安全讀 fast.next.next。以下約定偶數長度回傳第二個中點：4 個節點的索引 0、1、2、3，回傳索引 2。

    def middle_second(head):
    """偶數長度時回傳第二個中點；空串列回傳 None。"""
    slow = fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next
    return slow

    環入口題意：輸入 head，沿 next 判斷是否有環；有環時回傳入口節點本身，無環回傳 None，不修改原串列。

    延伸練習：LeetCode 142 · Linked List Cycle II。原題也要求找出環入口，且不能修改串列。頁面中的 pos 只用來描述測試資料如何接回環入口，並不是函式輸入。

    找環不能只看「數值重複」：6 → 6 → None 沒有環。Floyd 方法讓兩個指標從 head 出發，先移動，再比較身分。無環時 fast 會碰到 None；有環時，兩者進入同一個環後，相對距離每輪縮短一格（模環長），因此最多再經一個環長便相遇。

    def cycle_entry(head):
    slow = fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            seeker = head
            while seeker is not slow:
                seeker = seeker.next
                slow = slow.next
            return seeker
    return None

    為什麼第二階段能找入口？設入口距離為 μ、環長為 L，第一次相遇時 slow 共走 t 步、fast 走 2t 步，所以 t 是 L 的倍數。相遇點相對入口的位置是 (t − μ) mod L。讓 seeker 從 head 出發，兩個指標再各走 μ 步：seeker 到入口，slow 的位置則是 t mod L，也正是入口。在 seeker 到入口之前，它仍在環外，兩者不可能提前相遇。

    中點與環入口皆為 O(n) 時間、O(1) 額外空間；有環時 n 指可從 head 抵達的不同節點數。雜湊集合記錄節點也能找重訪點，但多用 O(n) 空間，優點是容易延伸記錄路徑。

    4. Dummy 節點與固定間距：刪倒數第 k 個

    自編題意：輸入無環串列的 head 與正整數 k，刪除倒數第 k 個節點並回傳新 head；空串列或 k 超界時拋 ValueError，且不修改原串列。

    相近題型：LeetCode 19 · Remove Nth Node From End of List。原題用 n 表示倒數位置，保證位置有效。本章改用 k，並補上不合法輸入的檢查；本章 n 仍表示節點總數。

    刪除節點時，要「讓前驅跨過它」。頭節點沒有前驅，所以在 head 前方放一個 dummy（虛擬前驅），就能把刪頭與刪中間統一。dummy.value 沒有資料意義，最後回傳 dummy.next。

    令 slow、fast 從 dummy 出發，先讓 fast 前進 k 步，再同步移動直到 fast 是尾節點。此時 fast 與 slow 恰好相距 k 條邊，因此 slow 是倒數第 k 個節點的前驅。注意停止條件是 fast.next 為 None；若改成 fast 為 None，slow 的位置也要跟著重新推導。

    def remove_from_end(head, k):
    """移除倒數第 k 個節點；k 無效時拋 ValueError 且不修改串列。"""
    if k <= 0:
        raise ValueError("k 必須為正整數")
    dummy = Node(0, head)
    slow = fast = dummy
    for _ in range(k):
        fast = fast.next
        if fast is None:
            raise ValueError("k 大於串列長度")
    while fast.next is not None:
        slow = slow.next
        fast = fast.next
    slow.next = slow.next.next
    return dummy.next

    逐步例二：6 → 2 → 9，刪倒數第 2 個

    步驟slowfast理由／結果
    初始化dummydummy相距 0
    fast 先走第 1 步dummy6相距 1
    fast 先走第 2 步dummy2建立固定間距 2
    同步走一輪69fast 已是尾端
    slow.next 跨過 269結果 6 → 9

    k = n 時，fast 的預走剛好到尾端，slow 仍在 dummy，因此會刪除 head。k = 1 時，slow 最後停在倒數第二個位置。程式先完整驗證 k 的範圍，才改 next；空串列或 k 超界會拋 ValueError，保留原串列。

    時間 O(n)、額外空間 O(1)。dummy 只有一個節點，屬常數空間；垃圾回收何時釋放被移除節點不屬於這段指標推理，其他參照仍可能讓該物件存活。

    5. 合併已排序串列：維持輸出邊界

    自編題意：輸入兩條非遞減、無環且不共享節點的單向串列，沿用原節點合併，回傳排序後的新 head。允許空串列；兩條都為空時回傳 None。

    延伸練習：LeetCode 21 · Merge Two Sorted Lists。原題同樣要求接合既有節點，回傳排序後的串列頭。本章另外明寫不共享節點及相等值先取第一條串列的規則。

    對兩條遞增串列，a 與 b 各是尚未輸出的最小元素。選較小者接到 tail 後方，再移動被選串列的入口。每輪完成後，dummy.next 到 tail 是已確定的排序前綴；a 與 b 是剩餘輸入。相等時先取 a，讓第一條串列的同值元素優先，形成穩定的合併規則。

    def merge_sorted(a, b):
    """兩串列必須無環、遞增（可重複），且不能共享任何節點。"""
    dummy = Node(0)
    tail = dummy
    while a is not None and b is not None:
        if a.value <= b.value:
            tail.next, a = a, a.next
        else:
            tail.next, b = b, b.next
        tail = tail.next
    tail.next = a if a is not None else b
    return dummy.next

    一側耗盡後，另一側已排序且都不小於既有輸出尾值，可直接接上整段。tail 之後的暫時連線還不一定是最終答案，不變量只保證到 tail 為止。兩條輸入必須節點互不重疊：若它們共享尾段，重接時可能把節點接回自己而造成環。

    兩串列長 m、n，時間 O(m + n)，額外空間 O(1)，沿用原節點。若要求不更改輸入，就必須建立新節點，輸出空間為 O(m + n)。

    6. 自編練習與邊界檢查

    延伸練習：LeetCode 876 · Middle of the Linked List。下方自編練習把原題的第二個中點改為第一個中點，請依新的回傳規格調整指標初始位置。

    練習 A：偶數長度改回傳第一個中點

    目前 8 → 3 → 5 → 1 回傳 5。若規格改回傳 3，要如何初始化快慢指標？空串列仍回傳 None。

    參考解答

    先處理 head is None；其餘令 slow = head、fast = head.next，再保留原來的 while fast is not None and fast.next is not None。fast 少了最後一輪可走的空間：n = 2 時 slow 不動，n = 4 時走一輪，落在索引 (n − 1) // 2。奇數長度的中點不變。仍為 O(n) 時間、O(1) 空間。

    延伸練習：LeetCode 237 · Delete Node in a Linked List。原題保證給定節點不是尾節點、各節點值不重複，且以刪除後的值與順序定義結果。下方自編練習則追問：拿掉這些前提，或要求移除特定節點物件時，方法是否仍成立。

    練習 B：只有待刪節點，真的能 O(1) 刪除嗎？

    你只拿到串列中某個節點 target，沒有 head 或前驅。有人建議把下一個節點的值複製過來，再跳過下一個節點。這個方法在哪些規格下不成立？

    參考解答

    target 是尾節點時沒有下一個可複製。即使有下一個節點，這個方法實際移除的也是下一個節點，改寫的則是 target 的值。如果外界靠節點身分保存參照、節點包含不可任意複製的資源，或規格要求真的移除 target，方法就不符合需求。一般單向串列仍需前驅才能正常 O(1) 重接。

    延伸練習：LeetCode 234 · Palindrome Linked List。原題要求回傳串列是否為回文。下方自編練習另要求檢查後還原輸入，並明定空串列與單節點的結果。

    練習 C：回文串列，額外空間 O(1)

    判斷 3 → 8 → 8 → 3 是否左右對稱，並要求函式結束後輸入結構不變。請描述可行步驟與要特別處理的邊界。

    參考解答

    先用快慢指標找「前半段的尾端」，反轉它後面的後半段；從 head 與反轉後的入口比較，走到後半段耗盡即可。最後無論比較是否成功，都把後半段再反轉並接回。不要在第一個不相等時直接 return，否則沒有還原。空串列與單節點直接為真；奇數長度的中間值不用比較。時間 O(n)、額外空間 O(1)，前提仍是無環且允許暫時修改。

    依規格檢查邊界：本章可執行測試涵蓋空／單節點、偶數與奇數長度、反轉兩次還原節點身分、所有合法 k 與超界 k、每個可能環入口、自環、合併重複值。測試應涵蓋迴圈的各個分支，不能只檢查正常輸入的結果。

    7. 決策小結

    • 需要直接讀第 i 個元素：先考慮陣列，鏈結串列沒有隨機存取優勢。
    • 要改 next：先畫改線前後，寫下還需要的入口並保存它。
    • 頭節點常要特殊處理：先試 dummy，把邊界轉成一般前驅操作。
    • 一趟找中點、尾端距離或環：考慮不同速度或固定間距的雙指標。
    • 比較「是不是同一節點」用身分；比較排序或回文內容才用 value。
    • 報告空間前，分清楚原節點、測試轉陣列、輸出新節點與遞迴堆疊。

    05　堆疊與佇列：從配對到單調候選

    本章的範例數據與練習敘述為自編。相關 LeetCode 題目列在對應段落旁，標為「相近題型」或「延伸練習」；規格不同處會另行說明。可先依本章題意完成，再開連結練習。

    遇到需要「回到最近還沒完成的事」，想到堆疊；遇到需要「照抵達順序處理」，想到佇列。如果問題還要求快速找下一個更大的值，或維護視窗最大值，就進一步思考：目前保留的索引中，哪些已找到答案，哪些不必再當候選？本章先說明操作規則，再推導單調結構中 while 迴圈的條件與理由。

    讀完要能做到：分清 LIFO 與 FIFO，說明括號配對為何要檢查堆疊頂端，正確處理重複值的嚴格／非嚴格比較，並證明單調堆疊與單調佇列的總工作量為 O(n)。除特別說明外，整數比較與四則運算採固定大小數值模型。

    1. 兩種等待規則，兩種 Python 容器

    堆疊（stack）是後進先出 LIFO；加入稱 push，拿走最近加入者稱 pop。佇列（queue）是先進先出 FIFO；從尾端加入、頭端取出。這些是抽象規則，不限定某種實體儲存方式。Python 通常以 list 實作堆疊，以 collections.deque 實作雙端佇列。

    from collections import deque

stack = []
stack.append("A")
stack.append("B")
assert stack.pop() == "B"

queue = deque(["A", "B"])
queue.append("C")
assert queue.popleft() == "A"
assert queue[0] == "B"

    操作成本注意事項
    list.append／末端 pop攤銷 O(1)擴容可能讓單次操作較貴
    list.pop(0)O(n)其餘參照須往前移
    deque.append／pop／appendleft／popleft約 O(1)適合兩端操作
    deque 的頭尾索引O(1)中間索引最壞 O(n)

    空容器 pop 或 popleft 會拋 IndexError，要由規格決定回傳特殊值還是先檢查。deque(maxlen=k) 滿時會自動丟棄另一端元素，適合固定容量歷史，但用來存 BFS 待辦或單調候選時，要確認自動丟棄的元素是否仍有用途，否則可能漏掉必要狀態。樹與圖的廣度優先走訪會在第 06 章使用 FIFO。

    2. 括號配對：最近開啟者必須最先關閉

    自編題意：輸入只含 ()、[]、{} 的字串，判斷括號種類與巢狀順序是否完全配對，回傳布林值；空字串為真，其他字元拋 ValueError。

    延伸練習：LeetCode 20 · Valid Parentheses。原題同樣判斷括號是否有效，且保證輸入只含括號。本章額外處理空字串及不合法字元，追蹤例子也自行編寫。

    讀到開括號，把它存入 stack；讀到閉括號，必須與頂端的開括號同種類。只數左右括號無法判斷巢狀順序，例如 ([)] 各類數量都平衡，卻不是合法配對。也不能從堆疊中任選一個相符括號：跨過頂端，就會在內層尚未結束時先結束外層。

    不變量是：只要目前前綴仍合法，stack 從底到頂，恰好保存尚未關閉的開括號，由外層到內層排列。以下輸入只允許六種括號，遇其他字元一律拋 ValueError。即使前面已判定不合法，程式仍掃完整段，以維持這項輸入檢查規格；valid 一旦變 False 就不會恢復。

    def valid_brackets(text):
    """只接受六種括號；其他字元拋 ValueError。"""
    partner = {")": "(", "]": "[", "}": "{"}
    stack = []
    valid = True
    for ch in text:
        if ch in "([{":
            stack.append(ch)
        elif ch in partner:
            if not stack or stack[-1] != partner[ch]:
                valid = False
            else:
                stack.pop()
        else:
            raise ValueError("輸入只能包含括號")
    return valid and not stack

    3. 表達式解析：逆波蘭式與運算元順序

    自編題意：輸入逆波蘭式的字串 token 清單，內容為整數或 +、-、*、//，回傳計算後的整數。例如 ["8", "3", "-", "2", "*"] 回傳 10。不完整式子拋 ValueError，除零拋 ZeroDivisionError。

    相近題型：LeetCode 150 · Evaluate Reverse Polish Notation。原題使用 /，且整數除法向零截斷；本章使用 // 並向下取整，負數結果可能不同。原題保證表達式有效且不除零，因此本章程式不能未經調整就直接提交。

    一般算式要處理優先級與括號；逆波蘭式（後綴式）把運算子放在兩個運算元之後。例如 8 3 − 2 × 表示 (8 − 3) × 2。每讀到數字就 push，讀到運算子就取出兩個已完成的子運算結果，計算後再 push。

    def evaluate_rpn(tokens):
    """逆波蘭式整數運算，// 採 Python 向下取整。"""
    stack = []
    for token in tokens:
        if token not in {"+", "-", "*", "//"}:
            stack.append(int(token))
            continue
        if len(stack) < 2:
            raise ValueError("運算元不足")
        b, a = stack.pop(), stack.pop()
        if token == "+":
            stack.append(a + b)
        elif token == "-":
            stack.append(a - b)
        elif token == "*":
            stack.append(a * b)
        else:
            stack.append(a // b)
    if len(stack) != 1:
        raise ValueError("運算式不完整")
    return stack[0]

    不變量：stack 保存「已讀前綴中，尚未被後續運算子合併的子表達式結果」。先 pop 出來的是右運算元 b，第二個才是左運算元 a，所以要算 a − b 或 a // b。把順序寫反，在加法與乘法測試可能完全看不出來。8 3 − 的堆疊狀態依序是 [8]、[8, 3]、[5]。

    本例 // 明確採 Python 向下取整，因此 −7 // 3 為 −3，並非向零截斷的 −2。不要先用浮點除法再 int，巨大整數可能失去精確度。除零會拋 ZeroDivisionError；運算元不足、最後剩多個結果或沒有結果，都是不完整的表達式。

    t 個 token 的容器操作總共 O(t)，stack 最壞 O(t)。若整數位數可無限成長，字串轉整數、乘法與除法不能再當 O(1)；應額外計算數值的位元長度成本。

    4. 單調堆疊：下一個嚴格較大元素

    相近題型：LeetCode 739 · Daily Temperatures。原題要找下一個嚴格較高溫的日子，回傳等待天數，找不到時填 0。本章先回傳下一個嚴格較大元素的索引，找不到時填 −1；改成距離時，要同時調整輸出值與無解記號。

    任務：對每個索引 i，找右側第一個值嚴格大於 values[i] 的索引，沒有就回傳 −1。逐格向右找最壞 O(n²)。掃描時也可以從新值出發：它是否是某些舊位置一直在等的第一個較大值？

    stack 存索引，而且索引遞增、對應值從底到頂非遞增。看到 value 時，頂端若比較小，它的第一個較大值就是現在：如果更早已有較大值，它當時早就被移除了。持續 pop 所有小於 value 的頂端，再把目前索引加入。相等值不能解決「嚴格較大」的要求，所以保留下來。

    def next_greater_indices(values):
    answer = [-1] * len(values)
    stack = []  # 未找到右側「嚴格較大」值的索引。
    for i, value in enumerate(values):
        while stack and values[stack[-1]] < value:
            answer[stack.pop()] = i
        stack.append(i)
    return answer

    5. 單調雙端佇列：固定視窗最大值

    自編題意：輸入整數陣列 values 與合法視窗長度 k，依視窗從左往右的順序，回傳每個視窗的最大值清單。例如 [4,1,3,3,0,5]、k = 3 回傳 [4,3,3,5]；k 不合法時拋 ValueError。

    延伸練習：LeetCode 239 · Sliding Window Maximum。原題同樣回傳每個固定長度視窗的最大值。下方使用自編數據，另示範同值候選如何選擇與過期。

    現在對每個長度 k 的連續視窗找最大值。堆疊只能在一端移除，不方便淘汰最舊元素；deque 能從頭移除過期索引，從尾移除被新值壓過的候選。deque 中只保存仍可能成為某個未來視窗最大值的索引。

    維持三個不變量：索引由小到大；所有索引都在目前視窗中；對應值由大到小。對新位置 i，先移除索引 ≤ i − k 的過期頭端，再移除尾端所有值 ≤ values[i] 的候選，最後加入 i。當視窗已湊滿 k 個，頭端就是最大值。

    from collections import deque

def sliding_maximum(values, k):
    if not 1 <= k <= len(values):
        raise ValueError("k 必須介於 1 與資料長度之間")
    candidates = deque()  # 索引遞增，對應值嚴格遞減。
    answer = []
    for i, value in enumerate(values):
        while candidates and candidates[0] <= i - k:
            candidates.popleft()
        while candidates and values[candidates[-1]] <= value:
            candidates.pop()
        candidates.append(i)
        if i >= k - 1:
            answer.append(values[candidates[0]])
    return answer

    1／1無無[0:4, 1:1]未滿

    刪除尾端的正確性來自「支配關係」：若較新的 i 之值不小於舊 j，任何之後仍包含 j 的視窗也包含 i，而且 i 不會更早過期，所以 j 永遠不再必要。這個推理說明了為什麼可以安全刪除 j；只檢查「維持遞減」，還不足以證明不會漏掉答案。

    每個索引加入一次，從某一端離開至多一次，因此時間 O(n)，候選空間 O(k)，輸出空間 O(n − k + 1)。本例要求 1 ≤ k ≤ n，空資料沒有合法 k；若產品規格想在空資料回傳 []，要明確加上例外規則並測試。

    不要把所有位置只存成值：重複值會讓「哪一個已過期」難以區分。也不要從一般 list 做 pop(0)；雖然結果可能仍正確，複雜度卻可能變成 O(nk)。

    def first_bracket_error(text):

    for i, ch in enumerate(text):
        if ch in "([{":
            stack.append((ch, i))

            stack.pop()
        else:

    06｜樹與圖：走訪、邊界與狀態

    樹與圖的題目在選演算法之前，往往要先說清楚「什麼是一個狀態、哪些狀態相鄰、什麼時候算走過」。本章從二元樹談到迷宮，以待處理集合與不變量為共同線索，說明 DFS、BFS、BST 與隱式圖。

    學完要能做到：依需要選擇 DFS 或 BFS；分清一般二元樹與二元搜尋樹；把「找得到」與「最短」分開；知道 visited 應在何時標記，以及它的鍵應包含哪些資訊。先備：第 01 章遞迴、第 05 章堆疊與佇列。

    一、寫走訪程式前，先確認資料結構

    圖由頂點與邊構成。無向邊表示雙向連結，有向邊表示只能沿箭頭走。簡單無向樹是連通且無環的圖；選一個根之後，除了根以外，每個節點都有一個父節點。二元樹進一步限制每個節點最多兩個孩子，而且左右位置有意義。

    本章二元樹假設沒有環，也沒有被兩個父節點共用的孩子；若輸入其實是一般物件圖，就不能直接省略 visited。節點「值相同」不代表「同一個節點」，所以一般樹的走訪不能拿 value 當成去重鍵。圖範例則把頂點編號為 0 到 V−1，鄰居編號都必須有效。

    • 深度：從根到節點的邊數；根深度為 0。
    • 高度：從節點到最深葉子的邊數；葉子高度為 0。本章約定空樹高度為 −1。
    • n 是樹的節點數，h 是高度，w 是最寬一層的節點數；圖使用 V、E 表示頂點與邊數。

    二、二元樹 DFS：把「做事時機」放在正確位置

    對應原題：前序與中序走訪分別對應 LeetCode 144：Binary Tree Preorder Traversal、LeetCode 94：Binary Tree Inorder Traversal。輸入是一棵二元樹，輸出依指定次序排列的節點值；空樹輸出 []。本章的樹形、數字與逐步表格均為自編，上圖的中序結果是 [2,5,9,12,18,21]。

    相近題型：高度計算可對照 LeetCode 104：Maximum Depth of Binary Tree。該題以最長根到葉路徑的「節點數」計最大深度；本章 tree_height 以「邊數」計高度，空樹為 −1。因此上圖在該題答案是 3，在本章高度函式則是 2，不能直接照抄回傳值。

    DFS 是先深入某個分支，再回來處理尚未完成的分支。以遞迴 visit(node) 為例，進入函式時處理 node 是前序；左子樹回來後處理是中序；左右子樹都回來後處理是後序。三種次序共用同一個走訪架構，差別在於何時處理節點。

    • 前序：根、左、右。適合在往下走時帶入路徑資訊。
    • 中序：左、根、右。嚴格 BST 的中序值會嚴格遞增；一般二元樹沒有這個保證。
    • 後序：左、右、根。適合等孩子的答案都算好後，組合高度、大小或子樹結果。
    def preorder(root: Node | None) -> list[int]:
    if root is None:
        return []
    result, stack = [], [root]
    while stack:
        node = stack.pop()
        result.append(node.value)
        # LIFO: push right first so left is visited first.
        if node.right is not None:
            stack.append(node.right)
        if node.left is not None:
            stack.append(node.left)
    return result

def inorder(root: Node | None) -> list[int]:
    result = []

    def visit(node: Node | None) -> None:
        if node is None:
            return
        visit(node.left)
        result.append(node.value)
        visit(node.right)

    visit(root)
    return result

def tree_height(root: Node | None) -> int:
    # Height is measured in edges: empty = -1, leaf = 0.
    if root is None:
        return -1
    return 1 + max(tree_height(root.left), tree_height(root.right))

    不變量與正確性：堆疊存著已發現、尚未處理的子樹根。每次取出一個根，只把它的孩子各放入一次；依照「先右後左」安排，左子樹的待處理節點都位於右子樹的待處理節點上方。因此每個節點恰好輸出一次，且符合根、左、右。高度函式則用結構歸納：空樹的 −1 是基底；假設兩個孩子回傳正確高度，較深孩子的高度加一，就是父節點高度。

    三個函式都走訪 n 個節點，時間 O(n)。遞迴或二元樹 DFS 堆疊輔助空間最壞 O(h+1)，退化成鏈時可達 O(n)；有輸出清單的版本另需 O(n) 結果空間。不要把一般 n 叉樹一次推入所有孩子的堆疊也一概寫成 O(h)。Python 的執行環境限制了遞迴深度。輸入深度未知或極深時，優先改用顯式堆疊，以免正確的演算法仍因超過深度限制而失敗。
    遞迴中反覆使用「左清單 + [根] + 右清單」會複製清單；在退化樹可能累積 O(n²) 時間。上面的中序版本把值 append 到同一個結果清單，避免這個成本。

    三、二元樹 BFS：一輪處理一整層

    對應原題：LeetCode 102：Binary Tree Level Order Traversal。給二元樹，按深度由淺至深回傳各層的值，同層由左到右；空樹回傳 []。本節用自編六節點樹示範，輸出為 [[12],[5,18],[2,9,21]]。

    BFS 使用先進先出的佇列。若只是想訪問全部節點，DFS 與 BFS 都行；若答案跟深度、層數或同一層有關，BFS 通常更直接。每一輪開始時要先固定這一層的大小，否則這一輪中新加入的孩子也可能被算進本層。

    def level_order(root: Node | None) -> list[list[int]]:
    if root is None:
        return []
    result, queue = [], deque([root])
    while queue:
        level = []
        for _ in range(len(queue)):
            node = queue.popleft()
            level.append(node.value)
            if node.left is not None:
                queue.append(node.left)
            if node.right is not None:
                queue.append(node.right)
        result.append(level)
    return result

    上圖依序形成 [12]、[5, 18]、[2, 9, 21]。第二輪開始時 len(queue)=2；彈出 5 後即使已加入 2、9，這一輪也只剩下一個原本的節點 18 要處理。Python 的 range(len(queue)) 在建立 range 時就固定了次數。

    不變量：每輪開始時佇列恰好是同一深度的所有節點，且由左至右排列。依序取出它們並依左右順序加入孩子，恰好建立下一層，所以分層結果正確。

    時間 O(n)，輔助佇列空間 O(w)，結果另外占 O(n)。佇列在一輪中可能同時含兩層的部分節點，但仍是 O(w)。使用 deque.popleft()，不要用 list.pop(0)，後者會搬動其餘元素。

    四、BST：大小條件適用於整棵子樹

    對應原題：搜尋與驗證分別對應 LeetCode 700：Search in a Binary Search Tree、LeetCode 98：Validate Binary Search Tree。搜尋回傳目標節點及其子樹，找不到回傳 None；驗證則回傳是否符合嚴格 BST 規則。例如在前圖搜尋 5，會回傳以 5 為根、孩子為 2 與 9 的子樹。兩題原題都給非空樹，本章程式另處理空樹。圖例與節點數字為自編。

    本章採用嚴格 BST：左子樹每個值都小於根，右子樹每個值都大於根，不接受重複值。其他題目可能允許重複鍵，並指定重複鍵要放哪一側；必須先確認規則，再決定能否沿用這個驗證式。

    搜尋時，比根小就往左，比根大就往右；被捨棄的整個子樹都不可能有答案。這個推理依賴輸入已經是 BST，不能拿搜尋函式順便「驗證」它。搜尋只走一條根到葉的路徑，時間 O(h+1)、空間 O(1)；平衡時 h 為 O(log n)，未平衡時可以是 n−1。

    def bst_search(root: Node | None, target: int) -> Node | None:
    while root is not None:
        if root.value == target:
            return root
        root = root.left if target < root.value else root.right
    return None

def is_valid_bst(root: Node | None) -> bool:
    # Strict BST: duplicate keys are not permitted.
    stack = [(root, None, None)]
    while stack:
        node, lower, upper = stack.pop()
        if node is None:
            continue
        if lower is not None and node.value <= lower:
            return False
        if upper is not None and node.value >= upper:
            return False
        stack.append((node.right, node.value, upper))
        stack.append((node.left, lower, node.value))
    return True

    驗證不變量：每個待處理項目的 lower、upper，是所有祖先對這棵子樹的共同限制。往左保留下界、收緊上界；往右保留上界、收緊下界。如果每個節點都在嚴格開區間內，所有祖先的左右子樹要求就都成立。時間 O(n)，二元樹顯式堆疊 O(h+1)；用 None 表示無界，避免把合法整數值誤當哨兵。

    五、一般圖 DFS：環、重複路徑與不連通分量

    自編範例／相近題型：本節輸入鄰接清單與有效起點，回傳整個可達頂點集合。可延伸練習 LeetCode 1971：Find if Path Exists in Graph；該題輸入無向邊清單，只問指定起終點是否連通，回傳布林值，沒有要求輸出可達集合。

    一般圖的同一頂點可能經由不同路徑到達。菱形中的兩條路可能在同一頂點會合，無向圖還能沿同一條邊走回去。因此，除了待處理集合，還需要 seen 記錄已經發現的頂點。

    鄰接清單 graph[u] 列出 u 能走到的鄰居。無向邊 (u,v) 通常存兩次，一次放在 graph[u]、一次放在 graph[v]；有向邊只放指定方向。這個表示法儲存 O(V+E) 個項目，無向邊的兩份不改變漸近量級。

    def dfs_reachable(graph: list[list[int]], start: int) -> set[int]:
    seen, stack = {start}, [start]
    while stack:
        node = stack.pop()
        for neighbor in graph[node]:
            if neighbor not in seen:
                seen.add(neighbor)  # Mark before pushing.
                stack.append(neighbor)
    return seen

    在推入堆疊時就標記。這使每個頂點最多進入待處理集合一次。若等彈出才標記，多個鄰居可能在它還沒處理之前把它重複推入；若沒有進一步跳過已訪問節點，甚至會重做大量工作。本函式只保證可達集合，不保證與遞迴 DFS 完全相同的訪問順序，也不能直接把它的彈出順序當成 DFS 完成時間。

    從起點出發只能得到該起點可達的部分。無向圖若想數連通分量，要再用一個外層迴圈掃過所有頂點，遇到未見過的起點才啟動走訪。有向圖不能把這個外層技巧直接稱為強連通分量演算法；沿有向邊到得了對方，不代表對方也到得了自己。

    單次走訪的時間為 O(Vᵣ+Eᵣ)，其中 Vᵣ、Eᵣ 是可達部分的頂點與相鄰邊數；整張圖完整掃描為 O(V+E)。seen 與堆疊至多 O(V)。以上使用 Python set/dict 平均 O(1) 的查找假設；這個平均分析不保證極端碰撞時仍有相同成本。

    六、無權圖 BFS：第一次發現，就得到最少邊數

    自編範例：本節求無權圖的一條最短路，沒有指定的 LeetCode 原題。圖例可寫成 graph=[[1,2],[0,3],[0,3],[1,2,4],[3],[]]；起點 0、終點 4 時，本程式回傳 [0,1,3,4]。若有多條同長最短路，任一條都合法；起終點須是有效頂點，找不到路時回傳 None。

    如果每走一條邊的代價相同，最短路就是最少邊數。BFS 先處理距離 0，再處理距離 1、2……。除了 visited，還可以記錄 parent：某頂點第一次被誰發現。從終點不斷回溯父節點，再反轉，就能重建一條最短路。

    def shortest_path(graph: list[list[int]], start: int,
                  target: int) -> list[int] | None:
    parent = {start: None}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        if node == target:
            path = []
            while node is not None:
                path.append(node)
                node = parent[node]
            return path[::-1]
        for neighbor in graph[node]:
            if neighbor not in parent:
                parent[neighbor] = node
                queue.append(neighbor)
    return None
    逐步例子 B：從 0 找到 4
    彈出新發現與父節點處理後佇列
    0parent[1]=0；parent[2]=0[1, 2]
    1parent[3]=1[2, 3]
    23 已發現，略過[3]
    3parent[4]=3[4]
    4回溯 4 → 3 → 1 → 0答案 [0, 1, 3, 4]

    為什麼第一次發現就是最短？佇列按距離不遞減順序取出頂點。當距離 d 的 u 發現 v 時，長度 d+1 的路已存在；如果 v 有更短路，那條路的倒數第二個頂點距離小於 d，理應更早處理並發現 v，與「這是第一次」矛盾。

    parent 同時兼作 visited；起點的 parent 是 None，因此起點也被標記了。start==target 時回傳 [start]，路徑含一個頂點但距離是 0。找不到時回傳 None，與合法空步數區分。最壞時間 O(V+E)，輔助空間 O(V)，重建路徑再花與路徑長度成正比的時間與空間。

    有權圖中，一條邊不一定比兩條邊便宜。BFS 不能拿來最小化任意票價或耗時；第 13 章的非負權重最短路才使用 Dijkstra。DFS 找到的第一條路也不保證最短。

    七、隱式圖：依規則產生鄰居

    自編範例：本節網格只允許上下左右移動，以移動次數計距離。下圖輸入是 [[0,0,1,0],[1,0,0,0],[0,0,1,0]]，輸出為 5。不能走牆格；空網格、起終點為牆或無路可走時回傳 −1，非矩形輸入拋 ValueError。

    迷宮、字串替換、鎖碼與遊戲局面都是圖，只是鄰居由規則即時計算。以 0 代表可走、1 代表牆的矩形網格為例：頂點是 (row,col)，相鄰是上下左右的合法空格。每步代價相同，所以找最少移動次數用 BFS；起點左上、終點右下。

    def grid_distance(grid: list[list[int]]) -> int:
    # 0 = open, 1 = wall. Return the number of moves, not cells.
    if not grid or not grid[0]:
        return -1
    rows, cols = len(grid), len(grid[0])
    if any(len(row) != cols for row in grid):
        raise ValueError('grid must be rectangular')
    if grid[0][0] or grid[-1][-1]:
        return -1
    queue = deque([(0, 0, 0)])
    seen = {(0, 0)}
    while queue:
        row, col, distance = queue.popleft()
        if (row, col) == (rows - 1, cols - 1):
            return distance
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = row + dr, col + dc
            if (0 <= nr < rows and 0 <= nc < cols
                    and grid[nr][nc] == 0 and (nr, nc) not in seen):
                seen.add((nr, nc))
                queue.append((nr, nc, distance + 1))
    return -1

    走到同一個格子卻有不同剩餘資源，是否還算同一個狀態？不一定。若可以破牆一次，「已用掉破牆」和「還留著破牆」會影響未來可走的路。visited 只放座標就可能刪掉必要路徑。狀態必須保留所有會影響後續選擇的資訊；後面的動態規劃與限制轉乘最短路，也需要依這個原則定義狀態。

    練習 1｜只加總葉節點

    自編題：本題加總所有葉節點，沒有額外限制只取左葉或右葉。完整題意、範例與空樹規格如下。

    給一般二元樹，回傳所有葉節點值的總和。值可以是負數；空樹回傳 0。上面的六節點樹答案是 2+9+21=32。請不要把「只有一個孩子」的節點算成葉子。

    參考解答

    使用 DFS；只有左右都不存在才累加。不變量是 total 恰好等於已彈出葉節點的值之和，每個節點恰好處理一次。時間 O(n)，輔助空間 O(h+1)。

    def leaf_sum(root: Node | None) -> int:
    if root is None:
        return 0
    total, stack = 0, [root]
    while stack:
        node = stack.pop()
        if node.left is None and node.right is None:
            total += node.value
        if node.right is not None:
            stack.append(node.right)
        if node.left is not None:
            stack.append(node.left)
    return total

    練習 2｜每個社群有多少成員？

    自編題／相近題型：可對照 LeetCode 547：Number of Provinces。該題用對稱鄰接矩陣表示城市連線，輸出連通分量的個數；本題用鄰接清單，輸出各分量的大小。輸入表示法與回傳內容都不同。

    給無向圖的鄰接清單，回傳每個連通分量的大小，依最小未訪問頂點啟動的順序輸出。五個互相連通的頂點加一個孤立頂點，應得到 [5,1]。空圖得到 []。

    參考解答

    外層迴圈尋找新的起點，內層迴圈走訪該起點所在分量的所有頂點。內層結束時，所有與起點相連的頂點都已被標記，後續不會重複計數。所有走訪共用 seen，所以總時間是 O(V+E)，不是「外層 V 次 × 每次完整走圖」；輔助空間 O(V)。

    def component_sizes(graph: list[list[int]]) -> list[int]:
    # graph must be undirected; every edge is represented both ways.
    seen, sizes = set(), []
    for start in range(len(graph)):
        if start in seen:
            continue
        seen.add(start)
        stack, size = [start], 0
        while stack:
            node = stack.pop()
            size += 1
            for neighbor in graph[node]:
                if neighbor not in seen:
                    seen.add(neighbor)
                    stack.append(neighbor)
        sizes.append(size)
    return sizes

    練習 3｜多一張破牆券

    改編題型：對照 LeetCode 1293：Shortest Path in a Grid with Obstacles Elimination：同樣在矩形網格由左上走到右下，只准上下左右移動，求最少步數。原題最多可移除 k 個障礙；本題固定 k=1，使用自編輸入，另處理空網格與無效矩形。原題與本題都要求起終點為空格。

    延續網格題，最多可以進入一個牆格；起點與終點仍必須是空格。求最少步數，無解回傳 −1。[[0,1],[1,0]] 的答案應是 2。請說明為什麼不能沿用只記錄座標的 visited。

    參考解答

    把節點擴成 (row,col,used)，used 只有 0、1 兩種。每次進入牆格便加一，超過一就不能入隊。visited 只排除完全相同的狀態；同座標但不同券數可以同時存在。BFS 的最短路證明仍適用於這張擴展圖。最多 2RC 個狀態，每個四條轉移，因此時間、空間皆 O(RC)。

    def grid_one_break(grid: list[list[int]]) -> int:
    # At most one wall cell may be entered; start/end must be open.
    if not grid or not grid[0]:
        return -1
    rows, cols = len(grid), len(grid[0])
    if any(len(row) != cols for row in grid):
        raise ValueError('grid must be rectangular')
    if grid[0][0] or grid[-1][-1]:
        return -1
    queue = deque([(0, 0, 0, 0)])  # row, col, used, moves
    seen = {(0, 0, 0)}
    while queue:
        row, col, used, moves = queue.popleft()
        if (row, col) == (rows - 1, cols - 1):
            return moves
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = row + dr, col + dc
            if 0 <= nr < rows and 0 <= nc < cols:
                next_used = used + grid[nr][nc]
                state = (nr, nc, next_used)
                if next_used <= 1 and state not in seen:
                    seen.add(state)
                    queue.append((nr, nc, next_used, moves + 1))
    return -1

    練習 4｜「中序有排序」真的夠嗎？

    自編推理題：延伸自本章嚴格 BST 驗證問題，可回看 LeetCode 98：Validate Binary Search Tree。這裡要論證中序序列與 BST 條件的關係，並非另有一題要求這種文字回答。

    在本章禁止重複鍵的規則下，能否把整棵樹中序走訪後，檢查相鄰值是否嚴格遞增，作為 BST 驗證？如果只檢查「不遞減」呢？

    參考解答

    嚴格遞增是充分且必要的。每個根的左子樹在中序序列中全部排在根之前，右子樹全部排在之後；序列嚴格遞增便能保證左側全小於根、右側全大於根。不遞減不足以符合本章規則，例如根 4、左孩子 4 的中序是 [4,4]，仍非法。若儲存完整結果，時間 O(n)、空間 O(n)；也可以顯式中序走訪時只保留上一個值，把輔助空間降至 O(h+1)。

    九、邊界測試與方法選擇

    • 空樹、單節點、全部偏左的鏈、重複值、負值，以及只違反祖先範圍的 BST 反例。
    • 圖有孤立頂點、自環、重複鄰居、起終點相同、終點不可達；無向邊是否雙向存放。
    • 網格只有一格、起終點堵住、無解；步數是否誤算成經過格數。

    07　堆積與優先佇列：保留最重要的候選

    你未必需要把所有資料完整排序。工作排程可能只需要下一個最早到期者，資料流只需要目前第 k 大，多條排序串流合併時只需要各來源的下一個值。堆積（heap）只維持部分排序關係，讓加入資料與取出極值的成本較低。本章以 Python 的最小堆積為基礎，說明如何保留 top-k、維持穩定優先權，以及合併多條串流。

    先釐清名詞：本章的 heap 是二元堆積資料結構，與程式記憶體區域的「heap」不同。優先佇列是抽象需求，二元堆積是常見實作。所有輸入值須可相互比較，並遵守一致的排序規則；不把浮點 NaN 混入教學範例。

    1. 陣列裡的完全二元樹

    最小堆積維持兩項條件：形狀是一棵完全二元樹，最後一層由左至右填滿；每個父節點的值不大於其子節點。採零起算索引時，位置 i 的左子是 2i + 1、右子是 2i + 2、父節點是 (i − 1) // 2（根沒有父節點）。因此不必建立樹節點物件，就能用陣列表示。

    沿根出發的每條路徑，值都不會變小，因此根是全域最小值；次小值可能在左子或右子，更深處也沒有跨子樹排序保證。讀 heap[0] 是 O(1)，找任意值則仍可能 O(n)。如果需求是大量查第 i 小、區間搜尋或完整有序走訪，堆積未必適合。

    2. 上浮、下沉與 O(n) 建堆

    加入新值時，把它放在陣列末端以保留完全樹形，再與父節點比較，必要時往上交換，稱為上浮。刪除根時，先把最後一個值補到根，然後反覆與較小的子節點交換，稱為下沉。每次只沿一條根到葉的路徑，所以比較與交換步數都是 O(log n)。

    修復前，新值所在路徑以外的父子關係都仍合法。沿正確方向交換，就能把唯一可能違反堆積條件的位置往上或往下移，直到所有父子關係都符合條件。下沉若任意挑一個子節點交換，可能讓另一個更小的子節點留在父節點下方，破壞堆積條件。

    heapify 不是把每個元素逐一 heappush。它從最後一個非葉節點往根修復；葉節點本身已是合法的單節點堆積，不需要修復。大約一半的節點不需下沉，四分之一最多下一層，八分之一最多下兩層；總成本可用 n × (1/4 + 2/8 + 3/16 + …) 這個收斂和來估計，所以是 O(n)，不是 O(n log n)。

    import heapq

heap = [12, 3, 8, 7, 9, 5, 6]
heapq.heapify(heap)            # 原地建堆；陣列不必是唯一排列
assert heap[0] == 3
heapq.heappush(heap, 2)
assert heapq.heappop(heap) == 2
assert heapq.heappop(heap) == 3

    heapq 操作一般的 list，函式不會替你確認整個 list 已經有堆積性質。heapify 會原地更動資料；若要保留原序列，要先 heap = list(values)，而這個複製另用 O(n) 空間。Python 底層 list 偶爾需要擴容，所以加入的常見 O(log n) 分析對容器配置採攤銷成本；數值比較也假設是 O(1)。

    常用 heapq 操作
    操作意義成本與空堆行為
    heapify(h)把現有 list 原地變成最小堆積O(n)，空 list 合法
    heappush(h, x)加入 xO(log(n + 1))
    heappop(h)取出原本最小值O(log n)，空時 IndexError

    heappushpop 與 heapreplace 順序不同。若 h = [4, 8, 6] 且 x = 2，pushpop 回傳 2，留下原本三個元素；replace 回傳 4，堆中則加入 2。固定容量 top-k 若不先檢查新值，就直接 heapreplace，可能把較大的候選換成較小者。

    3. 最大的 k 個，為何使用「最小」堆積？

    自編範例／相近題型：本節回傳最大的 k 個值，並由大到小排列。可對照 LeetCode 215：Kth Largest Element in an Array；該題只回傳第 k 大的一個值，且保證 1 ≤ k ≤ n。兩者都把重複值算成各自的名次；本章另定義 k=0 與 k>n 的行為。

    要留下最大的 k 個值，根應放目前保留值中最容易被淘汰的那一個。它是「目前保留集合中最小的值」，因此選最小堆積。新值比根大就有資格進來，否則直接略過。只看「找最大」這個說法，容易誤以為這裡應該用最大堆積。

    不變量：處理任一前綴後，heap 恰好保存該前綴最大的 min(k, 已讀數量) 個值，重複值按各次出現計數。未滿 k 時全部保留；已滿時，只有新值大於根才交換。因為根是保留者中最小的，交換後仍是前綴最大的 k 個。

    import heapq

def largest_k(numbers, k):
    """回傳最大的至多 k 個數，降序排列；相同數值按出現次數計。"""
    if k < 0:
        raise ValueError("k 不可為負")
    if k == 0:
        return []
    heap = []
    for value in numbers:
        if len(heap) < k:
            heapq.heappush(heap, value)
        elif value > heap[0]:
            heapq.heapreplace(heap, value)
    return sorted(heap, reverse=True)

    逐步例一：資料 11、4、8、15、7、13，k = 3

    讀入動作heap 陣列（合法排列之一）目前第 3 大
    11未滿，加入[11]資料不足
    4未滿，加入[4, 11]資料不足
    8未滿，加入[4, 11, 8]4
    1515 > 4，替換根[8, 11, 15]8
    77 ≤ 8，略過[8, 11, 15]8
    1313 > 8，替換根[11, 13, 15]11

    函式最後排序得到 [15, 13, 11]。不能直接回傳 heap 並宣稱它已由大到小排序。若只要第 3 大，根 11 就足夠，不用最後排序。

    令 r = min(k, n)，k > 0 時，維護成本 O(n log(r + 1))，最後排序 O(r log(r + 1))；heap 與回傳結果各用 O(r) 空間。k = 0 立即回傳 []，連輸入迭代器也不消耗。k > n 時本規格回傳全部 n 個，k < 0 則拋 ValueError。

    如果 k 接近 n，直接 sorted(numbers) 可能更簡單；如果資料已全在記憶體、只問一次第 k 大，也可研究選擇演算法。當 k 很小、資料逐筆到來，或答案需要持續更新時，堆積較能發揮作用。

    4. 資料流的第 k 大

    改編題型：對照 LeetCode 703：Kth Largest Element in a Stream。原題建構子接收 k 與初始 nums，條件保證首次 add 後已有至少 k 筆資料。本章從空資料流開始，建構子只接收 k，資料不足時回傳 None；要提交原題，須依原題介面加入初始資料處理。下方輸入與回傳序列為自編。

    處理資料流時，無法預先知道總長度，也不適合每收到一筆就把所有資料重新排序。把上面的 heap 保留下來，每次 add 只更新這個大小至多 k 的狀態。資料不足 k 筆時回傳 None，避免把「目前最小值」誤稱為「第 k 大」。

    import heapq

class KthLargest:
    """add 回傳目前第 k 大；不足 k 筆則回傳 None。"""
    def __init__(self, k):
        if k <= 0:
            raise ValueError("k 必須為正整數")
        self.k = k
        self.heap = []

    def add(self, value):
        if len(self.heap) < self.k:
            heapq.heappush(self.heap, value)
        elif value > self.heap[0]:
            heapq.heapreplace(self.heap, value)
        return self.heap[0] if len(self.heap) == self.k else None

    對 k = 3，依序加入 11、4、8、15、7、13，add 的回傳依序是 None、None、4、8、8、11。重複值有獨立名次：5、5、2 的第 2 大是 5，而不是 2。若題目要第 k 個「不同值」，不變量與去重規則都要改。

    每次 add 最壞 O(log(k + 1))，被略過的值只需 O(1) 比較；查根 O(1)，狀態 O(k)，不足 k 筆時實際只保存已收到的筆數。這裡的資料流只會加入，不支援過期或刪除；滑動視窗的第 k 大不能直接照搬。

    5. 平手、無法比較的物件與更新陷阱

    自編實作題：這是一般優先佇列介面示範，沒有指定的 LeetCode 原題。push 加入優先權與資料，pop 回傳優先權最小的資料；同優先權按加入順序取出，空佇列 pop 會拋 IndexError。

    Python tuple 由左到右比較。若放 (priority, payload)，兩個 priority 相同時就會比較 payload；dict 等資料不一定可排序，可能在平手時拋 TypeError。加入唯一遞增序號，改存 (priority, serial, payload)，就能讓平手維持先到先出，且完全不需要比較 payload。

    import heapq
from itertools import count

class StablePriorityQueue:
    """priority 越小越先取出；相同 priority 保持加入順序。"""
    def __init__(self):
        self.heap = []
        self.serial = count()

    def push(self, priority, payload):
        heapq.heappush(self.heap, (priority, next(self.serial), payload))

    def pop(self):
        return heapq.heappop(self.heap)[2]

    這個實作會先處理 priority 較小的項目；若需求定義為數字越大越優先，可存負 priority。這種負號技巧也能以最小堆積模擬數值的最大堆積，並讓範例不依賴較新版本才有的 API。

    不要直接修改 heap 中某項的 priority，父子順序不會自動修復。一般 heapq 也沒有直接按任意 key 找元素、降低優先權的操作。簡單方案是重建 O(n)；更進階可另存 task 的版本，在 heap 加入新版，取出時跳過舊版。但舊項目會累積，空間要按「尚未清理的項目數」計算，不能仍宣稱只與有效任務數成正比。

    平手是否按加入順序處理、任務能否取消，以及是否需要併發安全，都要在優先佇列的規格中另外確認；heapq 不會自動保證這些行為。本章範例假設只在單執行緒使用。

    6. 合併多條排序串流：每條只保留一個前端候選

    相近題型：LeetCode 23：Merge k Sorted Lists 要合併多條已排序的鏈結串列，回傳合併後的鏈結串列。本節改用排序串流與迭代器，逐筆產生值，沒有建立或重接鏈結節點；前端候選的選取原理相同，介面不能直接互換。A、B、C 的示範資料為自編。

    有 m 條遞增串流，每條都已排序。全域下一個最小值一定是某一條的第一個未輸出值，因此不必把全部 N 筆資料放進 heap。先放每條非空串流的一個前端候選；取出最小者後，只向同一來源索取下一個值。

    import heapq

def merge_sorted_streams(streams):
    """每條輸入須已依遞增排序；同來源只保留下一個候選。"""
    heap = []
    for source, stream in enumerate(streams):
        iterator = iter(stream)
        try:
            value = next(iterator)
        except StopIteration:
            continue
        heap.append((value, source, iterator))
    heapq.heapify(heap)
    while heap:
        value, source, iterator = heapq.heappop(heap)
        yield value
        try:
            following = next(iterator)
        except StopIteration:
            continue
        heapq.heappush(heap, (following, source, iterator))

    heap 中的 tuple 是 (value, source, iterator)。source 是唯一的來源編號；每個來源同時至多一個候選，因此 value 相同時，比較到 source 就能分出順序，不會比較 iterator。相同值時編號小的來源先出；若需要別種平手規則，應另放對應的穩定序號。

    逐步例二：A = [−2, 5, 10]、B = [1, 5]、C = [0, 6, 9]

    回合取出前候選（列成有序方便閱讀）輸出同來源補入
    1A:−2、C:0、B:1−2A:5
    2C:0、B:1、A:50C:6
    3B:1、A:5、C:61B:5
    4A:5、B:5、C:65A:10
    5B:5、C:6、A:105B 耗盡
    6C:6、A:106C:9
    7C:9、A:109C 耗盡
    8A:1010A 耗盡，heap 空

    正確性由來源排序保證：任何尚未輸出的值都不小於自己來源的前端，所以 heap 根就是所有剩餘資料中的最小值。輸出根並補入同來源下一個值，恢復這個不變量；heap 空代表所有來源耗盡。若有一條來源不是排序的，例 [9, 1]，藏在後面的 1 就可能太晚出現，整體結果不再有序。

    設總輸出 N 筆、來源數 m、非空來源數 a。初始化掃描 O(m)，heapify O(a)，逐筆處理 O(N log(a + 1))，內部候選空間 O(a)。生成器 yield 不會自行保存全部輸出；若呼叫者用 list(...) 收集，另需 O(N) 輸出空間。來源集合需有限，否則初始化可能永遠不能完成。

    7. 原創練習與解答

    練習 A：留下最小的 k 筆延遲

    自編題：將本章保留最大值的規則反向使用，以固定大小狀態保留最小延遲。延遲資料與題目要求為本教材自編。

    測試延遲依序為 [42, 17, 31, 12, 29]，只留最小的 2 筆，要求不保存全部輸入。你應把哪個值放在淘汰門檻？

    參考解答

    門檻應是保留者中最大的值。以最小堆積存負值：保留 17、42 時存 [−42, −17]，根代表最大保留值 42。新值 x 小於 −heap[0] 才替換根，實際放入 −x。最後取反並排序得到 [12, 17]。k > 0 時維護 O(n log(k + 1))、空間 O(k)，並需處理 k = 0 與負 k。

    練習 B：第 k 大「不同」值

    自編延伸題／相近題型：可練習 LeetCode 414：Third Maximum Number。該題固定找第 3 大不同值；不足 3 個不同值時回傳最大值。本題允許一般 k，且不足 k 個不同值時回傳 None，因此邊界規格不能混用。

    資料 [8, 8, 5, 9, 5, 7]，k = 3，答案應是 7。如何以 O(k) 狀態避免把相同值占成多個名次？是否一定要記住歷史所有值？

    參考解答

    用大小最多 k 的最小堆積，搭配只含「目前堆內值」的 set。新值已在 set 就略過；未滿就同時加入兩者；已滿且比根大，就移除舊根及其 set 紀錄，再加入新值。不需要記住已淘汰的所有值：門檻只會上升，被淘汰的值再次出現時不可能超過目前門檻。set 採平均 O(1) 模型，總維護時間 O(n log(k + 1))，狀態 O(k)。不足 k 個不同值時仍回傳 None。

    練習 C：兩個 heap 追蹤中位數

    對應原題：LeetCode 295：Find Median from Data Stream。原題要求實作加入整數與查詢中位數的介面，且保證查詢前至少已有一筆資料；本練習只要求說明結構與不變量。可自行驗算：依序加入 4、8、2，每次加入後的中位數為 4、6、4；偶數筆時取中間兩值的平均。

    資料只加入，要求每次回傳目前中位數。請描述兩個 heap 的內容、不變量與偶數筆時的答案，不必寫完整程式。

    參考解答

    lower 用最大堆積保存較小半部，可用負值模擬；upper 用最小堆積保存較大半部。保持 lower 的最大值 ≤ upper 的最小值，且 lower 筆數等於 upper 或多一筆。每次先按邊界分配新值，再從較大堆移動根來平衡。奇數筆時答案是 lower 的根取反，偶數筆時是兩個根的平均。加入 O(log n)，查詢 O(1)，空間 O(n)；此法不是只保存固定 k 的 top-k。若數值巨大，平均的精度規格也要說清楚。

    8. 決策小結與驗證清單

    • 反覆只要極值：可用 heap，讀根的成本低，不必完整排序。
    • 保留最大的 k 個：最小 heap 將保留值中的最小值放在根；保留最小的 k 個則反過來。
    • 合併已排序來源：一個來源一個前端候選，空間跟來源數而非總資料量成正比。
    • 遇到 tuple：先想平手時會比較誰；用唯一序號隔離不可排序的 payload。
    • 需求包括刪除、更新或過期：修改 heap 內元素時，必須另外處理查找與堆積修復。
    • 說明複雜度時別漏最後排序、收集生成器結果，以及 lazy deletion 尚未清掉的舊資料。

    tests/examples_07.py 驗證 top-k 與資料流對完整排序的結果、每一步的父子不變量、負數與重複值、空來源、多路合併平手、不可比較的 dict 載荷，以及 pushpop／replace 的差異。小值域窮舉有助於抓出 k 邊界與重複值錯誤，但不取代不變量證明。

    08　貪心：先證明，再相信直覺

    貪心演算法每一步只做一個當下最好的選擇，之後不回頭。即使迴圈很簡單，仍要證明「當下最好」的選擇不會犧牲後續結果。本章會連同程式說明選擇規則與正確性：先確認目標，找出能夠交換的決策，再寫排序與掃描。

    學習目標：能用反例否定規則；用交換論證或領先性質支持規則；分辨「選最多個」、「總價值最大」、「總等待最少」是不同問題。看過幾個成功案例，只代表規則尚未被推翻。

    1. 一個貪心主張，必須回答四件事

    1. 目標：最大化數量、最小化成本，還是只判斷可不可行？
    2. 可行性：做完這個選擇後，是否仍符合容量、時間、先後順序等限制？
    3. 安全選擇：是否至少存在一個最優解，包含這個當下選擇？
    4. 剩餘問題：固定此選擇後，剩下的問題能否用同一種規則處理？

    「最優子結構」本身不保證可以貪心；動態規劃也常有最優子結構，但需要比較多個第一步。要採用貪心，還需證明某一個選擇可以安全地固定，不必探索其他分支。若只能說「我覺得最小的比較好」，先把它寫成猜想。

    2. 工作室排程：最多不重疊區間

    自編排程情境／相近題型：LeetCode 435：Non-overlapping Intervals 問最少刪除幾個區間，才能讓剩餘區間互不重疊。本節改成回傳最多能留下的活動清單；若原有 n 場、最多留下 m 場，原題答案就是 n−m。兩者都允許端點相接，工作室與 A–F 範例為自編。

    有一間工作室，活動用半開區間 [start, end) 表示，且 start < end。任兩場不能重疊，但 [1, 3) 與 [3, 5) 可以連排。所有活動價值相同，目標是選最多場。貪心規則：按結束時間由早到晚檢查，若活動開始不早於上一場結束，就接受。

    為什麼不是最早開始？[0, 10) 會擋住 [1, 2)、[2, 3)、[3, 4)。為什麼不是最短？在 [0, 3)、[2, 4)、[3, 6) 中，最短的 [2, 4) 與另外兩個都重疊，只能選一場；兩個長度 3 的區間卻可以一起選。按最早結束選取，是為了「保留後綴的空間」；單場活動的長短不足以決定這件事。

    3. 交換論證：把某個最優解改成貪心開頭

    令 g 為目前候選中結束最早的活動，O 為任意一個最多場的可行排程，o 為 O 的第一場。因為 g 結束不晚於 o，所以把 o 換成 g 後，原本排在 o 後面的所有場次仍能接在 g 後面，場數也沒變。於是，存在以 g 開頭的最優解。

    固定 g 後，只留下 start ≥ g.end 的候選；這又是同樣的排程問題。對剩餘場次數做歸納：空集合顯然正確，而交換論證保證第一步安全，因此整個演算法正確。注意證明不是聲稱「每個最優解都一定選 g」，而是聲稱「至少有一個最優解可改成選 g」。

    掃描不變量：chosen 中的活動彼此不重疊；last_end 是最後一場結束時間；已跳過且與最後已選活動重疊的候選，之後也不可能接到目前排程。這個不變量只能保證排程可行；選擇是否安全，仍須由交換論證證明。
    def select_intervals(intervals):
    """選最多個互不重疊半開區間 [start, end)；要求 start < end。"""
    if any(start >= end for start, end in intervals):
        raise ValueError("區間必須有正長度")
    chosen = []
    last_end = None
    for start, end in sorted(intervals, key=lambda x: (x[1], x[0])):
        if last_end is None or start >= last_end:
            chosen.append((start, end))
            last_end = end
    return chosen

    時間 O(n log n)，排序後掃描 O(n)。此版本 sorted 建立新串列，排序工作記憶體及輸出各最多 O(n)，總額外空間 O(n)。若題目只要數量，可以不存 chosen，但在 Python 使用 sorted 仍有 O(n) 記憶體；不能直接宣稱 O(1)。輸入需為可重複遍歷的序列，不能直接傳一次性的 generator。

    5. 第二種貪心：短工作先做，總等待最少

    自編範例：這是所有工作同時就緒、等待權重相同的單機排程題，沒有指定的 LeetCode 原題。輸入為非負工時序列，輸出等待時間總和的最小值；空序列的總等待為 0。下方 [6,2,4] 的答案是 8。

    一台機器，所有工作在時間 0 就緒，工作不可中途切換，每件工作的等待成本權重相同。若工時為 [6, 2, 4]，要怎麼排序，才能讓所有工作開始前的等待時間總和最小？應按工時由短到長處理。本題沒有截止期限，因此無法依截止期限決定順序。

    設相鄰兩件工作 a > b，在時間 t 開始處理這一對。a 在前時，兩件等待總和是 t + (t+a)；b 在前時是 t + (t+b)，後者少 a−b。兩件做完的時間相同，因此後續工作的等待不變。持續交換所有逆序對，得到升冪順序，且總等待只會減少或持平。這是「相鄰交換」證明。

    def schedule_shortest_first(durations):
    """所有工作在時間 0 可開始，回傳順序及總等待時間。"""
    if any(duration < 0 for duration in durations):
        raise ValueError("工時不可為負")
    order = sorted(durations)
    elapsed = total_wait = 0
    for duration in order:
        total_wait += elapsed
        elapsed += duration
    return order, total_wait

    逐步範例：工時 [6, 2, 4] 排成 [2, 4, 6]。

    工時開始前 elapsed累加後 total_wait完成後 elapsed
    2002
    4226
    66812

    原順序的等待總和是 0+6+8=14；短工時優先是 0+2+6=8。全部完成時間都是 12，所以「越快做完全部工作」並不是此排序改善的目標。總完成時間之和等於總等待加上固定的工時總和，因此同一順序也能讓總完成時間之和最小。

    排序 O(n log n)，掃描 O(n)，額外空間 O(n)。零工時合法且可排最前；負工時不符合本模型，程式會拒絕這類輸入。若工作有到達時間、切換成本或不同等待權重，上述交換式改變，不能直接沿用結論。

    6. 用可達範圍決定能否繼續前進

    對應原題：LeetCode 55：Jump Game。輸入每個位置最多可往前跳幾格，輸出能否從開頭到最後一格；只問可不可達，不問最少跳幾次。原題不允許空陣列，本章另約定空序列回傳 True，章末兩組測試資料為自編。

    給定非負整數 jumps[i]，可以從 i 往右跳任意 1 到 jumps[i] 格，問從 0 能否到最後一格。對可達索引 i，將最遠邊界更新成 max(farthest, i+jumps[i])。若遇到 i > farthest，表示目前位置已無法到達，也就無法再向後擴張可達範圍。

    def can_reach_end(jumps):
    """jumps[i] 是由 i 往右最多前進的步數；空陣列視為可完成。"""
    if any(jump < 0 for jump in jumps):
        raise ValueError("步數不可為負")
    farthest = 0
    for i, jump in enumerate(jumps):
        if i > farthest:
            return False
        farthest = max(farthest, i + jump)
        if farthest >= len(jumps) - 1:
            return True
    return True

    不變量是：處理下一個索引之前，從 0 到 farthest 之間的索引都可達。這依賴「可以跳不超過上限的任意步數」；若必須剛好跳 jumps[i] 格，可達集合中間可能夾著不可達位置，不能只用單一邊界表示。此法時間 O(n)，額外空間 O(1)，只判斷存在性，沒有求最少跳躍次數。空序列的 True 是我們明訂的介面慣例，面試時要先確認。

    7. 反例實驗室：別把成功規則帶到不同目標

    自編反例／延伸練習：以下反例用自編數字比較規則。加權區間可延伸到 LeetCode 1235：Maximum Profit in Job Scheduling：求不重疊工作的最大總報酬；原題開始時間為正數，本章反例從 0 起算。最少硬幣可延伸到 LeetCode 322：Coin Change：各幣值可不限次使用，無法湊成目標時回傳 −1。前者不能直接套用「最早結束」，後者也不能保證「先拿最大硬幣」會得到最佳解。

    • 最大總價值：[0,2) 值 2、[2,4) 值 2、[0,4) 值 9。最早結束會拿 4，最佳是 9。交換第一場不再保值，通常要考慮加權區間 DP。

    練習一：最少刪幾場？

    對應原題：LeetCode 435：Non-overlapping Intervals。題目目標與端點規則相同；下方區間資料及從最大保留數推得最少刪除數的問法為自編。

    活動為 [(0,2),(1,3),(2,4),(4,5)]，至少刪掉幾場才能互不重疊？說明與最多選取問題的關係。

    參考解答

    保留 [(0,2),(2,4),(4,5)]，刪 1 場。若 n 場中最多能留下 m 場，最少刪除就是 n−m；否則留下更多就會與 m 的最大性矛盾。可回傳 len(intervals)−len(select_intervals(intervals))，時間 O(n log n)。

    練習二：帶權等待打破規則

    自編推理題：這題改變了前面單機排程的等權假設，以具體權重檢查短工時優先是否仍然成立。沒有指定的 LeetCode 原題。

    A 工時 1、每單位等待成本 1；B 工時 3、每單位等待成本 10。短工時先做是否最佳？

    參考解答

    A→B 的加權等待是 0×1+1×10=10；B→A 是 0×10+3×1=3，應先做 B。一般相鄰交換比較 a 的工時 pₐ 與權重 wₐ、b 的 pᵦ 與 wᵦ：a 在前安全的條件是 pₐwᵦ ≤ pᵦwₐ。從這個條件可以看出，原本的證明在哪裡用到等權前提；正權重時等價於按 p/w 升冪。

    練習三：可達邊界手算

    自編測例：沿用 LeetCode 55：Jump Game 的非空輸入規則，以下兩組陣列用來手動檢查可達邊界，並非原題頁面的範例。

    分別判斷 [2,1,0,1] 與 [2,2,0,1] 是否可達末端。為什麼不能只看最大的一個跳躍數？

    參考解答

    第一組在 i=0 後 farthest=2，i=1、2 都無法擴張；到 i=3 時失敗。第二組在 i=1 把 farthest 從 2 擴到 3，因此成功。跳躍數只在其索引可達時才有用，例如 [0,100] 仍失敗。

    練習四：排序之後一定能貪心嗎？

    自編推理題：這是檢查貪心論證是否完整的問答，沒有指定的 LeetCode 原題或唯一程式介面。

    有人說「先排序，然後每次選最便宜的，就是最優」。你會先追問哪三件事？

    參考解答

    先問要最小化或最大化哪個量、選擇是否會排除其他可行選項、能否把任意最優解的第一個選擇換成最便宜者而不變差。沒有具體限制與目標，單靠排序只能改變資料順序，無法證明選擇一定最優。

    09　二分搜尋：找一個永遠不會被丟掉的邊界

    二分搜尋可以處理「有序陣列找數字」，也能用來找由 False 轉為 True 的分界。每次觀察中間一點，就排除不可能包含答案的一半。實作時先說清楚 lo、hi 各代表什麼，以及哪些位置已經確定，才能決定如何更新這兩個變數。

    本章約定：陣列為非遞減排序，允許重複值。陣列索引搜尋採半開區間 [lo, hi)；整數容量的答案搜尋採閉區間 [lo, hi]。兩套寫法都正確，但初始化、更新及停止條件必須成套使用。

    1. 把找值改成找邊界

    相近題型：插入位置可對照 LeetCode 35：Search Insert Position，重複值範圍可對照 LeetCode 34：Find First and Last Position of Element in Sorted Array。第 35 題的輸入非空且沒有重複值；本章 lower_bound 另支援空陣列與重複值。第 34 題要回傳含首尾的 [first,last]，不存在時回傳 [-1,-1]；本章先求半開邊界，命中後才轉成 [lower,upper−1]。範例 [2,4,4,4,9] 的 target=4 對應第 34 題答案為 [1,3]。

    在 [2,4,4,4,9] 搜尋 4，任意一個 4 的索引都能回答「有沒有」。若題目問第一個、最後一個、出現幾次，找到任意一個後就停止，仍無法回答這些問題。定義 lower_bound(x) 為第一個值 ≥ x 的位置；若不存在，回傳 n。upper_bound(x) 則找第一個值 > x 的位置。

    邊界 q 可以是 0，也可以是 n。q 表示分界位置，該位置不一定有元素，因此搜尋結束後不能直接存取 values[q]。判斷目標存在的完整條件是 q < len(values) 且 values[q] == target。先檢查範圍，再讀元素。

    2. 半開模板：未知的是索引，答案是分界

    初始化 lo=0、hi=n。每次迴圈開始時保持：

    • 0 ≤ lo ≤ hi ≤ n。
    • 所有 i < lo 都滿足 values[i] < target。
    • 所有 i ≥ hi 的合法索引都滿足 values[i] ≥ target。
    • 待判斷的陣列索引是 [lo, hi)，而邊界 q 仍在閉範圍 [lo, hi]。
    def lower_bound(values, target):
    lo, hi = 0, len(values)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if values[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

    若 values[mid] < target，因為已排序，mid 及更左側都不可能是第一個 ≥ target 的位置，所以 lo=mid+1。否則 mid 有可能就是第一個，不能跳過；設 hi=mid，讓 mid 成為已知右側的一部分。每次 hi−lo 都嚴格縮短。當 lo=hi 時，這個位置同時符合左右區域的性質，就是唯一的分界。

    常見混搭：半開模板用了 while lo ≤ hi，可能碰到 values[n]；判斷小於後寫 lo=mid，可能在長度一或二時停不下來；判斷不小於後寫 hi=mid−1，則可能刪掉真正邊界。先寫不變量，再決定加減一。

    values=[2,4,4,4,9]，target=4。以下每列記錄本輪探查前的區間。

    搜尋lohimid / 值更新

    def upper_bound(values, target):
    lo, hi = 0, len(values)

        if values[mid] <= target:
            lo = mid + 1
        else:
            hi = mid

    對支援 O(1) 隨機存取的 Python list，每次探查 O(1)，共 O(log(n+1)) 時間、O(1) 額外空間；n=0 時不探查。若用鏈結串列，尋找中點不再是 O(1)，不能照搬這個成本分析。若一開始才為單次查詢排序，總成本是 O(n log n)，未必比直接掃描更好。

    5. 用 first_true 搜尋單調判斷的分界

    相近題型：LeetCode 278：First Bad Version 以 isBadVersion 查詢版本是否出錯，找第一個錯誤版本。原題版本從 1 到 n，並保證有錯誤版本；本章 first_true 使用 [0,n)，允許全 False 並回傳 n，也處理 n=0，呼叫範圍與不存在時的規格不同。

    如果 predicate(i) 在索引 [0,n) 呈現 False、False、…、True、True，就可以直接找第一個 True，不需要存出整個布林陣列。若全 False，回傳 n；若全 True，回傳 0；n=0 也回傳 0，且不呼叫 predicate。

    def first_true(n, predicate):
    """predicate 在 [0, n) 先 False 後 True；全 False 回傳 n。"""
    lo, hi = 0, n
    while lo < hi:
        mid = (lo + hi) // 2
        if predicate(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

    前提是 n ≥ 0，predicate 在搜尋期間保持一致且具單調性。如果輸出是 False、True、False，就不能使用這個模板。找最後 True 的問題若呈現 True→False，可以搜尋第一個 False 再減一，並處理全部為 False 時的 −1 哨兵。改寫函式時，要一併確認判斷方向，不能只換名稱。

    若一次 predicate 的成本是 T，二分成本是 O(T log(n+1))；分析時必須計入每次判斷的成本。空間包含 predicate 自己需要的記憶體。這裡的 first_true 不會呼叫 predicate(n)，所以即使 n 是「不存在」的哨兵也安全。

    6. 答案二分：最低每日運送容量

    對應原題：LeetCode 1011：Capacity To Ship Packages Within D Days。貨箱必須按既有順序運送，每天裝載不超過容量，求期限內運完的最低容量。本章重量序列與逐步表為自編；原題保證貨箱非空，且天數不超過貨箱數，本章另處理空輸入與更多天數。例子 weights=[3,2,4,1,3]、D=3 的答案是 5。

    有依序到達的貨箱，重量為正整數。每天最多運送容量 C；不能拆箱、不能改順序，同一天運走一段連續貨箱。求在至多 D 天完成的最小整數 C。例子 weights=[3,2,4,1,3]，D=3。

    1. 下界：最重貨箱不可拆，所以 C ≥ max(weights)。
    2. 上界：sum(weights) 能一天運完，對 D ≥ 1 一定可行。
    3. 判斷：給 C 後，每天依序放到下一箱會超重才換天，計算需要幾天。
    4. 單調：如果 C 可行，更大的 C 可以直接沿用原分組，因此一定可行。搜尋第一個可行 C。

    判斷器為何正確？固定 C，每一天貪心放入最大的可行前綴。任何合法分組的第一天都不可能放得比這個前綴更多。以天數歸納：若貪心在 d−1 天後已不比另一分組落後，第 d 天若尚未到達對方當天終點，只需運送對方第 d 天貨箱的某個後綴，重量不會更多，因此貪心仍不落後。因此，貪心分組使用的天數最少，能正確判斷這個容量是否可行。

    def minimum_capacity(weights, days):
    """依序運送正整數重量；每天裝入一段，可使用少於 days 天。"""
    if days <= 0:
        raise ValueError("天數必須為正整數")
    if any(weight <= 0 for weight in weights):
        raise ValueError("重量必須為正整數")
    if not weights:
        return 0

    def feasible(capacity):
        used_days, load = 1, 0
        for weight in weights:
            if load + weight > capacity:
                used_days += 1
                load = 0
            load += weight
        return used_days <= days

    lo, hi = max(weights), sum(weights)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if feasible(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

    此處改用閉區間 [lo,hi]：最小答案一直保留在區間內，而且 hi 一定可行。mid 可行時保留它，令 hi=mid；不可行時排除它及更小值，令 lo=mid+1。lo=hi 時就是最小答案。feasible 只會收到至少 max(weights) 的容量，所以內部不用再處理單箱超重；若把它抽成公共函式，必須補上該檢查。

    令 n 為貨箱數，L=max(weights)、U=sum(weights)。初始化 O(n)，每次判斷 O(n)，總時間 O(n log(U−L+2))，額外空間 O(1)。這不是 O(n log n)，因為二分的是數值範圍。這裡採常見的成本模型，將整數加總與比較視為常數成本；但 Python 整數極大時，仍須考慮位元長度造成的成本。

    8. 何時不要急著二分

    • 單調性不成立：某個容量可行，下一個卻不可行，就必須重新定義判斷。單調性必須從原本的限制推得，不能只根據幾個樣本判斷。
    • 答案不在界內：hi 必須能覆蓋答案或代表合法的不存在哨兵，不能隨意填一個大數。
    • 「至多」變「恰好」：若允許空天、貨箱可再切成更多非空天，以及 D 是否大於 n，都會影響問題。本文只求至多 D 天。
    • 浮點答案：實數區間沒有 mid+1 這種操作，常需誤差門檻或固定次數；不能直接套整數停止條件。
    • 旋轉陣列：原始值並非整段排序，必須另外辨識有序半邊。重複值可能使單次無法排除一半，最壞情況也可能退化。

    手動追蹤時：先畫出所有可能的分界位置，而不是只畫元素。長度五的陣列有六個可能邊界，包含最前面與最尾端。每次更新後，重新檢查被排除的部分是否符合已知條件。若你說不出某個端點為什麼還需要保留，就先不要修改程式中的加減一。最後記錄停止當下 lo、hi 的值，再翻譯成「不存在」、「第一個位置」或「最小可行容量」等題目需要的語意。這樣能把區間定義、端點更新與回傳值一起核對，減少混用不同模板的機會。

    10．回溯法：選擇、限制與撤銷

    你要替工作坊挑講題、安排順序，或在格子裡找一條符合字元的路徑。這類問題通常需要一連串決策，無法只靠一個固定公式求解。回溯法（backtracking）把「試一個選擇，不行就退回」寫成可驗證的搜尋：維護目前的部分解，往下補一個決策，返回時恢復現場，接著試另一個決策。

    讀這章時，不能只背 dfs 模板，還要能回答這些問題：一個節點代表什麼？哪些選項仍合法？哪些分支確定不必探索？答案應該何時複製？若只能找到一個解，提早返回會不會破壞狀態？

    適用訊號：列舉所有組合／排列／配置、找出滿足多個限制的解、問題規模容許指數搜尋。若只求數量或最佳值，而且不同路徑常抵達同一個「未來完全相同」的狀態，下一章的動態規劃可能更合適。

    10.1 把候選答案畫成決策樹

    題目對照：LeetCode 78．Subsets 要列出輸入陣列的所有子集合，原題保證元素值互不相同。本節改用講題卡，並額外討論空輸入與重複值；程式把不同位置視為不同選項，輸入值重複時不會自動去重。輸入 [A,B]，會回傳 []、[B]、[A]、[A,B] 這四個子集合。

    節點是部分解，邊是一個選擇，葉節點是完整決策。有些葉節點合法，有些不合法。子集合問題每件物品有選／不選兩條邊；排列問題每層從尚未使用的元素挑一個；格子搜尋則從鄰居挑下一格。回溯通常用深度優先走這棵隱含樹，不需要先把樹建成資料結構。

    以兩張不同講題卡 A、B 為例，選與不選的位置固定，所以四個葉子各代表一種子集合。不變量是：進入 dfs(i) 時，前 i 個位置的決策已完成，path 恰好包含其中被選的元素，而且順序與原輸入一致。i 每次增加一，必然抵達終點。

    def subsets(items):
    """items 中的位置視為不同選項；若值相同，輸出可能值相同。"""
    answer, path = [], []

    def dfs(i):
        if i == len(items):
            answer.append(path.copy())
            return
        dfs(i + 1)                 # 不選第 i 個
        path.append(items[i])      # 選擇
        dfs(i + 1)                 # 探索
        path.pop()                 # 撤銷

    dfs(0)
    return answer

    逐步例子一：從 [] 到 [A,B]，再回到 []

    步驟目前呼叫／動作path已儲存答案
    1不選 A，不選 B，到 i=2[][[]]
    2回到 i=1，選 B[B][[],[B]]
    3撤銷 B，回到 i=0，選 A[A]不變
    4不選 B，到 i=2[A]再加入 [A]
    5回到 i=1，選 B，到 i=2[A,B]再加入 [A,B]
    6先撤銷 B，再撤銷 A[]四份獨立的答案保留下來

    為何不漏、不重？任何子集合都能唯一寫成 n 個選／不選的決策。程式兩條分支都走，因此涵蓋全部；不同決策必有某個位置不同，因此索引集合不重複。注意這個論證區分的是「位置」：若輸入是 [A,A]，兩個位置各自選取會產生兩份值相同的 [A]。是否要視它們為同一答案，是題目定義，不能默默混用。

    n 個相異位置產生 2ⁿ 個子集合。只走樹是 O(2ⁿ)，但複製並回傳所有答案要 O(n·2ⁿ) 時間和輸出空間；遞迴堆疊與 path 的輔助空間為 O(n)。空輸入回傳 [[]]，因為空集合也有一種選法。

    10.2 撤銷是正確性條件，不是可選的清理

    共享可變狀態時，每條分支要遵守「進入與離開的現場一致」：append 對應 pop，集合 add 對應 remove，used=True 對應 used=False。撤銷順序通常與修改相反。下一個兄弟分支才能從同樣的狀態開始，不受前一條路留下的修改影響。

    path.copy() 是淺複製；本章 path 裝的是整數或字元，足以保存答案。若裡面放的是之後還會修改的巢狀串列，淺複製仍共享內層物件，要改存不可變值，或依資料結構複製必要層級。也能用 dfs(path + [x]) 避免手動撤銷，但每次連接都要 O(path 長度) 的複製，峰值記憶體也可能增加。

    提早返回陷阱：找到答案後直接 return，可能跳過 pop 或 remove。若只做存在性搜尋，先把結果存起來、撤銷後再 return；也可以像本章格子練習一樣，使用 try/finally，讓成功與失敗都恢復現場。遞迴深度也有限制；即使把限制調得很大，仍無法解決指數時間的問題，也不保證堆疊不會耗盡。

    10.3 組合與排列：下一層可以選誰？

    題目對照：本節的去重排列對應 LeetCode 47．Permutations II：輸入可含重複值，回傳所有不重複的完整排列，答案順序不限。原題使用整數，本節用字卡說明；[A,A,B] 的三個結果是 AAB、ABA、BAA，也另外測試空輸入。本節也用組合來比較兩種搜尋方式。

    組合不計順序，[2,5] 與 [5,2] 是同一答案；用 start 限制後續只選更右邊的位置，就把順序固定下來。若每個位置至多一次，遞迴傳 j+1；若題目允許同一正值重複使用，才可能傳 j。排列計順序，下一層必須從所有尚未用過的位置選，不能只往右，因此改用 used。

    輸入有重複值時，排序後能讓等值相鄰；我們只保留相同值的一種代表順序。下面的跳過條件不是「看見第二個 A 就禁止」，而是「前一個相同 A 還沒用時，禁止先用後面的 A」。若前面的 A 已經在目前 path 中，後面的 A 就可以接上去。

    def unique_permutations(items):
    values = sorted(items)
    used = [False] * len(values)
    answer, path = [], []

    def dfs():
        if len(path) == len(values):
            answer.append(path.copy())
            return
        for j, value in enumerate(values):
            if used[j]:
                continue
            # 同層中，先使用前一個相同值，固定相同值的相對次序。
            if j > 0 and values[j] == values[j - 1] and not used[j - 1]:
                continue
            used[j] = True
            path.append(value)
            dfs()
            path.pop()
            used[j] = False

    dfs()
    return answer

    path候選與檢查結果
    []A₀ 可選；A₁ 因 A₀ 未用而跳過只開一次以 A 起頭的分支
    [A₀]A₁ 的前一個 A₀ 已用允許 [A₀,A₁,B] → AAB
    [A₀]改選 B，最後選 A₁得到 ABA

    10.4 剪枝必須有證明：正值包裹挑選

    自編延伸練習：相近題型是 LeetCode 40．Combination Sum II。兩者都讓每個輸入位置最多使用一次，且相同值組合只回傳一次；本節多了「恰好挑 k 件」的限制，不能直接當成同一道題。以下以正整數重量、件數 k 與目標 target 為輸入，回傳符合條件的重量組合，沒有解就回傳 []。

    有一批重量為正整數的樣品，挑恰好 k 件使總重等於 target；每個位置至多用一次，相同重量的值組合只列一次。狀態是 (start, need, remain)，path 則記錄已挑的重量。不變量：path 的索引遞增，need 是仍須挑的件數，remain 是仍須湊的重量。

    排序後可以安全使用三種界限：剩餘件數不足就失敗；剩餘 need 件的最小可能總和已大於 remain 就失敗；最大可能總和仍小於 remain 也失敗。前綴和讓這兩個加總檢查都是 O(1)。候選大於 remain 時，由於所有值都正且有序，後面的候選更不可能，因此可以 break。

    def choose_k_sum(numbers, k, target):
    """恰選 k 個位置、每個至多一次；回傳不重複的值組合。"""
    if k < 0 or any(x <= 0 for x in numbers):
        raise ValueError("k 必須非負，數值必須為正整數")
    values = sorted(numbers)
    n = len(values)
    prefix = [0]
    for x in values:
        prefix.append(prefix[-1] + x)
    answer, path = [], []

    def dfs(start, need, remain):
        if need == 0:
            if remain == 0:
                answer.append(path.copy())
            return
        if n - start < need:
            return
        smallest = prefix[start + need] - prefix[start]
        largest = prefix[n] - prefix[n - need]
        if remain < smallest or remain > largest:
            return
        for j in range(start, n - need + 1):
            if j > start and values[j] == values[j - 1]:
                continue
            if values[j] > remain:
                break
            path.append(values[j])
            dfs(j + 1, need - 1, remain - values[j])
            path.pop()

    dfs(0, k, target)
    return answer

    狀態推理動作
    (0,3,8)，path=[]最小 1+2+2=5，最大 2+4+5=11尚有可能
    (1,2,7)，path=[1]先選第一個 2剩下 1 件要湊 5
    path=[1,2,2] 或 [1,2,4]件數用完，但剩餘重量不是 0不記錄；撤銷
    path=[1,2,5]need=0 且 remain=0記錄第一個答案
    path=[1]，同層的第二個 2會重做相同值組合跳過
    path=[1,4]，剩 1 件湊 3剩餘最小候選是 5下界剪枝
    path=[2,2,4]三件總重 8記錄第二個答案
    把「超過目標就停止」套到含負數的輸入可能漏解。例如目標 3，先選 5 後還能選 −2。剪枝一定要依賴明確假設。本實作拒絕非正值，是為了維持問題模型；若要支援零或負數，重新檢查終止性、重用規則與所有界限，不能只刪掉檢查。

    剪枝能減少實際搜尋量，但不會因此就把指數問題變成多項式。這個實作的保守時間上界是 O(n log n + n·2ⁿ + kR)，其中 R 是答案數；前兩項涵蓋排序與候選掃描，最後一項是輸出複製。實際可用「被探索的節點數、每節點掃過的候選數、輸出長度」更精準衡量。輔助空間 O(n+k)，含排序副本、前綴和與深度至多 k 的路徑。

    10.5 多重限制：一列一列放皇后

    題目對照：LeetCode 51．N-Queens 要回傳 n 個皇后的所有合法配置。原題用 Q 與 . 組成棋盤字串；本節改用每列皇后的欄索引表示，所以 n=4 回傳 [[1,3,0,2],[2,0,3,1]]。沒有配置時回傳 []；本節另定義 n=0 回傳 [[]]，代表唯一的空配置。

    在 n×n 棋盤放 n 個皇后，任兩個不能同列、同欄或同對角線。我們把「每列一個」直接編進搜尋層數；下一層只處理 row+1，因此不用額外集合追蹤列。其餘限制各用一個集合記錄，選候選位置時就能排除衝突。

    def queens_columns(n):
    """每個解是一串欄編號，第 r 個值表示第 r 列皇后的欄。"""
    if n < 0:
        raise ValueError("n 必須非負")
    columns, diagonal_down, diagonal_up = set(), set(), set()
    path, answer = [], []

    def dfs(row):
        if row == n:
            answer.append(path.copy())
            return
        for col in range(n):
            if (col in columns or row - col in diagonal_down
                    or row + col in diagonal_up):
                continue
            columns.add(col)
            diagonal_down.add(row - col)
            diagonal_up.add(row + col)
            path.append(col)
            dfs(row + 1)
            path.pop()
            columns.remove(col)
            diagonal_down.remove(row - col)
            diagonal_up.remove(row + col)

    dfs(0)
    return answer

    進入 dfs(row) 時，前 row 列各有一個互不攻擊的皇后，三個集合恰好描述它們佔用的欄與對角線。只接受不在集合的候選，維持不變量；到 row=n 就得到合法配置。每個合法配置的第 row 欄值都會在該層被考慮，因此不漏解。撤銷會把集合回復成前 row 列的狀態。

    只看「欄不得重複」，深度 r 最多有 P(n,r) 種狀態。此版本每個非葉節點仍掃 n 欄，安全上界為 O(n·n! + nQ)，Q 為輸出的解數；對角線剪枝通常讓實際搜尋小很多。使用集合的查找視為平均 O(1)。輔助空間 O(n)，輸出 O(nQ)。這不是 O(n²)，棋盤大小不能代表搜尋樹大小。

    10.6 回溯、DFS 與記憶化的分界

    DFS 描述走訪順序；回溯強調探索決策與撤銷；它們不是互斥概念。圖形 DFS 的全域 visited 用來保證一個節點處理一次。回溯中的 used 常常只代表目前路徑使用過的元素，離開路徑就必須清除。把兩者混用，會錯把其他合法路徑排除。

    想加 cache 之前，先問「相同 key 的所有呼叫，未來合法選擇真的相同嗎？」排列不能只記 len(path)，因為 [A] 與 [B] 尚可用的字元不同；格子找字也不能只記 (r,c,i)，因為已佔用的格子可能不同。把 used 的位元遮罩放進 key 可能正確，但狀態數隨格數指數成長。對列舉任務，僅快取布林或「看過狀態」也可能讓不同前綴應產生的答案消失。

    10.7 練習：從限制推導狀態

    練習一：不相鄰的展示時段

    自編題。要列出所有合法選法，不是求最多能選幾個。例如 n=2 時，回傳 []、[0]、[1]；[0,1] 因為相鄰而不合法。下方題目沿用這個輸出規格。

    編號 0 到 n−1 的時段中，可以挑任意多個，但不能挑相鄰時段。列出所有可行編號組合，包括空組合。先手算 n=3，再寫出不重複的生成器或回傳串列。

    參考解答

    在位置 i 決定不選時往 i+1；選它時下一個可考慮位置是 i+2。每條路徑都有唯一的第一個決策差異。n=3 的答案為 []、[2]、[1]、[0]、[0,2]，順序不限。

    def nonadjacent_slots(n):
    if n < 0:
        raise ValueError("n 必須非負")
    answer, path = [], []

    def dfs(i):
        if i >= n:
            answer.append(path.copy())
            return
        dfs(i + 1)
        path.append(i)
        dfs(i + 2)  # 下一格不能選
        path.pop()

    dfs(0)
    return answer

    設答案數為 R，R 滿足費波那契型遞迴 R(n)=R(n−1)+R(n−2)，R(0)=1、R(1)=2，仍呈指數成長。包含答案複製的保守上界 O(nR)，輔助空間 O(n)。

    練習二：合法的巢狀括號

    題目對照：LeetCode 22．Generate Parentheses。輸入括號對數，回傳所有合法字串，順序不限。例如 n=2 時回傳 ["(())","()()"]。原題從 n=1 開始，本節另外處理 n=0 的空字串答案。

    輸入 n，列出包含 n 對括號的所有合法字串。任何前綴裡，右括號都不能多於左括號。不要先生成所有長度 2n 的二元字串再過濾。

    參考解答

    opened、closed 是已使用數量。只在 opened<n 時放左括號，在 closed<opened 時放右括號。這兩個條件直接維持前綴合法性；closed=n 時也必然 opened=n。

    def balanced_parentheses(n):
    if n < 0:
        raise ValueError("n 必須非負")
    answer, path = [], []

    def dfs(opened, closed):
        if closed == n:
            answer.append("".join(path))
            return
        if opened < n:
            path.append("(")
            dfs(opened + 1, closed)
            path.pop()
        if closed < opened:
            path.append(")")
            dfs(opened, closed + 1)
            path.pop()

    dfs(0, 0)
    return answer

    解數為第 n 個 Catalan 數 Cₙ=(2n)!／(n!(n+1)!)，不是 2ⁿ。保守時間 O(nCₙ)，輸出空間 O(nCₙ)，輔助空間 O(n)。n=0 回傳 [""]。

    練習三：字卡格子尋路

    題目對照：LeetCode 79．Word Search。輸入字元棋盤與 word，回傳能否沿上下左右相鄰格拼出單字的布林值，同一格不能在同一條路重用。本頁使用自己的小棋盤範例，並補上原題範圍外的空字串、空棋盤規則；空 word 回傳 True，空棋盤搭配非空 word 回傳 False。

    矩形字卡板只能上下左右走，同一條路不得重複用格子。判斷能否拼出 word。board=["AB","CD"] 可以拼 ABDC，不能拼 ABA。成功時也要清理暫存狀態。

    參考解答

    used 是路徑區域的集合；每個起點都要能從乾淨狀態搜尋。try/finally 保證 any 的短路成功與提早 return 都不會省略撤銷。此版本完全不修改輸入棋盤。

    def word_exists(board, word):
    """矩形字元格；上下左右相鄰，同一次路徑不得重複使用格子。"""
    if not word:
        return True
    if not board or not board[0]:
        return False
    rows, cols = len(board), len(board[0])
    if any(len(row) != cols for row in board):
        raise ValueError("board 必須為矩形")
    if len(word) > rows * cols:
        return False
    used = set()

    def dfs(r, c, i):
        if (r < 0 or r >= rows or c < 0 or c >= cols
                or (r, c) in used or board[r][c] != word[i]):
            return False
        used.add((r, c))
        try:
            if i == len(word) - 1:
                return True
            return any(dfs(r + dr, c + dc, i + 1)
                       for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)))
        finally:
            used.remove((r, c))  # 成功提早回傳時也必定撤銷

    return any(dfs(r, c, 0) for r in range(rows) for c in range(cols))

    令格子數為 RC、字長為 L≥1，安全上界 O(RC·4ᴸ)；排除立即走回上一格可分析出更緊的 O(RC·3ᴸ) 等級（常數首步分支另計）。實際最深只到 L，輔助空間 O(L)，且 L>RC 時立即失敗。空字串定義為可拼出。

    10.8 邊界測試與選擇清單

    不要只測「有一個漂亮答案」：空輸入、無解、單一元素、全重複元素、k=0、k>n、目標小於可行下界、成功提早返回，都是能揭露狀態錯誤的測試。附檔 tests/examples_10.py 用 itertools 暴力枚舉比對小型輸入，並檢查皇后的欄與對角線互斥，以及找字後輸入未變。

    • 要所有答案：先估答案量；若答案本身太大，換演算法也無法省掉輸出成本。
    • 組合：固定索引遞增；排列：追蹤已使用位置；允許重用時，證明遞迴會終止。
    • 每個剪枝寫一句「這裡不可能有答案，因為……」，說不出來就先別剪。
    • 每個可變欄位都找出對應撤銷；記錄答案時檢查是否共用物件。
    • 只求最佳值／數量：若不同前綴共享相同未來，考慮下一章 DP；先確認狀態完整，再加 cache 裝飾器。

    下一章：把重複子問題整理成動態規劃狀態。

    11．動態規劃：狀態、轉移與計算順序

    動態規劃（dynamic programming，DP）需要先定義狀態，不能只把答案放進陣列。狀態要能完整描述「接下來的問題」，又捨去不影響未來的過去。若許多路徑抵達同樣的狀態，就只解一次，再重用結果。DP 可以求最大值、最小值、可行性或數量；不是每題都在找最佳值。

    解題時要交代六件事：狀態定義、轉移、邊界、計算順序、答案位置、複雜度。本章從一維湊數開始，再處理背包、雙字串、矩陣與狀態機，也會說明「使用 DP」並不等於「多項式時間」。

    11.1 填 dp 表前，先回答六個問題

    1. 狀態：dp 的每個索引與儲存值是什麼？例如 dp[a] 是「恰好湊成 a 的最少硬幣數」，不是含糊的「到這裡的答案」。
    2. 轉移：依最後一步／下一個選擇，把答案連到較小的子問題。最佳化通常用 min 或 max，計數通常相加，可行性通常用 or。
    3. 邊界：空問題的答案是什麼？哪些狀態不可達？最小化的不可達通常用正無限大，最大化常用負無限大。
    4. 順序：讀取某個狀態前，它依賴的結果是否都已算好？依賴較小金額就由小到大；區間依賴較短區間就由短到長。
    5. 答案：是 dp[n]、整列最大值、所有合法終態的最大值，還是其他位置？
    6. 成本：狀態數 × 每狀態轉移成本，再加前處理、輸出與資料結構操作。空間要包含表格、遞迴、重建答案。
    足夠的狀態：兩段歷史若映射到同一狀態，它們之後的合法選擇與所求結果必須相同；最佳化時，可只保留這個狀態下最好的已累積值。若過去某個資訊仍會改變未來，就不能丟掉它。回溯的整條 path 往往資訊太多，但只存「目前走到第幾步」又可能太少。

    「重疊子問題」說明為什麼可以省下重算；「最優子結構」說明局部子問題的最佳答案能組成整體最佳答案。兩者都需要由題意論證。用遞迴求解的問題，也不一定適合 DP：若子問題根本不重複，cache 可能只增加開銷；若轉移含循環，普通遞迴記憶化還可能無限遞迴，需另外處理循環與求解方法。

    11.2 自頂向下：先寫遞迴，再記住答案

    題目對照：LeetCode 322．Coin Change。輸入正整數硬幣面額 coins 與非負金額 amount，每種面額可重複使用，輸出最少枚數，無解回傳 −1。這裡與下一節解同一個問題，只改計算方式；例如 coins=[1,3,4]、amount=6，兩個版本都回傳 2。

    面額都是正整數，每種硬幣可以無限使用。求恰好湊成 amount 的最少枚數，不能湊出就回傳 −1。令 best(a) 為湊 a 的最少枚數。最後放入一枚 c 之前，必須先湊出 a−c，因此 best(a)=min(1+best(a−c))，只考慮 c≤a。best(0)=0，沒有合法選法則為無限大。

    不加記憶化時，相同餘額會被沿不同路徑重算。加上 cache 後，每個餘額的函式主體只執行一次。面額正值保證餘額嚴格下降，轉移沒有循環。下面將快取放在函式內，讓每次呼叫使用自己的面額集合，不會把另一組輸入的答案誤當成相同問題。

    from functools import cache
from math import inf


def minimum_coins_memo(coins, amount):
    if amount < 0 or any(c <= 0 for c in coins):
        raise ValueError("amount 必須非負，硬幣面額必須為正整數")
    values = tuple(sorted(set(coins)))

    @cache
    def best(remain):
        if remain == 0:
            return 0
        answer = inf
        for coin in values:
            if coin > remain:
                break
            answer = min(answer, 1 + best(remain - coin))
        return answer

    answer = best(amount)
    return -1 if answer == inf else answer

    正確性：任意最優解都有最後一枚 c。刪掉它，剩下的硬幣必須是 a−c 的最優解，否則可用更少枚數替換，和原解最優相矛盾。枚舉所有可作為最後一枚的 c，便包含某個最優解；轉移不會產生不合法總額。由 a=0 向上做歸納，即得所有有限答案正確。

    令 A=amount，D=不同面額數，最多 A+1 個狀態、每狀態至多 D 次轉移，時間 O(A·D + D log D)，另計讀取原始面額清單的成本。cache 空間 O(A)，遞迴深度最壞 O(A／最小面額)。Python 可能先遇到遞迴深度限制，此時所需的 DP 表格還遠小於可接受的大小；大 A 優先考慮迭代。

    11.3 自底向上：按相依順序填表

    同題的另一種實作：LeetCode 322．Coin Change。輸入與回傳規格和上一節相同；此版本由小金額往大金額填表，避免遞迴深度限制。

    由於 a−c<a，金額從 0 遞增就是合法順序。dp[a] 更新時，它讀取的所有較小金額都已完成。這樣不用遞迴，也省下函式呼叫和雜湊快取的開銷。

    def minimum_coins(coins, amount):
    if amount < 0 or any(c <= 0 for c in coins):
        raise ValueError("amount 必須非負，硬幣面額必須為正整數")
    values = sorted(set(coins))
    dp = [float("inf")] * (amount + 1)
    dp[0] = 0
    for total in range(1, amount + 1):
        for coin in values:
            if coin > total:
                break
            dp[total] = min(dp[total], dp[total - coin] + 1)
    return -1 if dp[amount] == float("inf") else dp[amount]

    逐步例子一：面額 [1,3,4]，湊出 6

    a候選轉移dp[a]一種最優組合
    0邊界0空組合
    1dp[0]+111
    2dp[1]+121+1
    3min(dp[2]+1, dp[0]+1)13
    4min(dp[3]+1, dp[1]+1, dp[0]+1)14
    5min(dp[4]+1, dp[2]+1, dp[1]+1)24+1

    這也是貪婪法的反例：每次拿最大面額會取 4+1+1，共 3 枚；DP 比較所有最後一步，找到 3+3。若要回傳硬幣本身，可在每次得到更小值時記住最後一枚 c，再從 A 不斷減去 c，直到 0。必須先確定 A 可達，否則無法重建。只存枚數並不能直接回推出唯一方案，因為最佳解可能不只一種。

    面向記憶化遞迴（memoization）表格法（tabulation）
    計算範圍只算從目標實際觸及的狀態通常填指定範圍內所有狀態
    相依順序由遞迴自然往下追需自行選擇拓樸順序
    主要額外成本函式呼叫、快取雜湊、遞迴堆疊可能計算不會用到的格子
    適合情況狀態稀疏，遞迴清楚且深度可控狀態密集，需省空間或避免深遞迴
    O(A·D) 是依「金額數值」而非其二進位輸入長度的多項式，稱為偽多項式（pseudo-polynomial）。A=10⁹ 就可能完全不可行。使用 DP 前，先代入最大狀態量，確認時間與記憶體能否承受，再決定要不要開陣列。

    11.4 二維狀態與壓縮：0/1 背包

    自編例題：使用標準 0/1 背包模型。輸入 items 中的每個項目是（正整數重量，價值），capacity 是非負整數；回傳總重不超過容量時的最大價值，不是選中的物品清單。可一件都不選，因此空輸入或全負價值時回傳 0。

    每件樣品有重量與價值，只能挑一次；總重至多 W，可不選任何東西。令 f[i][w] 表示只考慮前 i 件、容量上限 w 時的最大價值。處理第 i 件（重量 a、價值 v）有兩種互斥選擇：

    • 不選：f[i−1][w]。
    • 選：若 w≥a，得到 f[i−1][w−a]+v。

    兩者取 max，邊界 f[0][w]=0。狀態是 (i,w)，不能只快取 i，因為不同剩餘容量會改變可選物品。由於每一列只依賴上一列，先以兩列計算，再考慮壓成一列。

    def knapsack_01(items, capacity):
    """items 為 (正整數重量, 價值)；可不選，總重至多 capacity。"""
    if capacity < 0 or any(weight <= 0 for weight, _ in items):
        raise ValueError("capacity 必須非負，重量必須為正整數")
    dp = [0] * (capacity + 1)
    for weight, value in items:
        for limit in range(capacity, weight - 1, -1):
            dp[limit] = max(dp[limit], dp[limit - weight] + value)
    return dp[capacity]

    一維不變量：處理某件物品、由大容量往小容量掃描時，比目前容量更小的格子尚未更新，所以 dp[w−a] 仍代表「沒有使用這一件」的上一輪答案。這正是每件只用一次所需的語意。若改由小往大，會讀到本輪新值，等同允許重用同一物品。

    逐步例子二：樣品 (2,4)、(3,5)、(4,7)，容量 5

    完成的物品容量 012345
    尚未處理000000
    (2,4)004444
    再處理 (3,5)004559
    再處理 (4,7)004579

    第二輪先更新容量 5：max(4, dp[2]+5)=9。此時 dp[2]=4 仍是上一輪的值，恰好代表挑第一件、再挑第二件。答案為 9，沒有必要用完所有物品。

    n 件物品、容量 W：時間 O(nW)，完整二維表 O(nW) 空間，一維壓縮 O(W)。這同樣是偽多項式。若題目改成「恰好用滿 W」，初值必須改成 dp[0]=0、其餘負無限大，並維持不可達語意；全部設 0 會把沒湊出的重量誤認為合法。

    壓縮空間時，也會丟掉歷史決策。若要重建選了哪些物品，最直接的做法是保留二維表，從最後一列逆推選／不選；不要假設最後那一維數字已保留每次取用的物品。先確認狀態與計算順序都正確，再壓縮空間。

    11.5 兩個進度：最長共同子序列

    題目對照：LeetCode 1143．Longest Common Subsequence。輸入兩個字串，回傳最長共同子序列的長度，不回傳子序列本身；沒有共同字元時回傳 0。本節用 CABA 與 ACBA 作例子，答案是 3；另外也處理空字串，原題則限定非空的小寫英文字串。

    子序列可以刪掉元素，但保留相對順序；不要求連續。令 dp[i][j] 為 a 的前 i 個元素與 b 的前 j 個元素的最長共同子序列（LCS）長度。兩個前綴各有自己的進度，所以要兩個索引，不能只記較短長度或目前匹配總數。

    • 末元素相同：存在一個最優解配對這兩個末元素，故 dp[i][j]=dp[i−1][j−1]+1。
    • 末元素不同：它們不可能作為同一配對，至少跳過一邊，故取 max(dp[i−1][j], dp[i][j−1])。
    • 任一前綴長度為 0：共同子序列長度是 0。
    def lcs_length(a, b):
    """子序列可跳過元素，但不能改變相對次序。"""
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[m][n]

    例如 a="CABA"、b="ACBA"，長度是 3，可取 "ABA" 或 "CBA"。連續子字串的題目是不同問題：不相等時通常會把連續匹配長度清為 0，不能拿那個轉移來解子序列。

    時間與完整表格空間皆為 O(mn)。若只求長度，可用兩列把空間壓成 O(min(m,n))。若壓成單列，還需要暫存「左上角舊值」；直接由左到右覆寫會失去 dp[i−1][j−1]。Python 建表要寫每列獨立的串列推導式，不能用 [[0]*(n+1)]*(m+1)，後者讓各列指向同一物件。

    11.6 矩陣 DP：路徑與障礙

    自編延伸練習：相近題型是 LeetCode 64．Minimum Path Sum，都只能向右或向下，求左上到右下的最小路徑總和。原題的格子代價非負，也沒有障礙；本頁加入 None 障礙、負代價及無路可走時回傳 None 的規則。例如 [[1,None],[2,3]] 的答案是 6，路徑經過 1、2、3。

    在矩形格子中，每格有通過代價，只能向右或向下；None 表示不可走。求從左上走到右下的最小總和，起點與終點代價都算。dp[r][c] 是「抵達這格」的最小總和，並非「從這格出發」的剩餘代價。相依格子是上方與左方，因此按列、再按欄遞增即可。

    def minimum_grid_path(grid):
    """只能往右或下；None 是障礙。回傳最小總和，無路可走則 None。"""
    if not grid:
        return None
    rows, cols = len(grid), len(grid[0])
    if any(len(row) != cols for row in grid):
        raise ValueError("grid 必須為矩形")
    if cols == 0:
        return None
    infinity = float("inf")
    dp = [infinity] * cols
    for r in range(rows):
        for c in range(cols):
            cost = grid[r][c]
            if cost is None:
                dp[c] = infinity
            elif r == 0 and c == 0:
                dp[c] = cost
            else:
                above = dp[c]  # 尚未覆寫，仍是上一列
                left = dp[c - 1] if c > 0 else infinity
                dp[c] = min(above, left) + cost
    return None if dp[-1] == infinity else dp[-1]

    逐步例子三：障礙不是零成本

    列原始格子代價處理後 dp觀察
    0[2,1,5,2][2,3,8,10]第一列只能從左累積
    1[4,None,2,1][6,∞,10,11]障礙清成 ∞，不能保留上一列的 3
    2[1,3,1,2][7,10,11,13]答案 13；到第 2 欄可取上方 10 或左方 10

    最後一列更新第 1 欄時，dp[1] 仍是上方的 ∞，dp[0] 已是同列左方的 7，所以得到 7+3=10。這種一維陣列在迴圈途中混合「上一列」與「這一列」，是刻意設計的相依關係。

    這裡即使代價為負也能處理，因為只能向右或下，路徑永遠不會回頭，依然是無環圖。若允許四方向移動，就不能直接沿用這個填表順序；可能產生循環，問題需要重新定義路徑限制並選擇合適的圖論演算法。R×C 格子時間 O(RC)，本實作輔助空間 O(C)，無可行路徑回傳 None。

    11.7 狀態機 DP：昨天的資格決定今天的動作

    題目對照：LeetCode 309．Best Time to Buy and Sell Stock with Cooldown。輸入每日非負價格，回傳遵守賣出後冷卻一天規則的最大已實現收益，可完全不交易。本頁 [2,5,1,4,6] 的答案是 5，例如在價格 1 買入、6 賣出；也另外定義空價格串列的答案為 0。

    每天有一個價格，可以多次買賣，但最多持有一股；賣出後隔天必須冷卻，不能買入。光存「到今天的最高收益」不足以描述明天能做什麼：持股與否、今天是否剛賣出都會影響下一步。把一天結束的狀態分成：

    • hold：結束時持有一股的最大淨現金；買入花的錢已扣除。
    • sold：恰在今天賣出，結束時不持股的最大收益。
    • rest：結束時不持股，而且今天沒有賣出的最大收益；明天可買。

    處理今天價格 p 時，新 hold=max(舊 hold, 舊 rest−p)，新 sold=舊 hold+p，新 rest=max(舊 rest, 舊 sold)。舊 sold 今天只能進入 rest 度過冷卻，不能直接買入。所有轉移都必須讀昨天的值；若先覆寫 rest，再拿新 rest 去算 hold，就可能讓昨天剛賣出的錢在今天立刻買入。

    def cooldown_profit(prices):
    """可多次交易，最多持有一股；賣出後隔天不能買入。"""
    if any(price < 0 for price in prices):
        raise ValueError("價格必須非負")
    hold = sold = float("-inf")
    rest = 0
    for price in prices:
        old_hold, old_sold, old_rest = hold, sold, rest
        hold = max(old_hold, old_rest - price)
        sold = old_hold + price
        rest = max(old_rest, old_sold)
    return max(rest, sold)  # 只有不持股狀態是已實現的收益

    時刻／價格holdsoldrest

    第 0 天：2−2−∞0

    n 天、每一天只有 3 個狀態且每狀態 O(1) 轉移：時間 O(n)，空間 O(1)。冷卻、手續費、交易次數限制會改變轉移或增加狀態維度，不能直接拼貼互相矛盾的模板。此題是演算法模型，未包含真實市場成本與交易條件。

    11.8 先審狀態，再估複雜度

    完整性檢查：背包狀態漏掉容量會混合不同問題；路徑不能重訪時漏掉 visited 集合會混合不同合法選項；限制相鄰字元時漏掉上一個字元會允許違規轉移。反過來，把整段 path 放進 key 可能完全保留歷史，卻幾乎無法合併狀態，並付出建立 tuple 與雜湊的成本。

    狀態數檢查：i 有 n 種、容量 w 有 W 種，最多 nW 個；但「已選集合」有 2ⁿ 種，不能因為它只用一個整數 mask 儲存，就說只有 n 種狀態。若還記最後一個點 last，狀態可能是 n·2ⁿ，每個狀態再試 n 個下一點，時間可能到 O(n²·2ⁿ)。cache 只避免同狀態重算，無法消除本來就不同的指數個狀態。

    Python 成本檢查：切片、拼字串、建立 tuple 都可能不是 O(1)；使用 a[i:] 當狀態，不如用索引 i。大整數計數可能長到數百或數千位，整數加法也有位元成本。本章常見 O(狀態×轉移) 估計採用比較與有界整數運算為 O(1) 的模型；處理巨大計數或位元遮罩時需補上數值長度成本。

    11.9 練習：把題意翻成狀態

    練習一：配送機器人的步伐序列

    自編情境，對應題型：LeetCode 377．Combination Sum IV。把原題可重用的正整數看成步長，順序不同要分開計數。本題固定步長為 1、3、4，並補上 n=0 的空序列規則；n=5 的輸出是 6，回傳的是序列數量。

    機器人一次前進 1、3 或 4 格，走到距離 n 有幾種有順序的步伐序列？例如 1+3 與 3+1 是兩種。定義距離 0 有一種空序列，手算 n=5。

    參考解答

    dp[t] 是總距離恰為 t 的序列數；依最後一步 s 分組，dp[t] 加上 dp[t−s]。每個序列最後一步唯一，所以這些分組不重疊。外層按總距離遞增，內層枚舉最後一步。

    def count_step_sequences(n, steps=(1, 3, 4)):
    if n < 0 or any(step <= 0 for step in steps):
        raise ValueError("n 必須非負，步長必須為正整數")
    choices = sorted(set(steps))
    dp = [0] * (n + 1)
    dp[0] = 1
    for total in range(1, n + 1):
        for step in choices:
            if step > total:
                break
            dp[total] += dp[total - step]
    return dp[n]

    dp[0..5]=[1,1,1,2,4,6]，答案 6。D 種步長下時間 O(nD + D log D)、空間 O(n)，以整數加法 O(1) 模型估計。若改成「不計順序的面額組合數」，外層先枚舉面額、內層金額遞增，才會固定組合的建構順序；兩種問題的迴圈不能混用。

    練習二：不能連續接案

    自編延伸練習：相近題型是 LeetCode 198．House Robber，同樣是在相鄰位置不能一起選的限制下求最大總和。原題金額非負；本題把情境改成接案，允許負分與空輸入，而且可全部不接，不能把「至少選一天」當成隱含條件。

    每天接案會得到 values[i] 分，接案後隔天必須休息，可全部不接；求最高分。分數可能為負。例如 [4,−1,6,3] 的答案為 10。請使用 O(1) 輔助空間。

    參考解答

    令 f[i] 為前 i 天的最高分。最後一天不接是 f[i−1]，接則是 f[i−2]+當天分數。邊界空前綴為 0，只保留前兩個值。允許不接任何案子，所以全負輸入答案為 0。

    def best_nonadjacent(values):
    before_previous = previous = 0
    for value in values:
        current = max(previous, before_previous + value)
        before_previous, previous = previous, current
    return previous

    每一天兩個選擇，時間 O(n)、空間 O(1)。若題目規定至少接一天，不能照抄這組全零邊界，因為空選擇不再合法。

    練習三：最少插入成回文

    題目對照：LeetCode 1312．Minimum Insertion Steps to Make a String Palindrome。只允許插入字元，回傳最少插入次數；原字串已是回文就回傳 0。本頁使用大寫字元範例，並額外定義空字串答案為 0；原題輸入是非空的小寫英文字串。

    可以在字串任意位置插入字元，不能刪除或替換，求變成回文的最少插入次數。"ABCA" 只要插入一個字元就能得到 "ABCBA"。

    參考解答

    dp[l][r] 是原字串閉區間 l..r 的答案。兩端相同，只處理內部；不同則在另一端插入一個字元，代價是 1+min(dp[l+1][r],dp[l][r−1])。長度 0 或 1 已是回文。每次依賴較短區間，因此外層按區間長度遞增。

    def minimum_palindrome_insertions(text):
    n = len(text)
    if n == 0:
        return 0
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n + 1):
        for left in range(n - length + 1):
            right = left + length - 1
            if text[left] == text[right]:
                dp[left][right] = dp[left + 1][right - 1] if length > 2 else 0
            else:
                dp[left][right] = 1 + min(dp[left + 1][right],
                                         dp[left][right - 1])
    return dp[0][n - 1]

    O(n²) 時間、O(n²) 空間。若從左到右隨意掃 l、r，可能讀到尚未算好的較短區間；依賴圖比陣列外觀更重要。

    練習四：指數 DP 的工作分配

    自編題。輸入一張方形代價矩陣，回傳一對一工作分配的最低總代價，不回傳分配名單。例如 cost=[[3,1],[2,4]]，讓第 0 人做第 1 份工作、第 1 人做第 0 份工作，輸出 3。

    n 個人分配 n 份工作，每人一份、每份只用一次。cost[i][j] 是第 i 人做第 j 份工作的代價，求總代價最小值。只討論 n 很小的情況；這題也有更適合大型輸入的專門演算法。

    參考解答

    mask 的第 j 位為 1 表示第 j 份工作已用；已安排的人數等於 mask 中 1 的數量，所以不用再存 person。dp[mask] 是前 person 人完成這些工作的最小代價。枚舉下一份未使用的工作，設位後的 next_mask 一定大於 mask，數值遞增就是合法順序。

    def minimum_assignment(cost):
    """n 個人各分配一份不同工作；cost[人][工作] 為代價。"""
    n = len(cost)
    if any(len(row) != n for row in cost):
        raise ValueError("cost 必須為方陣")
    size = 1 << n
    dp = [float("inf")] * size
    dp[0] = 0
    for mask in range(size):
        person = mask.bit_count()
        if person == n:
            continue
        for job in range(n):
            if not (mask & (1 << job)):
                next_mask = mask | (1 << job)
                dp[next_mask] = min(dp[next_mask],
                                    dp[mask] + cost[person][job])
    return dp[-1]

    cost=[[6,2,4],[3,5,1],[2,6,4]] 的答案為 5，分別挑工作 1、2、0。共有 2ⁿ 個 mask，每個至多 n 次轉移，所以時間 O(n·2ⁿ)、空間 O(2ⁿ)，以位元運算 O(1) 的一般小 n 模型估計。n=0 回傳 0，代表唯一的空分配。這是 DP，但仍是指數演算法。

    4. 原創模擬一：挑一段監測紀錄

    自編延伸練習：可搭配 LeetCode 904．Fruit Into Baskets 練習。原題找最多含兩種水果的連續區間，回傳長度；本題改成任意 k 種字串標籤，回傳半開索引，並規定同長時選最早開始。這些輸入與輸出差異都要保留，不能直接照搬原題介面。

    題目：感測系統依時間留下標籤序列 labels。分析畫面一次最多能顯示 k 種不同標籤。請找最長的一段連續紀錄，使其中標籤種類數至多為 k，回傳半開索引 (left, right)。同長選最早開始；空輸入或 k=0 回傳 (0,0)。本題假設 0≤n≤200,000，k 是非負整數，標籤為可雜湊字串，不可修改輸入。

    範例 labels=[A,B,A,C,C,B,B]、k=2，答案 (3,7)，對應 C,C,B,B。這裡的 n 上限是本練習自訂的條件，不是外部題庫資料。

    基準解：枚舉 O(n²) 個區間，每次重建 set 最壞 O(n)，總 O(n³)。若每個左端固定後漸進擴張並更新 set，可降到 O(n²)，仍不適合本題設定。進一步觀察：右端每加入一個標籤，只需更新一次計數；若種類太多，左端一直移到合法為止。

    def longest_label_window(labels, k):
    """回傳至多 k 種標籤的最長半開區間；同長時選最早。"""
    if k < 0:
        raise ValueError("k 不可為負")
    counts = {}
    left = 0
    best = (0, 0)
    for right, label in enumerate(labels):
        counts[label] = counts.get(label, 0) + 1
        while len(counts) > k:
            old = labels[left]
            counts[old] -= 1
            if counts[old] == 0:
                del counts[old]
            left += 1
        if right + 1 - left > best[1] - best[0]:
            best = (left, right + 1)
    return best

    正確性：while 結束後，counts 正好記錄 [left,right+1) 內的正次數標籤，種類數不超過 k。左端只在不合法時移動；較早被排除的左端，在增加更多右端元素後仍不可能重新合法。因此當前 left 是這個 right 下能保留的最早合法左端，所得視窗是以 right 結尾的最長合法視窗。遍歷所有 right，就覆蓋了全域最優解。同長不更新，保留最早找到的答案；同長區間依 right 增加，left 也增加，所以符合最早規則。

    逐步追蹤

    right / 新標籤收縮後 left有效計數本輪長度最佳 [L,R)
    0 / A0A:11[0,1)
    1 / B0A:1,B:12[0,2)
    2 / A0A:2,B:13[0,3)
    3 / C2A:1,C:12[0,3)
    4 / C2A:1,C:23[0,3)
    5 / B3C:2,B:13[0,3)
    6 / B3C:2,B:24[3,7)

    加入第一個 C 時，不是左端移一次就好：移除第一個 A 仍有 A、B、C 三種，必須再移除 B。因此這裡必須用 while，不能用 if。

    兩個指標各最多移動 n 次，雜湊平均 O(1) 的假設下總時間 O(n)。計數表穩定時至多 k 種，加入新值瞬間至多 k+1 種，因此額外空間 O(min(n,k+1))；k=0 仍可能短暫存一個鍵。回傳索引為 O(1) 輸出；若回傳整段 labels[L:R]，還要 O(答案長度) 複製。

    面試延伸：如果資料是無法回頭讀的串流，移除左端仍要知道舊標籤，就需保留視窗中的資料或其他足夠資訊。不能僅因原本用了兩指標就聲稱串流也只要 O(k) 記憶體。

    5. 原創模擬二：園區接駁轉乘

    自編題。輸入有向圖的鄰接表、起點與終點，回傳經過站點的串列，每一段的成本相同。以下範例可寫成 graph={"S":["A","B"],"A":["C"],"B":["C","T"],"C":["S","T"],"T":[]}，start="S"、goal="T" 時回傳 ["S","B","T"]。

    題目：園區站點用非空字串命名，graph[u] 是可直接從 u 前往的站點，路線有方向，每搭一段都算一次。給起點 start 與終點 goal，回傳搭乘段數最少的站點路徑；無法抵達回傳 []，起終點相同回傳 [start]。鄰接表沒出現的站點視為沒有出邊；可能有環與重複邊。同長路徑任取，這份實作按鄰接順序選。

    本例：S→A、B；A→C；B→C、T；C→S、T；T 沒有出邊。求 S 到 T。

    這是無權最短路徑，BFS 佇列按距離層次處理。用 parent 同時記錄「已發現集合」與「路徑來源」：在節點入列時就記錄它，而非出列時才標記，可避免多個來源反覆加入同一節點。起點以 None 作父節點哨兵，因此此介面禁止節點本身為 None。

    from collections import deque

def shortest_route(graph, start, goal):
    """無權有向圖；鄰接順序決定同長路徑的選擇。"""
    parent = {start: None}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        if node == goal:
            path = []
            while node is not None:
                path.append(node)
                node = parent[node]
            return path[::-1]
        for neighbor in graph.get(node, ()):
            if neighbor not in parent:
                parent[neighbor] = node
                queue.append(neighbor)
    return []

    正確性：佇列中節點按起點距離不減排列。從距離 d 的節點第一次發現鄰居時，距離為 d+1；若存在更短的路，該更短路的前一個節點應更早出列並先發現它，矛盾。因此第一次記錄的父節點鏈即為最短路徑，遇到終點後逆向追 parent 並反轉即可。

    逐步追蹤

    本輪出列新增 parent處理後 queue說明
    初始化S:None[S]起點已發現
    SA:S、B:S[A,B]距離 1
    AC:A[B,C]C 距離 2
    BT:B[C,T]C 已發現，不再入列
    C無[T]S、T 都已發現
    T無[]反向 T→B→S，輸出 S→B→T

    設可達區域有 V 個節點、E 筆鄰接項，最壞時間 O(V+E)，額外空間 O(V)。重建長度 L 的路徑需 O(L) 時間與輸出空間；path[::-1] 也建立新串列，仍在 O(V) 總界內。若邊有不同非負耗時，BFS 最少段數不保證最短時間，應改考慮 Dijkstra。

    6. 可攜模板：保留不變量，不盲目複製

    上面兩個 mock 已提供視窗與 BFS 模板。這裡再補上兩個短模板，方便搭配前章的方法使用。使用每份模板前，都要確認輸入契約；修改條件後，先重新讀一遍註解與不變量。

    模板 A：有序序列中的第一個不小於目標的位置

    相近題型：LeetCode 35．Search Insert Position。原題的陣列值互不相同；本模板也接受重複值與空陣列，回傳第一個不小於 target 的位置。例如 values=[2,4,4,9]、target=4，回傳 1；若 target=10，回傳 4，表示插在尾端。

    def first_at_least(values, target):
    lo, hi = 0, len(values)
    while lo < hi:
        mid = (lo + hi) // 2
        if values[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

    前提是非遞減且支援隨機存取；[0,lo) 都小於 target，[hi,n) 都不小於 target，返回值可能為 n。O(log(n+1)) 時間，O(1) 額外空間。若題目允許標準庫，可用 bisect_left，但仍要能解釋回傳語意。

    模板 B：含負數也能計數的前綴和

    題目對照：LeetCode 560．Subarray Sum Equals K。輸入整數陣列與目標總和，回傳總和符合目標的連續非空子陣列數量。原題的 k 對應本模板的 target；本頁也接受空陣列，回傳 0。

    def count_target_sum(values, target):
    """連續非空子陣列總和；支援負值。"""
    seen = {0: 1}
    total = answer = 0
    for value in values:
        total += value
        answer += seen.get(total - target, 0)
        seen[total] = seen.get(total, 0) + 1
    return answer

    在目前前綴 total，若某個更早前綴等於 total−target，兩者之間的非空子陣列和就是 target。seen={0:1} 代表空前綴，讓從索引 0 開始的答案被計入；一定要先查再加入當前前綴，避免 target=0 時把長度零的區間算進去。在雜湊平均常數時間下，時間 O(n)、空間 O(n)。

    測 [2,−2,2]、target=2：三個答案是索引 [0,1)、[2,3)、[0,3)。這個模板數的是「有幾個」，不是回傳所有區間；若要列舉，需儲存前綴出現的索引，還要算輸出量。

    視窗程式把 counts[old] 減到零，但沒有 del。對 [A,B]、k=1，可能發生什麼事？

    參考解答

    加入 B 後字典有 A、B 兩鍵。移除 A 後 A:0 還在，len(counts) 仍是 2，所以 while 繼續收縮，甚至移到陣列範圍外。字典長度要代表種類數，就必須只保留正次數；另一種做法是另存 distinct 計數並正確維護。

    練習二：BFS 能處理不同票價嗎？

    S→T 票價 20；S→A、A→T 各 3。想找最低總票價，原模板會錯在哪裡？

    參考解答

    BFS 會偏好一段的 S→T，但兩段 S→A→T 只要 6。模板的不變量是最少邊數，不是最低總成本。非負票價可用 Dijkstra；不能只把 queue 改名成 cost 就保留原證明。

    練習三：前綴和加入順序

    對 values=[0,0]、target=0，正確有幾個非空子陣列？如果先增加 seen[total] 再查會多算什麼？

    參考解答

    正確三個：[0,1)、[1,2)、[0,2)。先更新會在每輪把當前前綴與自己配對，各多算一個空區間，兩輪後錯得 5。先查歷史、再登記現在，就只配對嚴格較早的前綴。

    練習四：口頭複雜度修正

    「我用 sorted 找中位數，只保留一個答案，所以空間 O(1)。」如何修正？

    參考解答

    sorted 會建立 n 個元素的新串列，排序本身也有工作記憶體，總額外空間 O(n)；輸出雖只有一個值，不能忽略中間資料。時間最壞 O(n log n)。若討論其他選擇演算法，需另說實作、是否改動原陣列與最壞成本。

    一、差分陣列：記錄「從哪裡開始改變」

    自編延伸例題：相近題型是 LeetCode 1109．Corporate Flight Bookings，把每筆訂位數加到一段連續航班，最後回傳各班總數。原題航班從 1 編號、增加量為正；本節改成從 0 編號的陣列，也接受負增量。若用本節函式解原題，要先把每筆更新的兩個端點都減 1。

    假設有長度 n 的零陣列，收到 q 個指令「索引 left 到 right，每格加 delta」，最後才需要完整陣列。逐格修改最壞 O(nq)。若只記錄變化的起點與終點，每次更新只要兩個位置。

    差分 d 的意思是相鄰值之差：d[0]=a[0]，d[i]=a[i]−a[i−1]。反過來把 d 做前綴和，就能還原 a。因此閉區間 [left,right] 增加 delta 時，只需 d[left]+=delta、d[right+1]−=delta。第一個位置讓之後的累積多 delta，第二個位置讓效果停止。

    def range_add(n: int, updates: list[tuple[int, int, int]]) -> list[int]:
    if n < 0:
        raise ValueError('n must be nonnegative')
    difference = [0] * (n + 1)
    for left, right, delta in updates:
        if not 0 <= left <= right < n:
            raise ValueError('invalid inclusive interval')
        difference[left] += delta
        difference[right + 1] -= delta
    result, running = [], 0
    for i in range(n):
        running += difference[i]
        result.append(running)
    return result
    逐步例子 A：兩次更新，再還原一次
    階段difference（含哨兵）意義
    初始化[0,0,0,0,0,0,0]尚未改動
    [1,4] 加 3[0,3,0,0,0,−3,0]1 起生效，5 起取消
    [3,5] 加 −2[0,3,0,−2,0,−3,2]3 起生效，6 起取消
    累積前 6 格running：0,3,3,1,1,−2得到最終答案

    不變量：還原到索引 i 時，running 等於所有 left≤i≤right 的更新量總和。每個區間恰好在它的左界加入，超過右界後扣回，因此一個區間對每個位置的貢獻都正確；多個更新可以相加，整體也正確。

    q 次更新加一次還原共 O(q+n) 時間；差分與輸出各 O(n) 空間。這適合批次更新、最後一次輸出的情境。如果每次更新後立刻詢問某個區間總和，重新累積仍可能很慢，需要另學 Fenwick tree 或 segment tree。原陣列非零時，可以先建立它的差分，或把上面得到的「增量」逐格加回原值。
    最容易漏的是 right+1。若寫成 difference[right]−=delta，右端點就少更新了一格。請先寫清楚區間是閉區間還是半開區間，再安排終止位置。

    二、Trie：讓共同字首只走同一段路

    題目對照：LeetCode 208．Implement Trie (Prefix Tree) 要實作插入單字、查詢完整單字與查詢字首。本頁的方法 starts_with 對應原題 startsWith；原題只用非空小寫英文字串，本頁另支援 Unicode 與空字串，相關回傳規則在本節明訂。

    Trie（字首樹）把每條邊標記成一個字元。從根走過 c、a、r，就代表字首 car。節點還需要 end 標記，區分「這條路存在」與「有一個完整單字在這裡結束」。沒有 end 時，插入 cart 會讓查找 car 被誤判為完整單字。

    from __future__ import annotations

class TrieNode:
    def __init__(self) -> None:
        self.children: dict[str, TrieNode] = {}
        self.end = False

class Trie:
    def __init__(self) -> None:
        self.root = TrieNode()

    def insert(self, word: str) -> None:
        node = self.root
        for char in word:
            if char not in node.children:
                node.children[char] = TrieNode()
            node = node.children[char]
        node.end = True

    def _walk(self, text: str) -> TrieNode | None:
        node = self.root
        for char in text:
            if char not in node.children:
                return None
            node = node.children[char]
        return node

    def search(self, word: str) -> bool:
        node = self._walk(word)
        return node is not None and node.end

    def starts_with(self, prefix: str) -> bool:
        return self._walk(prefix) is not None

    插入的逐步狀態：先插入 car，建立 c→a→r 並將 r 標記 end；再插入 cart，重用前三條邊，只新增 t，保留 r 的 end；最後插入 cat，重用 c→a，再新增另一條 t 邊。此時 search("ca") 為 False，starts_with("ca") 為 True，search("car") 為 True。

    不變量：處理完字串前 i 個字元後，node 恰好代表長度 i 的字首。下一條匹配字元的邊存在，就延長一個字元；不存在，整個字首也不可能存在。走完全部字元後，再查 end 才能決定完整單字是否存在。

    長度 L 的插入、完整查找、字首查找，平均時間 O(L)，假設字典單次操作平均 O(1)。總儲存量 O(S)，S 是所有插入字串長度總和的上界；共用字首會減少實際節點數。Python 每個節點與字典本身都有額外記憶體成本，若只需要查詢完整單字是否存在，set 往往更簡單。這個實作支援 Unicode 字元，但不自動做大小寫、重音、字形正規化。

    本版採集合語意，重複插入同一字不增加計數。空字首永遠有根這條零步路徑，所以 starts_with("") 為 True；search("") 只有在 insert("") 後才為 True。刪除、出現次數與自動補全排序都需要另外設計，不能從 end 一個布林值直接推得。

    三、位元：把一小群布林值放進一個整數

    延伸實作：LeetCode 191．Number of 1 Bits 要回傳整數二進位表示中 1 的個數，原題輸入範圍為 1 到 2³¹−1。本節的 popcount 接受任意非負 Python 整數，因此也處理 0 與超過固定字寬的數；例如 44 的輸出是 3。

    若候選元素編號為 0 到 b−1，可用整數 mask 的第 i 位代表元素 i 是否在集合中。這很適合小集合、狀態壓縮和子集合枚舉。這樣只是改變集合的表示法，子集合的數量仍是 2ᵇ 個。

    操作Python 表達式意思
    建立第 i 位1 << i只有第 i 位是 1
    檢查成員(mask & (1 << i)) != 0交集是否非空
    加入mask | (1 << i)把第 i 位設成 1
    移除mask & ~(1 << i)把第 i 位設成 0
    切換mask ^ (1 << i)0、1 互換
    集合交集／聯集a & b ／ a | b每一位各自運算

    一個常用技巧是 x & (x−1)：它會移除最右邊的一個 1。因為減一把最右邊的 1 變成 0、它右邊的 0 變成 1；再與原數 AND，剛剛那個 1 就消失，其餘較高位保留。

    def popcount(value: int) -> int:
    if value < 0:
        raise ValueError('this implementation requires a nonnegative integer')
    count = 0
    while value:
        value &= value - 1
        count += 1
    return count

    101100₂ → 101000₂ → 100000₂ → 000000₂。每輪恰好少一個 1，迴圈執行三次，所以 popcount(44)=3。對應集合是 {2,3,5}；位元從右邊以 0 開始編號。

    不變量：count 加上目前 value 的 1 數量，始終等於原數的 1 數量；每次減少一個 1 並增加 count，直到 value=0。若原數有 k 個 1，執行 k 次位元運算迴圈。固定機器字寬的模型可寫 O(k) 時間、O(1) 空間。

    Python 整數不是固定 32 位。~x 等於 −x−1，若要 b 位補數，寫 (~x) & ((1 << b)−1)。本版 popcount 拒絕負數；不能拿「負數一直清除 1」當成會結束的迴圈。對大整數，位元運算需要處理多個內部數位：設其內部數位數為 L，上面保守分析是 O(kL) 時間、O(L) 暫存空間，不能一律宣稱 O(1) 成本。

    四、區間：先定義端點，再排序合併

    題目對照：LeetCode 56．Merge Intervals。輸入閉區間清單，回傳合併後彼此不重疊的區間；共用端點也算重疊。例如 [(1,4),(3,6),(8,9)] 回傳 [[1,6],[8,9]]。本頁另外接受負端點與空輸入，空輸入回傳 []；後面的半開會議區間則是另一套端點規則。

    合併區間前，要先依左端點排序，確保後來區間的左界不會比前面更小；不能只看到重疊就任意合併。維護一個目前尚可延伸的區間，後面的區間若與它重疊就擴大右界；否則目前區間的範圍就能確定下來。

    def merge_closed(intervals: list[tuple[int, int]]) -> list[list[int]]:
    if any(left > right for left, right in intervals):
        raise ValueError('left endpoint exceeds right endpoint')
    merged: list[list[int]] = []
    for left, right in sorted(intervals):
        if not merged or left > merged[-1][1]:
            merged.append([left, right])
        else:
            merged[-1][1] = max(merged[-1][1], right)
    return merged

    不變量：處理完前 i 個已排序區間後，merged 依序表示這些區間的完整聯集，彼此不重疊。下一段若 left 大於最後一段 right，兩者中間有空隙，可以另開一段；否則合併成相同左界與較大的右界，不會漏掉或多出覆蓋位置。

    排序 O(n log n)，掃描 O(n)。sorted 會建立新清單，Python 排序也可能需要 O(n) 暫存，因此即使不算輸出，此實作的額外空間仍是 O(n)。它不改動輸入的區間容器；輸出以新 list 建立。
    • 閉區間 [1,3] 與 [3,4] 在 3 重疊，上面的函式會合併。
    • 半開會議 [1,3) 與 [3,4) 不重疊，可以使用同一間會議室；釋放條件是 end≤next_start。
    • 表示連續覆蓋範圍時，相接的半開區間也可合成 [1,4)，但這不表示兩場會議時間衝突。
    • [1,2] 與 [3,4] 在實數線上有間隙；若題目只在乎整數點且允許相鄰合併，則是另一種規則，不能偷換定義。

    五、模運算：加減乘可逐步取餘數，除法要另問

    自編例題。輸入整數 base、非負整數 exponent 與正整數 modulus，回傳 base 的 exponent 次方除以 modulus 的餘數。以下範例 pow_mod(7,13,11) 回傳 2；目標是直接算出餘數，無須先建立整個次方值。

    當答案只需要除以正整數 m 的餘數，計算可以保持在 0 到 m−1。加法、減法、乘法都與「最後才取模」相容，例如 (a×b)%m 等於 ((a%m)×(b%m))%m。這能限制中間數字的成長，但不會自動保留原數的大小順序。

    除法不能直接搬進來：模 6 時，2×1 與 2×4 都得到 2，知道乘積餘數是 2 並不能唯一倒推出另一個因數。a 的模反元素存在，當且僅當 a 與 m 互質；若 m 是質數，也仍要求 a 不被 m 整除。這些前提沒有確認，就不應使用「除以 a」的捷徑。

    要算 base 的 exponent 次方，可利用 exponent 的二進位表示，把底數不斷平方。指數最低位為 1 時，把目前底數乘入 result；接著把指數右移一位。

    def pow_mod(base: int, exponent: int, modulus: int) -> int:
    if exponent < 0 or modulus <= 0:
        raise ValueError('requires exponent >= 0 and modulus > 0')
    result = 1 % modulus
    base %= modulus
    while exponent:
        if exponent & 1:
            result = result * base % modulus
        base = base * base % modulus
        exponent >>= 1
    return result

    不變量：result×baseᵉ 模 m 始終等於原問題的答案，其中 e 是目前 exponent。若 e=2t，baseᵉ=(base²)ᵗ；若 e=2t+1，先把一份 base 乘入 result，剩下同樣變成平方底數的 t 次方。到 e=0 時，答案全部留在 result。

    指數 e≥1 時只做 O(log e) 次模乘；e=0 是常數次工作。這是運算次數，並不表示任意大整數的乘除都 O(1)。本版保留常數個整數，底數與結果需要 O(log m) 位、指數需要 O(log e) 位。實務上可以直接使用 Python 的 pow(base, exponent, modulus)，不需要先算出巨大次方。

    本函式只接受非負指數與正模數。modulus=1 時任何結果都是 0，因此 result 用 1%modulus 初始化；exponent=0 按乘法單位元計算。Python 對正模數的 % 會給非負餘數，其他語言的負數餘數規則可能不同，移植時要再確認。

    六、Dijkstra：最便宜的未完成狀態先擴展

    自編例題，相近題型：LeetCode 743．Network Delay Time。原題頂點從 1 編號，回傳所有頂點都收到訊號所需的最短時間；有頂點不可達就回傳 −1。本節頂點從 0 編號，直接回傳起點到每個頂點的最短距離，不可達位置保留 inf。圖中從 S 出發的輸出是 [0,5,2,6,inf]；兩者都要求非負邊權重。

    第 06 章 BFS 最小化邊數。若每條邊是不同但非負的票價，便要把先進先出的佇列換成最小堆積。distance[v] 記錄目前發現的最便宜路線，heap 每次彈出最小暫定成本。沿邊試算更便宜的新路線，叫做「鬆弛」。

    from heapq import heappop, heappush
from math import inf

def dijkstra(graph: list[list[tuple[int, int]]], start: int) -> list[float | int]:
    if any(weight < 0 for edges in graph for _, weight in edges):
        raise ValueError('Dijkstra requires nonnegative weights')
    distance = [inf] * len(graph)
    distance[start] = 0
    heap = [(0, start)]
    while heap:
        cost, node = heappop(heap)
        if cost != distance[node]:
            continue  # An old, more expensive entry.
        for neighbor, weight in graph[node]:
            candidate = cost + weight
            if candidate < distance[neighbor]:
                distance[neighbor] = candidate
                heappush(heap, (candidate, neighbor))
    return distance
    逐步例子 C：同一個頂點可以有舊的堆積項目
    彈出項目更新distance[S,A,B,T]
    (0,S)A=8，B=2 入堆[0,8,2,∞]
    (2,B)A 降至 5，T=11[0,5,2,11]
    (5,A)T 降至 6[0,5,2,6]
    (6,T)沒有出邊[0,5,2,6]
    (8,A)8≠distance[A]，略過舊項目不變
    (11,T)11≠distance[T]，略過舊項目不變

    為什麼非負很重要？當一個未過期的最小成本項目 (d,u) 彈出，若還有更便宜的路到 u，沿那條路看第一個尚未確定的頂點；它之前的部分應已完成鬆弛。因為剩下所有邊都非負，它的暫定成本不會大於那條更便宜路的總成本，理應先於 u 彈出，矛盾。因此 u 的成本此時已是最優值。

    不能在「第一次加入 heap」就把頂點鎖死；上例 A 先以 8 入堆，之後才降成 5。Python heapq 沒有這段程式所需的原地 decrease-key 操作，因此放入新項目、等舊項目彈出時跳過即可。只有成本嚴格小於目前值時才更新，也能避免零成本環不斷加入相同成本項目。

    本版先掃描所有 E 條邊檢查負權重。每次成功鬆弛至多新增一個堆項目，懶刪除堆積可能有 O(E) 項，所以一般鄰接清單含重邊時，時間可寫 O(V+E log(E+2))，額外空間 O(V+E)。簡單圖有 E≤V²，常見寫法因此是 O((V+E) log V)，但不能忘記堆中的過期項目會占空間。這些分析把成本加法與比較視為固定成本；巨大 Python 整數另有位元長度成本。
    含負邊時，以上「一旦彈出便最優」的證明失效，不能靠換一個 visited 時機修好。程式明確拒絕負邊，包含不可達部分的負邊。若題目允許負權重，應改選符合條件的演算法，例如限制邊數的分層動態規劃，或另學 Bellman–Ford。

    七、限制轉乘：同一個城市，也可能是不同狀態

    延伸實作：LeetCode 787．Cheapest Flights Within K Stops 要求最多 K 個中途停靠點下的最低總票價。原題以航班清單輸入、無解回傳 −1；本頁用鄰接表、無解回傳 None，並額外測試零票價、起終點相同及 K=−1。以下範例仍依本頁介面作答，不能把停靠點數直接當成可走的邊數。

    假設票價非負，但最多允許 K 個中途停靠點。若起點與終點不同，這表示最多 B=K+1 條邊。容易出錯的寫法是只保留 distance[city]，以為到某城市越便宜就越好；但較便宜的路可能已用完額度，無法繼續飛。

    正確狀態是 (city,used_edges)。distance[city][used_edges] 表示恰好用這麼多條邊抵達城市的最低費用，不是「最多」；答案則從 0 到 B 邊的合法終點狀態中取最小值。每條原本的邊 u→v 變成 (u,e)→(v,e+1)，只有 e<B 才能走。這是一張更大的圖，非負權重 Dijkstra 的證明原封不動適用。

    def cheapest_with_stops(graph: list[list[tuple[int, int]]], start: int,
                        target: int, max_stops: int) -> int | None:
    # max_stops counts intermediate vertices, so max_edges = max_stops + 1.
    if max_stops < -1:
        raise ValueError('max_stops must be at least -1')
    if any(weight < 0 for edges in graph for _, weight in edges):
        raise ValueError('requires nonnegative weights')
    max_edges = max_stops + 1
    distance = [[inf] * (max_edges + 1) for _ in graph]
    distance[start][0] = 0
    heap = [(0, start, 0)]
    while heap:
        cost, node, used = heappop(heap)
        if cost != distance[node][used]:
            continue
        if node == target:
            return cost
        if used == max_edges:
            continue
        for neighbor, weight in graph[node]:
            candidate = cost + weight
            if candidate < distance[neighbor][used + 1]:
                distance[neighbor][used + 1] = candidate
                heappush(heap, (candidate, neighbor, used + 1))
    return None

    上圖編號 S=0、a=1、b=2、v=3、T=4。K=2 時，演算法先到 (v,3) 費用 3，但它不能擴展；之後仍保留 (v,1) 費用 5，走到 (T,2) 費用 6。若把 K 改成 3，可用四條邊，答案才變成 4。每次彈出的項目按費用排序，因此第一個未過期的目標狀態，就是所有合法用邊數中的最便宜答案。

    不變量：每個距離項目只與相同城市、相同已用邊數的路徑比較。只有一個狀態同時「費用不更高、使用邊數不更多」，才可能支配另一個狀態；單獨費用較低並不足以刪除它。本版保留所有維度，沒有做這種額外剪枝。

    當 B≥1，擴展圖有 (B+1)V 個狀態與最多 BE 條轉移。此懶刪除實作時間 O(BV+BE log(BE+2))、額外空間 O(BV+BE)，最壞堆積也要計入。B=0 時不能走邊，起終點相同才可用零成本完成；本實作仍會配置距離與檢查輸入，花 O(V+E) 時間。K=−1 是程式特別允許的「最多零條邊」測試值，普通航班題通常從 K=0 開始。
    另一條思路：固定用邊數逐層做 DP，每一輪只從上一輪狀態計算下一輪，即可在 O(B(V+E)) 時間求限制邊數最短路，也能處理負邊。一定要使用新的下一層陣列；若在同一輪讀到剛寫入的距離，就可能在一輪內走了多條邊。本章測試使用這個獨立版本做交叉驗證。

    八、練習：替工具補上它需要的前提

    練習 1｜同時處理中的工作有多少？

    自編延伸練習。沿用本章差分的閉區間加法模型，但輸出改成最高負載這一個數字，不是每一格的完整負載陣列。下方例子的答案 2 表示最多有兩個工作同時占用同一時間格。

    共有 n 個離散時間格，每個工作覆蓋閉區間 [left,right]，每格負載增加 1。回傳最高負載。n=7、工作 [(0,2),(2,5),(4,6)] 的答案是 2。沒有時間格也沒有工作時回傳 0。

    參考解答

    這是批次區間加法，直接把 delta 設為 1，再取最大值。差分的前綴和就是該時間仍在執行的工作數，不會把結束之後也算進去。時間 O(n+q)，額外空間 O(n)。若時間戳範圍巨大而工作很少，不應配置巨大陣列；可以另學排序事件或座標壓縮。

    def peak_load(n: int, intervals: list[tuple[int, int]]) -> int:
    counts = range_add(n, [(left, right, 1) for left, right in intervals])
    return max(counts, default=0)

    練習 2｜最少會議室

    自編練習。以下面的半開區間規格作答，輸出房間數，不回傳每場會議的房號。結束時間等於另一場的開始時間時可以共用房間；空會議清單的答案是 0。

    每場會議使用正長度半開區間 [start,end)。回傳足夠容納全部會議的最少房間數。[(1,4),(4,6),(2,3)] 應回傳 2；第二場可以接手第一場的房間。

    參考解答

    依開始時間排序，用最小堆積保留目前仍在進行的會議結束時間。在新會議開始前，先把所有 end≤start 的會議釋放。堆積大小就是這一刻同時進行的會議數；其最大值是必要的房間數，也可用回收空房的方式達到，因此充分。時間 O(n log n)，空間 O(n)。

    def min_rooms(intervals: list[tuple[int, int]]) -> int:
    # Positive-length, half-open intervals [start, end).
    if any(start >= end for start, end in intervals):
        raise ValueError('meetings must have positive duration')
    ends: list[int] = []
    answer = 0
    for start, end in sorted(intervals):
        while ends and ends[0] <= start:
            heappop(ends)
        heappush(ends, end)
        answer = max(answer, len(ends))
    return answer

    練習 3｜成對資料中多出哪個值？

    題目對照：LeetCode 136．Single Number。輸入保證只有一個值出現一次，其餘各出現兩次；回傳那個值，並要求線性時間與常數額外空間。這個次數保證是題目條件，不能靠相同程式順便驗證。

    給整數陣列，保證恰有一個值出現一次，其餘每個不同值都恰好出現兩次。不排序、不用頻率表，找出單獨值。[13,8,13,−4,8] 應得到 −4。

    參考解答

    XOR 滿足 x^x=0、x^0=x，且可交換與結合，所以成對值全部抵消。累積值是不斷加入前綴元素後的 XOR，處理完便只剩單獨值。固定字寬下時間 O(n)、額外空間 O(1)；Python 大整數仍需計入字長。這個方法依賴次數保證，不能拿它偵測輸入是否真的符合保證。

    def xor_unique(values: list[int]) -> int:
    # Exactly one value occurs once; every other value occurs twice.
    result = 0
    for value in values:
        result ^= value
    return result

    練習 4｜排除自己後的乘積，模數可能不是質數

    自編延伸練習：相近題型是 LeetCode 238．Product of Array Except Self，原題要求每格以外元素的完整乘積，且不能用除法。本題多了正整數模數 m，回傳乘積的餘數，並額外處理單元素與空陣列；不能直接用模除法代替前後綴乘積。

    回傳每個位置之外所有元素乘積對正整數 m 的餘數。允許零與負數，m 也可能是合數；不能使用除法。values=[2,3,4]、m=6 時得到 [0,2,0]。單元素陣列的空乘積是 1%m。

    參考解答

    第一輪把「左側乘積」存入結果，第二輪由右向左累乘「右側乘積」，把兩者相乘。每個位置的左、右集合互不重疊且正好排除自己。全程只用乘法與取模，因此零與沒有模反元素都不成問題。使用 O(n) 次模乘，結果 O(n)；不計結果只保留常數個整數，位元空間仍由 m 決定。

    def products_except_self_mod(values: list[int], modulus: int) -> list[int]:
    if modulus <= 0:
        raise ValueError('modulus must be positive')
    result = [1 % modulus] * len(values)
    prefix = 1 % modulus
    for i, value in enumerate(values):
        result[i] = prefix
        prefix = prefix * value % modulus
    suffix = 1 % modulus
    for i in range(len(values) - 1, -1, -1):
        result[i] = result[i] * suffix % modulus
        suffix = suffix * values[i] % modulus
    return result

    練習 5｜為什麼不能只記「抵達城市時剩幾站」？

    自編反例題。沿用上節限制轉乘問題，可對照 LeetCode 787．Cheapest Flights Within K Stops。這題要判斷刪除狀態的規則是否安全，回答理由或反例，不需要再寫一份完整求最短路的程式。

    另一位同學想只保留每個城市「剩餘邊數最多」的那條路，忽略費用。這樣能解限制轉乘的最低票價嗎？

    參考解答

    也不行。例如允許三條邊，S→v 票價 100，S→a→v 每段票價 1，v→T 票價 1。兩條抵達 v 的路都有足夠額度去 T，但只保留剩餘額度最多的直達路會得到 101，正確答案是 3。費用與已用邊數都影響答案，不能只按任一軸保留一條；上一節的二維狀態會保留兩者並找到 3。

    九、怎麼選，以及接下來練什麼

    • 大量區間加法，最後才看結果：差分；更新與查詢交錯：再學樹狀陣列或線段樹。
    • 字首是否存在：Trie；只有完整鍵存在：先考慮 set。選工具時把 Python 物件成本算進去。
    • 元素種類很少的集合：位元遮罩；不要忘記列舉所有子集合仍是指數級。
    • 區間合併：排序後維護最右一段；排程衝突：先確定端點語意。
    • 巨大指數取模：平方快速冪；需要模除法：先確認互質，或改用不含除法的方法。
    • 相同步長：BFS；非負不同權重：Dijkstra；有限制步數或資源：先擴充狀態，再選求解方法。
