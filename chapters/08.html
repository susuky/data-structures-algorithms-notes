08 · 把眼前的選擇證明成完整解

貪婪法每一步只看當下做一個決定。它能省下大量搜尋，全靠你能證明這個決定不會把最佳解排除在外。

把選擇規則說成一句可檢查的話

排活動時可以按開始最早、時間最短，或結束最早選第一場。這些規則看起來都有道理，答案由目標與限制決定。本章目標是「安排最多場互不重疊活動」。

一個可推導的貪婪規則會說清楚：現在可選誰、按照什麼指標選、選了之後剩下哪個子問題，以及最優解如何接受這個選擇。

最常用的證法是交換：從某個最優解出發，把它的一項換成貪婪選擇，並證明總目標不變差。交換後，剩下部分仍是同類問題，就能反覆使用。

活動每場收入不同，原本「最多場」的評分方式要改哪裡？

看推理

目標改成收入加總。場數相同的兩種安排可能價值差很多，要重新推導狀態與選擇規則。

最早結束，留下最多後續時間

一間工作室有多個活動申請，使用半開區間 [start,end)。挑最早結束的相容活動，接著再選開始時間不早於上一場結束的下一場。

活動怎麼排最多

每一步維持的關係

每次挑相容且最早結束的活動，保留後面的可用時間。

排序 O(n log n)，掃描 O(n)；半開區間允許端點相接。

互動把活動依結束時間排列。接受一場後，觀察它的結束時間如何成為下一次的門檻；端點相接的活動可以連排。長活動即使最早開始，也可能擋掉好幾個短活動。

每個區間需要 start<end，輸出最多場的其中一組。排序 O(n log n)，之後只掃一次 O(n)，保存排序與答案的空間 O(n)。

[0,10)、[1,3)、[3,5)、[5,7)，最多能安排幾場？

看推理

選後面三場，共 3 場。先選最早開始的 [0,10) 只會留下 1 場。

把最優解的第一場換掉

設 g 是全體最早結束的活動，某個最優解第一場選 o。因為 g.end≤o.end，把 o 換成 g 後，原本排在 o 後面的每場活動仍然排得下。

交換後場數相同，而且最優解已經採用貪婪的第一場。刪去與 g 衝突的活動，餘下問題與原題相同；重複這個交換理由，就得到整個貪婪序列的最優性。

這個證明靠的是活動數量與結束時間。select_intervals 先按 (end,start) 排序，逐一接上 start≥last_end 的活動。

def select_intervals(intervals):
    """選最多個互不重疊半開區間 [start, end)；要求 start < end。"""
    ordered = sorted(intervals, key=lambda x: (x[1], x[0]))
    if any(start >= end for start, end in ordered):
        raise ValueError("區間必須有正長度")
    chosen = []
    last_end = None
    for start, end in ordered:
        if last_end is None or start >= last_end:
            chosen.append((start, end))
            last_end = end
    return chosen

交換 g 與 o 時，哪一個不等式保證後面的活動仍可保留？

看推理

g.end≤o.end。任何原本能在 o 之後開始的活動，也能在 g 之後開始。

接得上就選，衝突就略過

按結束時間讀活動，每一輪只問 start 是否至少為 last_end。接受後更新 last_end；略過時維持原值，讓下一個候選仍與最後一場已選活動比較。

例如已選 [1,4)，接著看到 [3,5) 會衝突，last_end 繼續是 4；再看到 [4,6) 則可以接受，更新成 6。

排序中的候選與真正已選活動是兩份不同角色。狀態只需記住最後已選活動的結束時間與答案清單。

總等待時間，短工作先做

所有工作在時間 0 都可開始，只有一台機器、工作不拆開，目標是總等待時間最少。相鄰兩項工時 a、b，在共同等待時間 t 之後執行：a 先做時，它們總等待為 2t+a；b 先做則為 2t+b。

a≤b 時，把 a 放前面不會增加這兩項的總等待；後面的工作開始時間仍是 t+a+b。反覆交換逆序相鄰項，就得到工時由短到長的順序。

schedule_shortest_first 回傳排序後工時與總等待時間。每項的等待等於之前工時累計；排序 O(n log n)，掃描 O(n)，工時允許 0、拒絕負數。

def schedule_shortest_first(durations):
    """所有工作在時間 0 可開始，回傳順序及總等待時間。"""
    order = sorted(durations)
    if any(duration < 0 for duration in order):
        raise ValueError("工時不可為負")
    elapsed = total_wait = 0
    for duration in order:
        total_wait += elapsed
        elapsed += duration
    return order, total_wait

把所有可達位置縮成最遠邊界

jumps[i] 表示從 i 最多往右走幾格。維護 farthest，代表目前已處理位置能到達的最遠索引。只要 i≤farthest，就能從位置 i 繼續更新 max(farthest,i+jumps[i])。

若遇到 i>farthest，前面所有能出發的位置都接不上它，搜尋便停下。若 farthest 已達最後一格，就知道存在路徑。

這裡只問能否抵達，空陣列視為完成，跳躍距離為非負。每個位置看一次，時間 O(n)、額外空間 O(1)。若題目改成回傳路徑或最少跳數，狀態需要增加對應資訊。

def can_reach_end(jumps):
    """jumps[i] 是由 i 往右最多前進的步數；空陣列視為可完成。"""
    if any(jump < 0 for jump in jumps):
        raise ValueError("步數不可為負")
    farthest = 0
    for i, jump in enumerate(jumps):
        if i > farthest:
            return False
        farthest = max(farthest, i + jump)
        if farthest >= len(jumps) - 1:
            return True
    return True

[2,0,0,1] 會在哪裡發現接不上？

看推理

前面最遠只能到索引 2，走到 i=3 時 i>farthest，回傳 False。

從一個交換，看見整體規則

拿兩個相鄰工作 a、b 比較次序，寫出它們對總目標的貢獻；如果交換後後面部分完全相同，就只需比較這兩項。短工作先做的證明正是如此。

區間排程則從最優解第一場交換成 g，確認後續仍可行。兩種證法分別處理「排序次序」與「保留哪些項目」。

試著把約束增加一項：工作有不同到達時間、活動有收入、跳躍要付代價。每次都回到交換後的目標，看看原不等式是否還成立。

選之前說清楚評分：最多場、最短等待、能否到達，還是總收入。接著把當前決策寫成具體條件，並指出保留哪些狀態給下一輪。
