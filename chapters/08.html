08　貪心：先證明，再相信直覺

貪心演算法每一步只做一個當下最好的選擇，之後不回頭。即使迴圈很簡單，仍要證明「當下最好」的選擇不會犧牲後續結果。本章會連同程式說明選擇規則與正確性：先確認目標，找出能夠交換的決策，再寫排序與掃描。

學習目標：能用反例否定規則；用交換論證或領先性質支持規則；分辨「選最多個」、「總價值最大」、「總等待最少」是不同問題。看過幾個成功案例，只代表規則尚未被推翻。

1. 一個貪心主張，必須回答四件事

  1. 目標：最大化數量、最小化成本，還是只判斷可不可行？
  2. 可行性：做完這個選擇後，是否仍符合容量、時間、先後順序等限制？
  3. 安全選擇：是否至少存在一個最優解，包含這個當下選擇？
  4. 剩餘問題：固定此選擇後，剩下的問題能否用同一種規則處理？

「最優子結構」本身不保證可以貪心；動態規劃也常有最優子結構，但需要比較多個第一步。要採用貪心，還需證明某一個選擇可以安全地固定，不必探索其他分支。若只能說「我覺得最小的比較好」，先把它寫成猜想。

2. 工作室排程：最多不重疊區間

自編排程情境／相近題型：LeetCode 435：Non-overlapping Intervals 問最少刪除幾個區間，才能讓剩餘區間互不重疊。本節改成回傳最多能留下的活動清單；若原有 n 場、最多留下 m 場，原題答案就是 n−m。兩者都允許端點相接，工作室與 A–F 範例為自編。

有一間工作室，活動用半開區間 [start, end) 表示，且 start < end。任兩場不能重疊，但 [1, 3) 與 [3, 5) 可以連排。所有活動價值相同，目標是選最多場。貪心規則：按結束時間由早到晚檢查，若活動開始不早於上一場結束，就接受。

為什麼不是最早開始？[0, 10) 會擋住 [1, 2)、[2, 3)、[3, 4)。為什麼不是最短？在 [0, 3)、[2, 4)、[3, 6) 中，最短的 [2, 4) 與另外兩個都重疊，只能選一場；兩個長度 3 的區間卻可以一起選。按最早結束選取，是為了「保留後綴的空間」；單場活動的長短不足以決定這件事。

3. 交換論證：把某個最優解改成貪心開頭

令 g 為目前候選中結束最早的活動，O 為任意一個最多場的可行排程，o 為 O 的第一場。因為 g 結束不晚於 o，所以把 o 換成 g 後，原本排在 o 後面的所有場次仍能接在 g 後面，場數也沒變。於是，存在以 g 開頭的最優解。

固定 g 後，只留下 start ≥ g.end 的候選；這又是同樣的排程問題。對剩餘場次數做歸納：空集合顯然正確，而交換論證保證第一步安全，因此整個演算法正確。注意證明不是聲稱「每個最優解都一定選 g」，而是聲稱「至少有一個最優解可改成選 g」。

掃描不變量：chosen 中的活動彼此不重疊；last_end 是最後一場結束時間；已跳過且與最後已選活動重疊的候選，之後也不可能接到目前排程。這個不變量只能保證排程可行；選擇是否安全，仍須由交換論證證明。
def select_intervals(intervals):
    """選最多個互不重疊半開區間 [start, end)；要求 start < end。"""
    if any(start >= end for start, end in intervals):
        raise ValueError("區間必須有正長度")
    chosen = []
    last_end = None
    for start, end in sorted(intervals, key=lambda x: (x[1], x[0])):
        if last_end is None or start >= last_end:
            chosen.append((start, end))
            last_end = end
    return chosen

時間 O(n log n)，排序後掃描 O(n)。此版本 sorted 建立新串列，排序工作記憶體及輸出各最多 O(n)，總額外空間 O(n)。若題目只要數量，可以不存 chosen，但在 Python 使用 sorted 仍有 O(n) 記憶體；不能直接宣稱 O(1)。輸入需為可重複遍歷的序列，不能直接傳一次性的 generator。

5. 第二種貪心：短工作先做，總等待最少

自編範例：這是所有工作同時就緒、等待權重相同的單機排程題，沒有指定的 LeetCode 原題。輸入為非負工時序列，輸出等待時間總和的最小值；空序列的總等待為 0。下方 [6,2,4] 的答案是 8。

一台機器，所有工作在時間 0 就緒，工作不可中途切換，每件工作的等待成本權重相同。若工時為 [6, 2, 4]，要怎麼排序，才能讓所有工作開始前的等待時間總和最小？應按工時由短到長處理。本題沒有截止期限，因此無法依截止期限決定順序。

設相鄰兩件工作 a > b，在時間 t 開始處理這一對。a 在前時，兩件等待總和是 t + (t+a)；b 在前時是 t + (t+b)，後者少 a−b。兩件做完的時間相同，因此後續工作的等待不變。持續交換所有逆序對，得到升冪順序，且總等待只會減少或持平。這是「相鄰交換」證明。

def schedule_shortest_first(durations):
    """所有工作在時間 0 可開始，回傳順序及總等待時間。"""
    if any(duration < 0 for duration in durations):
        raise ValueError("工時不可為負")
    order = sorted(durations)
    elapsed = total_wait = 0
    for duration in order:
        total_wait += elapsed
        elapsed += duration
    return order, total_wait

原順序的等待總和是 0+6+8=14；短工時優先是 0+2+6=8。全部完成時間都是 12，所以「越快做完全部工作」並不是此排序改善的目標。總完成時間之和等於總等待加上固定的工時總和，因此同一順序也能讓總完成時間之和最小。

排序 O(n log n)，掃描 O(n)，額外空間 O(n)。零工時合法且可排最前；負工時不符合本模型，程式會拒絕這類輸入。若工作有到達時間、切換成本或不同等待權重，上述交換式改變，不能直接沿用結論。

6. 用可達範圍決定能否繼續前進

對應原題：LeetCode 55：Jump Game。輸入每個位置最多可往前跳幾格，輸出能否從開頭到最後一格；只問可不可達，不問最少跳幾次。原題不允許空陣列，本章另約定空序列回傳 True，章末兩組測試資料為自編。

給定非負整數 jumps[i]，可以從 i 往右跳任意 1 到 jumps[i] 格，問從 0 能否到最後一格。對可達索引 i，將最遠邊界更新成 max(farthest, i+jumps[i])。若遇到 i > farthest，表示目前位置已無法到達，也就無法再向後擴張可達範圍。

def can_reach_end(jumps):
    """jumps[i] 是由 i 往右最多前進的步數；空陣列視為可完成。"""
    if any(jump < 0 for jump in jumps):
        raise ValueError("步數不可為負")
    farthest = 0
    for i, jump in enumerate(jumps):
        if i > farthest:
            return False
        farthest = max(farthest, i + jump)
        if farthest >= len(jumps) - 1:
            return True
    return True

不變量是：處理下一個索引之前，從 0 到 farthest 之間的索引都可達。這依賴「可以跳不超過上限的任意步數」；若必須剛好跳 jumps[i] 格，可達集合中間可能夾著不可達位置，不能只用單一邊界表示。此法時間 O(n)，額外空間 O(1)，只判斷存在性，沒有求最少跳躍次數。空序列的 True 是我們明訂的介面慣例，面試時要先確認。

7. 反例實驗室：別把成功規則帶到不同目標

自編反例／延伸練習：以下反例用自編數字比較規則。加權區間可延伸到 LeetCode 1235：Maximum Profit in Job Scheduling：求不重疊工作的最大總報酬；原題開始時間為正數，本章反例從 0 起算。最少硬幣可延伸到 LeetCode 322：Coin Change：各幣值可不限次使用，無法湊成目標時回傳 −1。前者不能直接套用「最早結束」，後者也不能保證「先拿最大硬幣」會得到最佳解。

  • 最大總價值：[0,2) 值 2、[2,4) 值 2、[0,4) 值 9。最早結束會拿 4，最佳是 9。交換第一場不再保值，通常要考慮加權區間 DP。
  • 任意幣值的最少硬幣：幣值 {1,4,6}、目標 8。先取最大會得到 6+1+1 三枚，而 4+4 只需兩枚。不能因某套貨幣系統可行就推廣到任意集合。
  • 0/1 背包：容量 4，物品 (重量3,價值5)、(重量2,價值3)、(重量2,價值3)。按價值密度先取第一件只能得 5，後兩件共得 6。可切分物品與不可切分物品是不同限制。
  • 只測正向案例：空輸入、重複活動、負時間座標、端點相等都該測。時間座標可負，區間長度不可負，不要混為一談。

8. 練習：先寫理由，再寫程式

練習一：最少刪幾場？

對應原題：LeetCode 435：Non-overlapping Intervals。題目目標與端點規則相同；下方區間資料及從最大保留數推得最少刪除數的問法為自編。

活動為 [(0,2),(1,3),(2,4),(4,5)]，至少刪掉幾場才能互不重疊？說明與最多選取問題的關係。

參考解答

保留 [(0,2),(2,4),(4,5)]，刪 1 場。若 n 場中最多能留下 m 場，最少刪除就是 n−m；否則留下更多就會與 m 的最大性矛盾。可回傳 len(intervals)−len(select_intervals(intervals))，時間 O(n log n)。

練習二：帶權等待打破規則

自編推理題：這題改變了前面單機排程的等權假設，以具體權重檢查短工時優先是否仍然成立。沒有指定的 LeetCode 原題。

A 工時 1、每單位等待成本 1；B 工時 3、每單位等待成本 10。短工時先做是否最佳？

參考解答

A→B 的加權等待是 0×1+1×10=10；B→A 是 0×10+3×1=3，應先做 B。一般相鄰交換比較 a 的工時 pₐ 與權重 wₐ、b 的 pᵦ 與 wᵦ：a 在前安全的條件是 pₐwᵦ ≤ pᵦwₐ。從這個條件可以看出，原本的證明在哪裡用到等權前提；正權重時等價於按 p/w 升冪。

練習三：可達邊界手算

自編測例：沿用 LeetCode 55：Jump Game 的非空輸入規則，以下兩組陣列用來手動檢查可達邊界，並非原題頁面的範例。

分別判斷 [2,1,0,1] 與 [2,2,0,1] 是否可達末端。為什麼不能只看最大的一個跳躍數？

參考解答

第一組在 i=0 後 farthest=2，i=1、2 都無法擴張；到 i=3 時失敗。第二組在 i=1 把 farthest 從 2 擴到 3，因此成功。跳躍數只在其索引可達時才有用，例如 [0,100] 仍失敗。

練習四：排序之後一定能貪心嗎？

自編推理題：這是檢查貪心論證是否完整的問答，沒有指定的 LeetCode 原題或唯一程式介面。

有人說「先排序，然後每次選最便宜的，就是最優」。你會先追問哪三件事？

參考解答

先問要最小化或最大化哪個量、選擇是否會排除其他可行選項、能否把任意最優解的第一個選擇換成最便宜者而不變差。沒有具體限制與目標，單靠排序只能改變資料順序，無法證明選擇一定最優。

9. 章末決策卡

看到「每一步挑一個」時：先列可行性與目標 → 嘗試小反例 → 指出交換後哪個量不變、哪個量改善 → 固定選擇並縮小問題 → 最後處理排序成本及平手。若交換會破壞價值、容量或後續順序，就停下來考慮 DP、回溯或其他資料結構。
