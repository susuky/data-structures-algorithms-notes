08　貪心：先證明，再相信直覺

貪心演算法（Greedy Algorithm）具備一種極具吸引力的簡潔性：在演算法執行的每一步，它都只根據當前資訊做出「看似最划算」的局部最優決策，並且一經選定便絕不回頭。然而，這種「目光短淺」的策略往往也是演算法設計中最容易讓人踩坑的溫床。直覺會告訴你「挑便宜的準沒錯」，但現實卻常常是前期的自私選擇直接封死了全域最優解的道路。要讓貪心演算法成立，核心絕不在於寫出短短幾行的迴圈，而在於嚴格證明局部最優決策必然能導向全域最優解。本章將帶你從目標定義、交換論證（Exchange Argument）、前鋒可達性到反例實驗室，徹底鍛鍊看穿問題本質的演算法直覺。

核心學習目標：學會用極小反例推翻不可靠的直覺；掌握「交換論證」與「領先性質（Greedy Stays Ahead）」的證明架構；精準分辨「選取最多數量」、「累積最大總價值」與「最小化總等待時間」屬於完全不同性質的決策問題。

1. 一個貪心主張，必須回答四件事

當你想提出一個貪心策略時，切勿直接動手寫程式，請先冷靜回答以下四個核心問題：

  1. 目標函式是什麼？我們是要最大化選取的活動數量、最小化資源消耗總成本，還是單純判斷終點是否可達？目標不同，排序鍵值就會天差地別。
  2. 可行性約束為何？做出這一步選擇之後，剩餘的系統狀態是否依然滿足容量上限、時間先後順序或不重疊等硬性限制？
  3. 安全選擇性質（Greedy-Choice Property）：是否至少存在一個全域最優解，正好包含了當下的這個貪心選擇？這是貪心之所以能成立的關鍵基石。
  4. 最優子結構（Optimal Substructure）：做出當前選擇並將其固定後，剩餘的子問題是否能在相同的規則下繼續遞迴求解，且子問題的最優解與當前選擇結合後依然是最優的？

很多工程師容易把「最優子結構」與「貪心法」畫上等號，但這其實是常見的觀念混淆。動態規劃（DP）同樣具備最優子結構，然而動態規劃在每一步必須同時保留多個可能的分支並比較整體收益；貪心法則是更為苛刻的特例——它要求我們能明確證明「只要無腦鎖定當下某個特定選擇，就絕對不會比其他任何選擇差」，從而完全不必探索其他分支。如果你只能憑感覺說「我覺得先選最小的比較合適」，那它充其量只能算是一個未經證實的猜想。

2. 工作室排程：最多不重疊區間

LeetCode 435 · Non-overlapping Intervals 求最少刪除數。本節求最多能留下的活動清單；若 n 場中留下 m 場，最少刪除數就是 n−m。

情境如下：某間熱門會議室收到許多租借申請，每個活動皆以半開區間 $[start, end)$ 表示，且滿足 $start < end$。兩場活動若有重疊就不能同時舉行，但邊界相接（例如 $[1, 3)$ 與 $[3, 5)$）是允許的。所有活動的租金與重要性完全相同，我們的目標是「排入最多場互不衝突的活動」。面對這個問題，標準的貪心策略是：將所有活動依照結束時間由早到晚排序，並由左至右掃描；只要當前活動的開始時間不早於前一場的結束時間，就毫不猶豫地接納它。

為什麼貪心規則是挑「最早結束」而不是「最早開始」？試想反例：一個從 0 開始、長度為 10 的長活動 $[0, 10)$，會蠻橫地佔滿整天，直接封殺掉 $[1, 2)$、$[2, 3)$、$[3, 4)$ 三個短活動。那為什麼不是挑「耗時最短」的活動？再看反例：給定 $[0, 3)$、$[2, 4)$、$[3, 6)$ 三個區間，其中最短的是長度為 2 的 $[2, 4)$，但若選了它，兩側的活動都被干擾，最終只能排入 1 場；反之若不選它，兩側長度為 3 的活動可以完美並存，合計 2 場！挑選「最早結束」的根本哲學在於：越早結束，留給後續活動的時間裕度就越大。這是一種純粹為了極大化後續可行解空間的精妙策略。

3. 交換論證：把某個最優解改成貪心開頭

如何從數學上嚴謹證明「挑最早結束」永遠不會讓你吃虧？我們使用經典的「交換論證（Exchange Argument）」：

設所有候選活動中結束時間最早的活動為 $g$。假設存在一個能夠安排最多場次的全域最優解 $O$，其按時間排序的第一場活動記為 $o$。現在我們把 $O$ 中的第一場活動 $o$ 拿掉，直接換成我們的貪心選擇 $g$：

  1. 可行性維持：因為 $g$ 是所有活動中結束時間最早的，所以 $g.end \le o.end$。既然原最優解中 $o$ 後方的所有活動都不早於 $o.end$ 開始，那麼它們自然也絕不會早於更早結束的 $g.end$ 開始。換言之，把 $o$ 換成 $g$ 之後，後面的所有活動完全不需要任何更動，依然百分之百互不衝突！
  2. 品質不降：替換前後，排入的活動總場數完全沒有變少。因此，修改後的解依然是一個合法的全域最優解。

這項推導得出了一個無可撼動的結論：在所有可能的最優解中，至少存在一個是以貪心選擇 g 作為第一步的。既然最優解的世界裡本來就包含了 $g$，那我們在第一步大膽固定選擇 $g$，就絕對不會錯失找到最優解的機會！隨後，我們把與 $g$ 衝突的活動全部剃除，剩餘的活動依然構成一個完全同構的子問題。透過數學歸納法，整個貪心演算法的正確性便水到渠成。

掃描不變量：在掃描過程中，chosen 清單中的所有活動互不重疊；last_end 忠實記錄已納入排程的最後結束時間；任何被跳過的活動，都確定與當前排程衝突，未來也絕不可能再被撿回。請記住：迴圈不變量只能保證產生出來的排程「合法可行」，但要證明該排程「達到數量上限」，必須依賴交換論證的數學支撐。
def select_intervals(intervals):
    """選最多個互不重疊半開區間 [start, end)；要求 start < end。"""
    ordered = sorted(intervals, key=lambda x: (x[1], x[0]))
    if any(start >= end for start, end in ordered):
        raise ValueError("區間必須有正長度")
    chosen = []
    last_end = None
    for start, end in ordered:
        if last_end is None or start >= last_end:
            chosen.append((start, end))
            last_end = end
    return chosen

效能分析：排序耗費 $O(n \log n)$，隨後的單次線性掃描耗費 $O(n)$，整體時間複雜度為 $O(n \log n)$。在空間方面，sorted() 會產生新的排序清單，且 chosen 儲存了最終結果，額外空間複雜度為 $O(n)$。若業務場景只需要知道「最大活動場數」而不需要保留名單，雖然可以省去 chosen，但 Python 的 sorted() 依然會配置內部陣列，因此切勿隨意宣稱其為 $O(1)$ 空間。

5. 第二種貪心：短工作先做，總等待最少

輸入非負工時，回傳 (處理順序, 最小總等待時間)。空輸入回傳 ([],0)；[6,2,4] 回傳 ([2,4,6],8)。

考慮單處理器排程問題：所有任務在時間 0 時均已就緒，每個任務一旦開始就必須一次執行完畢不可中斷（Non-preemptive），且每件任務每等待 1 個時間單位的痛苦成本完全相同。若給定各任務所需工時為 [6, 2, 4]，我們該如何安排執行先後順序，才能讓「所有任務在開始執行前的等待時間總和」達到最小？直覺告訴我們：工時越短的應該越先做（Shortest Job First, SJF）。我們同樣透過「相鄰逆序交換」來給予嚴密證明。

假設在某個排程中，存在相鄰的兩件工作 $a$ 與 $b$ 滿足 $a > b$（也就是長工時被排在短工時前面）。假設這兩件工作在時間 $t$ 開始連續執行：

  • 若維持 a 先於 b：工作 $a$ 等待了 $t$，工作 $b$ 必須等待 $a$ 執行完畢，等待了 $t + a$。兩者合計等待時間為 $2t + a$。
  • 若交換順序讓 b 先於 a：工作 $b$ 等待了 $t$，工作 $a$ 等待了 $t + b$。兩者合計等待時間為 $2t + b$。

因為 $a > b$，交換後這兩件工作的總等待時間足足減少了 $a - b$！更關鍵的是：不論誰先誰後，兩件工作合計佔用的總時間都是 a + b，因此排在它們之後的所有其他工作的開始時間與等待時間，完全沒有受到任何影響。這意味著：只要排程中存在任何逆序對，將其對調必定能使整體成本單調下降。持續消除所有逆序對，最終必然收斂至純粹的工時升冪排列！

def schedule_shortest_first(durations):
    """所有工作在時間 0 可開始，回傳順序及總等待時間。"""
    order = sorted(durations)
    if any(duration < 0 for duration in order):
        raise ValueError("工時不可為負")
    elapsed = total_wait = 0
    for duration in order:
        total_wait += elapsed
        elapsed += duration
    return order, total_wait

工時開始前 elapsed累加後 total_wait完成後 elapsed
2002
4226
66812

按短工時優先排程，總等待時間僅為 0 + 2 + 6 = 8；若按原本順序 [6, 2, 4]，總等待時間則高達 0 + 6 + 8 = 14。請特別體會：機器處理完全部工作的總時間始終都是 12，這套演算法改善的是「排隊群眾的總委屈時間」，而不是機器的下班時間。

時間複雜度由排序主導，為 $O(n \log n)$；線性掃描耗時 $O(n)$，額外空間為 $O(n)$。若輸入含有負工時，程式將引發 ValueError。但請務必留意邊界前提：如果工作具備不同的到達時間（Release Time）或是不同的緊急權重（Weight），相鄰交換的式子將會改寫，無法再直接生搬硬套純工時排序。

6. 用可達範圍決定能否繼續前進

LeetCode 55 · Jump Game：由開頭能否到最後一格。本節另定義空序列回傳 True。

這是一類不需要排序、直接在線性掃描中透過維持「前鋒境界（Frontier）」來實現貪心決策的經典問題。陣列中每個位置 jumps[i] 代表在此處最多能往右跳躍的步數。我們不需要枚舉所有可能的跳躍路徑，只需要在向右走訪時，動態維護一個指標 farthest，代表當前「所能觸及的最遠極限座標」。當走到座標 i 時，若發現 i > farthest，代表我們竟然走到了連之前所有跳躍都碰觸不到的死胡同，此時便可斷定永遠不可能抵達終點。

def can_reach_end(jumps):
    """jumps[i] 是由 i 往右最多前進的步數；空陣列視為可完成。"""
    if any(jump < 0 for jump in jumps):
        raise ValueError("步數不可為負")
    farthest = 0
    for i, jump in enumerate(jumps):
        if i > farthest:
            return False
        farthest = max(farthest, i + jump)
        if farthest >= len(jumps) - 1:
            return True
    return True

這段程式背後的嚴格不變量是：在準備檢查索引 i 之前，從座標 0 到 farthest 之間的所有整數座標，全都是確定可達的連續區間。這項性質之所以能成立，是因為規則允許我們自由選擇跳躍「1 到 jumps[i]」的任意步數。如果今天規則改為「必須嚴格跳剛好 jumps[i] 步」，那麼可達的位置就會支離破碎成不連續的孤立點，單一的 farthest 邊界貪心將徹底失效，必須轉向 BFS 或圖走訪。此演算法僅需 $O(n)$ 時間與極致的 $O(1)$ 額外空間。

7. 反例實驗室：別把成功規則帶到不同目標

加權區間可練習 LeetCode 1235 · Maximum Profit in Job Scheduling；不限次硬幣可練習 LeetCode 322 · Coin Change。

在學習貪心演算法的過程中，看清「什麼時候不能用貪心」往往比「背誦貪心模板」更具價值。以下是四個極其經典的直覺陷阱：

  • 加權區間排程（Weighted Interval Scheduling）：若活動帶有價值，例如活動 A=[0,2) 價值 2，活動 B=[2,4) 價值 2，而活動 C=[0,4) 價值 9。若繼續照「最早結束」貪心選取，我們會選到 A 與 B（總價值 4），但最佳解其實是選 C（總價值 9）！交換論證在此失效，因為交換第一場不再保證總收益不降，必須轉用動態規劃。
  • 任意幣值的零錢兌換：在日常生活中，先挑面額最大的硬幣往往是對的（如 50、10、5、1 元）；但若面額設定為 {1, 4, 6} 且目標為 8 元：貪心策略會先選 6 元，隨後只能補兩枚 1 元，共需 3 枚；但最優解其實是選兩枚 4 元（只需 2 枚）。這證明了貪心策略高度依賴幣值系統的特殊代數性質（Matroid），不可任意套用。
  • 0/1 背包問題：背包耐重 4，物品分別為 (重 3, 值 5)、(重 2, 值 3)、(重 2, 值 3)。若依單位價值密度貪心，第一件密度 1.67 最高，選了之後背包剩重 1 啥也裝不下，總價值僅 5；而最佳選擇是捨棄第一件，選後兩件（總重 4，總價值 6）。分數背包可貪心，整數 0/1 背包絕不可貪心！
  • 忽略邊界測試：長度為 0 的空輸入、完全重複的區間、起迄點相等、負座標時間等，都是生產環境中容易引發崩潰的邊界。座標值可以為負，但區間長度與工時絕不可為負，兩者概念必須嚴格劃清界線。

8. 練習：先寫理由，再寫程式

練習一：最少刪幾場？

給定活動清單 [(0,2),(1,3),(2,4),(4,5)]，我們至少需要刪除幾場活動才能讓其餘活動互不重疊？請說明此問題與「挑選最多不重疊活動」之間的對偶關係。

參考解答

最少刪除場數等於「總場數減去最多可保留場數」。本題最多可保留 [(0,2),(2,4),(4,5)] 共 3 場，因此最少只需刪除 $4 - 3 = 1$ 場。其背後邏輯在於：每刪除一場活動就等於少保留一場，兩者互為補集。若能用貪心法在 $O(n \log n)$ 內算出最多保留 $m$ 場，最少刪除量就保證是 $n - m$。

練習二：帶權等待打破規則

假設任務 A 工時 1、每單位時間等待成本為 1；任務 B 工時 3、每單位時間等待成本高達 10。此時優先處理短工時任務 A 是否依然最優？

參考解答

不再最優。若先做 A 再做 B，A 等待 0，B 等待 1，加權等待為 $0 \times 1 + 1 \times 10 = 10$；反之若先做 B 再做 A，B 等待 0，A 等待 3，加權等待僅為 $0 \times 10 + 3 \times 1 = 3$！這說明在有權重的情況下，相鄰交換比較的是 $p_a \times w_b$ 與 $p_b \times w_a$。最佳的排序鍵值不再是純工時 $p$，而是「工時與權重之比」$p / w$ 升冪排序（Smith's Rule）。

練習三：可達邊界手算

請分別手算推演跳躍陣列 [2,1,0,1] 與 [2,2,0,1] 是否能成功抵達終點。為什麼我們不能只盯著陣列中最大的跳躍數看？

參考解答

在 [2,1,0,1] 中：$i=0$ 時最遠邊界更新為 2；$i=1$ 時邊界仍為 $1+1=2$；$i=2$ 時邊界仍為 $2+0=2$；走到 $i=3$ 時因 $3 > 2$ 斷裂失敗。而在 [2,2,0,1] 中：$i=1$ 時最遠邊界成功推展為 $1+2=3$，成功跨越 0 的陷阱抵達末端。如果單看最大跳躍數，例如 [0, 100]，即使後方數字再大，起點根本踩不過去，終究是空中樓閣。

練習四：排序之後一定能貪心嗎？

有開發者主張：「遇到最佳化問題，只要先把資料排好序，然後每次無腦挑最便宜的，就一定是最優解。」你會提出哪三點質疑？

參考解答

首先，必須追問「目標函式與限制條件到底是什麼」；其次，必須追問「先挑最便宜的是否會排除掉其他更高性價比的組合」（如背包問題）；最後，必須要求對方提出「交換論證」——能否在數學上證明將任意最優解的第一個選擇換成最便宜者，整體解品質絕不下降。若無法給出交換證明，排序後的貪心充其量只是賭博。

9. 章末決策卡

當你遇到「每一步做一個單向選擇」的問題時，請依循以下標準作業流程：明確定義目標與限制 → 嘗試構造微型反例自我推翻 → 建構交換論證（證明任意最優解皆可無痛置換為貪心選擇）→ 確定剩餘子問題結構不變 → 實作排序與線性維護 → 妥善處理邊界與平手規則。若在交換過程中發現會犧牲整體價值或違反容量限制，請立刻踩剎車，果斷轉向動態規劃或搜尋回溯！
