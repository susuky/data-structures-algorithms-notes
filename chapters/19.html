19 · 圖的群組、關鍵連線與路線

學會 DFS 和 BFS 之後，接著看圖裡更進階的結構：怎麼用最便宜的邊把所有點接起來、怎麼把每條路剛好走一遍、怎麼找出互相繞得回來的強連通群組，還有拿掉哪條邊會讓整個路網斷線。

接通所有據點，總線路費用最少是多少

五個據點之間有幾種拉線方案，只要求每個據點都能透過線路連到其他據點。Kruskal 從最便宜的邊往上看，兩端還在不同群組就選，已相連就跳過。選出的連通樹就是 Minimum Spanning Tree（最小生成樹）。

為什麼能直接拿最便宜的跨群組邊？把其中一個群組和其餘節點切開，任何連通方案都要跨過這個切口。若某個最優方案用更貴的邊跨過，換成眼前這條就能接通、總成本也不增加。這是 cut property 的交換理由，允許相同權重與負權重。

權重相同時任選順序，此例以輸入順序打破同分
邊（成本）判斷已選總成本
0—2（1）接起兩群1
1—3（1）接起兩群2
1—2（2）合併前面兩群4
3—4（3）全部五點相連7
0—1（4）、2—3（5）兩端已相連，略過7
def minimum_spanning_forest(n, edges):
    parent, size = list(range(n)), [1] * n
    def find(node):
        while node != parent[node]:
            parent[node] = parent[parent[node]]
            node = parent[node]
        return node
    chosen, cost = [], 0
    for edge_id in sorted(range(len(edges)), key=lambda i: edges[i][2]):
        a, b, weight = edges[edge_id]
        a, b = find(a), find(b)
        if a == b:
            continue
        if size[a] < size[b]:
            a, b = b, a
        parent[b] = a
        size[a] += size[b]
        chosen.append(edge_id)
        cost += weight
    return cost, chosen

Union-Find 負責查兩端的群組與合併。排序花 O(E log E)，所有合併搭配路徑壓縮與按大小合併，攤銷 O(E α(V))；總計 O(V+E log E)，額外空間 O(V+E)。連通圖選 V−1 條邊，原圖分成 c 群就選 V−c 條，結果是最小生成森林。

另一個常用選擇是 Prim：從一個點長出一棵樹，每次選跨出目前樹的最小邊。已有鄰接表與 heap 時很好接；Kruskal 直接拿邊清單排序，跟 Union-Find 搭配最短。兩者的目標都是選邊總成本，輸出還可保存邊編號，讓平行邊各自被辨認。

把所有邊權重都加 10，原本的最小生成樹還能用嗎？五個節點的總成本增加多少？

看推理

仍可用。每棵生成樹都選四條邊，因此總成本一律增加 40，排序與最優方案的比較維持原樣。

每條路都走一次，回到原點

路線要巡過每一條道路，再回到起點。你可以重訪路口，每條道路各走一次。Eulerian Circuit（歐拉迴路）看的正是邊的使用次數，Hierholzer 演算法把局部小環接成完整路線。

本節處理無向圖。帶有邊的節點要在同一個連通群組，而且每個節點度數為偶數：每次沿一條邊進來，就要配一條邊出去。孤立節點不影響道路路線；完全沒有邊時，保留單一起點作為長度零的路線。

路徑堆疊頂端還有未用邊，就沿那條邊前進並標記邊編號；沒有未用邊時，把節點從堆疊取出放進答案。這個退回順序是倒著長出的路線，最後反轉。對同一個無向邊，兩端鄰接表共用同一編號；兩條平行邊則用不同編號。

def eulerian_circuit(n, edges):
    if n == 0:
        return [] if not edges else None
    adjacency = [[] for _ in range(n)]
    for edge_id, (a, b) in enumerate(edges):
        adjacency[a].append((b, edge_id))
        adjacency[b].append((a, edge_id))
    if any(len(neighbors) % 2 for neighbors in adjacency):
        return None
    start = next((v for v in range(n) if adjacency[v]), 0)
    stack, circuit = [start], []
    used = [False] * len(edges)
    while stack:
        node = stack[-1]
        while adjacency[node] and used[adjacency[node][-1][1]]:
            adjacency[node].pop()
        if adjacency[node]:
            neighbor, edge_id = adjacency[node].pop()
            used[edge_id] = True
            stack.append(neighbor)
        else:
            circuit.append(stack.pop())
    if len(circuit) != len(edges) + 1:
        return None
    return circuit[::-1]

每條邊只被標記一次，兩份鄰接項目各彈出一次，時間與空間都是 O(V+E)。完成路線要有 E+1 個節點；若長度不足，還有另一個帶邊的群組。若題目要開放路線，無向圖允許恰有兩個奇數度數節點，從其中一個出發、在另一個結束；有向閉合路線則改檢查每點入度等於出度，以及帶邊部分的可達關係。

兩個節點之間有兩條平行邊，度數各是多少？為什麼 visited[node] 不適合用來限制這條路線？

看推理

兩點度數都是 2，路線可走 0→1→0。路口會被重訪；每條道路的編號才是要標記的對象。

單向連結裡，哪些頁面可以繞回彼此

頁面 0→1→2→0 彼此能繞回；2 另有一條連結通往 3。Strongly Connected Component（強連通分量，SCC）把有向圖切成「任何兩點都互相可達」的最大群組。Tarjan 用一次 DFS 找出這些群組。

disc[v] 是第一次發現 v 的順序，low[v] 是這段搜尋可連回的最早活躍位置。進入新節點時把它放進 active 堆疊；這個堆疊保留尚未歸組的節點，節點的遞迴呼叫返回後，也可能繼續留在裡面。

遇到尚未發現的孩子，DFS 回來後用孩子的 low 更新自己；遇到仍在 active 堆疊的已發現節點，用對方的 disc 更新；遇到已經歸組的節點，略過這次 low 更新。當 low[v]==disc[v]，v 是這批群組最早的位置，從堆疊頂端一路取到 v 就完成一個 SCC。

同一個 DFS 分支裡，可以先完成較下游的 SCC
正在返回low 值與原因收出的群組
5沒有可回去的邊，low[5]=disc[5]{5}
4→34 可回到 3，3 是這批最早者{3,4}
2→1→02→0 把 low 降到 0{0,1,2}
def strongly_connected_components(n, edges):
    graph = [[] for _ in range(n)]
    for a, b in edges:
        graph[a].append(b)
    discovery, low = [-1] * n, [0] * n
    active, stack, components = [False] * n, [], []
    timer = 0
    def visit(node):
        nonlocal timer
        discovery[node] = low[node] = timer
        timer += 1
        stack.append(node)
        active[node] = True
        for neighbor in graph[node]:
            if discovery[neighbor] == -1:
                visit(neighbor)
                low[node] = min(low[node], low[neighbor])
            elif active[neighbor]:
                low[node] = min(low[node], discovery[neighbor])
        if low[node] == discovery[node]:
            component = []
            while True:
                top = stack.pop()
                active[top] = False
                component.append(top)
                if top == node:
                    break
            components.append(component)
    for node in range(n):
        if discovery[node] == -1:
            visit(node)
    return components

每個節點進出堆疊各一次，每條邊檢查一次，時間 O(V+E)，含圖的儲存 O(V+E)，DFS 與輔助陣列 O(V)。程式用遞迴表達回程；深鏈圖可改成顯式呼叫堆疊保存「節點、下一條邊位置、回程狀態」。

把每個 SCC 縮成一點後得到 DAG，可再做拓樸排序或 DAG 上的 DP。若群組之間還有環，環上的所有點就能互相抵達，應當已經被合成同一個 SCC。

先完成群組 {0,1}，後來從 2 看到邊 2→0。這條邊應該把 low[2] 降成 disc[0] 嗎？

看推理

跳過這次更新。0 已離開 active 堆疊，該群組已完成；目前的單向連結可保留為縮點圖上的邊。互動中的「指向已完成群組」可以直接比較。

移除哪個路口，會把道路網切開

兩個社區內部各有環路，中間靠一條道路相接。刪掉這條道路會斷線，刪掉它兩端的路口也會切開道路網。DFS 的 low 值能同時找出橋、割點，以及 Biconnected Component（點雙連通分量）。

本節採無向圖、邊兩端不同，允許平行邊。disc[v] 是發現時間；low[v] 是 v 的子樹沿樹邊往下，再接至多一條回邊，能碰到的最早發現時間。回程時把孩子的 low 傳給父節點，於是父節點知道孩子有沒有其他路能繞出去。

大於與大於等於各回答一個具體問題
回程條件代表的路線可得結論
low[child] > disc[v]孩子連 v 都繞不回來父子邊是橋
low[child] ≥ disc[v]孩子至多繞回 v，越不過 v在這裡收出一個點雙連通區塊
非根，且上條件成立孩子離開子樹要通過 vv 是割點
DFS 根有至少兩個樹孩子各孩子子樹彼此沒有回邊相通根是割點

找區塊時，走過的樹邊與向祖先的回邊放進 edge_stack。碰到 low[child]≥disc[v]，把邊取到這條父子邊為止，就是一個區塊。這裡把橋當作單邊區塊；孤立頂點沒有邊，回傳的 blocks 不替它建立邊區塊。割點可同時在多個區塊內，每條邊則恰好屬於一塊。

平行邊需要用邊編號判斷父邊。從 0 經 #0 到 1 後，另一條 1—0 的 #1 是合法回邊，會把 low[1] 降到 disc[0]；因此兩條平行邊都可互相替代，刪掉其中一條仍相連。

def biconnected_components(n, edges):
    # Undirected, parallel edges allowed; self-loops are excluded by contract.
    adjacency = [[] for _ in range(n)]
    for edge_id, (a, b) in enumerate(edges):
        if a == b:
            raise ValueError('use distinct endpoints')
        adjacency[a].append((b, edge_id))
        adjacency[b].append((a, edge_id))
    discovery, low = [-1] * n, [0] * n
    edge_stack, blocks, bridges, cuts = [], [], [], set()
    timer = 0
    def visit(node, parent_edge=-1):
        nonlocal timer
        discovery[node] = low[node] = timer
        timer += 1
        children = 0
        for neighbor, edge_id in adjacency[node]:
            if edge_id == parent_edge:
                continue
            if discovery[neighbor] == -1:
                children += 1
                edge_stack.append(edge_id)
                visit(neighbor, edge_id)
                low[node] = min(low[node], low[neighbor])
                if low[neighbor] > discovery[node]:
                    bridges.append(edge_id)
                if low[neighbor] >= discovery[node]:
                    if parent_edge != -1 or children > 1:
                        cuts.add(node)
                    block = []
                    while True:
                        top = edge_stack.pop()
                        block.append(top)
                        if top == edge_id:
                            break
                    blocks.append(block)
            elif discovery[neighbor] < discovery[node]:
                edge_stack.append(edge_id)
                low[node] = min(low[node], discovery[neighbor])
    for node in range(n):
        if discovery[node] == -1:
            visit(node)
    return {'blocks': blocks, 'cuts': sorted(cuts), 'bridges': bridges}

每條邊進出邊堆疊各一次，時間 O(V+E)，空間 O(V+E)。割點與橋能指出單點或單邊中斷的位置；把區塊與割點接成 block-cut forest，後續還能回答兩個路口之間必經哪些割點。

三角形 0—1—2—0 裡，DFS 從 0 到 1 再到 2，low[1] 會等於 disc[0]。0—1 是橋嗎？根 0 是割點嗎？

看推理

兩者都不是。low[1] 等於 disc[0]，表示可以繞回 0，橋的嚴格大於條件沒有成立。根 0 只有一個 DFS 樹孩子，刪去 0 後 1 與 2 仍相連。

路徑有折扣邊，讓新低價繼續傳出去

從 0 到 1 原價 4；經過 2 的成本先付 5，再得到 −3 的折扣，最後只要 2。當邊允許負權重，Bellman–Ford 反覆掃描全部邊：若 distance[a]+w 比 distance[b] 更小，就把 b 的價格降下來。

一輪至少能把最佳答案多傳一條邊。沒有起點可達負環時，最短路徑可移除重複節點形成的非負環，留下至多 V−1 條邊。所以做 V−1 輪已足夠；整輪都沒變動，可以提早停止。這個原地更新版本會利用同輪剛更新的值，依邊順序有時一輪就傳完好幾條邊。

鬆弛只接受更便宜的路徑；未知的 ∞ 不參與加價

初始化[0,∞,∞,∞]只有起點免費抵達
0→1，權重 4[0,4,∞,∞]抵達 1
0→2，權重 5[0,4,5,∞]抵達 2
2→1，權重 −3[0,2,5,∞]5−3 比 4 更小

from math import inf

def bellman_ford(n, edges, start):
    distance = [inf] * n
    distance[start] = 0
    for _ in range(n - 1):
        changed = False
        for a, b, weight in edges:
            if distance[a] != inf and distance[a] + weight < distance[b]:
                distance[b] = distance[a] + weight
                changed = True
        if not changed:
            break
    if any(distance[a] != inf and distance[a] + weight < distance[b]
           for a, b, weight in edges):
        raise ValueError('reachable negative cycle')
    return distance

多掃一次時，若起點可達的某條邊仍能降低距離，就存在可達負環。每多繞一次該環，成本持續下降，受影響節點沒有有限的最短值。下列函式用 ValueError 回報這個結果；互動則停在檢出負環的步驟。另一個完全走不到的群組有負環時，起點的距離表維持原樣。

最壞 O(VE) 時間，距離表 O(V)；輸入邊另佔 O(E)。所有權重非負且圖大時，用 heap Dijkstra；DAG 則依拓樸順序鬆弛一次，允許負邊，時間 O(V+E)。若你要的是「最多 k 條邊」，每輪讀上一輪快照、寫下一輪，才會維持邊數上限。

0→1 的成本是 0，1→2 是 −1，2→1 是 0。為什麼再多跑幾輪，距離還會一直減少？

看推理

1→2→1 每圈總成本 −1，且起點能抵達 1。多走一圈就再省 1，於是不存在有限的最低價。檢查額外一輪的可達邊即可發現這種情況。

延伸閱讀：Princeton：Shortest Paths

通道只分免費與付費，雙端佇列就夠用

地圖上的邊只花 0 或 1：免費通道可以多繞幾站，總費用仍可能比直走便宜。0–1 BFS 用 deque 維持目前最便宜的候選，沿免費邊改善的點放前端，沿成本 1 的邊改善的點放後端。

取出距離 d 的候選時，新距離只會是 d 或 d+1。把同距離放前面、下一級放後面，就保持處理次序。入列保存當時距離，取出時若已找到更低價，這份舊候選直接略過。只有嚴格變小才重新入列，零權重環會自然停止。

括號裡是候選入列時的距離，免費繞路把點 1 從成本 1 改成 0
動作deque（前→後）目前距離
起點 00(0)[0,∞,∞]
0→1，成本 11(1)[0,1,∞]
0→2，成本 02(0)、1(1)[0,1,0]
取出 2，2→1 成本 01(0)、1(1)[0,0,0]

from collections import deque
from math import inf

def zero_one_bfs(n, edges, start):
    graph = [[] for _ in range(n)]
    for a, b, weight in edges:
        if weight not in (0, 1):
            raise ValueError('weights must be 0 or 1')
        graph[a].append((b, weight))
    distance = [inf] * n
    distance[start] = 0
    queue = deque([(start, 0)])
    while queue:
        node, known = queue.popleft()
        if known != distance[node]:
            continue
        for neighbor, weight in graph[node]:
            candidate = known + weight
            if candidate < distance[neighbor]:
                distance[neighbor] = candidate
                if weight == 0:
                    queue.appendleft((neighbor, candidate))
                else:
                    queue.append((neighbor, candidate))
    return distance

用 deque 的兩端 O(1) 操作，整體時間 O(V+E)，含鄰接表與候選的空間 O(V+E)。互動為了顯示每個候選，把佇列狀態複製成畫面；分析演算法成本時，以這份 Python deque 實作為準。

全部邊都是 1，普通 BFS 已經足夠；非負權重有很多種，用 Dijkstra；有負邊時，可回到上一節的 Bellman–Ford。把「沿既有方向走」設成 0、「反轉一條邊」設成 1，就能用本節方法求最少反轉次數。

把 0→1 的成本設為 1，再加 0→2 成本 0、2→1 成本 0。節點 1 第一次入列時，可以立刻把它鎖成永久完成嗎？

看推理

距離還會由 1 降成 0，所以以 distance 是否改善來判斷。取出時檢查入列距離，略過舊候選，便能得到免費繞路的結果。
