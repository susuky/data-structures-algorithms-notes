01 · 把程式的工作量看清楚

同樣是找答案，有些寫法會反覆讀同一批資料。這一章從一個小型配對問題出發，追蹤實際做了幾次工作，再把這個數字推廣成時間與空間成本。

一筆輸入，先決定要回傳什麼

找出 [8, 3, 8] 的最大值，可以回傳 8；若要最大值的位置，答案可能是 0、2，或兩個都要。演算法的起點是把這個選擇定下來：輸入允許什麼，輸出長什麼樣，以及平手怎麼處理。

寫下 輸入：[8, 3, 8]；輸出：0；同值取最早位置，接著補一個空輸入的約定。這幾行會直接決定程式裡的 >、>=、初始值和回傳型別。若允許改動輸入，排序是一個選項；要保留原索引，就把索引和數值一起保存。

規模也要跟著問題走。n 筆資料、m 次查詢，總成本常是 O(n + m)；把兩個規模都寫出來，才看得出預處理能省下多少重複工作。

要回傳「第二次讀到的第一個重複值」，[8, 3, 8, 3] 應回傳哪個數？

看推理

回傳 8。掃描到索引 2 時，8 已經出現過；這個規格按照事件出現順序選答案。若題目改成最小的重複值，答案才會是 3。

資料翻倍，工作量怎麼變？

讀取每個元素一次，n 筆資料做 n 次工作；把每一對元素都拿來比較，工作量接近 n²。n 從 1,000 變成 2,000，前者約增為兩倍，後者約增為四倍。Big O（大 O 表示法）用成長率描述這種差距。

T(n) = O(f(n)) 表示 n 夠大後，T(n) 有一個常數倍的 f(n) 作為上界。Θ 表示上下界同階，Ω 表示下界。例如 3n + 20 = Θ(n)，n² + 5n = Θ(n²)。報出最緊確的量級，資訊才足夠。

搜尋第一格就命中是最佳情況，掃完整段才知道沒有答案是最壞情況。平均成本要指定輸入分布；攤銷成本則看一整串操作的總費用。例如動態陣列偶爾要搬移全部元素，但連續 append 的總成本仍可攤成每次 O(1)。實際毫秒數再由實作、資料布局與硬體決定。

兩個 O(n) 程式，一個每筆比較一次，另一個每筆處理一個長度 L 的字串，應如何補上成本？

看推理

若每筆字串處理要讀 L 個字元，總成本寫 O(nL)。n 只計筆數；鍵生成、字串比較與輸出內容都要依實際長度計算。

把雙層迴圈畫成三角形

n 個位置，想數出所有 0 ≤ j < i < n 的配對。i = 0 沒有前面的元素，i = 1 有一對，i = 2 有兩對。下方每一格就是一次 pairs += 1；把 n 改大，直接看總工作量如何增加。

配對數的成長

每一步維持的關係

第 i 列增加 i 對；已處理的所有配對都落在三角形內。

迴圈 Θ(n²) 時間、O(1) 額外空間。

第 i 輪開始時，前 i 個位置已經貢獻 i(i−1)/2 對。這一輪增加 i 對，下一輪就變成 (i+1)i/2。每一步都延續同一個說法，這就是迴圈不變量（loop invariant）。

累計工作是 0 + 1 + … + (n−1) = n(n−1)/2，所以迴圈版本花 Θ(n²) 時間、O(1) 額外空間。只回傳個數時可直接用公式；要列出每一對，輸出本身就有 Θ(n²) 項。兩個依序執行的單層迴圈則把成本相加，n 次與 m 次會得到 O(n+m)。

def count_position_pairs(n: int) -> int:
    """計算 0 <= j < i < n 的位置對數，不儲存所有位置對。"""
    if n < 0:
        raise ValueError("n 必須非負")
    pairs = 0
    for i in range(n):
        for j in range(i):
            pairs += 1
    return pairs

n = 5 時，最後一列新增幾格？總共幾對？

看推理

最後一列 i = 4 新增 4 格；總數是 0 + 1 + 2 + 3 + 4 = 10。若只求 10 這個數，可直接計算 5×4÷2。

一行 Python 裡藏了多少工作

nums[i] 直接找到第 i 個參照；nums[lo:hi] 會建立一份新清單。若視窗長 k，每輪都切片再 sum，一輪就要 O(k)，掃 n 輪變成 O(nk)。改成保留總和、移出一項再加入一項，一輪就能做完。

常見 CPython 操作中，list 索引與 len 是 O(1)，尾端 append/pop 為攤銷 O(1)，前端插入或 pop(0) 要移動後面的參照而花 O(n)。頻繁從兩端進出時，使用 collections.deque。dict/set 的平均查詢成本以鍵的計算與比較為 O(1) 為前提。

空間成本看同一時刻保留多少資料。新切片、排序緩衝、集合、遞迴堆疊都佔空間；輸出另列。遇到 b 位元的大整數或長字串，把算術與共同前綴比較的成本也放進模型。

常用動作通常成本注意事項
list 索引、len(list)O(1)Python 的 list 在底層是連續存放物件參照的陣列，透過索引可直接計算位址定位
list.append、尾端 pop()攤銷 O(1)底層空間不足時會觸發擴容或縮容搬移；但平均分攤至連續操作時仍是 O(1)
list.pop(0)、前端 insertO(n)移除或插入前端元素時，後續所有元素參照都必須整批往前或往後搬移；若需頻繁操作雙端，應改用 collections.deque
x in listO(n)底層需進行線性掃描逐一比對（假設每次相等比對耗時 O(1)）
list[l:r]、複製 listO(k)，k 為切片長度切片操作會建立一個全新 list，需要分配 O(k) 的記憶體空間來存放參照，屬於淺複製
dict / set 查找平均 O(1)依賴良好的雜湊函式分布與較短的鍵值；若發生嚴重雜湊碰撞，最壞情況可能退化為線性，詳見第 03 章
sorted(items)最壞 O(n log n)會建立並回傳全新排序後的 list；如果 key 函式本身耗時或元素比較成本高，需額外加成計算
''.join(parts)O(片段數 + 總字元數)產生新字串需要分配對應記憶體；若在迴圈中逐次用 + 串接字串，很容易導致嚴重的重複複製成本

for 迴圈做 n 次，每輪呼叫 sum(nums[:i])，總時間是多少？

看推理

第 i 輪複製並加總 i 個元素，累計 0+1+…+(n−1)，所以是 Θ(n²)。每輪切片使用後釋放，峰值額外空間是 O(n)。

呼叫往下走，答案往上合

計算 [7, −2, 5, 4] 的總和，可以一路累加，也可以拆成左右兩半。把遞迴函式定義成 total(lo, hi) 回傳 nums[lo:hi] 的和，空區間回傳 0、單元素回傳該值；較長區間拆開後，把兩個子答案相加。

呼叫 total(0, 4) 時，外層停下來等待 total(0, 2)。左半算出 5，再算右半得到 9，回到外層合成 14。傳入的是索引邊界，因此分割時只建立新的呼叫狀態。

每一個元素成為一個葉節點；非空輸入的完整二元遞迴樹有 2n−1 次呼叫，時間 Θ(n)。同時等待的是一條深度 O(log n) 的路徑，所以堆疊空間 O(log n)。若每次都傳切片，各層會重複複製資料，時間升為 O(n log n)，峰值空間 O(n)。CPython 深度上限會影響很長的鏈狀遞迴，這類走訪可改用顯式堆疊。

def linear_total(nums: list[int]) -> int:
    total = 0
    for value in nums:
        total += value
    return total


def recursive_total(nums: list[int]) -> int:
    """以半開區間分治；不建立 nums 的切片。"""
    def total(lo: int, hi: int) -> int:
        if lo == hi:
            return 0
        if hi - lo == 1:
            return nums[lo]
        mid = (lo + hi) // 2
        left = total(lo, mid)
        right = total(mid, hi)
        return left + right

    return total(0, len(nums))

把長度 n 每次減 1，與每次分半，堆疊深度各是多少？

看推理

每次減 1 要等到最內層才返回，最多同時保留 n 層，深度 O(n)。每次分半約經 log₂n 層抵達單元素，深度 O(log n)。

拿三個小程式練習計算成本

把 13 不斷整除 2，數值是 13 → 6 → 3 → 1 → 0，一共四輪。對 n > 0，輪數為 floor(log₂n)+1；n = 0 直接回傳 0。這個例子讓對數成本對應到實際縮小的次數。

串接 k 段文字、總長 L，使用 ''.join(tokens) 一次安排輸出，時間 O(k+L)、結果空間 O(L)。反覆把新片段接到既有字串，會讓已完成的前綴反覆被複製；等長片段的累計複製量可能成為平方級。

下面的實作可直接執行。試著在執行前算出結果：halving_steps(0)、halving_steps(8)，以及空 tokens 的 join。

Python · halving_steps
def halving_steps(n: int) -> int:
    if n < 0:
        raise ValueError("n 必須非負")
    steps = 0
    while n > 0:
        n //= 2
        steps += 1
    return steps
Python · join_tokens
def join_tokens(tokens: list[str]) -> str:
    return "".join(tokens)

n = 8 為何是四輪，而不是三輪？

看推理

8→4→2→1→0，最後把 1 除成 0 也執行了一輪。若題目改成「縮到 1 為止」，停止條件改為 n > 1，輪數才會少一輪。

從重複工作找到下一個改法

面對一道新題，拿三到五個元素手動走一遍。圈出重複掃描的位置：每個右端都回頭找搭檔、每個視窗都重算總和、每次查詢都重走同一段路。那些被反覆求出的資訊，就是值得保存的狀態。

接著寫一句可以隨迴圈延續的描述，例如「seen 包含目前位置之前出現的所有值」。用空輸入、重複值與無解各走一次，看更新順序是否符合這句話。從具體例子推到每一步的理由，再把成本加總起來。

本書後續會反覆使用這個過程：雙指標排除候選，視窗保留重疊區間的資訊，雜湊索引過去，動態規劃保存子問題答案。

某一步刪掉一個候選，你要能回答哪個問題？

看推理

說明被刪掉的候選為何在後續也不會成為更好的答案。例如有序兩數和太小時，最左值即使配上剩餘最大值也不足，整批以它為左端的配對都可排除。
