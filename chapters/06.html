06｜樹與圖：走訪、狀態與相依順序

在面對樹（Tree）與圖（Graph）的題目時，許多人容易急著套用 DFS 或 BFS 的模板程式碼，但真正決定解法成敗的關鍵，往往是在動筆前先精準回答三個核心問題：「在當前問題中，什麼才算是一個完整的狀態？」、「哪些狀態彼此相鄰且能合法轉移？」、以及「在什麼時機點才能宣告一個狀態已經造訪過（Visited）？」本章將以待處理集合（Worklist）與狀態不變量為貫穿全篇的核心線索，從經典的二元樹出發，逐步推展至一般圖的遍歷、二元搜尋樹（BST）的嚴謹驗證、迷宮隱式圖的狀態空間擴展，以及任務排程必備的拓樸排序。

學習目標：能根據問題本質精準取捨 DFS 或 BFS；徹底分清一般二元樹與二元搜尋樹的結構差異；將「連通性存在（是否可達）」與「代價最優（最短路徑）」的思維截然分開；掌握 visited 集合應該在何時標記、以及它的複合鍵該收錄哪些維度；並能熟練運用入度拓樸排序來解決複雜的前置相依問題。前置知識：第 01 章遞迴分析、第 05 章堆疊與佇列。

一、寫走訪程式前，先確認資料結構

從數學結構來看，圖是由一組頂點（Vertices, V）與連接頂點的邊（Edges, E）所構成。無向邊代表雙向皆可自由通行，有向邊則限定只能沿著箭頭單向推進。而無向樹本質上就是一種「連通且保證無任何環路」的極簡特殊圖；當我們指定某個頂點為根節點（Root）之後，除了根節點之外，樹上的每個節點都恰好只擁有唯一的父節點。二元樹（Binary Tree）則進一步限制每個節點最多只能擁有兩個子節點，並且在幾何與語意上嚴格區分「左子節點」與「右子節點」。

本章的二元樹範例皆保證結構無環，且不存在被多個父節點共享的子樹。但在遍歷包含環路或共享節點的一般物件參照圖時，必須嚴格以物件身分記錄 visited 集合，因為不同節點物件完全可能裝載著相同的數值。在一般圖的實作中，我們統一將頂點編號為 0 到 V − 1，所有相鄰邊的端點編號都必須合法有效。

  • 節點深度（Depth）：從根節點沿著樹枝走訪至該節點所經過的邊數；根節點本身的深度定義為 0。
  • 節點高度（Height）：從該節點向下尋訪至其最深葉節點所經過的最大邊數；葉節點自身的高度定義為 0。本書依業界慣例，約定空樹的高度為 −1。
  • 在複雜度分析中，n 代表樹的節點總數，h 代表樹的高度，w 代表單層節點數最多的那一層寬度；在圖結構中，則標準使用 V 與 E 分別代表頂點數與邊數。
from __future__ import annotations
from collections import deque
from dataclasses import dataclass

@dataclass
class Node:
    value: int
    left: Node | None = None
    right: Node | None = None

二、二元樹 DFS：把「做事時機」放在正確位置

前序與中序走訪：LeetCode 144 · Binary Tree Preorder Traversal、LeetCode 94 · Binary Tree Inorder Traversal。輸出依指定次序排列的節點值，空樹回傳 []。

LeetCode 104 · Maximum Depth of Binary Tree 以路徑的節點數計深度；tree_height 以邊數計高度。因此上圖分別是 3 與 2，空樹分別是 0 與 −1。

深度優先搜尋（DFS）的本質，是沿著單一條路徑不斷向深處探底，直到無路可走再回溯並處理其他尚未完成的分支。以遞迴函式 visit(node) 為例：在剛踏入函式時立刻處理 node 稱為「前序走訪（Preorder）」；在左子樹完整遞迴完畢、正準備進入右子樹前處理 node 稱為「中序走訪（Inorder）」；而在左右兩側子樹皆已探訪完畢並成功返回後才處理 node 則稱為「後序走訪（Postorder）」。這三種走訪共用完全一致的尋訪拓樸骨架，唯一的根本區別只在於：你究竟選擇在哪個時機點停下來收集或處理該節點。

  • 前序走訪（根 → 左 → 右）：非常適合「由上而下」的場景，例如在向下深入時將祖先路徑的上下文資訊一層層傳遞給子孫節點。
  • 中序走訪（左 → 根 → 右）：在嚴格二元搜尋樹（BST）中，中序走訪輸出的數值序列天然保證嚴格單調遞增；但在一般無序二元樹中則無此性質。
  • 後序走訪（左 → 右 → 根）：非常適合「由下而上」的資訊匯總，例如必須等待左右子樹各自的高度、節點數或子問題解計算完畢後，再組合產出當前父節點的解答。
def preorder(root: Node | None) -> list[int]:
    if root is None:
        return []
    result, stack = [], [root]
    while stack:
        node = stack.pop()
        result.append(node.value)
        # LIFO: push right first so left is visited first.
        if node.right is not None:
            stack.append(node.right)
        if node.left is not None:
            stack.append(node.left)
    return result

def inorder(root: Node | None) -> list[int]:
    result = []

    def visit(node: Node | None) -> None:
        if node is None:
            return
        visit(node.left)
        result.append(node.value)
        visit(node.right)

    visit(root)
    return result

def tree_height(root: Node | None) -> int:
    # Height is measured in edges: empty = -1, leaf = 0.
    if root is None:
        return -1
    return 1 + max(tree_height(root.left), tree_height(root.right))
逐步追蹤範例 A：使用顯式堆疊模擬前序 DFS

堆疊內部遵循後進先出（LIFO）。如果希望下一個彈出的是左子節點，就必須在程式碼中「先將右子節點推入堆疊，再將左子節點推入堆疊」。本例各節點數值剛好互不相同，為便於閱讀，表格中以數值代表節點物件；堆疊底層實際存放的是 Node 的記憶體參照。

核心不變量與正確性歸納：在顯式堆疊實作中，stack 中始終存放著所有已被發現、但其內部子樹尚未被完整展開的子樹根節點。每次彈出一個節點時，我們將其子節點依照「先右後左」順序入棧，這保證了左子樹的所有節點必定在堆疊中高於右子樹的節點，進而確保了左邊必定先於右邊被處理，嚴格滿足「根 → 左 → 右」的前序定義。在計算高度的 tree_height 中，則利用結構歸納法：空樹回傳 −1 作為基底；當左右兩側子樹的高度正確算出時，父節點高度顯然等於兩側最大高度加 1。

上述三個演算法都恰好造訪每個節點常數次，時間複雜度皆為 O(n)。在空間方面，二元樹 DFS 在遞迴或顯式堆疊上的記憶體佔用取決於樹的高度，最壞情況下為 O(h + 1)；若樹不幸退化成單鏈，高度將達到 O(n)。值得注意的是：Python 直譯器對呼叫堆疊設有嚴格的預設深度上限（通常為 1000 層左右）；當輸入資料深度未知或極深時，應優先採用顯式堆疊寫法，防止程式在遞迴中意外崩潰。

在撰寫中序或前序走訪時，許多初學者喜歡寫出 return visit(node.left) + [node.value] + visit(node.right) 的遞迴拼接語法。請務必警惕：清單加法每次都會複製產生新陣列，在退化樹上會導致時間複雜度急遽膨脹至 O(n²)！標準做法是像範例那樣，將所有數值直接 append 進入同一個共用的結果清單中，以確保純粹的 O(n) 線性效能。

三、二元樹 BFS：一輪處理一整層

LeetCode 102 · Binary Tree Level Order Traversal：按深度由淺至深回傳各層，同層由左到右；空樹回傳 []。上圖範例樹應得到 [[12], [5, 18], [2, 9, 21]]。

廣度優先搜尋（BFS）藉由 FIFO 佇列的特性，以波浪擴散的方式逐層向外推進。如果題目只關心「所有節點是否全部被造訪」，那麼 DFS 與 BFS 皆可勝任；但如果題目的輸出或計算邏輯與「節點所在的深度、層數、或是同一水平層的左右關係」高度相關，BFS 絕對是首選。在實現層序遍歷時，最精妙的技巧在於：在每一輪外部迴圈開始時，先鎖定當前層的佇列長度（len(queue)），否則在該輪中剛加入的新生代孩子節點就會與本層的節點混淆。

def level_order(root: Node | None) -> list[list[int]]:
    if root is None:
        return []
    result, queue = [], deque([root])
    while queue:
        level = []
        for _ in range(len(queue)):
            node = queue.popleft()
            level.append(node.value)
            if node.left is not None:
                queue.append(node.left)
            if node.right is not None:
                queue.append(node.right)
        result.append(level)
    return result

追蹤細節：在上圖中，第一輪開始時佇列只有 [12]，長度為 1，輸出第一層 [12]，並將孩子 5 與 18 入隊；第二輪開始時長度鎖定為 len(queue) = 2，內部迴圈只會精確執行 2 次，因此即便彈出 5 時將 2 與 9 塞入佇列，這兩個新孩子也不會干擾本層對 18 的處理，順利將第二層結算為 [5, 18]。在 Python 中，for _ in range(len(queue)) 在迴圈啟動瞬間就已經將迭代次數固定為靜態整數，語法上極為安全。

核心不變量：在每一輪外部 while 迴圈開始時，佇列中恰好精確收錄了屬於同一深度的所有節點，且嚴格按照由左至右的次序排列。依序將它們全數彈出並將各自的左右孩子排入隊尾，便能嚴絲合縫地建構出下一層的完整集合。

演算法的時間複雜度為 O(n)；輔助佇列空間取決於樹的最大寬度，為 O(w)，最終分層結果清單另佔 O(n)。在佇列操作上，必須使用 collections.deque 的 popleft()；絕對不可使用 list.pop(0)，否則每次出隊都會導致 O(len) 的記憶體平移，將演算法拖慢成平方時間。

四、BST：大小條件適用於整棵子樹

搜尋與驗證：LeetCode 700 · Search in a Binary Search Tree、LeetCode 98 · Validate Binary Search Tree。搜尋回傳目標節點，找不到回傳 None；驗證回傳布林值。在上圖搜尋 5，會得到以 5 為根、孩子為 2 與 9 的子樹。

本書採用嚴格標準的二元搜尋樹（Binary Search Tree, BST）定義：對於樹中任意節點，其左子樹中的所有節點數值都必須嚴格小於該節點數值，而其右子樹中的所有節點數值都必須嚴格大於該節點數值，全樹不允許任何重複鍵值。在部分競賽題中可能允許重複鍵，並規定重複鍵固定放在左側或右側；遇到此類題目時必須先確認規則，再微調比較運算子。

在合格的 BST 中搜尋極為高效：比當前根節點小就果斷向左走，比當前根節點大就果斷向右走；被排除的整半邊子樹在數學上被證明絕不可能包含目標值。搜尋過程只會沿著單一條路徑由根下探至葉子，時間複雜度為 O(h + 1)，輔助空間為 O(1)；當樹維持平衡時高度 h 為 O(log n)，但在最壞退化情況下高度可達 n − 1。

def bst_search(root: Node | None, target: int) -> Node | None:
    while root is not None:
        if root.value == target:
            return root
        root = root.left if target < root.value else root.right
    return None

def is_valid_bst(root: Node | None) -> bool:
    # Strict BST: duplicate keys are not permitted.
    stack = [(root, None, None)]
    while stack:
        node, lower, upper = stack.pop()
        if node is None:
            continue
        if lower is not None and node.value <= lower:
            return False
        if upper is not None and node.value >= upper:
            return False
        stack.append((node.right, node.value, upper))
        stack.append((node.left, lower, node.value))
    return True

驗證 BST 的經典陷阱：許多新手會直覺寫出「只檢查左孩子小於根、右孩子大於根」的遞迴，這是徹底錯誤的！看上方的反例圖：根節點是 12，右孩子是 18，18 的左孩子是 9。單獨看 18 與 9，9 確實小於 18，父子關係完全吻合；但 9 位於 12 的右子樹中，它違反了「整棵右子樹所有節點都必須大於 12」的祖先約束！因此，正確的驗證演算法必須將所有祖先施加的上下邊界 (lower, upper) 一路向下傳遞收緊：往左子樹走時，繼承既有下界、收緊上界為當前節點值；往右子樹走時，繼承既有上界、收緊下界為當前節點值。使用 None 代表無邊界限制，時間複雜度為 O(n)，顯式堆疊空間為 O(h + 1)。

五、一般圖 DFS：環、重複路徑與不連通分量

輸入鄰接清單與有效起點，回傳可達頂點集合。LeetCode 1971 · Find if Path Exists in Graph 改以無向邊清單輸入，判斷指定起終點是否連通。

與樹結構最大的不同在於：一般圖中完全可能存在環路，同一個頂點也可能經由多條不同路徑重複抵達；在無向圖中，甚至可以沿著同一條邊立刻原路折返。因此在圖的走訪中，必須引入 seen 集合，負責記錄哪些節點已經被發現過，防止演算法陷入無窮死循環或進行無意義的重複探索。

在記憶體表示法中，鄰接清單（Adjacency List）graph[u] 列出所有從頂點 u 可以一步抵達的鄰居。對於無向邊 (u, v)，我們在 graph[u] 放入 v，同時也在 graph[v] 放入 u；對於有向邊則僅按指定方向儲存。這種結構佔用的記憶體空間為極其經濟的 O(V + E)。

def dfs_reachable(graph: list[list[int]], start: int) -> set[int]:
    seen, stack = {start}, [start]
    while stack:
        node = stack.pop()
        for neighbor in graph[node]:
            if neighbor not in seen:
                seen.add(neighbor)  # Mark before pushing.
                stack.append(neighbor)
    return seen

至關重要的工程實踐：在推入堆疊前就立刻標記 seen。這項防護確保了：整張圖中的每一個頂點，在全過程中最多只會被推進待處理堆疊一次。如果偷懶改成「等從堆疊彈出時才標記」，那麼一個有多個相鄰節點的熱門頂點，就可能在還沒來得及被處理前，被各個鄰居重複狂塞入棧數次，引發記憶體與計算時間的不必要膨脹。

請留意：單次 DFS 只能探訪從 start 出發可達的連通區塊。如果要求解無向圖的所有連通分量（Connected Components），外層必須配合一個從 0 到 V − 1 的迴圈，只有當發現頂點尚未出現在全局 seen 時才啟動新一輪 DFS。但請特別警惕：這套外層迴圈技巧在有向圖中絕不能直接拿來算強連通分量（SCC），因為在有向圖中「我能走到你」並不等價於「你也能走回我」（有向圖強連通需使用 Tarjan 或 Kosaraju 演算法）。

走訪從 start 可達區域的時間為 O(Vᵣ + Eᵣ)；若遍歷全圖所有頂點與邊，總時間複雜度為 O(V + E)。seen 集合與待處理堆疊所需空間至多為 O(V)。

六、無權圖 BFS：第一次發現，就得到最少邊數

圖例 graph=[[1,2],[0,3],[0,3],[1,2,4],[3],[]]，起點 0、終點 4 時回傳 [0,1,3,4]。起終點須為有效頂點；多條同長最短路可回傳任一條，無路時回傳 None。

在所有邊的權重皆相等（或者無權圖）的場景下，「走訪邊數最少」就等價於「路徑成本最低的最短路」。廣度優先搜尋（BFS）天然具備同心圓擴散的性質：它會先完全探訪所有距離起點為 0 步的節點，接著是 1 步的節點，然後是 2 步的節點……。為了重建出具體的行走軌跡，我們用 parent 字典記錄每個節點「最初是由哪個節點發現的」；當抵達終點時，只需沿著 parent 一路回溯至起點並進行清單反轉，就能無損復原出最短路徑。

def shortest_path(graph: list[list[int]], start: int,
                  target: int) -> list[int] | None:
    parent = {start: None}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        if node == target:
            path = []
            while node is not None:
                path.append(node)
                node = parent[node]
            return path[::-1]
        for neighbor in graph[node]:
            if neighbor not in parent:
                parent[neighbor] = node
                queue.append(neighbor)
    return None
逐步追蹤範例 B：從頂點 0 尋找前往頂點 4 的最短路
當前從隊首彈出的頂點本輪新發現的鄰居與記錄的 parent操作後的 FIFO 佇列
0（距離 0）parent[1] = 0；parent[2] = 0[1, 2]（皆為距離 1）
1（距離 1）parent[3] = 1[2, 3]
2（距離 1）鄰居 3 已存在於 parent 中，直接略過[3]（距離 2）
3（距離 2）parent[4] = 3[4]（距離 3）
4（距離 3）命中終點！回溯 4 → 3 → 1 → 0 反轉產出最短路徑 [0, 1, 3, 4]

為什麼在無權圖中，BFS 第一次看到某個節點就必定是最短路？這背後有堅不可摧的單調性證明：FIFO 佇列彈出節點的順序，天然按照與起點的距離單調不遞減推進。當我們從一個距離為 d 的頂點 u 第一次看見鄰居 v 時，說明了一條長度為 d + 1 的通往 v 的路徑已經確定。試想如果 v 存在另一條更短的路徑（長度 ≤ d），那麼那條更短路徑上的倒數第二個頂點的距離必定 ≤ d − 1；按照佇列順序，那個頂點早就應該在更早的輪次被處理完畢，並早已提前發現了 v，這與「這是第一次發現 v」產生矛盾！因此，第一次發現時記錄的距離與前驅，必然是最優解。

本演算法的時間複雜度為 O(V + E)，輔助空間為 O(V)。特別提醒：這項最短保證僅在所有邊的權重完全相等時成立；若邊具有不同的非負權重（例如不同路線的通行費用或時間），一條邊未必比兩條邊便宜，此時必須改用 Dijkstra 演算法（詳見第 13 章）。同樣地，DFS 找到的第一條路徑也完全無法保證是最短路徑。

七、隱式圖：依規則產生鄰居

網格只准上下左右移動，以移動次數計距離。下圖 [[0,0,1,0],[1,0,0,0],[0,0,1,0]] 的答案為 5。空網格、起終點為牆或無路時回傳 −1；各列長度不一致時拋 ValueError。

在現實開發中，並非所有圖都會事先明確給出整張頂點與鄰接清單。迷宮探索、棋盤走法、拼圖還原、甚至是字串接龍等問題，本質上都是「隱式圖（Implicit Graph）」：頂點對應到特定的盤面狀態，而邊則是根據業務規則合法動態生成的狀態轉移。以二維網格走迷宮為例：狀態是座標 (row, col)，而相鄰邊則是上下左右四個方向未撞牆且未越界的鄰居。求起點到終點的最少步數，標準採用隱式圖上的 BFS。

def grid_distance(grid: list[list[int]]) -> int:
    # 0 = open, 1 = wall. Return the number of moves, not cells.
    if not grid:
        return -1
    rows, cols = len(grid), len(grid[0])
    if any(len(row) != cols for row in grid):
        raise ValueError('grid must be rectangular')
    if cols == 0:
        return -1
    if grid[0][0] or grid[-1][-1]:
        return -1
    queue = deque([(0, 0, 0)])
    seen = {(0, 0)}
    while queue:
        row, col, distance = queue.popleft()
        if (row, col) == (rows - 1, cols - 1):
            return distance
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = row + dr, col + dc
            if (0 <= nr < rows and 0 <= nc < cols
                    and grid[nr][nc] == 0 and (nr, nc) not in seen):
                seen.add((nr, nc))
                queue.append((nr, nc, distance + 1))
    return -1

狀態維度擴展的重要性：在更複雜的問題中，同一個網格座標完全可能因為攜帶的外部資源不同而分化為不同的狀態。例如題目若允許「可以使用一次破牆技能」，那麼站在座標 (2, 3) 且「尚未使用破牆」的狀態，與站在相同座標 (2, 3) 但「已經用掉破牆」的狀態，在未來所能開展的探索空間是截然不同的！如果 visited 集合短視地只記錄座標 (row, col)，就會把保留充沛能力的重要狀態當作重複節點而過早剪枝。定義狀態時，必須包含所有會左右未來決策走向的關鍵維度，這項思維將直接引領我們進入後續動態規劃與進階最短路的世界。

八、拓樸排序：先完成所有前置工作

在大型軟體套件編譯、大學課程擋修規則、或是任務依賴排程中，事物之間往往存在著不可顛倒的先後順序。我們以有向邊 u → v 代表「工作 u 必須完全執行完畢，工作 v 才能被允許開始」。所謂的拓樸排序（Topological Sort），就是將圖中的所有頂點排成一條線性序列，使得圖中每一條有向邊的起點，在序列中都保證排在終點的前面。在數學上，一個有向圖能夠排出合法的拓樸序列，當且僅當它是有向無環圖（DAG, Directed Acyclic Graph）；如果圖中存在任何環路，相依關係就會互相卡死（Deadlock）而永遠無解。

Kahn 演算法是利用 BFS 思維實現拓樸排序的經典方案。它從入度為 0（Indegree = 0）的頂點切入。一個頂點的入度，代表著有多少條邊指向它，在語意上恰好等於「它目前還欠缺多少個未完成的前置工作」。當某個頂點入度為 0 時，代表它所有的前置相依皆已圓滿解決，隨時可以開工！演算法將可開工的頂點加入答案序列，並模擬「該工作已完成」——將它所有後繼工作的入度各自減 1；一旦某個後繼工作的入度剛好降至 0，就代表它也完全解鎖，立刻將其推進 ready 佇列中。

def topological_order(graph: list[list[int]]) -> list[int] | None:
    """邊 u → v 表示 u 必須先於 v；有環回傳 None，空圖回傳 []。"""
    indegree = [0] * len(graph)
    for neighbors in graph:
        for neighbor in neighbors:
            indegree[neighbor] += 1
    ready = deque(node for node, degree in enumerate(indegree) if degree == 0)
    order = []
    while ready:
        node = ready.popleft()
        order.append(node)
        for neighbor in graph[node]:
            indegree[neighbor] -= 1
            if indegree[neighbor] == 0:
                ready.append(neighbor)
    return order if len(order) == len(graph) else None

追蹤上圖：鄰接清單為 [[2], [2, 3], [4], [4], []]，初始入度為 [0, 0, 2, 1, 2]，ready 佇列初始為 [0, 1]。

從隊首取出的頂點後續鄰居的入度扣減變化本輪處理後 ready 佇列的狀態
取出 0頂點 2 入度：2 降為 1[1]
取出 1頂點 2 入度：1 降為 0（解鎖！）；頂點 3 入度：1 降為 0（解鎖！）[2, 3]
取出 2頂點 4 入度：2 降為 1[3]
取出 3頂點 4 入度：1 降為 0（解鎖！）[4]
取出 44 無任何後繼邊[]（排程結束）

最終輸出序列為 [0, 1, 2, 3, 4]。請注意：[1, 3, 0, 2, 4] 同樣是完全合法的拓樸排序；拓樸排序的解往往不唯一，只要保證每條有向邊的箭頭始終由左指向右即可。

不變量與環路判定：在執行的任何時刻，indegree[v] 精確等於頂點 v 尚未完成的前置任務總數，ready 佇列中則嚴格只保存入度已經降為 0 的自由節點。因此，任何被加入 order 的節點，其所有前置條件必然已經在更早的順序中被滿足。如果 ready 佇列已經提早淨空，但最終產出的 order 長度卻小於總頂點數 V，這雄辯地證明了圖中必然存在有向環！因為此時剩餘的所有頂點各自都至少欠缺一個前置相依，彼此相互等待形成死結。透過 len(order) == len(graph) 判定，能以極致簡潔的邏輯同時兼顧不連通圖與環路檢測。

每個頂點入隊出隊各一次，每條邊被掃描與扣減入度各一次，時間複雜度為緊確的 O(V + E)，輔助空間為 O(V)。若題目要求在多個可執行任務中優先選取編號最小者，只需將 ready 佇列改為最小堆積（Min-Heap），時間複雜度相應變為 O(E + V log V)。在 Python 標準庫中，亦可直接使用 graphlib.TopologicalSorter。

九、練習：先寫不變量，再看解答

練習 1｜只加總葉節點數值

給定一棵一般二元樹，請計算並回傳所有葉節點數值的總和。節點數值可能為負數；若為空樹則回傳 0。以本章開頭的六節點樹為例，葉節點為 2、9、21，答案應為 2 + 9 + 21 = 32。請特別注意：只有「左孩子與右孩子皆為 None」的節點才是葉節點，單親節點絕對不能算作葉子。

參考解答

使用 DFS 配合顯式堆疊進行尋訪；只有當 node.left is None 且 node.right is None 同時成立時，才將 node.value 累加至 total。核心不變量是 total 始終精確等於所有已被彈出且判定為葉節點的數值加總，每個節點恰好進出堆疊一次。時間複雜度為 O(n)，輔助空間為 O(h + 1)。

def leaf_sum(root: Node | None) -> int:
    if root is None:
        return 0
    total, stack = 0, [root]
    while stack:
        node = stack.pop()
        if node.left is None and node.right is None:
            total += node.value
        if node.right is not None:
            stack.append(node.right)
        if node.left is not None:
            stack.append(node.left)
    return total

練習 2｜統計各個社交圈（連通分量）的大小

LeetCode 547 · Number of Provinces 給定對稱鄰接矩陣求省份數量；本題以鄰接清單輸入，要求回傳每個連通分量包含的頂點個數清單。

給定無向圖的鄰接清單，請回傳每個連通分量的大小清單，順序依據「外層迴圈首次遇到該分量中最小未造訪頂點」的時機產生。例如五個頂點互聯加上一個孤立節點，應回傳 [5, 1]。空圖回傳 []。

參考解答

外層迴圈從 0 到 V − 1 依序掃描，尋找尚未被標記的起點；內層利用 DFS 或 BFS 將該起點所屬連通分量中的所有頂點一次性全數走訪並計數。所有分量共享同一個全局 seen 集合，這保證了每條邊與每個頂點在全過程中依然只被檢驗常數次，總時間複雜度為純正的 O(V + E)，而絕非錯誤直覺以為的「V 次遍歷全圖」；輔助空間為 O(V)。

def component_sizes(graph: list[list[int]]) -> list[int]:
    # graph must be undirected; every edge is represented both ways.
    seen, sizes = set(), []
    for start in range(len(graph)):
        if start in seen:
            continue
        seen.add(start)
        stack, size = [start], 0
        while stack:
            node = stack.pop()
            size += 1
            for neighbor in graph[node]:
                if neighbor not in seen:
                    seen.add(neighbor)
                    stack.append(neighbor)
        sizes.append(size)
    return sizes

練習 3｜多一張破牆券的最短路徑

LeetCode 1293 · Shortest Path in a Grid with Obstacles Elimination 允許消除至多 k 個障礙物；本題設定 k = 1，起終點必須為空格。

在二維迷宮網格中，玩家全場最多允許穿過一次牆壁（即走入一個牆格）；起點與終點依舊必須是暢通的空格。請計算抵達終點的最少移動步數，無解回傳 −1。例如對於 [[0, 1], [1, 0]]，答案應為 2（穿過任一堵牆直達終點）。試說明為什麼在此題中，visited 集合不能只記錄純網格座標？

參考解答

因為「抵達該格時是否已經用掉了破牆券」是左右未來可行性的關鍵維度。我們必須將狀態擴充為 (row, col, used) 的三元組，其中 used 僅有 0 與 1 兩種取值。進入空格時 used 維持不變，進入牆格時 used 增加 1；只有當 next_used ≤ 1 且新狀態未曾造訪時才允許入隊。BFS 的最短路證明在擴展後的狀態圖上完全成立。擴展圖最多包含 2RC 個狀態，每個狀態至多 4 條合法邊，因此時間與空間複雜度皆為極佳的 O(RC)。

def grid_one_break(grid: list[list[int]]) -> int:
    # At most one wall cell may be entered; start/end must be open.
    if not grid:
        return -1
    rows, cols = len(grid), len(grid[0])
    if any(len(row) != cols for row in grid):
        raise ValueError('grid must be rectangular')
    if cols == 0:
        return -1
    if grid[0][0] or grid[-1][-1]:
        return -1
    queue = deque([(0, 0, 0, 0)])  # row, col, used, moves
    seen = {(0, 0, 0)}
    while queue:
        row, col, used, moves = queue.popleft()
        if (row, col) == (rows - 1, cols - 1):
            return moves
        for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)):
            nr, nc = row + dr, col + dc
            if 0 <= nr < rows and 0 <= nc < cols:
                next_used = used + grid[nr][nc]
                state = (nr, nc, next_used)
                if next_used <= 1 and state not in seen:
                    seen.add(state)
                    queue.append((nr, nc, next_used, moves + 1))
    return -1

練習 4｜「中序走訪有排序」能否完全等價證明 BST？

在本書嚴格禁止重複鍵值的規則下，如果我們將一棵二元樹進行中序走訪，檢查產出的數值序列是否「嚴格單調遞增」，能否作為 BST 的充分必要判定條件？如果只檢查「非遞減（允許相等）」呢？

參考解答

在不含重複鍵的前提下，「中序走訪嚴格單調遞增」是驗證合法 BST 的充分必要條件。因為在中序走訪中，任意節點的整棵左子樹在時間上必然全部排在該節點之前輸出，而其整棵右子樹必然全部排在該節點之後輸出；只要全域序列嚴格遞增，就 mathematically 確保了左子樹所有元素嚴格小於根、右子樹所有元素嚴格大於根。但若放寬為「非遞減」，條件便不再充分：例如根為 4、左孩子為 4，其產出的序列為 [4, 4]，雖然非遞減，卻違反了左子樹必須嚴格小於根的定義。在實作上，我們甚至不需要儲存整條陣列，只需在中序走訪時用一個變數記錄前一個節點的數值，即可在 O(h + 1) 的空間內完成線上驗證。

十、邊界測試與方法選擇

  • 樹的極端測試：空樹、只有單一節點、全部單向偏左的鏈狀樹、重複數值、負數節點，以及只在祖先跨層約束上違規的 BST 經典反例。
  • 圖的極端測試：包含孤立頂點、自環（頂點連向自己）、重複平行邊、起點與終點相同、終點完全不可達；無向圖的邊是否確實雙向記錄；拓樸排序是否能優雅識別有向環。
  • 迷宮網格邊界：網格只有 1×1 單一格子、起點或終點自身就是障礙物、完全無解；計算長度時釐清題目問的是「移動步數（邊數）」還是「經過的格子總數（頂點數）」。
  • 演算法決策心法：需要「由下而上」匯總子樹答案時用後序走訪；需要「按深度逐層推進」時用 BFS；純粹確認連通性與可達性時 DFS 與 BFS 皆可。
  • 求「最少步數」且每步權重完全等價時：首選 BFS；若邊帶有不同非負權重，請見第 13 章 Dijkstra；若每一步伴隨資源消耗限制，果斷將剩餘資源打包納入狀態。
