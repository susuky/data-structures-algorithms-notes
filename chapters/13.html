13．進階補充：差分、Trie、位元與最短路

在掌握了前十二章的核心基礎後，本章將帶你探索一系列在實務系統與競賽中高頻出現的進階資料結構與演算法模組。這些工具各自專注於解決特定維度的效能瓶頸：利用差分陣列實現批次區間增量更新；運用字典樹（Trie）高效率共享前綴路徑；透過位元遮罩極致壓縮小集合運算；以事件排序優雅合併連續區間；運用快速冪精確控制大數模運算；並在圖論中藉由狀態擴充化解帶限制條件的最短路徑問題，最後透過並查集（Union-Find）在動態加邊環境下以近乎常數時間維護連通分量。

先備知識建議：閱讀本章前，請確認你對陣列前綴和、雜湊表、自訂排序、二元堆積（heapq）以及圖的走訪（BFS/DFS）已有紮實理解（可隨時回顧第 02、03、06、07 章）。本章所有圖論最短路徑問題皆以非負整數邊權為基準，頂點編號約定為 $0$ 至 $V - 1$。

一、差分陣列：記錄「從哪裡開始改變」

LeetCode 1109．Corporate Flight Bookings。套用到原題時，先將航班的兩個端點都減 1；本節也接受負增量。

設想一個經典場景：我們有一個初始全為 0、長度為 $n$ 的計數陣列，隨後陸續收到 $q$ 筆批次更新指令，每筆指令要求「將閉區間 $[left, right]$ 內的所有格子全部加上增量 $\delta$」。如果每次更新都老老實實跑迴圈逐格修改，在指令繁多時最壞時間複雜度高達 $O(n \cdot q)$，效能直接崩潰。

差分陣列（Difference Array）的核心洞見是：我們不需要立即在整個區間上執行全面修改，只需要在「影響開始的起點」與「影響結束的隔一格」分別打上標記即可！定義差分序列 $d[i] = a[i] - a[i - 1]$。只要對差分陣列計算一次前綴和，就能原汁原味還原出原始陣列 $a$。因此，針對閉區間 $[left, right]$ 增加 $\delta$ 的操作，在差分視角下僅需兩次常數更新：d[left] += delta（讓從 left 開始向後的前綴和全部增加 $\delta$），以及 d[right + 1] -= delta（在跨過 right 的瞬間將這筆增加量及時抵銷，終止其擴散效應）。

from collections.abc import Iterable

def range_add(n: int, updates: Iterable[tuple[int, int, int]]) -> list[int]:
    if n < 0:
        raise ValueError('n must be nonnegative')
    difference = [0] * (n + 1)
    for left, right, delta in updates:
        if not 0 <= left <= right < n:
            raise ValueError('invalid inclusive interval')
        difference[left] += delta
        difference[right + 1] -= delta
    result, running = [], 0
    for i in range(n):
        running += difference[i]
        result.append(running)
    return result

不變量保證：當前綴和還原推進到座標 $i$ 時，累加變數 running 精確等於所有覆蓋該座標（即 left ≤ i ≤ right）的更新增量總和。單次區間更新僅需 $O(1)$，最後一次線性前綴掃描僅需 $O(n)$。在處理 $q$ 筆批次更新時，整體時間複雜度從原本的 $O(nq)$ 斷崖式下降至優異的 $O(q + n)$！

最容易踩坑的失誤是邊界差一（Off-by-one）：若閉區間是 $[left, right]$，結束標記必須扣在 right + 1；若不小心寫成 difference[right] -= delta，那麼座標 right 本身就會被提前抵銷而少算了一次增量！另外，差分陣列的長度必須開到 $n + 1$，以便容納 $right = n - 1$ 時落在索引 $n$ 的抵銷哨兵。

二、Trie：讓共同字首只走同一段路

LeetCode 208．Implement Trie (Prefix Tree)。starts_with 對應原題的 startsWith。

字典樹（Trie / 前綴樹）是一種專門用來處理字串集合的高效樹狀結構。它的核心特徵是：樹中的邊代表字元，從根節點沿路徑走訪到某一節點，經過的字元序列恰好構成一個共享前綴。每個節點內部除了維護子節點字典 children 之外，還必須維護一個布林屬性 end，用來清晰區分「這個節點只是一個路過的前綴」還是「正好在此處完整結束了一個合法單字」。

from __future__ import annotations

class TrieNode:
    def __init__(self) -> None:
        self.children: dict[str, TrieNode] = {}
        self.end = False

class Trie:
    def __init__(self) -> None:
        self.root = TrieNode()

    def insert(self, word: str) -> None:
        node = self.root
        for char in word:
            if char not in node.children:
                node.children[char] = TrieNode()
            node = node.children[char]
        node.end = True

    def _walk(self, text: str) -> TrieNode | None:
        node = self.root
        for char in text:
            if char not in node.children:
                return None
            node = node.children[char]
        return node

    def search(self, word: str) -> bool:
        node = self._walk(word)
        return node is not None and node.end

    def starts_with(self, prefix: str) -> bool:
        return self._walk(prefix) is not None

查詢與前綴匹配：查詢完整單字 search 與前綴檢查 starts_with 共享統一的 _walk 輔助方法。沿著字串字元逐步深入：只要路徑中任何一個字元不存在於子節點字典中，便能立即斷定匹配失敗回傳 None。若能順利走完字串：starts_with 只關心該節點是否存在（前綴可達即回傳 True），而 search 則必須嚴格檢驗該節點的 end 屬性是否為 True。單詞插入與查詢的時間複雜度皆為純粹的 $O(L)$（$L$ 為字串長度），完全與詞庫中的單字總數無關！

三、位元：把一小群布林值放進一個整數

LeetCode 191．Number of 1 Bits。本節接受任意非負 Python 整數。

當候選元素的總數較少時（例如 $b \le 60$），我們可以用一個整數的二進位位元遮罩（Bitmask）來完美代表一個集合：整數的第 $i$ 位為 1 代表元素 $i$ 存在於集合中，為 0 則代表不存在。這種緊湊的表示法能讓集合的聯集（OR |）、交集（AND &）、差集（AND NOT & ~）以及對稱差（XOR ^）全部直接在 CPU 的單一週期指令內瞬間完成。

位元運算中有一個極具代表性的經典奇技：x & (x - 1) 能在常數時間內消除整數 x 二進位中最靠右側的那個 1（Brian Kernighan's Algorithm）。原理非常精妙：$x - 1$ 會將最右側的 1 借位變成 0，並將該位元右邊的所有 0 全數翻轉為 1；此時再與原本的 $x$ 進行 AND 運算，最右側的 1 及其右側全部歸零，而左側的所有高位元則完全不受影響：

def popcount(value: int) -> int:
    if value < 0:
        raise ValueError('this implementation requires a nonnegative integer')
    count = 0
    while value:
        value &= value - 1
        count += 1
    return count

迴圈執行的次數精確等於整數二進位中 1 的實際個數 $k$，在位元稀疏時效能極高。在固定字長的機器模型下時間為 $O(k)$，空間為 $O(1)$。

四、區間：先定義端點，再排序合併

LeetCode 56．Merge Intervals。閉區間共用端點時合併。

合併重疊區間的先決條件是「順序」。若區間隨機散落，我們無法判斷某個區間是否會與遙遠後方的某段重疊。將所有區間依照左端點 left 升冪排序後，問題立刻展現強大的單調性：後續到達的區間，其左端點絕不可能比前一個區間的左端點更靠左！

def merge_closed(intervals: list[tuple[int, int]]) -> list[list[int]]:
    if any(left > right for left, right in intervals):
        raise ValueError('left endpoint exceeds right endpoint')
    merged: list[list[int]] = []
    for left, right in sorted(intervals):
        if not merged or left > merged[-1][1]:
            merged.append([left, right])
        else:
            merged[-1][1] = max(merged[-1][1], right)
    return merged

掃描不變量：在處理完前 $i$ 個已排序區間後，merged 清單內部忠實記錄了這些區間的最小聯集，且清單內的各區間彼此嚴格互不重疊。當新區間 [left, right] 到來時：若其 left > merged[-1][1]，說明中間出現了真空斷層，我們大膽開啟一個全新的獨立區間；反之，若 left ≤ merged[-1][1]，則兩者必然重疊，我們只需將當前合併區間的右界動態擴展為 max(merged[-1][1], right)。整體時間由排序主導為 $O(n \log n)$，隨後單次掃描耗時 $O(n)$。

五、模運算：加減乘可逐步取餘數，除法要另問

在涉及大數計數或密碼學的計算中，運算結果常要求對正整數模數 $m$ 取餘數。同餘理論告訴我們：加法、減法與乘法都具備模運算的分配律，即 $(a \times b) \pmod m = ((a \pmod m) \times (b \pmod m)) \pmod m$。這項美妙性質允許我們在每一步中間運算時都立即取模，將數值牢牢箝制在 $[0, m - 1]$ 之間，徹底防範整數位元無限膨脹。

但請牢記：除法絕對不能隨意代入模運算！在模 6 系統下，$2 \times 1 \equiv 2$ 且 $2 \times 4 \equiv 2$，如果知道乘積餘數是 2，除以 2 根本無法唯一判定原本是 1 還是 4。除數只有在與模數 $m$ 互質時，才存在唯一的模反元素（Modular Multiplicative Inverse）。

若要計算 $base^{exponent} \pmod{modulus}$，使用二進位快速冪（Binary Exponentiation）能在對數時間內完成。將指數拆解為二進位位元：每當指數當前最低位為 1 時，將當前的基底乘入結果；隨後基底自我平方，指數右移折半：

def pow_mod(base: int, exponent: int, modulus: int) -> int:
    if exponent < 0 or modulus <= 0:
        raise ValueError('requires exponent >= 0 and modulus > 0')
    result = 1 % modulus
    base %= modulus
    while exponent:
        if exponent & 1:
            result = result * base % modulus
        base = base * base % modulus
        exponent >>= 1
    return result

無論指數高達數十億或數萬億，迴圈總共只需執行 $O(\log exponent)$ 次模乘，空間佔用為常數級 $O(1)$。在生產環境中，Python 內建的 pow(base, exponent, modulus) 直接以 C 實現了該演算法，效能更為極致。

六、Dijkstra：最便宜的未完成狀態先擴展

LeetCode 743．Network Delay Time 的延伸：這裡回傳每個頂點的距離，不可達為 inf。

在帶權圖中，若邊的權重皆為「非負實數或非負整數」，Dijkstra 演算法是尋找單源最短路徑（SSSP）的絕對標準解。它本質上是貪心思想與 BFS 的完美融合：不再使用先進先出的 FIFO 佇列，而是使用最小堆積（Min-Heap）隨時挑出「當前所有未確定頂點中，暫定累計距離最短的那一個」進行出列鬆弛：

from heapq import heappop, heappush
from math import inf

def dijkstra(graph: list[list[tuple[int, int]]], start: int) -> list[float | int]:
    if not 0 <= start < len(graph):
        raise ValueError('start must be a vertex in graph')
    if any(weight < 0 for edges in graph for _, weight in edges):
        raise ValueError('Dijkstra requires nonnegative weights')
    distance = [inf] * len(graph)
    distance[start] = 0
    heap = [(0, start)]
    while heap:
        cost, node = heappop(heap)
        if cost != distance[node]:
            continue  # An old, more expensive entry.
        for neighbor, weight in graph[node]:
            candidate = cost + weight
            if candidate < distance[neighbor]:
                distance[neighbor] = candidate
                heappush(heap, (candidate, neighbor))
    return distance

延遲刪除（Lazy Deletion）的優雅之處：標準庫的 heapq 不支援直接降低鍵值（Decrease-Key）的操作。我們採用簡潔高效的替代方案：每當透過鬆弛發現了一條通往 neighbor 的更短路徑時，我們直接將新的 (candidate, neighbor) 二元組推入堆積中。這會導致同一個節點在堆積中可能同時存在數個不同歷史時期的距離快照。在彈出時，只需一行守衛判斷：if cost != distance[node]: continue。若彈出的成本已經大於全域記錄的最佳距離，代表這是一筆已被更優解超越的過期殘影，直接丟棄！這種延遲清理保證了每個頂點只會真正執行其出邊鬆弛一次。總時間複雜度為 $O((V + E) \log E)$，額外空間為 $O(V + E)$。

Dijkstra 演算法的前提是所有邊權重必須大於等於 0！一旦圖中出現負權重邊，先前彈出的節點未來可能透過後續的負邊被進一步刷小，演算法的貪心不變量全面失效。若圖中存在負權重邊，必須改用 Bellman-Ford 演算法或 SPFA。

七、限制轉乘：同一個城市，也可能是不同狀態

LeetCode 787．Cheapest Flights Within K Stops。本頁以鄰接表輸入，無解回傳 None。

這是一類極具啟發性的圖論轉化問題：從起點飛往終點，但限制「最多只能中途轉機 K 次」（即最多只能使用 $K + 1$ 條邊），求最低總花費。若我們依然單純用 distance[city] 來記錄每個城市的最低花費，演算法會瞬間失靈——因為某條耗費極低的航班路徑，可能一口氣耗盡了所有的轉機次數，導致後續根本無法再起飛到達終點；而另一條花費略高一點的路徑，卻只用了一次轉機，留有充裕的步數餘裕繼續飛抵終點！

解法在於「將限制維度納入節點狀態中」，進行**狀態擴充（State Augmentation）**：圖中的頂點不再單純是「城市」，而是擴充為二元狀態 (city, used_edges)！二維陣列 distance[city][used_edges] 代表「恰好使用了 used_edges 條邊抵達該城市」的最低費用。原始圖中的一條航班邊 $u \to v$，在此擴充狀態圖中自然轉化為一條從 $(u, e)$ 指向 $(v, e + 1)$ 的有向邊（前提是 $e < \text{max\_edges}$）。由於邊權依然非負，擴充後的圖依然能直接套用 Dijkstra 的堆積優先策略：

def cheapest_with_stops(graph: list[list[tuple[int, int]]], start: int,
                        target: int, max_stops: int) -> int | None:
    # 非負邊的最優路徑可移除環，至多需要 V-1 條邊。
    if not (0 <= start < len(graph) and 0 <= target < len(graph)):
        raise ValueError('start and target must be vertices in graph')
    if max_stops < -1:
        raise ValueError('max_stops must be at least -1')
    if any(weight < 0 for edges in graph for _, weight in edges):
        raise ValueError('requires nonnegative weights')
    max_edges = min(max_stops + 1, len(graph) - 1)
    distance = [[inf] * (max_edges + 1) for _ in graph]
    distance[start][0] = 0
    heap = [(0, start, 0)]
    while heap:
        cost, node, used = heappop(heap)
        if cost != distance[node][used]:
            continue
        if node == target:
            return cost
        if used == max_edges:
            continue
        for neighbor, weight in graph[node]:
            candidate = cost + weight
            if candidate < distance[neighbor][used + 1]:
                distance[neighbor][used + 1] = candidate
                heappush(heap, (candidate, neighbor, used + 1))
    return None

因為堆積是按總花費遞增排序彈出，當目的地 target 第一次作為堆頂節點出列時，該花費就必然是所有步數合法路徑中的全域最低票價，可直接短路返回！擴充圖的總狀態數為 $O(B \cdot V)$，總邊數為 $O(B \cdot E)$（其中 $B = \min(K + 1, V - 1)$），完美化解了帶約束的最短路徑難題。

八、Union-Find：邊逐筆加入時，維護連通群組

在許多動態網路場景中，無向圖的邊是逐筆連續加入的。我們需要頻繁判定：「節點 a 與節點 b 目前是否已經連通？」、「全圖目前總共被劃分為幾個互不相連的獨立子島嶼？」。如果每次加邊都重新跑一次 BFS/DFS，單次查詢成本高達 $O(V + E)$。並查集（Union-Find / Disjoint Set Union，DSU）正是為此而生的天才資料結構。

並查集將每個連通分量組織成一棵樹，用樹根節點作為該群組的唯一代表（Representative）。判斷兩點是否連通，只需比對兩者的根節點是否相同（find(a) == find(b)）。為了防止樹退化成深長的單向鏈表，標準實現同時具備兩項至關重要的優化：

  1. 按大小合併（Union by Size）：在執行 union 時，總是將節點數量較小的那棵樹的根，掛在節點數量較大的樹根下方。這能保證整棵樹的高度的增長極其緩慢。
  2. 路徑壓縮（Path Compression）：在執行 find 尋找根節點的過程中，順道將路徑上所有造訪過的節點的父指標直接重新指向樹根！經過一次查詢後，整條長鏈瞬間被拍平成深度僅為 1 的扁平菊花圖。
class UnionFind:
    def __init__(self, n):
        if n < 0:
            raise ValueError("n 必須非負")
        self.parent = list(range(n))
        self.size = [1] * n
        self.components = n

    def find(self, node):
        if not 0 <= node < len(self.parent):
            raise ValueError("節點編號超出範圍")
        root = node
        while self.parent[root] != root:
            root = self.parent[root]
        while node != root:
            previous = self.parent[node]
            self.parent[node] = root
            node = previous
        return root

    def union(self, a, b):
        root_a, root_b = self.find(a), self.find(b)
        if root_a == root_b:
            return False
        if self.size[root_a] < self.size[root_b]:
            root_a, root_b = root_b, root_a
        self.parent[root_b] = root_a
        self.size[root_a] += self.size[root_b]
        self.components -= 1
        return True

在加入邊 $(0, 2)$ 時，因為兩者早已透過 0-1-2 連通，union 回傳 False，這能直接用來偵測無向圖中環路（Cycle）的生成！同時兼備路徑壓縮與按大小合併的並查集，其單次操作的均攤時間複雜度為不可思議的 $O(\alpha(V))$，其中 $\alpha$ 是阿克曼函數的反函數（Inverse Ackermann Function）。在宇宙中任何已知的物理資料規模下，$\alpha(V)$ 的值皆恆小於等於 4，這意味著並查集的查詢與合併在實務上等同於極速的常數時間 $O(1)$！

九、練習：替工具補上它需要的前提

練習 1｜同時處理中的工作有多少？

系統中有 $n$ 個離散的時間刻度，多項任務分別覆蓋閉區間 $[left, right]$。每項任務在其覆蓋的每格時間內都會為系統貢獻 1 個單位的負載。請計算出全域歷史中的「最高瞬間負載量」。若 $n=7$ 且任務清單為 [(0, 2), (2, 5), (4, 6)]，答案為 2。若無任何任務請回傳 0。

參考解答

這正是標準的差分陣列批次更新應用！將所有任務看成對區間 $[left, right]$ 增量 1 的更新指令，呼叫 range_add 還原出各時間點的負載陣列，隨後取 max 即可。前綴累積確保了離開任務區間後負載被精確扣除。總時間複雜度為 $O(n + q)$，空間複雜度為 $O(n)$：

def peak_load(n: int, intervals: list[tuple[int, int]]) -> int:
    counts = range_add(n, ((left, right, 1) for left, right in intervals))
    return max(counts, default=0)

練習 2｜最少會議室

每場會議使用半開時間區間 $[start, end)$，且 $start < end$。請問最少需要準備多少間會議室，才能讓所有會議完全互不衝突地順利舉行？例如給定 [(1, 4), (4, 6), (2, 3)]，答案為 2 間（第二場會議可直接接手第一場會議剛結束釋出的房間）。

參考解答

將所有會議依照開始時間升冪排序，並維護一個最小堆積 ends，記錄當前所有使用中會議室的「結束時間」。當新會議準備開始時：只要堆頂最早結束的會議其結束時間小於等於當前會議的開始時間（ends[0] <= start），就代表有舊會議室騰出，將其彈出回收；隨後將當前會議的結束時間推入堆中。堆積的大小即代表此時並行進行的會議數量，其全域最大值即為最少所需房間數。時間 $O(n \log n)$，空間 $O(n)$：

def min_rooms(intervals: list[tuple[int, int]]) -> int:
    # Positive-length, half-open intervals [start, end).
    if any(start >= end for start, end in intervals):
        raise ValueError('meetings must have positive duration')
    ends: list[int] = []
    answer = 0
    for start, end in sorted(intervals):
        while ends and ends[0] <= start:
            heappop(ends)
        heappush(ends, end)
        answer = max(answer, len(ends))
    return answer

練習 3｜成對資料中多出哪個值？

LeetCode 136．Single Number

給定一個整數陣列，已知除了某一個數值恰好只出現一次之外，其餘所有的數值都恰好成雙成對地出現兩次。在不排序、不使用任何額外雜湊表的極限限制下，以 $O(1)$ 輔助空間找出這個孤單的數值。例如 [13, 8, 13, -4, 8] 回傳 -4。

參考解答

利用 XOR 異或運算的優雅代數性質：$x \oplus x = 0$ 且 $x \oplus 0 = x$，且 XOR 運算滿足交換律與結合律。我們將陣列中的所有數字從頭到尾異或在一起，所有成雙成對出現的數值會全數自我抵銷歸零，最終留下來的唯一殘存值必然就是那個落單的數字！時間複雜度 $O(n)$，空間複雜度 $O(1)$：

def xor_unique(values: list[int]) -> int:
    # Exactly one value occurs once; every other value occurs twice.
    result = 0
    for value in values:
        result ^= value
    return result

練習 4｜排除自己後的乘積，模數可能不是質數

LeetCode 238．Product of Array Except Self 的延伸：回傳乘積對正整數模數 m 的餘數。

給定整數清單，請回傳一個新陣列，其中第 $i$ 個位置等於「排除該位置本身後、其餘所有元素的乘積」對模數 $m$ 的餘數。數值可能為 0 或負數，模數 $m$ 可能是非質數的合數，禁止使用除法。例如 values=[2, 3, 4] 且 m=6 時回傳 [0, 2, 0]。

參考解答

因為模數可能是合數且陣列中可能包含 0，除法與模反元素在此徹底失效。採用雙向前綴後綴積技巧：第一輪由左至右掃描，將「位於該元素左側的所有元素之累積乘積」暫存在結果陣列中；第二輪由右至左掃描，動態維護「右側所有元素的累積乘積」，並直接與剛才的左側乘積相乘取模。每個位置的左側集合與右側集合互不重疊且恰好完美排除自己！全程只用模乘，時間 $O(n)$，輔助空間 $O(1)$（不計回傳結果）：

def products_except_self_mod(values: list[int], modulus: int) -> list[int]:
    if modulus <= 0:
        raise ValueError('modulus must be positive')
    result = [1 % modulus] * len(values)
    prefix = 1 % modulus
    for i, value in enumerate(values):
        result[i] = prefix
        prefix = prefix * value % modulus
    suffix = 1 % modulus
    for i in range(len(values) - 1, -1, -1):
        result[i] = result[i] * suffix % modulus
        suffix = suffix * values[i] % modulus
    return result

練習 5｜為什麼不能只記「抵達城市時剩幾站」？

在帶有轉乘次數限制的最短路徑中，有同學提出：「我們何必開二維陣列？每個城市只要永遠保留『剩餘可飛行次數最多』的那條路徑就好，這不是能留給未來最大餘裕嗎？」。請給出致命反例推翻該想法。

參考解答

考慮反例：上限允許使用 3 條邊。路徑甲為 S 直達 v，費用高達 100，但只消耗 1 條邊（剩餘額度 2 邊）；路徑乙為 S 經過兩個中間站 a, b 抵達 v，每段費用僅為 1（總費用 3），但消耗了 3 條邊（剩餘額度 0 邊）。若目的地 T 恰好就在 v 的隔壁且飛行費用為 1：如果貪心只保留剩餘額度最多的路徑甲，最終算出的機票花費高達 $100 + 1 = 101$；但若題目目標是終點就在 v，或者允許 4 條邊時，路徑乙才是真正的超值首選！這證明了：花費低但步數多、與花費高但步數少，兩者在多階段決策中屬於互不支配的 Pareto 最優狀態，必須同時予以保留。

十、工具選擇

  • 批次區間增量修改，最後一次全量查詢：差分陣列；若需要頻繁交錯更新與區間查詢，請轉向樹狀陣列（Fenwick Tree）或線段樹。
  • 快速前綴過濾與字元路徑共享：字典樹（Trie）；若僅需查詢完整字串存在性，內建的 set 記憶體更輕量。
  • 離散狀態緊湊壓縮：位元遮罩（Bitmask）；請記住列舉所有可能狀態的複雜度依然是嚴格的指數級 $O(2^n)$。
  • 區間重疊處理：務必先依照左端點排序；並在動手前嚴格區分是閉區間 $[start, end]$ 還是半開區間 $[start, end)$。
  • 大數指數乘法：二進位快速冪；模除法前必須確認除數與模數互質，否則優先採用左右前綴積消除除法依賴。
  • 無權圖最短路選 BFS；非負帶權圖最短路選 Dijkstra；附帶資源或步數限制時，大膽將限制維度擴充進狀態二元組中。
  • 動態加邊環境下維護連通分量與偵測環：並查集（Union-Find），兼備按大小合併與路徑壓縮以達到近乎常數的極限效能。
