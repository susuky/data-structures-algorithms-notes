07 · 只保留眼前最值得處理的候選

資料持續進來時，常只需要最小值、最大的 k 個，或每條串流的下一筆。堆積把這些候選安排在一棵容易修復的樹裡。

陣列裡的完全二元樹

最小堆積（min-heap）讓每個父節點都不大於它的孩子，因此根節點就是全體最小值。樹從上到下、從左到右填滿，可以直接存在陣列裡。

0 起算時，索引 i 的孩子是 2i+1 與 2i+2，父節點是 (i−1)//2。孩子索引超過長度，就表示那個孩子不存在。這個布局省掉每個節點額外保存左右參照的需求。

堆積只要求父子關係，左右兄弟與不同子樹之間可有不同順序。要依序取出所有值，就反覆取根並修復堆積。Python heapq 的 heap[0] 可直接讀最小值。

heap=[1,4,2,8,6] 是否有序？是否為合法最小堆積？

看推理

整個陣列沒有排序，但每個父節點都不大於孩子：1≤4,2；4≤8,6，所以是合法最小堆積。

插入往上，取根往下

插入時先把新值放到陣列尾端；若比父節點小，就交換並繼續上浮。取出根時，把最後一個值搬到根，再與較小的孩子比較，需要時交換並向下走。

每次最多沿樹高移動，完全二元樹高度 O(log n)，所以 push/pop 各花 O(log n)。查看根只需 O(1)。

一次建堆可以從最後一個非葉節點向前逐個下沉。大量節點靠近底部，只需走零到一層；把各高度的工作量加總，heapify 為 O(n)。逐筆 heappush 建堆則為 O(n log n) 上界。

import heapq

heap = [12, 3, 8, 7, 9, 5, 6]
heapq.heapify(heap)            # 原地建堆；陣列不必是唯一排列
assert heap[0] == 3
heapq.heappush(heap, 2)
assert heapq.heappop(heap) == 2
assert heapq.heappop(heap) == 3

下沉時，為什麼要挑兩個孩子中較小的交換？

看推理

交換後新父節點要同時不大於左右孩子。若挑較大的，另一個較小孩子仍會違反父子關係。

保留最大的 k 個，根要放誰

想保留最大的三個值，維持大小最多 3 的最小堆積。根是入選者中最小的那個，也就是新值要超過的門檻。讀到 8，若根是 5，就讓 8 取代 5，再向下修復。

串流 Top K

每一步維持的關係

處理完一個前綴，堆積保存其中最大的 k 個值。

O(n log k) 時間（k=1 時為 O(n)）、O(k) 額外空間。

已讀每一個前綴後，堆積保存該前綴最大的 k 個值。堆積未滿就加入；已滿且新值不大於根，入選名單維持原狀。相同值按照出現次數計名次。

下方 largest_k 回傳由大到小的至多 k 個值，k=0 回傳 []，k<0 回報 ValueError。維護候選花 O(n log k)，最後排序候選再花 O(k log k)，空間 O(k)；k=1 時為線性掃描。

import heapq

def largest_k(numbers, k):
    """回傳最大的至多 k 個數，降序排列；相同數值按出現次數計。"""
    if k < 0:
        raise ValueError("k 不可為負")
    if k == 0:
        return []
    heap = []
    for value in numbers:
        if len(heap) < k:
            heapq.heappush(heap, value)
        elif value > heap[0]:
            heapq.heapreplace(heap, value)
    return sorted(heap, reverse=True)

表格讀入 [11,4,8,15,7,13] 並保留前三大，根就是每輪的入選門檻。

最大三個候選為 [5,7,9]，新值是 4，為什麼直接略過？

看推理

目前已有三個值都比 4 大，它無法進入前三。根 5 提供了這個判斷需要的最低門檻。

新的一筆抵達，更新第 k 大

KthLargest 把堆積保留在物件裡。每次 add(value) 都沿用之前最大的 k 個候選，更新後直接讀根；資料不足 k 筆時，回傳 None。

這個狀態與整段 largest_k 使用同一個原理。差別在輸出時機：串流每抵達一筆就回答一次，無須保存全部歷史。

每次新增 O(log k)，空間 O(k)。當需求改成第 k 個不同值時，還要處理去重規則；本實作把重複值當作各自獨立的一筆。

import heapq

class KthLargest:
    """add 回傳目前第 k 大；不足 k 筆則回傳 None。"""
    def __init__(self, k):
        if k <= 0:
            raise ValueError("k 必須為正整數")
        self.k = k
        self.heap = []

    def add(self, value):
        if len(self.heap) < self.k:
            heapq.heappush(self.heap, value)
        elif value > self.heap[0]:
            heapq.heapreplace(self.heap, value)
        return self.heap[0] if len(self.heap) == self.k else None

k=2，依序加入 5、5、2，三次回傳什麼？

看推理

None、5、5。前兩個 5 分別佔第一、第二大，2 不會進入前二。

原始文件與題目：LeetCode 703 · Kth Largest Element in a Stream

同優先權，照加入順序處理

工作可能有相同 priority，而 payload 可能是無法直接比較的物件。堆積項目使用 (priority,serial,payload)：先比較 priority，再比較唯一遞增的 serial。

相同 priority 會依加入順序出列，而且比較在 serial 就分出勝負，無須碰 payload。下方 StablePriorityQueue 的 pop 只回傳 payload。

要改已入堆積項目的優先權，常用方式是加入新版本並在取出時略過舊版本，或額外維護項目位置來做更新。選擇取決於更新量與允許的暫存資料量。

import heapq
from itertools import count

class StablePriorityQueue:
    """priority 越小越先取出；相同 priority 保持加入順序。"""
    def __init__(self):
        self.heap = []
        self.serial = count()

    def push(self, priority, payload):
        heapq.heappush(self.heap, (priority, next(self.serial), payload))

    def pop(self):
        return heapq.heappop(self.heap)[2]

省略 serial，直接放 (priority,payload)，會在什麼情況出錯？

看推理

兩個 priority 相同時，tuple 比較會繼續比 payload；若 payload 是未定義大小比較的物件，就會發生 TypeError。

每條串流，只放下一個候選

有 k 條已排序串流，整體下一個最小值一定出現在某條串流的前端。堆積各放一筆，取出最小者後，只向同一條串流再讀一筆補回。

每一條輸入已經有序，所以它後面的值會等到前端取出後才取得資格。空串流直接略過，已耗盡的來源不再補值。

初始化先讀取 k 條來源的前端並 heapify，花 O(k)。總共輸出 N 筆，每次從至多 k 個候選中取最小，總時間 O(k + N log(k+1))、候選空間 O(k)。generator 逐筆產出結果，呼叫端可隨用隨取。

import heapq

def merge_sorted_streams(streams):
    """每條輸入須已依遞增排序；同來源只保留下一個候選。"""
    heap = []
    for source, stream in enumerate(streams):
        iterator = iter(stream)
        try:
            value = next(iterator)
        except StopIteration:
            continue
        heap.append((value, source, iterator))
    heapq.heapify(heap)
    while heap:
        value, source, iterator = heapq.heappop(heap)
        yield value
        try:
            following = next(iterator)
        except StopIteration:
            continue
        heapq.heappush(heap, (following, source, iterator))

第三大、第三個不同值與中位數

一般第三大按出現次數計算；第三個不同最大值要先處理相同值的重複資格。拿 [5,5,4,3] 對照：第三大是 4，第三個不同值是 3。

串流中位數可用兩個堆積。較小一半放最大堆積，較大一半放最小堆積；讓兩邊大小差至多一個，且左半所有值不大於右半所有值。

新增後先維持分組大小與大小關係。奇數筆讀較大那邊的根，偶數筆取兩根平均。Python 3.14 起提供 heapq 的 max-heap API；較早版本常用數值取負來表示最大堆積。

資料 [1,4,8,10] 的兩個中間根可以是什麼，中位數是多少？

看推理

左半最大值為 4，右半最小值為 8，中位數 (4+8)/2=6。

候選很少，就保留候選

每次只取最小或最大者，用優先佇列；只要最大的 k 個，用小堆積維持門檻；合併已排序來源，每個來源只保留前端。

若最後必須依序輸出全部資料，排序通常是直接的選擇。若需要持續接收資料並即時回覆，堆積能把工作分攤到每次更新。

驗證堆積時，檢查父子關係與回傳結果，無須要求內部陣列完整排序。重複值、負數、k=0 與資料不足 k 筆，各自對應一項輸出規格。

拿到合法 heap，為何不能把 heap[1] 當第二小的完整保證？

看推理

根的兩個孩子各是其子樹最小者，第二小可能位於索引 1 或 2。依序 pop 才會按照全體大小逐個輸出。
