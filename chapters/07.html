07　堆積與優先佇列：保留最重要的候選

你未必需要把所有資料完整排序。工作排程可能只需要下一個最早到期者，資料流只需要目前第 k 大，多條排序串流合併時只需要各來源的下一個值。堆積（heap）只維持部分排序關係，讓加入資料與取出極值的成本較低。本章以 Python 的最小堆積為基礎，說明如何保留 top-k、維持穩定優先權，以及合併多條串流。

優先佇列定義「優先取出哪一筆」；二元堆積是實現這個介面的資料結構。本章以整數示範，先理解極值維護，再處理帶優先權的物件。

1. 陣列裡的完全二元樹

最小堆積維持兩項條件：形狀是一棵完全二元樹，最後一層由左至右填滿；每個父節點的值不大於其子節點。採零起算索引時，位置 i 的左子是 2i + 1、右子是 2i + 2、父節點是 (i − 1) // 2（根沒有父節點）。因此不必建立樹節點物件，就能用陣列表示。

沿根出發的每條路徑，值都不會變小，因此根是全域最小值；次小值可能在左子或右子，不同子樹之間沒有完整的大小順序。讀 heap[0] 是 O(1)，找任意值則仍可能 O(n)。如果需求是大量查第 i 小、區間搜尋或完整有序走訪，堆積未必適合。

2. 上浮、下沉與 O(n) 建堆

加入新值時，把它放在陣列末端以保留完全樹形，再與父節點比較，必要時往上交換，稱為上浮。刪除根時，先把最後一個值補到根，然後反覆與較小的子節點交換，稱為下沉。每次只沿一條根到葉的路徑，所以比較與交換步數都是 O(log n)。

修復前，新值所在路徑以外的父子關係都仍合法。沿正確方向交換，就能把唯一可能違反堆積條件的位置往上或往下移，直到所有父子關係都符合條件。下沉若任意挑一個子節點交換，可能讓另一個更小的子節點留在父節點下方，破壞堆積條件。

heapify 不是把每個元素逐一 heappush。它從最後一個非葉節點往根修復；葉節點本身已是合法的單節點堆積，不需要修復。大約一半的節點不需下沉，四分之一最多下一層，八分之一最多下兩層；總成本可用 n × (1/4 + 2/8 + 3/16 + …) 這個收斂和來估計，所以是 O(n)，不是 O(n log n)。

import heapq

heap = [12, 3, 8, 7, 9, 5, 6]
heapq.heapify(heap)            # 原地建堆；陣列不必是唯一排列
assert heap[0] == 3
heapq.heappush(heap, 2)
assert heapq.heappop(heap) == 2
assert heapq.heappop(heap) == 3

heapq 操作一般的 list，函式不會替你確認整個 list 已經有堆積性質。heapify 會原地更動資料；若要保留原序列，要先 heap = list(values)，而這個複製另用 O(n) 空間。Python 底層 list 偶爾需要擴容，所以加入的常見 O(log n) 分析對容器配置採攤銷成本；數值比較也假設是 O(1)。

heappushpop 與 heapreplace 順序不同。若 h = [4, 8, 6] 且 x = 2，pushpop 回傳 2，留下原本三個元素；replace 回傳 4，堆中則加入 2。固定容量 top-k 若不先檢查新值，就直接 heapreplace，可能把較大的候選換成較小者。

3. 最大的 k 個，為何使用「最小」堆積？

LeetCode 215 · Kth Largest Element in an Array 求第 k 大的一個值；本節回傳最大的至多 k 個值，並降序排列。重複值按出現次數計，k=0 回傳 []，k 超過資料數量時回傳全部資料。

要留下最大的 k 個值，根應放目前保留值中最容易被淘汰的那一個。它是「目前保留集合中最小的值」，因此選最小堆積。新值比根大就有資格進來，否則直接略過。只看「找最大」這個說法，容易誤以為這裡應該用最大堆積。

不變量：處理任一前綴後，heap 恰好保存該前綴最大的 min(k, 已讀數量) 個值，重複值按各次出現計數。未滿 k 時全部保留；已滿時，只有新值大於根才交換。因為根是保留者中最小的，交換後仍是前綴最大的 k 個。

import heapq

def largest_k(numbers, k):
    """回傳最大的至多 k 個數，降序排列；相同數值按出現次數計。"""
    if k < 0:
        raise ValueError("k 不可為負")
    if k == 0:
        return []
    heap = []
    for value in numbers:
        if len(heap) < k:
            heapq.heappush(heap, value)
        elif value > heap[0]:
            heapq.heapreplace(heap, value)
    return sorted(heap, reverse=True)

逐步例一：資料 11、4、8、15、7、13，k = 3

函式最後排序得到 [15, 13, 11]。不能直接回傳 heap 並宣稱它已由大到小排序。若只要第 3 大，根 11 就足夠，不用最後排序。

令 r = min(k, n)，k > 0 時，維護成本 O(n log(r + 1))，最後排序 O(r log(r + 1))；heap 與回傳結果各用 O(r) 空間。k = 0 立即回傳 []，連輸入迭代器也不消耗。k > n 時本規格回傳全部 n 個，k < 0 則拋 ValueError。

如果 k 接近 n，直接 sorted(numbers) 可能更簡單；如果資料已全在記憶體、只問一次第 k 大，也可研究選擇演算法。當 k 很小、資料逐筆到來，或答案需要持續更新時，堆積較能發揮作用。

4. 資料流的第 k 大

LeetCode 703 · Kth Largest Element in a Stream 的建構子接收 k 與初始 nums。本節從空資料流開始，建構子接收 k；add 在資料不足 k 筆時回傳 None。

處理資料流時，無法預先知道總長度，也不適合每收到一筆就把所有資料重新排序。把上面的 heap 保留下來，每次 add 只更新這個大小至多 k 的狀態。資料不足 k 筆時回傳 None，避免把「目前最小值」誤稱為「第 k 大」。

import heapq

class KthLargest:
    """add 回傳目前第 k 大；不足 k 筆則回傳 None。"""
    def __init__(self, k):
        if k <= 0:
            raise ValueError("k 必須為正整數")
        self.k = k
        self.heap = []

    def add(self, value):
        if len(self.heap) < self.k:
            heapq.heappush(self.heap, value)
        elif value > self.heap[0]:
            heapq.heapreplace(self.heap, value)
        return self.heap[0] if len(self.heap) == self.k else None

對 k = 3，依序加入 11、4、8、15、7、13，add 的回傳依序是 None、None、4、8、8、11。重複值有獨立名次：5、5、2 的第 2 大是 5，而不是 2。若題目要第 k 個「不同值」，不變量與去重規則都要改。

每次 add 最多 O(log(k + 1)) 次比較；計入 list 擴容時採攤銷 O(log(k + 1)) 時間。被略過的值只需 O(1) 比較；查根 O(1)，狀態 O(k)，不足 k 筆時實際只保存已收到的筆數。這裡的資料流只會加入，不支援過期或刪除；滑動視窗的第 k 大不能直接照搬。

5. 平手、無法比較的物件與更新陷阱

push 加入優先權與資料；pop 回傳優先權最小的資料，同優先權按加入順序取出。空佇列 pop 拋 IndexError。

Python tuple 由左到右比較。若放 (priority, payload)，兩個 priority 相同時就會比較 payload；dict 等資料不一定可排序，可能在平手時拋 TypeError。加入唯一遞增序號，改存 (priority, serial, payload)，就能讓平手維持先到先出，且完全不需要比較 payload。

import heapq
from itertools import count

class StablePriorityQueue:
    """priority 越小越先取出；相同 priority 保持加入順序。"""
    def __init__(self):
        self.heap = []
        self.serial = count()

    def push(self, priority, payload):
        heapq.heappush(self.heap, (priority, next(self.serial), payload))

    def pop(self):
        return heapq.heappop(self.heap)[2]

若數字越大越優先，可存負 priority，用最小堆積模擬最大堆積。Python 3.14 起也提供 heapify_max、heappush_max、heappop_max，直接操作最大堆積。

不要直接修改 heap 中某項的 priority，父子順序不會自動修復。一般 heapq 也沒有直接按任意 key 找元素、降低優先權的操作。簡單方案是重建 O(n)；更進階可另存 task 的版本，在 heap 加入新版，取出時跳過舊版。但舊項目會累積，空間要按「尚未清理的項目數」計算，不能仍宣稱只與有效任務數成正比。

6. 合併多條排序串流：每條只保留一個前端候選

LeetCode 23 · Merge k Sorted Lists 合併排序鏈結串列；本節使用排序迭代器逐筆產生值。兩者都以每個來源的下一筆作為候選。

有 m 條遞增串流，每條都已排序。全域下一個最小值一定是某一條的第一個未輸出值，因此不必把全部 N 筆資料放進 heap。先放每條非空串流的一個前端候選；取出最小者後，只向同一來源索取下一個值。

import heapq

def merge_sorted_streams(streams):
    """每條輸入須已依遞增排序；同來源只保留下一個候選。"""
    heap = []
    for source, stream in enumerate(streams):
        iterator = iter(stream)
        try:
            value = next(iterator)
        except StopIteration:
            continue
        heap.append((value, source, iterator))
    heapq.heapify(heap)
    while heap:
        value, source, iterator = heapq.heappop(heap)
        yield value
        try:
            following = next(iterator)
        except StopIteration:
            continue
        heapq.heappush(heap, (following, source, iterator))

heap 中的 tuple 是 (value, source, iterator)。source 是唯一的來源編號；每個來源同時至多一個候選，因此 value 相同時，比較到 source 就能分出順序，不會比較 iterator。相同值時編號小的來源先出；若需要別種平手規則，應另放對應的穩定序號。

正確性由來源排序保證：任何尚未輸出的值都不小於自己來源的前端，所以 heap 根就是所有剩餘資料中的最小值。輸出根並補入同來源下一個值，恢復這個不變量；heap 空代表所有來源耗盡。若有一條來源不是排序的，例 [9, 1]，藏在後面的 1 就可能太晚出現，整體結果不再有序。

設總輸出 N 筆、來源數 m、非空來源數 a。初始化掃描 O(m)，heapify O(a)，逐筆處理 O(N log(a + 1))，內部候選空間 O(a)。生成器 yield 不會自行保存全部輸出；若呼叫者用 list(...) 收集，另需 O(N) 輸出空間。來源集合需有限，否則初始化可能永遠不能完成。

標準庫提供相同用途的 heapq.nlargest、nsmallest 與 merge。前兩者直接回傳排序結果，merge 則逐筆產生合併值：

assert heapq.nlargest(3, [11, 4, 8, 15, 7, 13]) == [15, 13, 11]
assert heapq.nsmallest(2, [42, 17, 31, 12, 29]) == [12, 17]
assert list(heapq.merge([-2, 5, 10], [1, 5], [0, 6, 9])) == [-2, 0, 1, 5, 5, 6, 9, 10]

7. 練習與解答

練習 A：留下最小的 k 筆延遲

測試延遲依序為 [42, 17, 31, 12, 29]，只留最小的 2 筆，要求不保存全部輸入。你應把哪個值放在淘汰門檻？

參考解答

門檻應是保留者中最大的值。以最小堆積存負值：保留 17、42 時存 [−42, −17]，根代表最大保留值 42。新值 x 小於 −heap[0] 才替換根，實際放入 −x。最後取反並排序得到 [12, 17]。k > 0 時維護 O(n log(k + 1))、空間 O(k)，並需處理 k = 0 與負 k。

練習 B：第 k 大「不同」值

LeetCode 414 · Third Maximum Number 固定找第 3 大不同值，不足時回傳最大值；本題使用一般 k，不足時回傳 None。

資料 [8, 8, 5, 9, 5, 7]，k = 3，答案應是 7。如何以 O(k) 狀態避免把相同值占成多個名次？是否一定要記住歷史所有值？

參考解答

用大小最多 k 的最小堆積，搭配只含「目前堆內值」的 set。新值已在 set 就略過；未滿就同時加入兩者；已滿且比根大，就移除舊根及其 set 紀錄，再加入新值。不需要記住已淘汰的所有值：門檻只會上升，被淘汰的值再次出現時不可能超過目前門檻。set 採平均 O(1) 模型，總維護時間 O(n log(k + 1))，狀態 O(k)。不足 k 個不同值時仍回傳 None。

練習 C：兩個 heap 追蹤中位數

LeetCode 295 · Find Median from Data Stream。依序加入 4、8、2，中位數依序為 4、6、4；偶數筆時取中間兩值的平均。

資料只加入，要求每次回傳目前中位數。請描述兩個 heap 的內容、不變量與偶數筆時的答案，不必寫完整程式。

參考解答

lower 用最大堆積保存較小半部，可用負值模擬；upper 用最小堆積保存較大半部。保持 lower 的最大值 ≤ upper 的最小值，且 lower 筆數等於 upper 或多一筆。每次先按邊界分配新值，再從較大堆移動根來平衡。奇數筆時答案是 lower 的根取反，偶數筆時是兩個根的平均。加入 O(log n)，查詢 O(1)，空間 O(n)。

8. 決策小結與驗證清單

  • 反覆只要極值：可用 heap，讀根的成本低，不必完整排序。
  • 保留最大的 k 個：最小 heap 將保留值中的最小值放在根；保留最小的 k 個則反過來。
  • 合併已排序來源：一個來源一個前端候選，空間跟來源數而非總資料量成正比。
  • 遇到 tuple：先想平手時會比較誰；用唯一序號隔離不可排序的 payload。
  • 需求包括刪除、更新或過期：修改 heap 內元素時，必須另外處理查找與堆積修復。
  • 說明複雜度時別漏最後排序、收集生成器結果，以及 lazy deletion 尚未清掉的舊資料。
