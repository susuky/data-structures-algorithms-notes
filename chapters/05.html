05　堆疊與佇列：從配對到單調候選

遇到需要「回到最近還沒完成的事」，想到堆疊；遇到需要「照抵達順序處理」，想到佇列。如果問題還要求快速找下一個更大的值，或維護視窗最大值，就進一步思考：目前保留的索引中，哪些已找到答案，哪些不必再當候選？本章先說明操作規則，再推導單調結構中 while 迴圈的條件與理由。

讀完要能做到：分清 LIFO 與 FIFO，說明括號配對為何要檢查堆疊頂端，正確處理重複值的嚴格／非嚴格比較，並證明單調堆疊與單調佇列的總工作量為 O(n)。除特別說明外，整數比較與四則運算採固定大小數值模型。

1. 兩種等待規則，兩種 Python 容器

堆疊（stack）是後進先出 LIFO；加入稱 push，拿走最近加入者稱 pop。佇列（queue）是先進先出 FIFO；從尾端加入、頭端取出。這些是抽象規則，不限定某種實體儲存方式。Python 通常以 list 實作堆疊，以 collections.deque 實作雙端佇列。

from collections import deque

stack = []
stack.append("A")
stack.append("B")
assert stack.pop() == "B"

queue = deque(["A", "B"])
queue.append("C")
assert queue.popleft() == "A"
assert queue[0] == "B"

空容器 pop 或 popleft 會拋 IndexError，要由規格決定回傳特殊值還是先檢查。deque(maxlen=k) 滿時會自動丟棄另一端元素，適合固定容量歷史，但用來存 BFS 待辦或單調候選時，要確認自動丟棄的元素是否仍有用途，否則可能漏掉必要狀態。樹與圖的廣度優先走訪會在第 06 章使用 FIFO。

2. 括號配對：最近開啟者必須最先關閉

輸入由 ()、[]、{} 組成的字串，判斷括號種類與巢狀順序是否完全配對。空字串回傳 True；出現其他字元時拋 ValueError。

LeetCode 20 · Valid Parentheses

讀到開括號，把它存入 stack；讀到閉括號，必須與頂端的開括號同種類。只數左右括號無法判斷巢狀順序，例如 ([)] 各類數量都平衡，卻不是合法配對。也不能從堆疊中任選一個相符括號：跨過頂端，就會在內層尚未結束時先結束外層。

不變量是：只要目前前綴仍合法，stack 從底到頂，恰好保存尚未關閉的開括號，由外層到內層排列。valid 記錄是否曾經失配；繼續掃描可檢查後續字元，且失配結果會一直保留。

def valid_brackets(text):
    """只接受六種括號；其他字元拋 ValueError。"""
    partner = {")": "(", "]": "[", "}": "{"}
    stack = []
    valid = True
    for ch in text:
        if ch in "([{":
            stack.append(ch)
        elif ch in partner:
            if not stack or stack[-1] != partner[ch]:
                valid = False
            else:
                stack.pop()
        else:
            raise ValueError("輸入只能包含括號")
    return valid and not stack

長度 n 的輸入掃一次，時間 O(n)，最壞空間 O(n)，例如全是開括號。若最大巢狀深度為 d，合法前綴的 stack 空間可更精確寫成 O(d)。空字串按本章規格為合法。

3. 表達式解析：逆波蘭式與運算元順序

輸入逆波蘭式的字串 token 清單，內容為整數或 +、-、*、//，回傳計算結果。例如 ["8", "3", "-", "2", "*"] 回傳 10。不完整式子拋 ValueError，除零拋 ZeroDivisionError。

LeetCode 150 · Evaluate Reverse Polish Notation 使用 / 並向零截斷；本節的 // 向下取整。對 −7 除以 3，兩者分別得到 −2 與 −3。

一般算式要處理優先級與括號；逆波蘭式（後綴式）把運算子放在兩個運算元之後。例如 8 3 − 2 × 表示 (8 − 3) × 2。每讀到數字就 push，讀到運算子就取出兩個已完成的子運算結果，計算後再 push。

def evaluate_rpn(tokens):
    """逆波蘭式整數運算，// 採 Python 向下取整。"""
    stack = []
    for token in tokens:
        if token not in {"+", "-", "*", "//"}:
            stack.append(int(token))
            continue
        if len(stack) < 2:
            raise ValueError("運算元不足")
        b, a = stack.pop(), stack.pop()
        if token == "+":
            stack.append(a + b)
        elif token == "-":
            stack.append(a - b)
        elif token == "*":
            stack.append(a * b)
        else:
            stack.append(a // b)
    if len(stack) != 1:
        raise ValueError("運算式不完整")
    return stack[0]

不變量：stack 保存「已讀前綴中，尚未被後續運算子合併的子表達式結果」。先 pop 出來的是右運算元 b，第二個才是左運算元 a，所以要算 a − b 或 a // b。把順序寫反，在加法與乘法測試可能完全看不出來。8 3 − 的堆疊狀態依序是 [8]、[8, 3]、[5]。

本例 // 明確採 Python 向下取整，因此 −7 // 3 為 −3。若要向零截斷，可先計算 abs(a) // abs(b)，再依 a、b 是否異號決定正負；整個過程維持整數運算。除零會拋 ZeroDivisionError；運算元不足、最後剩多個結果或沒有結果，都是不完整的表達式。

t 個 token 的容器操作總共 O(t)，stack 最壞 O(t)。若整數位數可無限成長，字串轉整數、乘法與除法不能再當 O(1)；應額外計算數值的位元長度成本。

4. 單調堆疊：下一個嚴格較大元素

LeetCode 739 · Daily Temperatures 回傳等待天數，無解填 0。本節先求下一個較大值的索引，無解填 −1；已知索引 j 後，等待天數就是 j−i。

任務：對每個索引 i，找右側第一個值嚴格大於 values[i] 的索引，沒有就回傳 −1。逐格向右找最壞 O(n²)。掃描時也可以從新值出發：它是否是某些舊位置一直在等的第一個較大值？

stack 存索引，而且索引遞增、對應值從底到頂非遞增。看到 value 時，頂端若比較小，它的第一個較大值就是現在：如果更早已有較大值，它當時早就被移除了。持續 pop 所有小於 value 的頂端，再把目前索引加入。相等值不能解決「嚴格較大」的要求，所以保留下來。

def next_greater_indices(values):
    answer = [-1] * len(values)
    stack = []  # 未找到右側「嚴格較大」值的索引。
    for i, value in enumerate(values):
        while stack and values[stack[-1]] < value:
            answer[stack.pop()] = i
        stack.append(i)
    return answer

結果是 [3, 3, 3, −1, −1]。若題目要「等待幾步」，每次記錄 i − popped_index；若要下一個較大值，就記錄 value。修改程式前，先確認輸出要表示什麼。

看起來 for 裡還有 while，為什麼不是 O(n²)？每個索引只 push 一次、最多 pop 一次，整段 while 的成功迭代次數加總最多 n。可以想像每個索引加入時帶一張未來離場的票，票只能用一次。單一回合可能 O(n)，但 n 個回合的總成本仍是 O(n)。

時間 O(n)，額外 stack 空間 O(n)，另有 O(n) 輸出。最壞 stack 出現在非遞增輸入；相等值在此模板中也全部保留。

5. 單調雙端佇列：固定視窗最大值

輸入整數陣列 values 與整數視窗長度 k，回傳每個視窗的最大值。例如 [4,1,3,3,0,5]、k=3 得到 [4,3,3,5]；k 超出 1…len(values) 時拋 ValueError。

LeetCode 239 · Sliding Window Maximum

現在對每個長度 k 的連續視窗找最大值。堆疊只能在一端移除，不方便淘汰最舊元素；deque 能從頭移除過期索引，從尾移除被新值壓過的候選。deque 中只保存仍可能成為某個未來視窗最大值的索引。

維持三個不變量：索引由小到大；所有索引都在目前視窗中；對應值由大到小。對新位置 i，先移除索引 ≤ i − k 的過期頭端，再移除尾端所有值 ≤ values[i] 的候選，最後加入 i。當視窗已湊滿 k 個，頭端就是最大值。

from collections import deque

def sliding_maximum(values, k):
    if not 1 <= k <= len(values):
        raise ValueError("k 必須介於 1 與資料長度之間")
    candidates = deque()  # 索引遞增，對應值嚴格遞減。
    answer = []
    for i, value in enumerate(values):
        while candidates and candidates[0] <= i - k:
            candidates.popleft()
        while candidates and values[candidates[-1]] <= value:
            candidates.pop()
        candidates.append(i)
        if i >= k - 1:
            answer.append(values[candidates[0]])
    return answer

i／值過期移除尾端淘汰deque：索引:值輸出
0／4無無[0:4]未滿
1／1無無[0:4, 1:1]未滿
2／3無1:1[0:4, 2:3]4
3／30:42:3[3:3]3
4／0無無[3:3, 4:0]3
5／5無4:0、3:3[5:5]5

刪除尾端的正確性來自「支配關係」：若較新的 i 之值不小於舊 j，任何之後仍包含 j 的視窗也包含 i，而且 i 不會更早過期，所以 j 永遠不再必要。這個推理說明了為什麼可以安全刪除 j；只檢查「維持遞減」，還不足以證明不會漏掉答案。

每個索引加入一次，從某一端離開至多一次，因此時間 O(n)，候選空間 O(k)，輸出空間 O(n − k + 1)。本例要求 1 ≤ k ≤ n；空資料沒有合法的視窗長度。

不要把所有位置只存成值：重複值會讓「哪一個已過期」難以區分。也不要從一般 list 做 pop(0)；雖然結果可能仍正確，複雜度卻可能變成 O(nk)。

6. 練習與解答

練習 A：讓括號檢查器指出位置

對 ([)] 回傳第一個失配閉括號的索引 2。若沒有失配閉括號但仍有未關閉括號，回傳最早未關閉位置；完全合法則回傳 None。假設輸入只含括號。

參考解答

stack 改存 (括號, 索引)。關閉時只檢查頂端種類，失配就回傳目前位置；掃完若 stack 非空，回傳 stack[0] 的索引。

def first_bracket_error(text):
    """只接受括號；回傳第一個無法配對的關閉位置，否則最早未關閉位置。"""
    partner = {")": "(", "]": "[", "}": "{"}
    stack = []
    for i, ch in enumerate(text):
        if ch in "([{":
            stack.append((ch, i))
        elif ch in partner:
            if not stack or stack[-1][0] != partner[ch]:
                return i
            stack.pop()
        else:
            raise ValueError("輸入只能包含括號")
    return stack[0][1] if stack else None

時間 O(n)，空間 O(n)。測試至少包含空字串、第一個字元就是閉括號、巢狀失配、只有未關閉開括號四類。

練習 B：下一個嚴格較小值的等待距離

輸入 [5, 5, 2, 4, 1]，希望輸出 [2, 1, 2, 1, 0]，0 表示右側找不到更小值。請指出原模板要改的三處。

參考解答

答案初值由 −1 改為 0；while 條件改為 values[stack[-1]] > value；pop 出 j 時記 answer[j] = i − j。stack 的值改成非遞減，相等仍然不移除。每個索引只進出一次，所以 O(n) 時間、O(n) 空間。索引 0、1 都等到值 2，距離分別為 2、1。

練習 C：視窗最大值要回傳最早的索引

對 [3, 3, 2]、k = 2，最大值位置要回傳 [0, 1]。原程式保留較新的相同值，如何調整才能符合要求？

參考解答

尾端淘汰條件由 ≤ 改為 <，保留所有相同值，deque 的值不再嚴格遞減，而是非遞增。輸出 candidates[0] 本身，而不是對應值。索引依舊遞增，因此頭端是仍在視窗內的最早最大值。空間仍不超過 O(k)，時間仍 O(n)。

7. 決策小結

  • 最近開啟、尚未結束的事情：stack。配對、解析、DFS 的手動呼叫框架都屬此類。
  • 按加入順序處理：deque + append／popleft。避免 list.pop(0)。
  • 要找下一個較大／較小位置：單調 stack，先確定嚴格性與輸出是值、索引還是距離。
  • 視窗隨時間前進且求最大／最小：單調 deque，分開處理過期與被支配。
  • 看見巢狀迴圈先數「每個元素能被處理幾次」，不要只數程式縮排層數。
  • 候選結構只刪永遠不需要的資訊；若需求改成第 k 大或中位數，通常不能沿用同一套支配規則。
