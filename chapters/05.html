05 · 讓等待中的資料保持秩序

有些資料等著最近一次開啟的事件，有些等著最早到達的工作。堆疊、佇列與單調結構，都是在決定下一個該處理誰。

最近的先處理，還是最早的先處理

撤銷編輯時，最後做的修改先撤銷，使用後進先出的堆疊（stack）。排隊處理工作時，先到的先離開，使用先進先出的佇列（queue）。兩者的差別就是等待規則。

Python list 的尾端 append/pop 適合堆疊；collections.deque 的 append/popleft 適合佇列。list.pop(0) 每次搬動後面的參照，重複使用會增加大量移動成本。

雙端佇列（deque）可以從兩端操作，後面會用一端移除過期候選，另一端移除被新資料壓過的候選。

from collections import deque

stack = []
stack.append("A")
stack.append("B")
assert stack.pop() == "B"

queue = deque(["A", "B"])
queue.append("C")
assert queue.popleft() == "A"
assert queue[0] == "B"
操作成本原因
list.append()、尾端 pop()攤銷 O(1)多數操作只改動尾端；偶爾調整容量時需要搬移參照。
list.pop(0)、list.insert(0, v)O(n)前端有變動，後續參照需要移位。頻繁從隊首取資料時，選 deque.popleft()。
deque 的兩端 append / popO(1)兩端的區塊能直接定位，適合反覆入隊、出隊。
deque[0]、deque[-1]O(1)直接讀取兩端元素。
deque 中間的索引存取O(n)索引接近中間時，需要跨過多個區塊；頻繁隨機讀取可選 list。

BFS 需要每層依序擴展，應從哪端加入、哪端取出？

看推理

從尾端 append、前端 popleft，維持 FIFO。當前較近的節點會先被處理。

右括號要接上最近的左括號

讀到 (、[、{ 就放進堆疊；讀到右括號，堆疊頂端應是對應的左括號，配對成功就彈出。這正好符合內層先關閉的巢狀結構。

例如 ([)]：讀到 ) 時，頂端是 [，當下就出現型別衝突。(() 雖然每個右括號都能配到，結束後還留一個左括號，所以整體不完整。

valid_brackets 只接受六種括號，其他字元回報 ValueError；空字串回傳 True。每個字元各處理一次，時間 O(n)，最深巢狀需要 O(n) 空間。

def valid_brackets(text):
    """只接受六種括號；其他字元拋 ValueError。"""
    partner = {")": "(", "]": "[", "}": "{"}
    stack = []
    valid = True
    for ch in text:
        if ch in "([{":
            stack.append(ch)
        elif ch in partner:
            if not stack or stack[-1] != partner[ch]:
                valid = False
            else:
                stack.pop()
        else:
            raise ValueError("輸入只能包含括號")
    return valid and not stack

完整配對的 {[()]} 會讓堆疊依序長大，再從最內層退回空。

當前字元執行的決策動作stack 內部狀態（由底至頂）
{開啟最外層大括號，push['{']
[開啟中層中括號，push['{', '[']
(開啟最內層小括號，push['{', '[', '(']
)遇到閉小括號，比對頂端 '(' 吻合，執行 pop['{', '[']
]遇到閉中括號，比對頂端 '[' 吻合，執行 pop['{']
}遇到閉大括號，比對頂端 '{' 吻合，執行 pop[]（空堆疊）

為什麼只比較左右括號總數，無法辨認 ([)]？

看推理

三種括號的數量都平衡，但關閉順序違反巢狀關係。堆疊保存了尚未關閉的順序與型別。

運算子取出最近的兩個結果

逆波蘭式 8 3 - 2 * 把運算子放在運算元之後。讀到數字就推入；讀到 −，先取出的 3 是右運算元 b，再取 8 作左運算元 a，算 a−b=5，放回堆疊。最後乘 2 得到 10。

每個堆疊項目是一個已算完、等待後續使用的子運算式。運算子把兩個子答案合成一個，整段讀完應恰好剩一個值。

下方實作支援整數的 +、−、*、//；// 遵循 Python 向下取整，例如 −7//3=−3。若題目要求朝零截斷，要調整除法規則。運算元不足或最後剩多個值都回報輸入不完整。

def evaluate_rpn(tokens):
    """逆波蘭式整數運算，// 採 Python 向下取整。"""
    stack = []
    for token in tokens:
        if token not in {"+", "-", "*", "//"}:
            stack.append(int(token))
            continue
        if len(stack) < 2:
            raise ValueError("運算元不足")
        b, a = stack.pop(), stack.pop()
        if token == "+":
            stack.append(a + b)
        elif token == "-":
            stack.append(a - b)
        elif token == "*":
            stack.append(a * b)
        else:
            stack.append(a // b)
    if len(stack) != 1:
        raise ValueError("運算式不完整")
    return stack[0]

tokens=[8,3,-]，為什麼不能用第一次 pop 的值減第二次？

看推理

第一次 pop 得到右運算元 3，第二次得到左運算元 8。反過來算會得到 −5，原運算式的答案是 5。

下一個更大的值，一次解決一批等待

在 [2,1,2,4,3] 中，逐一找每個位置右側第一個嚴格較大值。堆疊放尚未解決的索引；4 到來時，可以依序解決等待中的 2 與 2，因為中間都沒有更早的較大值。

下一個較大值

每一步維持的關係

等待堆疊對應數值由底到頂非遞增，每個索引各進出一次。

O(n) 時間、O(n) 空間；答案為右側第一個較大值的索引。

堆疊對應的數值由底到頂非遞增。新值大於頂端時就彈出並填答案，直到頂端至少一樣大，再放入新索引。相等時留著等待，符合「嚴格較大」的條件。

每個索引最多入堆疊、出堆疊各一次，總時間 O(n)、空間 O(n)。Python 答案保存較大值的索引，找不到用 −1；互動中以 — 顯示。若題目問等待天數，再用答案索引減目前索引。

def next_greater_indices(values):
    answer = [-1] * len(values)
    stack = []  # 未找到右側「嚴格較大」值的索引。
    for i, value in enumerate(values):
        while stack and values[stack[-1]] < value:
            answer[stack.pop()] = i
        stack.append(i)
    return answer

另一組 [18, 15, 15, 20, 17] 保留兩個相等的 15，等 20 到來一起解決。

0／18無[0]無
1／15無[0, 1]無
2／15無（相等不符合嚴格較大）[0, 1, 2]無
3／20依序彈出 2、1、0[3]answer[2] = 3、answer[1] = 3、answer[0] = 3
4／17無[3, 4]無

視窗最大值，把過期與落敗分開處理

固定長度 k 的視窗需要最大值。候選佇列保存索引，前端是最大者。視窗右移時，從前端移除落在視窗外的索引；新值加入時，從尾端刪掉所有不大於它的候選。

較舊又較小的值已經沒有競爭力：新值更大，而且會更晚離開視窗。兩者相等時保留較新的位置，因為它能服務後續更多視窗。

索引由前到後遞增，值由前到後嚴格遞減。每個索引各進出一次，時間 O(n)、候選空間 O(k)，輸出另計。k 要在 1 到陣列長度之間。

from collections import deque

def sliding_maximum(values, k):
    if not 1 <= k <= len(values):
        raise ValueError("k 必須介於 1 與資料長度之間")
    candidates = deque()  # 索引遞增，對應值嚴格遞減。
    answer = []
    for i, value in enumerate(values):
        while candidates and candidates[0] <= i - k:
            candidates.popleft()
        while candidates and values[candidates[-1]] <= value:
            candidates.pop()
        candidates.append(i)
        if i >= k - 1:
            answer.append(values[candidates[0]])
    return answer

以 [4,1,3,3,0,5]、k = 3 為例，分別追蹤過期與被新值淘汰的索引。

5／5無依序淘汰 4:0 與 3:3[5:5]5（取頭端）

從判斷合法，改成指出錯在哪裡

first_bracket_error 在堆疊裡保存 (括號,索引)。右括號無法與頂端配對時，回傳這個右括號的位置；整段讀完還有左括號時，回傳最早未關閉的左括號位置。

例如 ([)] 回傳 2；()[() 留下索引 2 的 [，因此回傳 2。完整配對回傳 None。狀態只多一個位置欄位，輸出就能從 True/False 變成可定位的結果。

再拿單調堆疊與單調佇列比較：前者為等待者找到第一個答案，後者維持目前視窗的最佳候選。兩者刪除資料的理由不同。

Python · first_bracket_error
def first_bracket_error(text):
    """只接受括號；回傳第一個無法配對的關閉位置，否則最早未關閉位置。"""
    partner = {")": "(", "]": "[", "}": "{"}
    stack = []
    for i, ch in enumerate(text):
        if ch in "([{":
            stack.append((ch, i))
        elif ch in partner:
            if not stack or stack[-1][0] != partner[ch]:
                return i
            stack.pop()
        else:
            raise ValueError("輸入只能包含括號")
    return stack[0][1] if stack else None

輸入 ()[( 若最後仍有兩個左括號，要回傳哪個位置？

看推理

回傳 2，也就是 [ 的位置。堆疊剩下索引 2 的 [ 與索引 3 的 (；規格要求最早未關閉的位置，所以讀堆疊底部。

被彈出的資料，為什麼不用再看

括號堆疊彈出已配對的開啟事件；單調堆疊彈出已找到第一個答案的索引；單調佇列則彈出已過期或被更新候選壓過的索引。

用這個問題檢查程式：被刪除的資料還可能影響後面的答案嗎？若有，表示狀態保存得太少，或比較條件把相等情況處理錯了。

複雜度沿著資料生命週期計算。每項只進出各一次，while 在整段輸入中的工作總和就是 O(n)。

單調堆疊的 while 一輪可能彈出 n 個，整體為什麼仍是 O(n)？

看推理

那些索引彈出後不再回來。把所有輪次的 pop 加總，每個索引最多貢獻一次，總共最多 n 次。
