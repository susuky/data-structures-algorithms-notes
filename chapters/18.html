18 · 區間更新與有序查詢

資料三不五時就會改動，同時又一直有人來查一段區間的總和或最小值，每次重掃肯定來不及。這章把部分結果先存進樹和陣列裡，讓修改跟查詢都只走少數幾個節點。

每天都在修改的數列，怎麼快速查一段總和

六間店的今日訂單數是 [2,1,5,3,4,6]。第 2 間又收到訂單，要改成 9；同時有人一直問「第 1 到第 4 間合計多少？」把一個節點交給一段區間，父節點保存兩個孩子的總和，查詢就能一次收下一整段。

Segment Tree（線段樹）把位置範圍對半拆到單一元素。底層補到 2 的次方，補出的值放 0。修改索引 2 時，沿葉子到根重算；其餘子樹的數字都還正確。整棵樹有 O(n) 個節點，底部往上建樹只算每個父節點一次，建置 O(n)。

查詢使用半開區間 [left,right)。左端若是右孩子，左兄弟落在範圍外，就收下左端並往右一格；右端若是右孩子，退一格收下它的左兄弟。剩餘範圍再一起升一層。每層最多收兩個節點，查詢與單點修改都是 O(log n)，儲存 O(n)。

class SegmentTree:
    def __init__(self, values):
        self.n = len(values)
        self.size = 1
        while self.size < self.n:
            self.size *= 2
        self.tree = [0] * (2 * self.size)
        self.tree[self.size:self.size + self.n] = values
        for p in range(self.size - 1, 0, -1):
            self.tree[p] = self.tree[2 * p] + self.tree[2 * p + 1]

    def assign(self, index, value):
        if not 0 <= index < self.n:
            raise IndexError(index)
        p = self.size + index
        self.tree[p] = value
        while p > 1:
            p //= 2
            self.tree[p] = self.tree[2 * p] + self.tree[2 * p + 1]

    def sum(self, left, right):
        if not 0 <= left <= right <= self.n:
            raise IndexError((left, right))
        left += self.size
        right += self.size
        answer = 0
        while left < right:
            if left & 1:
                answer += self.tree[left]
                left += 1
            if right & 1:
                right -= 1
                answer += self.tree[right]
            left //= 2
            right //= 2
        return answer

要查最小值時，把合併改成 min，空區塊的單位元素換成 ∞；最大值用 max 與 −∞。合併要有結合律。若保存字串拼接等有順序的結果，查詢分成左累積與右累積，右側新區塊放到右累積的前面，再依順序合併。

遇到「整段加值、整段查總和」，可以在完整命中的節點保存 lazy 增量，該節點總和增加「區間長度 × 增量」；下探孩子時再推送。判斷是否需要 lazy，要看更新是否每次跨很多葉子。

答案分別是 0 與 −2。空區間左右邊界相同，while left < right 一開始就結束，保留加總的單位元素 0。

清掉最低位的 1，就走到下一塊前綴

商品庫存一直增減，查詢只需要「前幾項合計」。Binary Indexed Tree，也叫 Fenwick Tree，把幾段大小為 2 的次方的區塊藏進一個陣列，靠索引位元找下一站。

內部第 i 格涵蓋原數列 [i−lowbit(i),i)，其中 lowbit(i)=i & −i。索引 6 的二進位是 110，最低位的 1 代表 2，所以 BIT[6] 保存 [4,6)。讀前 7 項時，索引走 7→6→4→0，收下長度 1、2、4 的三塊。

增加原索引 2 的值時，從內部索引 3 開始，路徑是 3→4→8。每次加 lowbit，跳到下一個包含這個位置的大區塊。查詢則每次減 lowbit；兩種操作都只需 O(log n)。下列建樹把每格累積值送到父區塊，整體 O(n)，儲存 n+1 格。

class Fenwick:
    def __init__(self, values):
        self.n = len(values)
        self.bit = [0] + list(values)
        for i in range(1, self.n + 1):
            parent = i + (i & -i)
            if parent <= self.n:
                self.bit[parent] += self.bit[i]

    def add(self, index, delta):
        if not 0 <= index < self.n:
            raise IndexError(index)
        i = index + 1
        while i <= self.n:
            self.bit[i] += delta
            i += i & -i

    def prefix(self, end):
        if not 0 <= end <= self.n:
            raise IndexError(end)
        answer = 0
        while end:
            answer += self.bit[end]
            end -= end & -end
        return answer

    def sum(self, left, right):
        if not 0 <= left <= right <= self.n:
            raise IndexError((left, right))
        return self.prefix(right) - self.prefix(left)

從兩個前綴相減能得到任意區間的和，也能處理次數。一般區間最小值需要另一種合併方式，這時可直接用上一節的 Segment Tree。若值域巨大、實際只有少數值，先把值排序成名次，再用 Fenwick 保存各名次的出現次數。

BIT[12] 涵蓋哪一段原數列？prefix(13) 會讀哪些內部索引？

看推理

12 的二進位是 1100，lowbit 為 4，因此涵蓋 [8,12)。prefix(13) 走 13→12→8→0，三塊長度分別是 1、4、8。

預約時間一直插入，還要立即找下一個時段

已預約 10、20、30、40 分，你想找第一個不早於 21 分的時段，答案是 30。Ordered Set（有序集合）讓每個鍵只出現一次，並支援按大小找前後鄰居。資料持續增刪時，用平衡搜尋樹維持這個順序。

lower_bound(x) 從根出發。眼前的鍵至少為 x，就先存成候選，再往左找更小的；眼前的鍵小於 x，就往右。每走一步，都排除一整棵不會改善答案的子樹。插入相同鍵時保留原節點；刪除缺席的鍵時集合維持原樣。

普通 BST 的成本是樹高 h。AVL 每個節點保存高度，要求左右高度差至多 1。這個局部條件使高度保持 O(log n)：高度每多兩層，最少節點數至少翻倍。插入、刪除與 lower_bound 因而都有 O(log n) 最壞時間，整棵樹 O(n) 空間。

插入完成後，沿回程更新高度。偏左且左孩子偏右時先左旋孩子，再右旋根；其他方向對稱。刪除兩個孩子都在的節點時，以右子樹最小鍵補位，再刪掉那個後繼節點。高度變動可能一路傳到根，回程的每層都檢查平衡。

class OrderedSet:
    def __init__(self):
        self.root = None

    def add(self, key):
        def insert(node):
            if node is None:
                return AVLNode(key)
            if key < node.key:
                node.left = insert(node.left)
            elif key > node.key:
                node.right = insert(node.right)
            return balance(node)
        self.root = insert(self.root)

    def discard(self, key):
        def remove(node, value):
            if node is None:
                return None
            if value < node.key:
                node.left = remove(node.left, value)
            elif value > node.key:
                node.right = remove(node.right, value)
            elif node.left is None:
                return node.right
            elif node.right is None:
                return node.left
            else:
                successor = node.right
                while successor.left:
                    successor = successor.left
                node.key = successor.key
                node.right = remove(node.right, successor.key)
            return balance(node)
        self.root = remove(self.root, key)

    def lower_bound(self, key):
        node, answer = self.root, None
        while node:
            if node.key >= key:
                answer, node = node.key, node.left
            else:
                node = node.right
        return answer

    def values(self):
        def walk(node):
            if node:
                yield from walk(node.left)
                yield node.key
                yield from walk(node.right)
        return list(walk(self.root))

class AVLNode:
    def __init__(self, key):
        self.key = key
        self.left = self.right = None
        self.height = 1

def height(node):
    return node.height if node else 0

def refresh(node):
    node.height = 1 + max(height(node.left), height(node.right))
    return node

def rotate_right(top):
    root = top.left
    top.left = root.right
    root.right = refresh(top)
    return refresh(root)

def rotate_left(top):
    root = top.right
    top.right = root.left
    root.left = refresh(top)
    return refresh(root)

def balance(node):
    refresh(node)
    if height(node.left) - height(node.right) > 1:
        if height(node.left.left) < height(node.left.right):
            node.left = rotate_left(node.left)
        return rotate_right(node)
    if height(node.right) - height(node.left) > 1:
        if height(node.right.right) < height(node.right.left):
            node.right = rotate_right(node.right)
        return rotate_left(node)
    return node

數值到十億，陣列只需要保存它們的名次

依序看到 [1000000000,2,−1000000000,2]，每次都問「前面有幾個值比這次小？」這題只在乎誰大誰小，不在乎數字本身隔多遠。把不同值排序後編成 0、1、2，就能用三格 Fenwick 累積次數。

座標壓縮先收齊可能出現的鍵，排序去重建立 rank。每個值到來時，查 rank 左邊的前綴，再增加自己的次數。這裡需要嚴格小於，因此查 prefix(rank)；相等的值同名次，留在查詢範圍外。若題目問小於等於，查 prefix(rank+1)。

def compressed_counts(values):
    coordinates = sorted(set(values))
    rank = {value: i for i, value in enumerate(coordinates)}
    counts = Fenwick([0] * len(coordinates))
    answer = []
    for value in values:
        i = rank[value]
        answer.append(counts.prefix(i))
        counts.add(i, 1)
    return answer

排序 O(n log n)，每次查詢與加入 O(log m)，m 是不同值的數量；總時間 O(n log n)，額外空間 O(n)。需要任意新鍵隨時抵達時，上一節的平衡樹可直接接受新鍵；鍵集合預先已知時，壓縮後的陣列實作更直接。

排名保留大小關係。遇到「覆蓋長度」之類需要距離的問題，要保留原座標，段長使用 coordinates[i+1]−coordinates[i]，再交給樹維護；名次相差 1 的兩段，實際距離可能差很多。

把問題換成「前面有幾個值大於這次」，若目前已看過 seen 個值，查詢怎麼改？
