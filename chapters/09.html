09 · 把答案留在越縮越小的範圍裡

二分搜尋每次排除一半候選。這章從重複值的邊界開始，再把同一套推理用到運送容量這類看不見的答案空間。

找到 target 前後的兩道分界

排序陣列 [1,3,3,3,7] 中，第一個 ≥3 的位置是 1，第一個 >3 的位置是 4。這兩道邊界包住所有等於 3 的元素，個數為 4−1=3。

lower_bound 找第一個不小於 target，upper_bound 找第一個大於 target。全體都太小時回傳 n，空陣列回傳 0；回傳的是插入位置。

由兩個基本邊界可得到最後一個 < target 的位置 lower_bound−1，以及最後一個 ≤target 的位置 upper_bound−1。讀元素之前，再確認回傳索引是否落在 0…n−1。

[1,3,3,7] 搜尋 target=4，lower_bound 與 upper_bound 各為多少？

看推理

兩者都是 3，因為索引 3 的 7 同時是第一個 ≥4 與第一個 >4 的元素。

原始文件與題目：LeetCode 35 · Search Insert Position LeetCode 34 · Find First and Last Position of Element in Sorted Array

一半確定太小，一半確定夠大

用半開區間 [lo,hi) 保存尚未檢查的索引。lo 左邊都小於 target，hi 右邊與 hi 都不小於 target。當 lo=hi，這個分界就是答案。

第一個不小於 target

每一步維持的關係

lo 左側小於 target；hi 右側與 hi 都不小於 target。

O(log n) 時間、O(1) 額外空間。

檢查 mid 時，若 values[mid]<target，連 mid 在內的左半都太小，令 lo=mid+1；否則 mid 可能就是第一個符合者，令 hi=mid。每一步保留分界的可能位置。

互動中 hi 可以等於 n，代表陣列尾端的邊界。區間寬度每輪縮小約一半，時間 O(log n)、額外空間 O(1)。

def lower_bound(values, target):
    lo, hi = 0, len(values)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if values[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

values[mid] 剛好等於 target，為什麼還要往左縮？

看推理

左邊可能還有相同值。lower_bound 要找第一次出現的位置，將 hi 設為 mid 能保留它，並繼續檢查更左的候選。

只改一個比較，答案就換成右邊界

upper_bound 將條件改為 values[mid]≤target 時往右。相等的元素也歸入左側，最後留下第一個嚴格較大位置。

同一份 [1,3,3,3,7,9]，target=3：lower_bound 的相等分支往左保留，得到 1；upper_bound 的相等分支往右排除，得到 4。

記住分區含義，比記四套模板直接。先寫左側要滿足 < 還是 ≤，分支就跟著確定。

def upper_bound(values, target):
    lo, hi = 0, len(values)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if values[mid] <= target:
            lo = mid + 1
        else:
            hi = mid
    return lo

用 bisect 查位置，插入成本另算

Python bisect_left 對應 lower_bound，bisect_right 對應 upper_bound。它們回傳維持排序的插入點，不修改陣列。

insort 會先二分找到位置，再做 list.insert。搜尋 O(log n)，搬移後方元素 O(n)，所以整個插入仍是 O(n)。連續大量插入時，要按照資料更新方式評估容器。

若使用 key，排序鍵作用於陣列項目，搜尋參數 x 依文件規格提供為相同鍵域的值。大量重複查詢昂貴的鍵時，可預先建立鍵陣列。

from bisect import bisect_left, bisect_right

values = [2, 4, 4, 4, 9]
left = bisect_left(values, 4)   # 1
right = bisect_right(values, 4) # 4
count = right - left           # 3
exists = left < len(values) and values[left] == 4

# 計算數值落在 [a, b) 的元素個數，要求 a <= b。
a, b = 4, 9
inside = bisect_left(values, b) - bisect_left(values, a)  # 3

搜尋 False 變成 True 的第一點

把問題改寫成判斷函式 predicate(x)：x 太小時 False，足夠大時 True。只要結果沿答案空間呈現一段 False 接一段 True，就能二分找第一個 True。

first_true(n,predicate) 在整數位置 [0,n) 搜尋。predicate(mid) 為 True 就令 hi=mid，False 就令 lo=mid+1；全 False 時回傳 n。

若一次 predicate 花 C，整體成本是 O(C log n)。真正的工作通常在設計可行性判斷器，並證明增大候選值後可行性不會倒退。

def first_true(n, predicate):
    """predicate 在 [0, n) 先 False 後 True；全 False 回傳 n。"""
    if n < 0:
        raise ValueError("搜尋範圍長度不可為負")
    lo, hi = 0, n
    while lo < hi:
        mid = (lo + hi) // 2
        if predicate(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

predicate 結果為 F,F,T,T,T，first_true 回傳多少？

看推理

2。若結果為 F,F,F，回傳範圍尾端 3；這個位置表示範圍內沒有 True。

每天容量多少，才能準時送完

包裹要依原順序運送，每天裝入一段，最多使用 days 天。容量至少是最重包裹，至多是全部重量總和；在這個整數區間找最低可行容量。

判斷某個容量 C 時，依序把包裹放進當天，放不下就換下一天。越早結束裝載只會把更多包裹留給後面，所以每一天裝到再放一件就超過 C，能用最少天數完成這次判斷。

容量增加後，原本可行的裝載方式仍可使用，因此結果具有單調性。一次判斷 O(n)，總時間 O(n log(S+1))，S 為搜尋範圍寬度，額外空間 O(1)。空包裹回傳 0，重量與 days 都採正整數。

def minimum_capacity(weights, days):
    """依序運送正整數重量；每天裝入一段，可使用少於 days 天。"""
    if days <= 0:
        raise ValueError("天數必須為正整數")
    if any(weight <= 0 for weight in weights):
        raise ValueError("重量必須為正整數")
    if not weights:
        return 0

    def feasible(capacity):
        used_days, load = 1, 0
        for weight in weights:
            if load + weight > capacity:
                used_days += 1
                if used_days > days:
                    return False
                load = 0
            load += weight
        return used_days <= days

    lo, hi = max(weights), sum(weights)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if feasible(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

為什麼答案下界是 max(weights)，不是 0？

看推理

每個包裹要完整裝入某一天，容量至少要容得下最重的那一件。

分界是否存在，直接拿例子檢查

二分需要一段連續的可行區域。像「x 是否為質數」會在 True 與 False 之間反覆變化，沒有單一分界；「容量 x 是否足夠」則隨容量增加保持可行。

每一輪必須縮小範圍。使用 lo=mid+1 與 hi=mid 的半開模板時，lo<hi 保證 mid 是可讀索引，更新後寬度至少少一。

浮點答案可依誤差或固定迭代次數停止；整數答案則利用離散邊界收斂。選定一種區間約定，讓初始化、分支與停止條件一致。

lo=0、hi=1，若 False 分支寫成 lo=mid，會怎樣？

看推理

mid=0，lo 仍是 0，範圍完全沒變。正確更新 lo=mid+1 才會縮到邊界 1。

從完成時間推回可行性

有多台車，各自每完成一趟需 t[i] 時間。問完成 totalTrips 趟的最短時間 T，可行性就是 sum(T//t[i])≥totalTrips。

T 增加時，每台車完成的趟數都不減，所以可二分第一個可行時間。上界可取最快車獨自完成全部趟數的時間，下界依正整數時間從 0 或 1 開始。

一次判斷掃 m 台車，成本 O(m)。累計趟數已達目標就可提前結束該次判斷。

t=[2,3]、totalTrips=5，T=6 與 T=5 各完成幾趟？

看推理

T=6 完成 6//2+6//3=3+2=5 趟；T=5 完成 2+1=3 趟，因此最短時間為 6。

原始文件與題目：LeetCode 2187 · Minimum Time to Complete Trips

答案分界、候選範圍、判斷成本

寫二分前，說出要找第一個 True、第一個 ≥target，或第一個 >target。接著給出搜尋範圍與每次分支後仍成立的左右條件。

對空範圍、全 False、全 True、重複值與答案落在尾端各走一次。這些例子能直接檢查回傳值與越界處理。

總複雜度是判斷成本乘上搜尋輪數。答案二分常見的 O(n log S)，n 來自每次掃資料，log S 來自容量或時間範圍。

first_true 回傳 n 時，要不要直接讀 values[n]？

看推理

n 是尾端分界，表示範圍內沒有符合項目。先依這個結果處理無解或插入尾端，再決定是否讀取陣列元素。
