09　二分搜尋：找一個永遠不會被丟掉的邊界

在許多人的第一印象中，二分搜尋（Binary Search）似乎只是「在排序陣列裡找某個數字在哪裡」的基礎技巧。然而在實戰工程與進階演算法中，二分搜尋真正的強大之處在於：在具備單調性（Monotonicity）的空間中，以對數級時間精確鎖定 True 與 False 的交界點。每一次觀察中點，我們都能藉由單調性質一口氣捨棄掉整整一半不可能包含答案的候選區間。寫二分搜尋最常見的挫折，莫過於在 lo < hi 還是 lo <= hi、mid + 1 還是 mid 之間迷失方向，最終陷入無窮迴圈或陣列越界。要徹底擺脫「隨機試錯憑運氣」的寫法，唯一的法門就是在動筆前先說清楚：lo 與 hi 分別代表什麼語意？未知的探查區間是什麼？迴圈的不變量又是如何被嚴格維持的？

本章設計慣例：針對陣列索引的搜尋，本章統一採用邏輯最為嚴謹、不容易出錯的「半開區間 $[lo, hi)$」模型；而在數值答案空間的連續整數搜尋中，則採用「閉區間 $[lo, hi]$」模板。這兩套寫法在數學上皆完全正確，但其初始化邊界、中點計算、端點更新與停止條件必須成套搭配，切忌東拼西湊。

1. 把找值改成找邊界

插入位置：LeetCode 35 · Search Insert Position；重複值範圍：LeetCode 34 · Find First and Last Position of Element in Sorted Array。本節 lower_bound 支援空陣列與重複值。第 34 題的含尾範圍由 [lower,upper−1] 得到，無命中時回傳 [-1,-1]。

假設給定一個已排序陣列 [2, 4, 4, 4, 9]，要在其中尋找數值 4。傳統的寫法只要撞見任何一個 4 就興奮地回傳其索引；但如果題目進一步追問：「4 出現的第一個位置在哪裡？」、「4 的最後一個位置在哪裡？」或是「4 總共重複了幾次？」，隨機命中任一個 4 的傳統寫法便顯得無能為力。更具普適性的思考方式，是將「找特定數值」昇華為「找劃分邊界」：

  • lower_bound(x)：尋找第一個數值 $\ge x$ 的元素索引。換句話說，它把陣列精確切分成兩半：左邊所有元素都嚴格小於 $x$，右邊所有元素（包含自己）都大於等於 $x$。若所有元素都小於 $x$，則回傳陣列長度 $n$。
  • upper_bound(x)：尋找第一個數值 $> x$ 的元素索引。左邊所有元素皆 $\le x$，右邊所有元素皆 $> x$。

請特別留意：回傳的切分點 $q$ 是一個「插入位置邊界」，它的合法數值範圍是 $[0, n]$。當 $q = n$ 時，代表陣列中根本沒有任何元素 $\ge x$；此時直接拿 $q$ 去存取 values[q] 會立刻觸發 IndexError。因此，要判定目標值是否存在，必須嚴格先檢查範圍：q < len(values) 且 values[q] == target，這兩者順序絕對不能顛倒。

2. 半開模板：未知的是索引，答案是分界

在半開區間 $[lo, hi)$ 的設計中，我們將區間初始化為 lo = 0、hi = len(values)。整個演算法運作期間，始終嚴格維持以下迴圈不變量：

  • 數值界限：$0 \le lo \le hi \le n$ 永遠成立。
  • 左側已知區：所有索引 $i < lo$ 的元素，皆已確定滿足 values[i] < target。
  • 右側已知區：所有索引 $i \ge hi$ 的合法元素，皆已確定滿足 values[i] ≥ target。
  • 中間未知區：當前尚待探查的索引區間恰好是半開區間 [lo, hi)，而真正的分界點必落在閉區間 [lo, hi] 之中。
def lower_bound(values, target):
    lo, hi = 0, len(values)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if values[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

讓我們仔細體會端點更新的微觀邏輯：當 values[mid] < target 時，根據排序單調性，mid 以及它左邊的所有元素都不可能成為「第一個 $\ge target$」的位置，因此將 lo 推進至 mid + 1；反之，若 values[mid] ≥ target，則 mid 本身極有可能就是我們要找的第一個滿足條件者，絕對不能將它隨意排除！因此我們將上界收斂為 hi = mid，讓 mid 納入右側已知合格區。每次迴圈執行後，待探查長度 hi - lo 都必然嚴格縮小。當 lo == hi 時，未知區間長度收縮為 0，此時 lo（亦即 hi）正好就是兩大區域唯一的黃金交界點！

常見寫法混用的致命傷：在半開區間框架下，如果隨意改寫成 while lo <= hi，在找不到數值時可能會導致 mid == n 進而存取越界；若在 values[mid] < target 後寫 lo = mid，在長度為 1 或 2 時會導致區間長度永遠無法縮短，直接陷入無窮迴圈；若在 else 後隨便寫 hi = mid - 1，則會粗暴地把真正的答案直接抹殺。千萬不要靠運氣增減 1，一切以不變量為準繩。

3. 逐步範例：同一份資料找兩個邊界

給定陣列 values = [2, 4, 4, 4, 9]，目標 target = 4。我們分別追蹤 lower_bound 與 upper_bound 的每一步收斂過程：

搜尋lohimid / 值更新
lower052 / 4hi=2
lower021 / 4hi=1
lower010 / 2lo=1，停止
upper052 / 4lo=3
upper354 / 9hi=4
upper343 / 4lo=4，停止

追蹤結束後，我們得到 lower = 1，upper = 4。這代表所有等於 4 的元素精準座落在半開索引區間 $[1, 4)$ 之中！其出現總次數為 $4 - 1 = 3$ 次，最後一次出現的索引則為 upper - 1 = 3。若 lower == upper，則代表目標數值在陣列中完全不存在；此時切勿直接存取 upper - 1，必須先驗證命中性。

def upper_bound(values, target):
    lo, hi = 0, len(values)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if values[mid] <= target:
            lo = mid + 1
        else:
            hi = mid
    return lo

複雜度分析：在支援 $O(1)$ 隨機存取的陣列（如 Python list）中，每次折半只需常數次比較，總時間複雜度為對數級的 $O(\log n)$，額外空間為極致的 $O(1)$。但如果面對的是單向鏈結串列，因為移動到中點需花費線性時間，二分搜尋的時間複雜度會退化為 $O(n)$，完全失去優勢。另外請注意：如果面對未排序陣列，為了單次查詢而先呼叫排序（耗時 $O(n \log n)$）往往得不償失，直接進行一次 $O(n)$ 的線性掃描才是明智之舉。

4. Python 實務：用 bisect 查詢排序資料

在日常生產開發中，除非面試有特殊要求，否則應優先採用 Python 內建且經過 C 語言極致優化的 bisect 模組。bisect_left 即為 lower_bound，而 bisect_right 即為 upper_bound：

from bisect import bisect_left, bisect_right

values = [2, 4, 4, 4, 9]
left = bisect_left(values, 4)   # 1
right = bisect_right(values, 4) # 4
count = right - left           # 3
exists = left < len(values) and values[left] == 4

# 計算數值落在 [a, b) 的元素個數，要求 a <= b。
a, b = 4, 9
inside = bisect_left(values, b) - bisect_left(values, a)  # 3
由邊界得到四種查詢位置
要找的值候選索引候選存在條件
第一個 ≥ xlower_bound(values, x)索引 < n
第一個 > xupper_bound(values, x)索引 < n
最後一個 < xlower_bound(values, x) − 1索引 ≥ 0
最後一個 ≤ xupper_bound(values, x) − 1索引 ≥ 0

從 Python 3.10 開始，bisect 家族函式全面支援 key 參數，這讓我們可以直接對結構化字典或元組資料進行二分搜尋，而不需要手動抽取清單。前提是原始資料本身必須已經依照該 key 函式的標準排序完畢：

records = [("Ada", 70), ("Lin", 85), ("Wei", 85), ("Yu", 92)]
position = bisect_left(records, 85, key=lambda row: row[1])
assert position == 1
assert records[position] == ("Lin", 85)

需要特別提醒的是：標準庫的 bisect.insort 雖然能在 $O(\log n)$ 內找到插入點，但隨後的陣列元素後移在底層依然需要 $O(n)$ 時間；頻繁呼叫 insort 維護大清單的總成本高達 $O(n^2)$。此外，切勿在二分搜尋迴圈中使用切片語法 values[:mid]，這會在每次折半時進行記憶體淺拷貝，直接將空間複雜度炸成 $O(n)$。在數值計算上，雖然 Python 整數具備任意精度不會發生 32-bit 整數溢位，但養成使用 lo + (hi - lo) // 2 的好習慣，能讓你的程式邏輯無縫跨語言移植。

5. 用 first_true 搜尋單調判斷的分界

LeetCode 278 · First Bad Version 搜尋版本 1…n 的第一個錯誤版本。本節 first_true 搜尋 [0,n)，全 False 時回傳 n。

二分搜尋的精髓遠不限於查詢靜態陣列！設想一個抽象函式 predicate(i)，它在索引區間 $[0, n)$ 上呈現單調性：前段全為 False，從某一處開始後段全變為 True（例如：系統負載在某一臨界值之後開始逾時、產品版本從某一版開始引入 Bug）。我們完全不需要把這些布林值預先計算並儲存成一個巨型陣列，直接在虛擬索引空間上呼叫判定函式進行二分即可：

def first_true(n, predicate):
    """predicate 在 [0, n) 先 False 後 True；全 False 回傳 n。"""
    if n < 0:
        raise ValueError("搜尋範圍長度不可為負")
    lo, hi = 0, n
    while lo < hi:
        mid = (lo + hi) // 2
        if predicate(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

這段邏輯的不變量十分明確：任何時候，我們都確信真正的第一個 True 必存在於 $[lo, hi]$ 之間。使用此模板的唯一前提是：predicate 函式必須在定義域內保持嚴格的單調性。如果判定結果呈現交替震盪（如 False, True, False, True），二分搜尋將直接失去方向感。若面對的是「先 True 後 False」並想找最後一個 True，只需將目標轉化為「尋找第一個 False」再將索引減 1 即可。

特別提醒複雜度分析：若單次執行 predicate(mid) 的時間成本為 T，則二分搜尋的總時間複雜度為 O(T log(n + 1))。在面試或工程評估中，千萬不要只看到二分搜尋就脫口而出 $O(\log n)$，必須嚴格將判定器內部的運算時間納入考量。

6. 答案二分：最低每日運送容量

LeetCode 1011 · Capacity To Ship Packages Within D Days。本節另定義空貨箱清單的容量為 0，並允許天數超過貨箱數量。

這是演算法設計中最優雅、威力也最龐大的模式之一——「對答案空間進行二分（Binary Search on Answer Space）」。有些最佳化問題，直接從正面推導最優配置極其困難，但如果反過來問：「假設答案是某個固定值 $C$，這套配置是否合法可行？」，判定可行性往往只需一次簡單的貪心或線性掃描！

以貨物運送為例：有一批貨箱必須按固定順序由傳送帶送達，我們必須在最多 $D$ 天內將所有貨箱全數運出。貨箱不可拆分，每天只能載運連續的一段貨物。問題是：船隻每天最低必須具備多少運載容量 $C$？

  1. 定義可行域下界：任何單一貨箱都不能被拆開，所以容量 $C$ 絕對不能小於所有貨箱中的最大重量，即 $lo = \max(weights)$。
  2. 定義可行域上界：若船隻容量一口氣大到能裝下所有貨箱總重，那麼一天之內就能運完，對任意 $D \ge 1$ 絕對足夠，故安全上界可設為 $hi = \sum weights$。
  3. 證明單調性：若每天運力 C 足以在 D 天內運完，那麼當運力提升至 C + 1 時，沿用原本的每日分組方案顯然依然安全，因此也必然可行！這保證了可行性答案空間呈現「前段 False、後段 True」的完美單調階梯。
  4. 設計線性判定器：對於任意給定的容量 $C$，我們只需使用貪心法由左至右裝箱——只要當天還能塞下下一箱就繼續塞，直到超重才被迫換天。

為什麼貪心裝箱判定是正確的？設想在固定容量 $C$ 下，貪心策略每一天都盡可能塞入最多數量的貨物。顯然，任何其他可行的合法調度方案，其第一天所運送的貨物量都不可能超越貪心策略。透過歸納法可知：貪心策略在第 $d$ 天結束時所覆蓋的貨箱進度，永遠不會落後於任何其他排程方式。因此，貪心裝箱所耗費的總天數必然是所有可行分組中的理論最小值，若連貪心裝箱都超時，該容量就必定宣告不可行。

def minimum_capacity(weights, days):
    """依序運送正整數重量；每天裝入一段，可使用少於 days 天。"""
    if days <= 0:
        raise ValueError("天數必須為正整數")
    if any(weight <= 0 for weight in weights):
        raise ValueError("重量必須為正整數")
    if not weights:
        return 0

    def feasible(capacity):
        used_days, load = 1, 0
        for weight in weights:
            if load + weight > capacity:
                used_days += 1
                if used_days > days:
                    return False
                load = 0
            load += weight
        return used_days <= days

    lo, hi = max(weights), sum(weights)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if feasible(mid):
            hi = mid
        else:
            lo = mid + 1
    return lo

在數值答案空間中，我們維持閉區間 $[lo, hi]$：最優解永遠被鎖定在區間內，且 hi 始終代表一個已知的可行安全值。當中點 mid 可行時，它有可能是最終最佳解，因此令 hi = mid 收縮右界；當 mid 不可行時，代表它以及所有更小的容量全數陣亡，因此果斷令 lo = mid + 1。當 lo == hi 時，迴圈終止，該點即為理論上的最小可行容量。

7. 逐步範例：用判斷器縮小整數答案

給定貨箱 weights = [3, 2, 4, 1, 3]，限制天數 days = 3。初始邊界 $lo = 4$，$hi = 13$：

lohimid按順序分組結果與更新
4138[3,2]｜[4,1,3]2 天，可行，hi=8
486[3,2]｜[4,1]｜[3]3 天，可行，hi=6
465[3,2]｜[4,1]｜[3]3 天，可行，hi=5
454[3]｜[2]｜[4]｜[1,3]4 天，不可行，lo=5

演算法最終收斂至 lo = hi = 5。請特別注意最後一步的關鍵意義：光是驗證容量 5 可行還不夠，唯有同時證明容量 4 確實不可行，5 才能被嚴格奉為全域最小值。若天數寬限為極端值（如 $D=1$），答案自然為總和 13；若 $D \ge 5$，每天載運一箱即可，答案就是最大單箱重 4。

效能分析：設貨箱總數為 $n$，單箱最大重為 $L$，總重為 $U$。每次判定耗時 $O(n)$，二分搜尋的次數取決於答案空間寬度 $\log(U - L + 1)$，整體時間複雜度為 $O(n \log(U - L + 1))$，空間複雜度為極其精簡的 $O(1)$。這種時間隨數值範圍對數增長的特質，使得即便資料總量或重量高達數十億，二分搜尋也能在數十微秒內瞬間完成！

8. 何時不要急著二分

二分搜尋固然強大，但在動手實作前，必須警惕以下常見的失效陷阱：

  • 單調性不成立：如果在某個參數下系統可行，調大或調小後卻忽好忽壞，代表問題背後並不具備單調結構。請記住：單調性必須從問題的物理或數學約束中推導出來，切勿單憑幾組局部測試數據就一廂情願地假設。
  • 邊界設定不安全：上界 hi 必須在數學上百分之百保證「一定可行」，若隨意設定一個不夠大的魔術數字，可能導致最優解直接被遺漏在搜尋範圍之外。
  • 問題約束從「至多」變為「恰好」：若題目要求天數必須「恰好為 D 天」且禁止空車，原本「容量越大越容易成功」的單調性可能會被完全打破，此時問題往往會昇華為動態規劃或 NP-Complete 分割問題。
  • 浮點數精度陷阱：面對連續實數空間的二分搜尋，不存在 mid + 1 的整數跳躍，端點更新應為 lo = mid 與 hi = mid，且終止條件必須改為誤差門檻（如 hi - lo > 1e-7）或固定執行 60~100 次折半。
  • 旋轉排序陣列（Rotated Sorted Array）：陣列被局部分割成兩段遞增區間。此時每次折半必須先判斷哪一側是嚴格單調區間；若陣列中包含大量重複元素，最壞情況下將退化為 $O(n)$ 線性掃描。

9. 練習：把停止條件寫進答案

練習一：重複值與空範圍

給定已排序陣列 [1, 1, 3, 5, 5]，請手算推導當 target 分別為 1、2、5、8 時，lower_bound 與 upper_bound 的回傳索引，並計算其出現次數。

參考解答

針對 1：lower=0, upper=2，出現 $2 - 0 = 2$ 次；針對 2：lower=2, upper=2，出現 $2 - 2 = 0$ 次；針對 5：lower=3, upper=5，出現 $5 - 3 = 2$ 次；針對 8：lower=5, upper=5，出現 $5 - 5 = 0$ 次。請注意：回傳值為長度 5 是合法的邊界哨兵，代表「所有元素皆小於目標」，切勿嘗試以 5 作為索引存取陣列。

練習二：第一個 True 不存在

若搜尋長度 $n=6$，且判定器 predicate 對所有索引皆恆為 False。請追蹤 first_true 的執行步驟，並確認它是否會存取到非法索引 6。

參考解答

初始區間為 (0, 6)。第一輪中點 mid=3，判定為 False，更新 lo=4；第二輪區間 (4, 6)，中點 mid=5，判定為 False，更新 lo=6。此時 lo==hi==6，迴圈終止並回傳 6。整個過程中判定器僅探查了合法索引 3 與 5，完全沒有存取索引 6。這證明了半開區間將 $n$ 作為安全哨兵的卓越自洽性。

練習三：找最小生產時間

LeetCode 2187 · Minimum Time to Complete Trips 用巴士趟數表示產出；本題以機器製品表示，每台獨立連續工作。

有兩台獨立機台，各自生產一件產品分別需要 3 與 5 單位時間，從時間 0 開始並行生產。若我們需要累積至少 7 件產品，所需的最小整數時間是多少？請寫出單調判定式與安全上界。

參考解答

單調判定式為：在時間 $t$ 內兩台機台累積的產出總量 $f(t) = (t // 3) + (t // 5) \ge 7$。因為 $f(t)$ 隨時間單調不減，此題可對時間二分。安全下界為 0，安全上界可假設只靠最快的機台獨自生產，即 $3 \times 7 = 21$。手算驗證：$t=14$ 時產出為 $4 + 2 = 6$（不足）；$t=15$ 時產出為 $5 + 3 = 8 \ge 7$（達標）。因此最小整數時間為 15。請注意條件必須寫「至少 7 件」，因為產出可能直接跳過 7 變成 8，寫等號會永遠找不到解答。

練習四：診斷無窮迴圈

在閉區間 [4, 5] 中尋找第一個滿足條件的答案 5。若中點公式採用 mid = (lo + hi) // 2，且在 mid 判定不可行後寫下 lo = mid。請問程式會發生什麼問題？

參考解答

在 $lo=4, hi=5$ 時，整數除法算出 $mid = 4$。若判定 4 不可行後執行 lo = mid，則 lo 依然被設為 4，區間維持 $[4, 5]$ 完全沒有縮小，下一輪依然算出 $mid = 4$，直接墜入無窮迴圈！正確做法：既然已經明確證明 4 是不可行的無效解，就必須大膽寫下 lo = mid + 1 將其排除，促使搜尋範圍嚴格收縮至 $[5, 5]$。

10. 章末決策卡

當你著手設計二分搜尋時，請依序完成以下檢查清單：先辨明「尋找的是具體元素還是邊界分割點」→ 明確列出邊界左右兩側各自滿足的嚴格定義 → 證明判定函式是否具備絕對的單調性 → 決定採用半開區間 $[lo, hi)$ 還是閉區間 $[lo, hi]$ 並維持整套不變量 → 驗證每次折半是否保證區間長度嚴格縮減 → 審慎處理回傳哨兵的邊界語意。如果是答案二分，務必評估單次判定器的時間複雜度是否划算！
