04｜鏈結串列：讓指標維持正確的關係

陣列依靠連續記憶體位址進行快速隨機存取，而鏈結串列（Linked List）則是透過一條條指標「誰指向下一個節點」動態串聯而成。在操作鏈結串列時，工程師最容易犯的錯誤就是指標斷鏈或記憶體迷航；因此在動手修改任何 next 指標之前，心中一定要隨時清楚三件事：哪些節點已經處理完畢？哪些節點尚待處理？以及通往尚未處理區域的入口參照有沒有被妥善保存？本章將透過反轉、刪除、合併與快慢指標等經典場景，帶領大家建立起精確維護指標關係的直覺不變量。

前置約定：除環偵測一節外，本章所有輸入皆保證為有限長度且無環的單向鏈結串列；head 可以為 None（代表空串列）。反轉、刪除與合併操作皆要求原地重接節點參照。以 n 表示節點總數，節點值的比較視為 O(1)。

1. 節點、參照與操作成本

在單向鏈結串列中，每個節點實體包含兩個欄位：存放資料的 value，以及通向下一個節點的指標 next。head 變數只是指向串列第一個節點的普通參照，當 head 為 None 時代表整個串列為空。請牢記：記憶體中兩個不同的節點物件，哪怕它們的 value 剛好裝著一模一樣的值，在實體身分上依然是完全獨立的個體。因此，在判斷「指標是否走到了同一個節點」或「串列是否有環」時，必須嚴格使用 is 運算子比對物件記憶體身分，而不能草率地使用 == 比較數值。在 Python 中，變數賦值通常只是複製物件參照；當我們寫下 cur = cur.next 時，僅僅是將本地變數游標向前移動一格，完全不會在記憶體中搬移或深拷貝節點本體。

當我們已經精確持有目標節點的前驅節點（Predecessor）時，刪除操作只需要修改一次 next 指向，代價僅為 O(1)；但如果手頭上只有目標數值，就必須先花費 O(n) 的時間沿鏈尋找其前驅。此外，Python 的各個 Node 節點是由直譯器獨立分散配置在堆積記憶體（Heap）中的，沿著 next 遍歷往往會引發嚴重的快取未命中（Cache Miss）；因此在工程實踐中，若系統需要頻繁進行循序掃描或下標隨機存取，優先選用連續記憶體的 list 往往能獲得更優異的實際執行效能。

from dataclasses import dataclass
from typing import Optional

@dataclass(eq=False)
class Node:
    value: int
    next: Optional["Node"] = None

def from_values(values):
    dummy = Node(0)
    tail = dummy
    for value in values:
        tail.next = Node(value)
        tail = tail.next
    return dummy.next

def to_values(head):
    """僅用於有限、無環串列；測試工具不算進解法的額外空間。"""
    result = []
    while head is not None:
        result.append(head.value)
        head = head.next
    return result

在上面的定義中，dataclass(eq=False) 使得節點類別嚴格保留原生依賴記憶體位址的物件身分比對語意，避免 Python 自動生成會遞迴比對整條串列的 == 函式。輔助函式 from_values 與 to_values 是為了方便撰寫單元測試與觀察演算法狀態的測試工具；請特別留意：to_values 會建立長度為 n 的全新清單，絕不能拿來列印未知是否有環的惡意串列，否則會陷入無窮迴圈。

2. 反轉：保住尚未處理的入口

題意：給定無環單向鏈結串列的頭節點 head，請原地反轉所有節點的 next 指標，並回傳反轉後的新頭節點；若輸入為空串列則回傳 None。例如輸入 6 → 2 → 9，反轉後應變為 9 → 2 → 6。

LeetCode 206 · Reverse Linked List

在每次迴圈迭代開始時，指標的語意必須劃分得涇渭分明：prev 指向已經完成反轉的前半段串列，而 cur 則指向尚未處理的後半段串列。這兩條鏈此時是互不相交的獨立片段，兩者所含的節點加總剛好完整覆蓋原串列的所有節點。下一步的重接邏輯至關重要：在修改 cur.next 之前，必須先用暫存變數 following 把 cur.next 的原始位址保存下來，才能安心執行 cur.next = prev。如果沒有事先保存就貿然轉向，原串列通往剩餘節點的唯一入口就會瞬間遺失，導致後續節點全部斷鏈蒸發。

def reverse(head):
    prev, cur = None, head
    while cur is not None:
        following = cur.next
        cur.next = prev
        prev, cur = cur, following
    return prev

正確性歸納證明：初始狀態下 prev 為 None，已反轉鏈為空，不變量成立；在後續每一步中，我們將 cur 的首個節點摘下並插在 prev 前方作為新頭，同時順暢地把 cur 指向預先保存好的 following，因此不變量在每一步皆嚴格維持；當 cur 最終抵達 None 時迴圈終止，所有原始節點都已被完整納入 prev 中，且順序剛好與原本完全相反。每走一步未處理節點數必定減 1，因此有限長度的無環串列必定能在 n 步內終止。

本演算法時間複雜度為 O(n)，輔助空間僅需 O(1)。雖然反轉也可以用遞迴實現，但 Python 的直譯器需要消耗 O(n) 的呼叫堆疊空間，當面對超長串列時容易觸發 RecursionError 崩潰，因此工程上強烈推薦迭代寫法。請特別留意：函式結束時回傳的是新的頭節點，呼叫端必須寫作 head = reverse(head)；原本的 head 在反轉結束後已經退化成了最後一個尾節點。

3. 快慢指標：中點與環

LeetCode 876 · Middle of the Linked List：本節沿用偶數長度取第二個中點的規則，並接受空串列。

在單向鏈結串列中，由於無法直接用長度計算下標除以二，尋找中央節點通常採用快慢雙指標技巧：slow 指標每輪前進 1 步，fast 指標每輪前進 2 步；當迭代進行了 t 輪後，slow 剛好來到索引 t 的位置，而 fast 則已經狂奔了 2t 步並抵達或越過串列尾端。在迴圈條件中，必須嚴格「先確認 fast 是否為 None，再確認 fast.next 是否為 None」，確認兩者皆安全後才能合法讀取 fast.next.next。在偶數長度下（例如長度為 4，索引 0、1、2、3），以下演算法會精準回傳第二個中點（即索引 2 的節點）。

def middle_second(head):
    """偶數長度時回傳第二個中點；空串列回傳 None。"""
    slow = fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next
    return slow

環入口題意：輸入串列的頭節點 head，判斷串列中是否存在循環環路；若有環，回傳環的入口節點本身；若無環則回傳 None。全程不得修改原始串列結構。

LeetCode 142 · Linked List Cycle II：原題的 pos 是測試資料標記，函式只接收 head。

偵測環路時，絕不能只看「節點數值是否重複出現」：例如 6 → 6 → None 完全是合法的無環串列。Floyd 判圈演算法（龜兔賽跑）讓快慢指標同時從 head 出發，並恪守「先讓指標各走一步與兩步，然後再用 is 比對物件身分」的原則。若串列無環，跑得快的 fast 必然會在有限步內撞上 None 終止；若串列存在環路，當快慢指標雙雙進入環內後，fast 相對於 slow 每輪淨縮小 1 步的距離（在模環長的意義下），因此兩者必定會在至多一個環長的步數內相遇。

def cycle_entry(head):
    slow = fast = head
    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            seeker = head
            while seeker is not slow:
                seeker = seeker.next
                slow = slow.next
            return seeker
    return None

為什麼相遇後啟動 seeker 就能精準鎖定環入口？背後的數論原理非常優美：設從 head 到環入口的步數為 μ，環的長度為 L。當兩者在環內第一次相遇時，假設 slow 總共走了 t 步，那麼 fast 必定剛好走了 2t 步；因為 fast 比 slow 整整多跑了幾圈環長，所以兩者步數之差 2t − t = t 必然是環長 L 的整數倍（即 t 是 L 的倍數）。此時 slow 所在的位置，距離環入口剛好前進了 (t − μ) 步。現在，我們讓一個全新的 seeker 指標從 head 出發，同時讓 slow 留在相遇點，兩者皆以每輪 1 步的等速同步向前走。當 seeker 剛好走了 μ 步抵達環入口時，slow 累積走過的總步數剛好是 t 步；又因為 t 是 L 的整倍數，slow 在環內繞完整數圈後，此時也必定精確停在環入口！由於 seeker 在抵達入口前始終處於環外，兩者絕不可能在環外提前相遇，因此它們第一次碰撞的點必定就是環的入口節點。

找中點與環入口演算法的時間複雜度皆為 O(n)，輔助空間為極致的 O(1)。若使用 set 來記錄已走訪的節點指標雖然也能找環，但需要 O(n) 的額外空間，其唯一的優勢是程式碼直觀且易於記錄路徑細節。

4. Dummy 節點與固定間距：刪倒數第 k 個

題意：輸入無環單向串列的 head 與正整數 k，請刪除串列中倒數第 k 個節點並回傳新串列的頭節點；若串列為空或 k 超出串列長度，應拋出 ValueError，且不得破壞或修改原始串列。

LeetCode 19 · Remove Nth Node From End of List：原題用 n 表示倒數位置，本節用 k 並檢查超界。

在鏈結串列中刪除節點的本質，是「將待刪節點的前驅節點的 next，直接跨接指到待刪節點的下下個節點（prev.next = prev.next.next）」。然而，如果被刪除的剛好是整個串列的第一個節點（頭節點），它本身是沒有前驅的，這往往迫使工程師寫出大量醜陋的 if 特判。解決之道是引入一個虛擬前驅——Dummy 節點：在真正的 head 前方掛上一個 dummy 節點（令 dummy.next = head），這樣一來，頭節點就擁有了現成的前驅，所有的刪除邏輯便得到了完全統一的優雅處理。dummy 節點的 value 沒有實質意義，函式最後只需安心回傳 dummy.next 即可。

要在一趟遍歷內找出倒數第 k 個節點的前驅，我們可以建立「固定間距的雙指標」：讓 slow 與 fast 同時從 dummy 出發，先讓 fast 單獨向前預先推進 k 步；此時 fast 與 slow 之間剛好建立了長度為 k 的安全間距。接著，讓兩者以相同速度同步前進，直到 fast 抵達最後一個實體節點（即 fast.next 為 None）時停止。因為此時 fast 位於尾端，而 slow 與它相距 k 個節點，slow 所停駐的位址剛好就是「倒數第 k 個節點的正前方前驅」！

def remove_from_end(head, k):
    """移除倒數第 k 個節點；k 無效時拋 ValueError 且不修改串列。"""
    if k <= 0:
        raise ValueError("k 必須為正整數")
    dummy = Node(0, head)
    slow = fast = dummy
    for _ in range(k):
        fast = fast.next
        if fast is None:
            raise ValueError("k 大於串列長度")
    while fast.next is not None:
        slow = slow.next
        fast = fast.next
    slow.next = slow.next.next
    return dummy.next

邊界情況全面覆蓋：當 k = n 時，fast 在預走階段剛好抵達原串列尾端，此時 slow 依舊停在 dummy，接下來直接執行跨接剛好將原頭節點刪除；當 k = 1 時，slow 最終精準停在倒數第二個節點上，將原本的最後一個節點安全移除。程式在動手修改任何指標前，會完整走完 k 步驗證；若中途 fast 提前撞見 None，會立即拋出異常，絕不玷污原始輸入串列。

本演算法的時間複雜度為 O(n)，額外空間僅需 O(1)（僅配置單一 dummy 節點）。在垃圾回收機制下，被跨接跳過的原節點若沒有其他外部參照持有，將會被記憶體自動釋放。

5. 合併已排序串列：維持輸出邊界

題意：輸入兩條已依非遞減順序排序、無環且互不共享節點的單向鏈結串列 a 與 b，請沿用原始節點將它們合併為一條全新的排序串列，並回傳新串列的頭節點。輸入允許為空串列，若兩者皆為空則回傳 None。

LeetCode 21 · Merge Two Sorted Lists

對於兩條遞增排好序的串列，指針 a 與 b 分別代表兩條串列目前尚未被接駁的最小節點。我們藉助一個 dummy 哨兵節點，並用 tail 指針隨時緊盯「已合併鏈條的最後一個尾節點」。在每一輪比對中，選取 a.value 與 b.value 中較小的一方掛載到 tail.next 上，並將對應的輸入指針向前推一步。每輪結束後，從 dummy.next 一路到 tail 的部分永遠是已確定且排好序的前綴。當兩者數值相等時，我們優先選取 a，這種穩定的 tie-breaking 規則能完美維持第一條串列元素的相對原始順序。

def merge_sorted(a, b):
    """兩串列必須無環、遞增（可重複），且不能共享任何節點。"""
    dummy = Node(0)
    tail = dummy
    while a is not None and b is not None:
        if a.value <= b.value:
            tail.next, a = a, a.next
        else:
            tail.next, b = b, b.next
        tail = tail.next
    tail.next = a if a is not None else b
    return dummy.next

當其中一條串列先行耗盡時，因為另一條串列本身就已經是排好序的，而且其剩餘的所有元素必然都大於或等於當前 tail 的數值，所以我們完全不需要繼續跑迴圈，只需要在 O(1) 內直接將尚未耗盡的整條剩餘鏈條接在 tail.next 上即可。重要前置假設：兩條輸入串列在實體記憶體中必須互不相交；如果兩條串列在末端共享了某些節點，重接操作可能會不小心把某個節點接回自己身上，從而在合併後的串列中意外製造出死循環環路。

設兩條串列的長度分別為 m 與 n，本演算法的時間複雜度為 O(m + n)，輔助空間為極致的 O(1)。若規格要求不得更動原本兩條輸入串列的指向關係，就必須在迴圈中配置全新 Node 節點進行深拷貝，此時輸出空間為 O(m + n)。

6. 練習與邊界檢查

練習 A：偶數長度改為回傳「第一個中點」

在目前實作中，面對輸入 8 → 3 → 5 → 1 會回傳第二個中點 5。如果規格要求改為回傳第一個中點 3，我們該如何調整快慢指標的初始化起點？空串列同樣需回傳 None。

參考解答

先對 head is None 進行特判回傳 None；對於非空情況，初始化時令 slow = head，而讓 fast = head.next，隨後保留原有的 while fast is not None and fast.next is not None 迴圈不變。透過讓 fast 預先多搶跑一步，fast 能前進的總輪數剛好減少了一次：當 n = 2 時 slow 停在原地索引 0，當 n = 4 時 slow 僅前進 1 步停在索引 1（對應 (n − 1) // 2）。而對於奇數長度串列，中點依然穩穩停在正中央。演算法時間複雜度仍為 O(n)，空間複雜度為 O(1)。

練習 B：只給待刪節點，真的能實現真正的 O(1) 刪除嗎？

假設你只拿到串列中的某個實體節點 target，完全沒有拿到 head 也沒有前驅節點。面試中有人建議「把下一個節點的 value 複製到 target，然後把下一個節點跳過刪除」。這個取巧的方法在哪些軟體工程規格下會徹底失效？

參考解答

首先，如果 target 剛好是整條串列的最後一個尾節點，它身後根本沒有下一個節點可供拷貝，該方法瞬間失效。更深刻的系統層面問題在於：這個手法實質上是抹殺了下一個節點的生命週期，並竄改了當前節點的數值。如果外部其他系統模組依賴節點物件的記憶體身分來綁定觀察者模式、如果節點內部包含不可任意淺拷貝的昂貴資源（如檔案控制代碼或網路 Socket），或者合約規格嚴格要求「必須釋放 target 本身的記憶體」，這項欺騙直譯器的手法就會引發嚴重的系統副作用。在正規的單向鏈結串列中，要安全乾淨地移除一個節點，依然必須掌握其前驅指標。

LeetCode 234 · Palindrome Linked List：本節另要求檢查後還原串列。

練習 C：原地判斷回文串列，並維持額外空間 O(1)

請判斷鏈結串列 3 → 8 → 8 → 3 是否為左右對稱的回文結構，並強烈要求函式返回前必須將原本的串列結構「原封不動完整還原」。請說明演算法步驟與核心邊界。

參考解答

標準做法分為四步：首先用快慢指標定位到前半段的尾端節點；其次將後半段串列進行原地反轉；第三步從 head 與反轉後的後半段頭部同步向內推進比對數值；最後也是最關鍵的——即便途中發現數值不符判定非回文，也絕不能草率直接 return，必須先用一個布林變數 matched 記錄結果，並堅持將後半段再次反轉還原接回原位。

def is_palindrome(head):
    """判斷無環串列是否為回文，結束前還原所有 next。"""
    if head is None or head.next is None:
        return True
    first_half_end = fast = head
    while fast.next is not None and fast.next.next is not None:
        first_half_end = first_half_end.next
        fast = fast.next.next

    second_half = reverse(first_half_end.next)
    left, right = head, second_half
    matched = True
    while right is not None:
        if left.value != right.value:
            matched = False
            break
        left, right = left.next, right.next

    first_half_end.next = reverse(second_half)
    return matched

在偶數長度下，first_half_end 恰好停在第一個中點；在奇數長度下，它停在正中央節點，後半段從其下一個節點開始反轉，中央元素天然不影響回文。全過程至多比對 n // 2 對節點，時間複雜度為 O(n)，輔助空間為極致的 O(1)。在離開函式前，每一根 next 指標都完美物歸原主。

鏈結串列的必備邊界檢查清單：空串列與單一節點、長度為偶數與奇數、反轉兩次後的節點身分是否原樣保持、合法與越界的 k 值、各類帶環拓樸、原地自環（節點指向自己）、合併時出現相同數值，以及回文檢驗後整條鏈的指標是否百分之百無損還原。

7. 決策小結

  • 需要按索引頻繁存取第 i 個元素：毫不猶豫優先選用陣列，單向鏈結串列完全沒有隨機存取的物理優勢。
  • 動手修改 next 指標前：務必在紙上畫出指標斷開前後的拓樸，並先用臨時變數牢牢保住通往未處理區域的唯一入口。
  • 頭節點涉及頻繁新增、刪除或換頭：第一時間引入 Dummy 虛擬前驅，把邊界特例徹底轉化為標準的前驅重接操作。
  • 一趟遍歷定位中點、倒數第 k 個或偵測環：善用「不同步速」或「固定幾何間距」的雙指標設計模式。
  • 比較「是否走回同一節點」時嚴格使用 is 比對記憶體身分；只有在比對業務內容或排序時才使用 value。
  • 在空間複雜度評估中，務必嚴格切分：原始既有節點、測試輔助轉換陣列、新配置的輸出節點以及遞迴呼叫堆疊。
