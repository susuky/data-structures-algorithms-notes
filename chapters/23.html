23 · 資料、文字與執行順序

不是每題都在寫單機演算法。有時你要用 SQL 先對齊「一列代表誰」，有時要用 Shell 管線一行行處理文字串流，還有多執行緒共用變數怎麼加鎖，以及只能靠有限次提問逼近答案的互動題。

先算每個人的總額，再排名

訂單是 A:12、A:8、B:20、C:7，要找總消費前兩名。A 有兩張訂單，B 只有一張，但兩人的總額都是 20。先決定「一列是一張訂單」還是「一列是一位客戶」，查詢就容易安排。

GROUP BY 把相同 customer 收成一組，SUM 產生每人的 total；DENSE_RANK 依 total 由大到小排名，相同總額共用名次，下一名接續加一。用一層 CTE 接住排名，再篩 place ≤ 2。

WITH orders(customer, amount) AS (
    VALUES ('A', 12), ('A', 8), ('B', 20), ('C', 7)
), totals AS (
    SELECT customer, SUM(amount) AS total
    FROM orders
    GROUP BY customer
), ranked AS (
    SELECT customer, total,
           DENSE_RANK() OVER (ORDER BY total DESC) AS place
    FROM totals
)
SELECT customer, total, place
FROM ranked
WHERE place <= 2
ORDER BY place, customer;

若題目要求恰好兩位，改用 ROW_NUMBER，並在 ORDER BY 加入明確的同分順序；若要求前兩種總額，就用 DENSE_RANK。SQL 的最外層 ORDER BY 決定輸出順序，視窗裡的排序決定名次。

再把需求改成「所有客戶，包括沒有下單的人」。從 customers LEFT JOIN orders，沒有訂單的 C 仍保留一列。COUNT(o.customer) 得到 0；SUM 的空值以 COALESCE 換成 0。COUNT(*) 會把 LEFT JOIN 保留的那一列也算進去。

WITH customers(id) AS (
    VALUES ('A'), ('B'), ('C')
), orders(customer, amount) AS (
    VALUES ('A', 20), ('A', 5), ('B', 10)
)
SELECT c.id, COUNT(o.customer) AS order_count,
       COALESCE(SUM(o.amount), 0) AS total
FROM customers AS c
LEFT JOIN orders AS o ON o.customer = c.id
GROUP BY c.id
ORDER BY c.id;

資料量變大時，用 EXPLAIN QUERY PLAN 看分組與排序是否建立暫存 B-tree，及 JOIN 是否走索引。以 N 張訂單、U 位客戶估算，分組需要掃過訂單，排名常需要 O(U log U) 排序；實際計畫取決於索引與資料庫的分組方法。

只保留金額大於 10 的訂單，再計算每人總額，條件放 WHERE 還是 HAVING？若想要總額大於 10 呢？

看推理

單張訂單的條件放 GROUP BY 前的 WHERE amount > 10；整組總額的條件放 HAVING SUM(amount) > 10，或在 totals CTE 之外篩 total。前者會先移除 A 的 8 元訂單，後者會讓它參與合計。

把詞頻問題拆成一段管線

輸入 Tea, coffee TEA. tea!，要得到 tea 3 次、coffee 1 次。每段指令只處理一件事，觀察它交給下一段的資料形狀。

本例把連續英文字母當成單字。tr 將其他字元換成換行並壓縮連續分隔字元，再把大寫換成小寫。開頭若有標點，可能產生空行，用 sed 移除。sort 把相同單字排在一起，uniq -c 才能一次數出完整的相鄰群組。

export LC_ALL=C
tr -cs 'A-Za-z' '\n' |
tr 'A-Z' 'a-z' |
sed '/^$/d' |
sort |
uniq -c |
sort -k1,1nr -k2,2

在 Git Bash 或 Bash 中執行，管線從標準輸入讀文字；也可在第一個 tr 後加 < words.txt 讀檔。LC_ALL=C 讓這個 ASCII 範例按固定的字元順序處理。末段先依第 1 欄數字遞減，再用第 2 欄單字決定同次數順序。

uniq 只合併相鄰的相同行。若把 sort 拿掉，第一次 tea 和後面的 tea 中間隔了 coffee，就會落在不同群組。以 w 個詞估算，排序通常花 O(w log w) 比較，其他階段線性掃描；大檔案的 sort 可以用外部排序處理記憶體放不下的內容。

輸入「red blue RED blue green」，最後順序是什麼？如果直接 sort -r，次數 9 與 10 會怎麼排？

看推理

blue 2、red 2、green 1；同次數依單字遞增。一般字串逆序會把開頭是 9 的行排在 10 前面，數字排序 -n 讓 10 正確地大於 9。

兩個人加一，怎麼只多一？

共用計數器從 0 開始，A、B 都要加一。把動作拆成「讀取」與「寫回讀值 + 1」：A 讀 0、B 讀 0、A 寫 1、B 寫 1，最後只有 1。問題出在兩次操作交錯時，各自拿著過期的讀值。

鎖包住完整的讀取、修改、寫回，持鎖者完成後才讓下一位進入。所有會改這個共享值的路徑都使用同一把鎖，兩次 increment 就依序發生，得到 2。

from threading import Lock

class LockedCounter:
    def __init__(self):
        self.value = 0
        self.lock = Lock()

    def increment(self):
        with self.lock:
            self.value += 1

需要等資料時，條件變數讓執行緒交出鎖並休眠。下面的有界信箱最多放 capacity 筆：生產者等空位，消費者等資料。wait_for 在醒來後重新檢查條件，符合時才繼續；notify_all 喚醒等待者，持鎖者離開 with 後，其他人才能重新取得鎖。

展開可執行的生產者／消費者信箱
from collections import deque
from threading import Condition

class BoundedMailbox:
    def __init__(self, capacity):
        if capacity < 1:
            raise ValueError("capacity 至少為 1")
        self.capacity = capacity
        self.items = deque()
        self.changed = Condition()

    def put(self, value):
        with self.changed:
            self.changed.wait_for(lambda: len(self.items) < self.capacity)
            self.items.append(value)
            self.changed.notify_all()

    def get(self):
        with self.changed:
            self.changed.wait_for(lambda: bool(self.items))
            value = self.items.popleft()
            self.changed.notify_all()
            return value

put 與 get 的佇列操作各是 O(1)，容量 c 使用 O(c) 空間；等待時間由其他執行緒何時提供資料或空位決定。範例以 None 作結束訊號，消費者讀到 None 後離開迴圈。

下方的圖解把排程順序固定下來，方便你每次重播都能看清交錯是怎麼發生的；把鎖打開之後，被擋住的工作者就會等鎖釋放再重試。範例測試檔裡也真的開了多條 Thread，直接檢查計數器跟信箱最後的結果。

鎖只包住寫回，讀取放在鎖外，ABAB 的結果會變成多少？把臨界區畫出來。

看推理

仍可能是 1。兩人都先讀到 0，即使兩次寫回互斥，也都寫入 1。臨界區應從讀取共享值開始，一直包到修改後的值寫回。

用有限次提問找出隱藏數字

評測程式藏了一個 1 到 n 之間的整數。你每次猜 middle，它只回覆「答案更小、相同、更大」。n=100 時，最多 7 次提問就能找到答案。

這一類 Interactive 題目透過問答取得資訊。把所有仍可能的答案保存為閉區間 [low, high]，詢問中點。回覆更大就把 low 改成 middle+1；更小就把 high 改成 middle−1；相同就結束。每次至少排除中點以及一側候選。

def query_secret(n, query):
    if n < 1:
        raise ValueError("n 至少為 1")
    low, high = 1, n
    while low <= high:
        middle = (low + high) // 2
        answer = query(middle)
        if answer == 0:
            return middle
        if answer > 0:
            low = middle + 1
        else:
            high = middle - 1
    raise ValueError("回覆與候選區間矛盾")

最壞提問數是 ⌊log₂ n⌋+1，也就是 Python 的 n.bit_length()，時間 O(log n)、額外空間 O(1)。每題的 oracle 格式由題面定義，寫解法時把它隔離成 query 函式，搜尋邏輯就能用本機的假評測程式測試所有隱藏答案。

走標準輸入／輸出的題目，每次輸出提問後要 flush，評測端收到問題才會回覆。例如題面若規定用「? 數字」提問，可寫 print("?", middle, flush=True)，再讀一行回應；完成時依題面輸出答案標記。診斷訊息放到 stderr，問答通道保留協定要求的內容。

n=1 時需要幾次提問？回覆「更大」後，為什麼用 middle+1，不能留 middle？

看推理

本範例提問一次確認唯一候選。更大的回覆已排除 middle，下一段從 middle+1 開始才會縮小區間；若 low=middle，剩兩個候選時可能反覆詢問同一個數字。
