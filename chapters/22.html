22 · 對手也會選，答案怎麼算

對手不是隨機亂走，他也會挑對你最不利的那一步。這章先把對手的回應放進狀態轉移；遇到看似要窮舉到天荒地老的謎題，就去找一個每步操作都不會破壞的數量關係。

留下四的倍數，對手就接到難題

桌上有 7 顆石子，兩人輪流拿 1 到 3 顆，拿到最後一顆的人贏。你該拿幾顆？拿 3 顆，把 4 顆留給對手；他拿 1、2、3 顆，你分別拿 3、2、1 顆收尾。

用 win[s] 表示「輪到自己、剩 s 顆時，能否在對手每一步也選得最好的情況下獲勝」。0 顆時沒有合法動作，所以 win[0]=False。只要存在一個合法拿法，把對手送進敗態，當前就是勝態；所有合法拿法都送到勝態，當前就是敗態。

def winning_moves(stones, max_take):
    if stones < 0 or max_take < 1:
        raise ValueError("石子數須非負，每回合至少可取一顆")
    win = [False] * (stones + 1)
    choice = [None] * (stones + 1)
    for remaining in range(1, stones + 1):
        for take in range(1, min(max_take, remaining) + 1):
            if not win[remaining - take]:
                win[remaining], choice[remaining] = True, take
                break
    return win, choice
每次可取 1–3 顆，狀態從小到大算

表格每四個狀態重複一次。敗態恰好是 4 的倍數：從倍數拿 1–3 顆會離開倍數；從其他數字可以拿掉餘數，走回倍數。把每回合上限換成 m，判斷式就成為 s % (m+1) != 0。表格版花 O(s·m) 時間、O(s) 空間，也保留了實際選擇；餘數版用 O(1) 時間直接判斷。

這是有限、雙方知道完整狀態、沒有機率動作的輪流遊戲。題目若改成「拿最後一顆的人輸」，0 顆的勝負定義和轉移終點要一起重推；拿 1 顆的局面立刻就會得到不同答案。

每回合可拿 1–4 顆，現在有 18 顆。第一步拿多少？若只有 15 顆呢？

看推理

18 除以 5 餘 3，拿 3 顆留下 15。15 是敗態，對手可在你每次取走後補到合計 5 顆，把局面送回 10、5、0。

自己選大的，對手選小的

你先選左或右，對手再選該分支的一個葉節點，葉上的數字是你的得分。左邊有 3、5，右邊有 2、9。對手會把左邊壓到 3、右邊壓到 2，因此你選左邊，能拿到 3。

評分固定從同一位玩家的角度看。輪到自己時取 max，輪到對手時取 min，從葉節點一路向根傳回。若每層都取最大，右邊的 9 就會誤導根節點。用固定視角也方便處理負分：-2 對自己比 -8 好。

def minimax_value(leaves):
    if not leaves or len(leaves) & (len(leaves) - 1):
        raise ValueError("葉節點數必須為 2 的次方")
    def visit(left, right, maximize):
        if right - left == 1:
            return leaves[left]
        middle = (left + right) // 2
        a = visit(left, middle, not maximize)
        b = visit(middle, right, not maximize)
        return max(a, b) if maximize else min(a, b)
    return visit(0, len(leaves), True)

分支數 b、深度 d 的完整樹含 O(bd) 個節點；逐一探訪的時間也是 O(bd)，深度優先遞迴堆疊 O(d)。這裡用葉陣列表示完整二元樹，以索引切區間，保留 O(log n) 呼叫深度。實際棋局可把 visit 的子節點改成合法走法。

alpha-beta 剪枝維持兩個門檻：alpha 是 MAX 沿已搜尋分支能取得的下界，beta 是 MIN 能壓到的上界。左子樹已給根 3；右子樹第一個葉是 2，MIN 最後至多回傳 2，根已有更好的選擇，右邊剩下的 9 可以略過。

展開 alpha-beta 的可執行版本
def alpha_beta(leaves):
    if not leaves or len(leaves) & (len(leaves) - 1):
        raise ValueError("葉節點數必須為 2 的次方")
    visited = []
    def visit(left, right, maximize, alpha, beta):
        if right - left == 1:
            visited.append(left)
            return leaves[left]
        middle = (left + right) // 2
        best = float("-inf") if maximize else float("inf")
        for start, end in ((left, middle), (middle, right)):
            value = visit(start, end, not maximize, alpha, beta)
            if maximize:
                best = max(best, value)
                alpha = max(alpha, best)
            else:
                best = min(best, value)
                beta = min(beta, best)
            if alpha >= beta:
                break
        return best
    return visit(0, len(leaves), True, float("-inf"), float("inf")), visited

當 alpha ≥ beta，後面的子分支已無法改善祖先的選擇。走法順序影響剪枝數量；最壞時間仍是 O(bd)，先探索好走法時常會減少需要評估的葉節點。

把葉改成 [7,4,8,1]，根回傳多少？右子樹看到第一個葉 8 時可不可以立刻剪掉另一個葉？

看推理

根回傳 max(min(7,4), min(8,1)) = 4。右邊先看到 8 時，beta=8 大於 alpha=4，還要讀下一個葉；看到 1 後才知道該分支至多給 1。

一次翻兩盞燈，奇偶性留下來

一排燈只能每次選兩個不同位置一起翻轉。1 是亮、0 是暗，目標是全暗。對 [1,0,1,1] 一直試很容易繞圈；它有三盞亮燈，亮燈數的奇偶性已經決定答案。

只看被選到的兩盞燈。兩盞都暗，亮燈數增加 2；一亮一暗，亮燈數不變；兩盞都亮，亮燈數減少 2。每一步都保持亮燈數的奇偶性，而全暗有 0 盞亮燈，是偶數。

偶數個亮燈也有直接做法：把所有亮燈位置兩兩配對，每次翻一對。若有 2k 盞亮燈，恰好 k 步全暗。任何一步最多關掉兩盞，所以 k 步同時是最少步數。這就把「可達條件」與「怎麼做」接在一起了。

def turn_off_pairs(bits):
    if any(bit not in (0, 1) for bit in bits):
        raise ValueError("每盞燈須為 0 或 1")
    on = [i for i, bit in enumerate(bits) if bit]
    if len(on) % 2:
        return None
    return list(zip(on[::2], on[1::2]))

掃描 n 盞燈花 O(n) 時間；若要回傳所有操作，結果使用 O(n) 空間。只問能否全暗時，可以用一個 parity 位元逐項 XOR，額外空間 O(1)。空列與原本全暗都回傳空操作序列。

把規則改成每次翻「相鄰」兩盞，偶數個亮燈還能全暗嗎？試著從最左邊一路處理。

看推理

可以。從左往右，若第 i 盞亮，就翻 i 與 i+1，讓第 i 盞固定為暗，之後不再碰它。走到最後一盞時，奇偶不變量保證它也是暗。這個相鄰版本的步數通常多於任選兩盞。
