11．動態規劃：狀態、轉移與計算順序

動態規劃（Dynamic Programming，簡稱 DP）是演算法中最具威力的思維武器之一。它的精髓非常純粹：將具有相同未來的子問題大膽合併，使其只被計算一次。許多初學者容易將動態規劃誤認為某種高深莫測的填表公式，但本質上，DP 不過是「懂得適度遺忘歷史、只萃取必要資訊」的精準記憶搜尋。在狀態中，我們只保留會對後續決策產生影響的關鍵特徵；而轉移方程式，則是依據最後一步或下一步的可行選擇，將大問題拆解為更小規模子問題的極值、總數或可行性組合。

面對任何動態規劃問題，在動手寫第一行程式碼之前，你必須先在腦海中清清楚楚回答六個關鍵問題：狀態如何定義？轉移式如何推導？初始與邊界條件是什麼？狀態的相依計算順序為何？最終答案位於表格的哪個座標？以及整體的時空複雜度是否能被系統承載？本章將從經典的一維零錢兌換出發，循序拆解 0/1 背包的空間壓縮奧秘、雙字串 LCS 網格、二維矩陣走訪、有限狀態機（FSM）DP 以及狀態壓縮，帶你建立無可撼動的動態規劃直覺。

11.1 填 dp 表前，先回答六個問題

在開始設計 DP 表格前，請養成逐一核對以下六大維度的嚴謹習慣：

  1. 狀態定義（State Definition）：dp 陣列的每個索引維度到底代表什麼現實意義？裡面儲存的純量值又是什麼？例如 dp[a] 必須精確定義為「湊齊總金額剛好為 a 所需的最少硬幣數量」，切忌使用「走到這一步的答案」這種語焉不詳的模糊描述。
  2. 狀態轉移（State Transition）：依據「最後一步可能做出的所有互斥選擇」，如何將當前狀態的答案由較小規模的子問題推導出來？求極值通常使用 min 或 max，求方案總數通常相加累計，求可行性則使用布林邏輯 or。
  3. 邊界與不可達狀態（Base Cases & Unreachability）：最基礎的空問題（例如金額為 0、字串為空）對應什麼數值？哪些在物理上根本無法抵達的非法狀態需要被特別標記？在求最小值問題中，不可達狀態通常初始化為正無窮大（$\infty$）；求最大值時則設為負無窮大（$-\infty$）。
  4. 計算順序與拓撲依賴（Evaluation Order）：在嘗試計算並填入某個狀態前，它所依賴的所有子問題是否都已經在記憶體中計算完畢？若當前狀態依賴較小金額，迴圈就必須由小到大；若區間 DP 依賴較短區間，外層迴圈就必須按區間長度由短到長推進。
  5. 答案位置（Answer Location）：最終的全域解答究竟存放在哪裡？是右下角的 dp[m][n]、最後一列的極值、所有合法終止狀態的最大值，還是需要將某些狀態累加？
  6. 複雜度審計（Complexity Audit）：時間複雜度嚴格等於「狀態總數量 × 單一狀態的轉移成本」，隨後再加上必要的前處理與答案重建開銷；空間複雜度則需涵蓋表格陣列、遞迴堆疊以及可能的路徑回溯指標。
什麼叫做「足夠的狀態」？如果兩段截然不同的決策歷史被映射到了同一個 DP 狀態，那麼從此刻開始，這兩個狀態在未來所有可行的決策分支、以及各分支產生的後續收益，必須完全一模一樣！如果在未來的某個判斷中，你還需要知道「過去到底有沒有用過第 3 件物品」，那麼這個資訊就屬於無法被遺忘的狀態特徵，必須老老實實擴充進狀態維度中。回溯法保留的整條 path 資訊量過大；而如果只記錄「目前走到第幾步」往往又遺漏過多，DP 的藝術就在於拿捏這份恰到好處的平衡。

只有當問題同時具備「最優子結構」（整體最優解可由子問題最優解構造）與「重疊子問題」（不同分支反覆造訪相同的局部狀態）時，動態規劃才能發揮其碾壓暴力搜尋的威力。若子問題之間完全不重疊，記憶化快取只會白白浪費記憶體；若狀態轉移圖中存在有向環（Circular Dependency），普通的遞迴記憶化將直接墜入無窮遞迴，此時必須轉用圖論的最短路徑演算法（如 Dijkstra 或 Bellman-Ford）來化解。

11.2 自頂向下：先寫遞迴，再記住答案

LeetCode 322．Coin Change。coins=[1,3,4]、amount=6，最少需要 2 枚。

給定一組正整數面額的硬幣，每種面額供應量無限。我們希望能以最少枚數湊出目標金額 amount；若無論如何都無法剛好湊出，則回傳 -1。令 best(a) 代表湊齊金額 a 所需的最少枚數。思考最後一步：在放入最後一枚面額為 $c$ 的硬幣之前，我們必定先湊出了金額 $a - c$。因此轉移關係非常自然：$best(a) = 1 + \min_{c \le a} best(a - c)$。基礎邊界為 $best(0) = 0$；若無任何合法硬幣可選，則回傳無窮大。

如果使用純暴力遞迴，湊成 6 的過程中，子問題 best(2) 會在 6 - 4 = 2 以及 6 - 1 - 3 = 2 等多條路徑上被反覆重複計算，遞迴樹呈現指數爆炸。但只要掛上快取字典（例如 @cache），每個不同的金額餘額就保證只會真正執行其內部迴圈一次。硬幣全為正數確保了每次遞迴時金額必定嚴格遞減，轉移圖是有向無環圖（DAG），絕對不會發生循環依賴。我們在函式內部建立快取，確保每次呼叫都能使用封裝的獨立狀態，避免不同測資之間相互污染。

from functools import cache
from math import inf


def minimum_coins_memo(coins, amount):
    values = tuple(sorted(set(coins)))
    if amount < 0 or any(c <= 0 for c in values):
        raise ValueError("amount 必須非負，硬幣面額必須為正整數")

    @cache
    def best(remain):
        if remain == 0:
            return 0
        answer = inf
        for coin in values:
            if coin > remain:
                break
            answer = min(answer, 1 + best(remain - coin))
        return answer

    answer = best(amount)
    return -1 if answer == inf else answer

最優子結構證明（反證法）：假設湊齊金額 $a$ 的某個最優解中最後一枚硬幣為 $c$。若扣除這枚硬幣後剩餘的金額 $a - c$ 不是透過最優解湊齊的，那麼我們必定能找到一套枚數更少的硬幣方案來湊齊 $a - c$，將這套更優方案補上硬幣 $c$ 之後，就能湊出總額為 $a$ 且枚數更少的新方案，這直接與「原方案為湊齊 a 的最優解」產生矛盾！因此，最優子結構必然成立。

設目標金額為 $A$，硬幣種類去重後有 $D$ 種。狀態總數最多為 $A + 1$ 個，每個狀態在內部最多嘗試 $D$ 次面額轉移，總時間複雜度為 $O(A \cdot D)$。空間方面，快取字典佔用 $O(A)$，遞迴呼叫堆疊最深可能達到 $A$ 層（例如只有面額 1 時）。在 Python 中，若金額高達數千，很容易直接觸發 RecursionError: maximum recursion depth exceeded，這時改用自底向上的迭代填表法是更為穩健的工程實踐。

11.3 自底向上：按相依順序填表

觀察狀態轉移式 $dp[a] = 1 + \min(dp[a - c])$，可以發現任何金額 $a$ 都只依賴於嚴格小於 $a$ 的子問題結果。這意味著：只要我們讓金額從 0 開始由小到大遞增跑迴圈，當我們準備計算 dp[total] 時，其所有可能需要查閱的前置狀態 dp[total - coin] 都保證百分之百已經算妥定案！這就是表格法（Tabulation）的核心邏輯——拋棄遞迴開銷，以純粹的陣列迭代循序推進。

def minimum_coins(coins, amount):
    values = sorted(set(coins))
    if amount < 0 or any(c <= 0 for c in values):
        raise ValueError("amount 必須非負，硬幣面額必須為正整數")
    dp = [float("inf")] * (amount + 1)
    dp[0] = 0
    for total in range(1, amount + 1):
        for coin in values:
            if coin > total:
                break
            dp[total] = min(dp[total], dp[total - coin] + 1)
    return -1 if dp[amount] == float("inf") else dp[amount]

從最少枚數還原一組硬幣

在實際系統開發中，業務需求往往不僅要回傳「最少需要幾枚」，更要給出「具體是哪幾枚硬幣」。我們只需在更新 dp[total] 的同時，額外使用一個 chosen[total] 陣列記錄下讓它取得最小值的最後那枚硬幣面額。運算完成後，從目標金額 amount 出發，不斷減去 chosen[amount] 回溯跳躍，就能輕鬆在 $O(\text{枚數})$ 時間內將整組最佳解答完整重建出來：

def minimum_coin_solution(coins, amount):
    """回傳一組最少硬幣；無解為 None，金額 0 為 []。"""
    values = sorted(set(coins))
    if amount < 0 or any(coin <= 0 for coin in values):
        raise ValueError("amount 必須非負，硬幣面額必須為正整數")
    dp = [float("inf")] * (amount + 1)
    chosen = [0] * (amount + 1)
    dp[0] = 0
    for total in range(1, amount + 1):
        for coin in values:
            if coin > total:
                break
            candidate = dp[total - coin] + 1
            if candidate < dp[total]:
                dp[total] = candidate
                chosen[total] = coin
    if dp[amount] == float("inf"):
        return None
    answer = []
    while amount:
        coin = chosen[amount]
        answer.append(coin)
        amount -= coin
    return answer

例如湊 6 時：chosen[6] = 3，金額減去 3 跳到 chosen[3] = 3，再減去 3 跳到 0 終止，成功還原 [3, 3]。這套「陣列記錄決策來源、逆向追蹤還原解答」的模式在所有 DP 方案重建中完全通用。

評估維度記憶化遞迴（Memoization / Top-Down）表格迭代法（Tabulation / Bottom-Up）
狀態探查範圍按需探查：只計算從初始目標向下實際觸及的子狀態全量探查：通常無差別填滿整個給定矩陣範圍
相依拓撲順序由遞迴呼叫棧自然隱式展開，無需人腦排定迴圈順序必須由開發者事先精確推導出無環的拓撲迭代順序
效能開銷額外的函式呼叫棧幀、雜湊表 Look-up 成本純陣列平鋪讀寫，快取局部性極佳，無呼叫開銷
空間最佳化潛力無法進行滾動壓縮，完整呼叫棧與快取必須常駐通常可透過滾動陣列將空間壓縮一個維度
特別提醒：時間複雜度 $O(A \cdot D)$ 中的 $A$ 是「數值大小」而非「輸入資料的長度」。在理論計算機科學中，這種複雜度稱為「偽多項式時間（Pseudo-polynomial Time）」。如果目標金額 $A$ 高達 $10^9$，即便 $D=3$，建立一個長度十億的陣列也會瞬間讓記憶體崩潰。在評估動態規劃方案時，永遠要先拿數值上限檢視記憶體容量！

11.4 二維狀態與壓縮：0/1 背包

背包問題是動態規劃的經典試金石。每件樣品具備重量與價值，且每件物品「至多只能被選取一次（0/1 決策）」；背包總耐重上限為 $W$。令二維狀態 $f[i][w]$ 代表「只在清單前 $i$ 件物品中挑選、且總重量不超過 $w$ 的最大累積價值」。當我們考慮第 $i$ 件物品（重 $a$、值 $v$）時，面臨兩個非此即彼的決策：

  • 不選第 i 件：容量完全不變，價值等於前 $i - 1$ 件在容量 $w$ 下的最佳解，即 $f[i - 1][w]$。
  • 選擇第 i 件：前提是背包還裝得下（$w \ge a$）。消耗 $a$ 容量後，剩餘的 $w - a$ 容量交給前 $i - 1$ 件去最佳化，得到 $f[i - 1][w - a] + v$。

兩者取 max，即為轉移方程式。觀察轉移可以發現：計算第 $i$ 列的任何數值時，我們只會向前查閱「第 $i - 1$ 列」的數據，完全不依賴更早的歷史列！這為我們進行空間壓縮提供了強大的理論依據。

如果我們把二維表格拍平成一維陣列 dp[w]，核心關鍵在於內層容量迴圈必須由大到小逆序倒著跑！為什麼？請仔細推演：當我們站在較大的容量 limit 時，我們需要查閱 dp[limit - weight] 的值。因為迴圈是從大容量往小容量掃描，此刻位於左側較小容量的 dp[limit - weight] 根本還沒被當前物品的邏輯覆寫過，它所保留的完完全全是「上一輪（即前 i - 1 件物品）」的舊答案！如果內層迴圈不小心寫成由小到大正序掃描，那麼 dp[2] 被更新為放入第 $i$ 件物品後，當掃到 dp[4] 時查閱 dp[2]，就會把已經放過第 $i$ 件物品的成果又疊加了一次，等同於無意間把單件物品拿了兩次（退化為完全背包）！

def knapsack_01(items, capacity):
    """items 為 (正整數重量, 價值)；可不選，總重至多 capacity。"""
    if capacity < 0:
        raise ValueError("capacity 必須非負")
    dp = [0] * (capacity + 1)
    for weight, value in items:
        if weight <= 0:
            raise ValueError("重量必須為正整數")
        for limit in range(capacity, weight - 1, -1):
            dp[limit] = max(dp[limit], dp[limit - weight] + value)
    return dp[capacity]

設物品總數為 $n$，容量上限為 $W$。時間複雜度為 $O(nW)$；完整二維空間為 $O(nW)$，經逆序滾動壓縮後空間直接銳減至 $O(W)$！但請格外注意題意約束：若題目要求背包「必須恰好裝滿 W」，初始條件就必須改為 dp[0] = 0，而其餘所有格子全設為負無窮大，以確保不可達容量絕不會被誤算為合法狀態。

11.5 兩個進度：最長共同子序列

LeetCode 1143．Longest Common Subsequence。回傳共同子序列的長度。

在雙字串或雙序列匹配問題中，單一進度指標無法描述兩條字串各自前進的步伐。令 dp[i][j] 代表「字串 a 的前 i 個字元」與「字串 b 的前 j 個字元」之間的最長共同子序列（LCS）長度。子序列允許跳過字元，但相對順序不得顛倒：

  • 當前兩字元匹配（a[i - 1] == b[j - 1]）：這對字元能被同時納入共同子序列，長度直接由兩者的前綴繼承並加一：$dp[i][j] = dp[i - 1][j - 1] + 1$。
  • 當前兩字元不同（a[i - 1] != b[j - 1]）：這兩個字元絕不可能同時結尾配對，因此必然至少要割捨其中一個：要麼放棄 a 的第 i 個字元，要麼放棄 b 的第 j 個字元，取兩者較大者：$dp[i][j] = \max(dp[i - 1][j], dp[i][j - 1])$。
  • 邊界條件：任一字串的前綴長度為 0 時，LCS 長度自然為 0。
def lcs_length(a, b):
    """子序列可跳過元素，但不能改變相對次序。"""
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[m][n]

請留意「子序列（Subsequence）」與「連續子字串（Substring）」在轉移上的本質差異：連續子字串若字元不匹配，連續性當場中斷，必須強制將匹配長度歸零；而子序列則具備傳承性，允許跳過不相干的字元繼續向後探索。時間與空間複雜度皆為 $O(mn)$。若只需輸出長度，利用滾動陣列保留前一列，能將輔助空間降至 $O(\min(m, n))$。

11.6 矩陣 DP：路徑與障礙

LeetCode 64．Minimum Path Sum 的延伸：加入 None 障礙、負代價與無路可走時回傳 None 的規則。

在二維網格走訪中，若移動規則限制為「只能向右或向下」，那麼抵達任何座標 $(r, c)$ 的唯二前置跳板，必定只可能來自其「正上方 $(r - 1, c)$」或「正左方 $(r, c - 1)$」。這種局部單向流動性保證了網格具備天然的有向無環拓撲結構，因此以雙層迴圈由上至下、由左至右掃描就是絕對正確的計算順序：

def minimum_grid_path(grid):
    """只能往右或下；None 是障礙。回傳最小總和，無路可走則 None。"""
    if not grid:
        return None
    rows, cols = len(grid), len(grid[0])
    if any(len(row) != cols for row in grid):
        raise ValueError("grid 必須為矩形")
    if cols == 0:
        return None
    infinity = float("inf")
    dp = [infinity] * cols
    for r in range(rows):
        for c in range(cols):
            cost = grid[r][c]
            if cost is None:
                dp[c] = infinity
            elif r == 0 and c == 0:
                dp[c] = cost
            else:
                above = dp[c]  # 尚未覆寫，仍是上一列
                left = dp[c - 1] if c > 0 else infinity
                dp[c] = min(above, left) + cost
    return None if dp[-1] == infinity else dp[-1]

這段實作巧妙展示了一維陣列的狀態混合之美：在計算當前位置 dp[c] 時，其右側的 dp[c] 尚未被寫入，因此依然保留著「上一列正上方格子」的數值；而其左側的 dp[c - 1] 剛剛被更新過，恰好代表「當前列左側格子」的新數值。一行 min(above, left) + cost 完美融合了兩個時空的資料，將空間消耗壓制在極其輕量的一行寬度 $O(cols)$。

11.7 狀態機 DP：昨天的資格決定今天的動作

LeetCode 309．Best Time to Buy and Sell Stock with Cooldown。價格非負，空輸入回傳 0。

有些問題的後續動作，高度依賴於「當前實體處於何種身分或狀態」。例如股票交易附帶冷卻期：每天有固定股價，最多只能同時持有一股；當你賣出股票後，次日強制進入冷卻期（Cooldown），完全禁止買入股票。此時單純記錄「截至今天為止的最大獲利」是無法轉移的，因為系統必須精確區分：你今天結束時到底手上是有股票、還是沒股票、還是正好今天剛賣出？

我們將每天結束時的系統劃分為三種明確的互斥狀態：

  • hold：今天結束時「手上持有股票」的最大累計淨收益（買入成本已從現金流中扣除）。
  • sold：「恰好在今天賣出股票」的最大累計淨收益（今天剛套現）。
  • rest：今天結束時「手頭無股票、且今天不是賣出日」的最大累計淨收益（處於隨時可買入的自由身分）。

在推導今日新狀態時，所有算式右側都必須嚴格參照昨天的舊狀態值：若想在今天買入股票進入 hold，昨天的狀態必須是 rest（因為若是 sold 代表昨天剛賣，今天受冷卻期保護禁止買入）；昨天剛賣出 sold 的資產，今天只能無奈轉入 rest 渡過冷卻期。先將昨日變數做快照存入 old_*，再行覆寫，是避免邏輯偷跑的最安全寫法。

def cooldown_profit(prices):
    """可多次交易，最多持有一股；賣出後隔天不能買入。"""
    hold = sold = float("-inf")
    rest = 0
    for price in prices:
        if price < 0:
            raise ValueError("價格必須非負")
        old_hold, old_sold, old_rest = hold, sold, rest
        hold = max(old_hold, old_rest - price)
        sold = old_hold + price
        rest = max(old_rest, old_sold)
    return max(rest, sold)

此演算法展現了極致的工程美感：每天只有 3 個狀態常數，每個狀態轉移耗費 $O(1)$，掃描完長度為 $n$ 的價格序列總共耗時 $O(n)$，而額外空間竟然是不可思議的 $O(1)$！這種將離散事件狀態機嵌入動態規劃的技巧，是處理各種附帶冷卻、凍結或交易手續費問題的標準解題範式。

11.8 先審狀態，再估複雜度

在實際面試與工程設計中，常有開發者憑感覺推算複雜度而翻車。請務必落實以下三道審查關卡：

  • 狀態維度的完備性審查：若背包問題遺漏了剩餘容量，就會把不同背包預算混為一談；若路徑搜尋不能重複踩踏，卻在狀態中遺漏了走訪紀錄，就會允許違法回頭。但反過來，若把回溯法的完整 path 串列原封不動塞入狀態 key 中，每個狀態都獨一無二，重疊子問題的機率直接降為零，DP 將退化為帶有龐大 Hash 開銷的假演算法。
  • 維度背後的實質狀態量：例如狀態參數包含一個長度為 $n$ 的位元遮罩 mask，初學者常誤以為這只是「增加了一個整數維度」，但實際上長度為 n 的位元遮罩隱含了高達 2ⁿ 種相異狀態！若後面再帶一個當前頂點座標 $last$，狀態空間為 $n \cdot 2^n$，總運算量直接飆升至 $O(n^2 \cdot 2^n)$。請看清維度的實質基數。
  • 底層操作的隱性代價：在 Python 中，字串切片 s[i:] 或元組拼接 tuple(lst) 都不是 $O(1)$ 操作，它們具有與長度成正比的記憶體分配成本。盡量在狀態中傳遞純量整數索引，才能保證單次轉移真正達到預期的 $O(1)$ 效能。

11.9 練習：把題意翻成狀態

練習一：配送機器人的步伐序列

LeetCode 377．Combination Sum IV。本題使用步長 1、3、4，順序不同分開計數。

物流機器人每次可前進 1、3 或 4 格，欲抵達距離 $n$ 處，總共有幾種「有順序區別」的步伐組合？（例如 1+3 與 3+1 視為兩種不同方案）。若定義距離 0 有 1 種空序列，請手算推演 n=5。

參考解答

定義 dp[t] 為抵達距離恰為 $t$ 的合法步伐序列總數。思考最後一步所跨越的步長 $s \in \{1, 3, 4\}$：因為每個序列的最後一步是互斥且唯一的，我們依最後一步分類累加：$dp[t] = \sum dp[t - s]$。程式碼：

def count_step_sequences(n, steps=(1, 3, 4)):
    choices = sorted(set(steps))
    if n < 0 or any(step <= 0 for step in choices):
        raise ValueError("n 必須非負，步長必須為正整數")
    dp = [0] * (n + 1)
    dp[0] = 1
    for total in range(1, n + 1):
        for step in choices:
            if step > total:
                break
            dp[total] += dp[total - step]
    return dp[n]

手算陣列 dp[0..5] = [1, 1, 1, 2, 4, 6]，最終解答為 6。請體會雙層迴圈的排列與組合語意：若外層枚舉總額、內層枚舉步長，算出來的是「有順序區別的排列序列」；反之若外層枚舉面額、內層枚舉金額，算出來的則是「無順序區別的組合總數」。

練習二：不能連續接案

LeetCode 198．House Robber 的延伸：允許負分與空輸入，可全部不選。

每天接案可獲取 values[i] 的報酬，但規定接案後次日必須強制休息；允許完全不接任何案子。求最高總報酬。陣列中可能包含負值。例如 [4, -1, 6, 3] 的最高得分為 10。請以 $O(1)$ 空間完成。

參考解答

令 f[i] 為前 $i$ 天能斬獲的最高總報酬。面對第 $i$ 天：若不接案，收益維持前一天的 f[i - 1]；若選擇接案，則前一天必定休息，收益為 f[i - 2] + values[i]。兩者取大值。狀態只需保留前兩天的數值：

def best_nonadjacent(values):
    before_previous = previous = 0
    for value in values:
        current = max(previous, before_previous + value)
        before_previous, previous = previous, current
    return previous

因為題目允許完全不接案，若整批輸入全為負數，函式回傳 0 滿足邊界語意。時間複雜度為 $O(n)$，空間複雜度為極簡的 $O(1)$。

練習三：最少插入成回文

LeetCode 1312．Minimum Insertion Steps to Make a String Palindrome。回傳最少插入次數，空字串回傳 0。

可以在字串任意位置插入字元（不可刪除或修改），問最少需要插入幾個字元才能讓整條字串變成對稱的回文字串？例如 "ABCA" 只要插入一個字元即可得到 "ABCBA"。

參考解答

這是標準的區間動態規劃（Interval DP）。令 dp[left][right] 代表將子字串閉區間 text[left..right] 轉變為回文所需的最少插入次數。若兩端字元相等（text[left] == text[right]），則這兩個字元天生對稱，插入成本直接等於內部子字串 dp[left + 1][right - 1]；若兩端字元不同，我們必須在左端或右端補入一個字元來完成對稱，成本為 $1 + \min(dp[left + 1][right], dp[left][right - 1])$。長區間必然依賴短區間的解答，因此外層迴圈必須以長度 length 由小到大推進：

def minimum_palindrome_insertions(text):
    n = len(text)
    if n == 0:
        return 0
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n + 1):
        for left in range(n - length + 1):
            right = left + length - 1
            if text[left] == text[right]:
                dp[left][right] = dp[left + 1][right - 1] if length > 2 else 0
            else:
                dp[left][right] = 1 + min(dp[left + 1][right],
                                         dp[left][right - 1])
    return dp[0][n - 1]

總時間與空間複雜度均為 $O(n^2)$。這展示了區間 DP「小區間推廣至大區間」的經典拓撲邏輯。

練習四：指數 DP 的工作分配

有 $n$ 個人與 $n$ 份工作，每個人必須恰好分配一份不同工作。cost[i][j] 代表第 $i$ 個人執行第 $j$ 份工作的代價。求將所有人分配完畢後的最小總代價。請以狀態壓縮動態規劃求解（適用於 $n \le 20$）。

參考解答

使用整數的二進位位元遮罩 mask 來標記「哪幾份工作已經被分配」。巧妙之處在於：當前已經被分配工作的人數，嚴格等於 mask 中二進位 1 的總數（即 mask.bit_count()）！因此我們完全不需要浪費維度去記錄 person。令 dp[mask] 代表完成這些工作集合的最小花費，枚舉下一份尚未被認領的工作進行轉移：

def minimum_assignment(cost):
    """n 個人各分配一份不同工作；cost[人][工作] 為代價。"""
    n = len(cost)
    if any(len(row) != n for row in cost):
        raise ValueError("cost 必須為方陣")
    size = 1 << n
    dp = [float("inf")] * size
    dp[0] = 0
    for mask in range(size):
        person = mask.bit_count()
        if person == n:
            continue
        for job in range(n):
            if not (mask & (1 << job)):
                next_mask = mask | (1 << job)
                dp[next_mask] = min(dp[next_mask],
                                    dp[mask] + cost[person][job])
    return dp[-1]

總狀態數為 $2^n$，每個狀態轉移 $n$ 次，時間複雜度為 $O(n \cdot 2^n)$，空間複雜度為 $O(2^n)$。相較於暴力排列窮舉的 $O(n!)$，動態規劃在 $n=20$ 時將運算量從百億億次壓縮至僅需千萬次，展現了狀態壓縮的極致威力。

11.10 邊界測試與面試小結

在交付動態規劃解答時，請對照以下清單自我驗收：是否嚴謹說明了狀態的物理語意？初始邊界與無窮大哨兵是否能防範非法偷渡？空間壓縮時的內外層迴圈走向是否保證了時空相依的正確性？

  • 狀態定義務求精確：清楚標註是「恰好湊出」還是「至多不超過」，定義偏差會直接導致轉移邏輯全盤崩潰。
  • 窮舉最後一步的互斥選擇：確保所有可能的決策分支被無漏涵蓋，並透過最優子結構論證局部最優的傳遞性。
  • 區隔空狀態與不可達狀態：切勿貪圖方便把所有初始格子全預設為 0，求極小值時未連通的節點必須嚴格設為 $\infty$。
  • 畫出相依圖再寫迴圈：依賴較小值就正序跑，依賴舊一輪就倒序跑，依賴短區間就依長度推進，嚴格順應拓撲順序。
  • 方案重建需預留追蹤指標：若調用端需要還原具體解路徑，記得維護 parent 或 chosen 陣列；若只需純量值，才考慮極限空間壓縮。

回看回溯與快取的分界，再試著把一題列舉問題改成計數或最佳化，觀察哪些 path 資訊不再需要保留。
