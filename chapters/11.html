11．動態規劃：狀態、轉移與計算順序

動態規劃（dynamic programming，DP）最重要的不是把答案放進陣列，而是找出一種狀態，能完整描述「接下來的問題」，又捨去不影響未來的過去。若許多路徑抵達同樣的狀態，就只解一次，再重用結果。DP 可以求最大值、最小值、可行性或數量；不是每題都在找最佳值。

本章依序建立六件事：狀態定義、轉移、邊界、計算順序、答案位置、複雜度。先從一維湊數開始，再走進背包、雙字串、矩陣、狀態機，最後確認「使用 DP」並不等於「多項式時間」。

11.1 六個問題，比一張 dp 表更重要

  1. 狀態：dp 的每個索引與儲存值是什麼？例如 dp[a] 是「恰好湊成 a 的最少硬幣數」，不是含糊的「到這裡的答案」。
  2. 轉移：依最後一步／下一個選擇，把答案連到較小的子問題。最佳化通常用 min 或 max，計數通常相加，可行性通常用 or。
  3. 邊界：空問題的答案是什麼？哪些狀態不可達？最小化的不可達通常用正無限大，最大化常用負無限大。
  4. 順序：讀某個狀態前，它的所有相依是否已求出？依賴較小金額就由小到大；區間依賴較短區間就由短到長。
  5. 答案：是 dp[n]、整列最大值、所有合法終態的最大值，還是其他位置？
  6. 成本：狀態數 × 每狀態轉移成本，再加前處理、輸出與資料結構操作。空間要包含表格、遞迴、重建答案。
足夠的狀態：兩段歷史若映射到同一狀態，它們之後的合法選擇與所求結果必須相同；最佳化時，可只保留這個狀態下最好的已累積值。若過去某個資訊仍會改變未來，就不能丟掉它。回溯的整條 path 往往資訊太多，但只存「目前走到第幾步」又可能太少。

「重疊子問題」說明為什麼可以省下重算；「最優子結構」說明局部子問題的最佳答案能組成整體最佳答案。兩者都需要由題意論證。遞迴也不自動適合 DP：若子問題根本不重複，cache 可能只增加開銷；若轉移含循環，普通遞迴記憶化還可能無限遞迴，需另外處理循環與求解方法。

11.2 自頂向下：先寫遞迴，再記住答案

面額都是正整數，每種硬幣可以無限使用。求恰好湊成 amount 的最少枚數，不能湊出就回傳 −1。令 best(a) 為湊 a 的最少枚數。最後放入一枚 c 之前，必須先湊出 a−c，因此 best(a)=min(1+best(a−c))，只考慮 c≤a。best(0)=0，沒有合法選法則為無限大。

不加記憶化時，相同餘額會被沿不同路徑重算。加上 cache 後，每個餘額的函式主體只執行一次。面額正值保證餘額嚴格下降，轉移沒有循環。下面將快取放在函式內，讓每次呼叫使用自己的面額集合，不會把另一組輸入的答案誤當成相同問題。

from functools import cache
from math import inf


def minimum_coins_memo(coins, amount):
    if amount < 0 or any(c <= 0 for c in coins):
        raise ValueError("amount 必須非負，硬幣面額必須為正整數")
    values = tuple(sorted(set(coins)))

    @cache
    def best(remain):
        if remain == 0:
            return 0
        answer = inf
        for coin in values:
            if coin > remain:
                break
            answer = min(answer, 1 + best(remain - coin))
        return answer

    answer = best(amount)
    return -1 if answer == inf else answer

正確性：任意最優解都有最後一枚 c。刪掉它，剩下的硬幣必須是 a−c 的最優解，否則可用更少枚數替換，和原解最優相矛盾。枚舉所有可作為最後一枚的 c，便包含某個最優解；轉移不會產生不合法總額。由 a=0 向上做歸納，即得所有有限答案正確。

令 A=amount，D=不同面額數，最多 A+1 個狀態、每狀態至多 D 次轉移，時間 O(A·D + D log D)，另計讀取原始面額清單的成本。cache 空間 O(A)，遞迴深度最壞 O(A／最小面額)。Python 可能在遠小於可接受 DP 表格大小時就遇到遞迴深度限制；大 A 優先考慮迭代。

11.3 自底向上：按相依順序填表

由於 a−c<a，金額從 0 遞增就是合法順序。dp[a] 更新時，它讀取的所有較小金額都已完成。不用遞迴，也不用函式呼叫和雜湊快取的開銷。

def minimum_coins(coins, amount):
    if amount < 0 or any(c <= 0 for c in coins):
        raise ValueError("amount 必須非負，硬幣面額必須為正整數")
    values = sorted(set(coins))
    dp = [float("inf")] * (amount + 1)
    dp[0] = 0
    for total in range(1, amount + 1):
        for coin in values:
            if coin > total:
                break
            dp[total] = min(dp[total], dp[total - coin] + 1)
    return -1 if dp[amount] == float("inf") else dp[amount]

11.4 二維狀態與壓縮：0/1 背包

每件樣品有重量與價值，只能挑一次；總重至多 W，可不選任何東西。令 f[i][w] 表示只考慮前 i 件、容量上限 w 時的最大價值。處理第 i 件（重量 a、價值 v）有兩種互斥選擇：

  • 不選：f[i−1][w]。
  • 選：若 w≥a，得到 f[i−1][w−a]+v。

兩者取 max，邊界 f[0][w]=0。狀態是 (i,w)，不能只快取 i，因為不同剩餘容量會改變可選物品。由於每一列只依賴上一列，先以兩列計算，再考慮壓成一列。

def knapsack_01(items, capacity):
    """items 為 (正整數重量, 價值)；可不選，總重至多 capacity。"""
    if capacity < 0 or any(weight <= 0 for weight, _ in items):
        raise ValueError("capacity 必須非負，重量必須為正整數")
    dp = [0] * (capacity + 1)
    for weight, value in items:
        for limit in range(capacity, weight - 1, -1):
            dp[limit] = max(dp[limit], dp[limit - weight] + value)
    return dp[capacity]

一維不變量：處理某件物品、由大容量往小容量掃描時，比目前容量更小的格子尚未更新，所以 dp[w−a] 仍代表「沒有使用這一件」的上一輪答案。這正是每件只用一次所需的語意。若改由小往大，會讀到本輪新值，等同允許重用同一物品。

第二輪先更新容量 5：max(4, dp[2]+5)=9。此時 dp[2]=4 仍是上一輪的值，恰好代表挑第一件、再挑第二件。答案為 9，沒有必要用完所有物品。

n 件物品、容量 W：時間 O(nW)，完整二維表 O(nW) 空間，一維壓縮 O(W)。這同樣是偽多項式。若題目改成「恰好用滿 W」，初值必須改成 dp[0]=0、其餘負無限大，並維持不可達語意；全部設 0 會把沒湊出的重量誤認為合法。

壓縮空間也會丟掉歷史決策。要重建選了哪些物品，最容易先保留二維表，從最後一列逆推選／不選；不要假設最後那一維數字已保留每次取用的物品。先讓狀態與順序正確，再談壓縮。

11.5 兩個進度：最長共同子序列

子序列可以刪掉元素，但保留相對順序；不要求連續。令 dp[i][j] 為 a 的前 i 個元素與 b 的前 j 個元素的最長共同子序列（LCS）長度。兩個前綴各有自己的進度，所以要兩個索引，不能只記較短長度或目前匹配總數。

  • 末元素相同：存在一個最優解配對這兩個末元素，故 dp[i][j]=dp[i−1][j−1]+1。
  • 末元素不同：它們不可能作為同一配對，至少跳過一邊，故取 max(dp[i−1][j], dp[i][j−1])。
  • 任一前綴長度為 0：共同子序列長度是 0。
def lcs_length(a, b):
    """子序列可跳過元素，但不能改變相對次序。"""
    m, n = len(a), len(b)
    dp = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if a[i - 1] == b[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])
    return dp[m][n]

例如 a="CABA"、b="ACBA"，長度是 3，可取 "ABA" 或 "CBA"。連續子字串的題目是不同問題：不相等時通常會把連續匹配長度清為 0，不能拿那個轉移來解子序列。

時間與完整表格空間皆為 O(mn)。若只求長度，可用兩列把空間壓成 O(min(m,n))。若壓成單列，還需要暫存「左上角舊值」；直接由左到右覆寫會失去 dp[i−1][j−1]。Python 建表要寫每列獨立的串列推導式，不能用 [[0]*(n+1)]*(m+1)，後者讓各列指向同一物件。

11.6 矩陣 DP：路徑與障礙

在矩形格子中，每格有通過代價，只能向右或向下；None 表示不可走。求從左上走到右下的最小總和，起點與終點代價都算。dp[r][c] 是「抵達這格」的最小總和，並非「從這格出發」的剩餘代價。相依格子是上方與左方，因此按列、再按欄遞增即可。

def minimum_grid_path(grid):
    """只能往右或下；None 是障礙。回傳最小總和，無路可走則 None。"""
    if not grid:
        return None
    rows, cols = len(grid), len(grid[0])
    if any(len(row) != cols for row in grid):
        raise ValueError("grid 必須為矩形")
    if cols == 0:
        return None
    infinity = float("inf")
    dp = [infinity] * cols
    for r in range(rows):
        for c in range(cols):
            cost = grid[r][c]
            if cost is None:
                dp[c] = infinity
            elif r == 0 and c == 0:
                dp[c] = cost
            else:
                above = dp[c]  # 尚未覆寫，仍是上一列
                left = dp[c - 1] if c > 0 else infinity
                dp[c] = min(above, left) + cost
    return None if dp[-1] == infinity else dp[-1]

11.7 狀態機 DP：昨天的資格決定今天的動作

每天有一個價格，可以多次買賣，但最多持有一股；賣出後隔天必須冷卻，不能買入。光存「到今天的最高收益」不足以描述明天能做什麼：持股與否、今天是否剛賣出都會影響下一步。把一天結束的狀態分成：

  • hold：結束時持有一股的最大淨現金；買入花的錢已扣除。
  • sold：恰在今天賣出，結束時不持股的最大收益。
  • rest：結束時不持股，而且今天沒有賣出的最大收益；明天可買。

處理今天價格 p 時，新 hold=max(舊 hold, 舊 rest−p)，新 sold=舊 hold+p，新 rest=max(舊 rest, 舊 sold)。舊 sold 今天只能進入 rest 度過冷卻，不能直接買入。所有轉移都必須讀昨天的值；若先覆寫 rest，再拿新 rest 去算 hold，就可能讓昨天剛賣出的錢在今天立刻買入。

def cooldown_profit(prices):
    """可多次交易，最多持有一股；賣出後隔天不能買入。"""
    if any(price < 0 for price in prices):
        raise ValueError("價格必須非負")
    hold = sold = float("-inf")
    rest = 0
    for price in prices:
        old_hold, old_sold, old_rest = hold, sold, rest
        hold = max(old_hold, old_rest - price)
        sold = old_hold + price
        rest = max(old_rest, old_sold)
    return max(rest, sold)  # 只有不持股狀態是已實現的收益

11.8 先審狀態，再估複雜度

完整性檢查：背包狀態漏掉容量會混合不同問題；路徑不能重訪時漏掉 visited 集合會混合不同合法選項；限制相鄰字元時漏掉上一個字元會允許違規轉移。反過來，把整段 path 放進 key 可能完全保留歷史，卻幾乎無法合併狀態，並付出建立 tuple 與雜湊的成本。

狀態數檢查：i 有 n 種、容量 w 有 W 種，最多 nW 個；但「已選集合」有 2ⁿ 種，不能因為它只用一個整數 mask 儲存，就說只有 n 種狀態。若還記最後一個點 last，狀態可能是 n·2ⁿ，每個狀態再試 n 個下一點，時間可能到 O(n²·2ⁿ)。cache 只避免同狀態重算，無法消除本來就不同的指數個狀態。

Python 成本檢查：切片、拼字串、建立 tuple 都可能不是 O(1)；使用 a[i:] 當狀態，不如用索引 i。大整數計數可能長到數百或數千位，整數加法也有位元成本。本章常見 O(狀態×轉移) 估計採用比較與有界整數運算為 O(1) 的模型；處理巨大計數或位元遮罩時需補上數值長度成本。

11.9 練習：把題意翻成狀態

練習一：配送機器人的步伐序列

機器人一次前進 1、3 或 4 格，走到距離 n 有幾種有順序的步伐序列？例如 1+3 與 3+1 是兩種。定義距離 0 有一種空序列，手算 n=5。

參考解答

dp[t] 是總距離恰為 t 的序列數；依最後一步 s 分組，dp[t] 加上 dp[t−s]。每個序列最後一步唯一，所以這些分組不重疊。外層按總距離遞增，內層枚舉最後一步。

def count_step_sequences(n, steps=(1, 3, 4)):
    if n < 0 or any(step <= 0 for step in steps):
        raise ValueError("n 必須非負，步長必須為正整數")
    choices = sorted(set(steps))
    dp = [0] * (n + 1)
    dp[0] = 1
    for total in range(1, n + 1):
        for step in choices:
            if step > total:
                break
            dp[total] += dp[total - step]
    return dp[n]

dp[0..5]=[1,1,1,2,4,6]，答案 6。D 種步長下時間 O(nD + D log D)、空間 O(n)，以整數加法 O(1) 模型估計。若改成「不計順序的面額組合數」，外層先枚舉面額、內層金額遞增，才會固定組合的建構順序；兩種問題的迴圈不能混用。

練習二：不能連續接案

每天接案會得到 values[i] 分，接案後隔天必須休息，可全部不接；求最高分。分數可能為負。例如 [4,−1,6,3] 的答案為 10。請使用 O(1) 輔助空間。

參考解答

令 f[i] 為前 i 天的最高分。最後一天不接是 f[i−1]，接則是 f[i−2]+當天分數。邊界空前綴為 0，只保留前兩個值。允許不接任何案子，所以全負輸入答案為 0。

def best_nonadjacent(values):
    before_previous = previous = 0
    for value in values:
        current = max(previous, before_previous + value)
        before_previous, previous = previous, current
    return previous

每一天兩個選擇，時間 O(n)、空間 O(1)。若題目規定至少接一天，不能照抄這組全零邊界，因為空選擇不再合法。

練習三：最少插入成回文

可以在字串任意位置插入字元，不能刪除或替換，求變成回文的最少插入次數。"ABCA" 只要插入一個字元就能得到 "ABCBA"。

參考解答

dp[l][r] 是原字串閉區間 l..r 的答案。兩端相同，只處理內部；不同則在另一端插入一個字元，代價是 1+min(dp[l+1][r],dp[l][r−1])。長度 0 或 1 已是回文。每次依賴較短區間，因此外層按區間長度遞增。

def minimum_palindrome_insertions(text):
    n = len(text)
    if n == 0:
        return 0
    dp = [[0] * n for _ in range(n)]
    for length in range(2, n + 1):
        for left in range(n - length + 1):
            right = left + length - 1
            if text[left] == text[right]:
                dp[left][right] = dp[left + 1][right - 1] if length > 2 else 0
            else:
                dp[left][right] = 1 + min(dp[left + 1][right],
                                         dp[left][right - 1])
    return dp[0][n - 1]

O(n²) 時間、O(n²) 空間。若從左到右隨意掃 l、r，可能讀到尚未算好的較短區間；依賴圖比陣列外觀更重要。

練習四：指數 DP 的工作分配

n 個人分配 n 份工作，每人一份、每份只用一次。cost[i][j] 是第 i 人做第 j 份工作的代價，求總代價最小值。只討論 n 很小的情況；這題也有更適合大型輸入的專門演算法。

參考解答

mask 的第 j 位為 1 表示第 j 份工作已用；已安排的人數等於 mask 中 1 的數量，所以不用再存 person。dp[mask] 是前 person 人完成這些工作的最小代價。枚舉下一份未使用的工作，設位後的 next_mask 一定大於 mask，數值遞增就是合法順序。

def minimum_assignment(cost):
    """n 個人各分配一份不同工作；cost[人][工作] 為代價。"""
    n = len(cost)
    if any(len(row) != n for row in cost):
        raise ValueError("cost 必須為方陣")
    size = 1 << n
    dp = [float("inf")] * size
    dp[0] = 0
    for mask in range(size):
        person = mask.bit_count()
        if person == n:
            continue
        for job in range(n):
            if not (mask & (1 << job)):
                next_mask = mask | (1 << job)
                dp[next_mask] = min(dp[next_mask],
                                    dp[mask] + cost[person][job])
    return dp[-1]

cost=[[6,2,4],[3,5,1],[2,6,4]] 的答案為 5，分別挑工作 1、2、0。共有 2ⁿ 個 mask，每個至多 n 次轉移，所以時間 O(n·2ⁿ)、空間 O(2ⁿ)，以位元運算 O(1) 的一般小 n 模型估計。n=0 回傳 0，代表唯一的空分配。這是 DP，但仍是指數演算法。
