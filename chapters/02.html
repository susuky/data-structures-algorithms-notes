02 · 用邊界整理陣列與字串

一段資料向右挪一格，通常只改變兩端。這章把這件事變成雙指標、滑動視窗與前綴和，讓已經算過的資訊繼續派上用場。

把區間畫成兩道邊界

陣列 [3, −2, 5, 1] 的 [1, 3) 包含索引 1、2，共兩個元素。右端的 3 是邊界，不讀進區間。採用半開區間後，長度就是 right−left；[i, i) 自然表示空區間。

相鄰的 [a, b) 與 [b, c) 可以直接接成 [a, c)。兩數配對則使用兩個實際元素索引，兩端都參與比較；讀程式時看清函式回傳的是索引對還是區間邊界。

Python str 的索引計算 Unicode 碼位。題目若談使用者眼中的字形，要另外採用字形分割規則；一般演算法題按照字串元素處理。list 切片會複製 k 個參照，維護兩個邊界只需常數空間。

閉區間 [2, 4] 換成半開區間後是多少？

看推理

[2, 5)，包括索引 2、3、4。單點 [2, 2] 則換成 [2, 3)。

最小值配最大值，夠不夠？

在排好序的 [−6, −2, 1, 5, 9] 中找總和 6。先算 −6+9=3：−6 已配上剩餘最大值，還是太小，所以任何包含 −6 的候選都可以刪掉。left 向右一格，接著算 −2+9=7，這次排除過大的 9。

有序兩數和

每一步維持的關係

排除端點後，至少一組可能答案仍留在兩端之間。

O(n) 時間、O(1) 額外空間。

候選依序縮成 [−2, 1, 5, 9]、[−2, 1, 5]、[1, 5]，最後回傳索引 (2, 3)。每次移動都有排序提供的大小關係，答案若存在，至少一組仍留在目前兩端之間。

每輪消掉一個端點，總時間 O(n)、額外空間 O(1)。負數與重複值都能處理；迴圈在 left < right 時進行，因此會選到不同位置。未排序資料可使用下一章的補數字典；若先排序，原索引就要隨數值保留。

def two_sum_sorted(nums: list[int], target: int):
    """前置條件：nums 已依非遞減順序排序。回傳兩個不同索引或 None。"""
    left, right = 0, len(nums) - 1
    while left < right:
        current = nums[left] + nums[right]
        if current == target:
            return left, right
        if current < target:
            left += 1
        else:
            right -= 1
    return None
left、right 索引當前元素相加決策動作與推理理由
0、4−6 + 9 = 3總和小於 6，排除不可能有解的 left = 0
1、4−2 + 9 = 7總和大於 6，排除不可能有解的 right = 4
1、3−2 + 5 = 3總和小於 6，排除 left = 1
2、31 + 5 = 6剛好命中目標，回傳 (2, 3)

刪掉元素，保留原來的先後

從 [5, 2, 5, 8] 移除 5 並維持順序。read 每格都讀，write 指向下一個要放保留值的位置。讀到 2 就寫進索引 0，讀到 8 就寫進索引 1，最後回傳有效長度 2。

處理 read 之前，nums[:write] 正好是已讀資料中應保留的內容，而且 write ≤ read。因此每次寫入都落在已經讀過的位置。尾端剩下什麼值不影響有效前綴；需要縮短 list 時，再做 del nums[write:]。

掃描 n 次，時間 O(n)、額外空間 O(1)。若每找到一個目標就 remove，後方元素要反覆搬動；read/write 把所有保留值各搬至多一次。

def remove_value(nums: list[int], unwanted: int) -> int:
    """原地穩定壓縮；僅前 write 個元素是有效輸出。"""
    write = 0
    for read in range(len(nums)):
        if nums[read] != unwanted:
            nums[write] = nums[read]
            write += 1
    return write

固定視窗

每一步維持的關係

sum 等於目前視窗的總和；best 保存已看過的最大值。

O(n) 時間、O(1) 額外空間。

current 保存目前 k 格的總和，best 保存看過的最大值。第一個完整視窗就是初始化 best 的資料：全負數輸入也會得到真正存在的答案，例如 [−5, −2, −4]、k=2 的結果是 −6。

所有長度 k 的視窗都會走到，更新各花常數時間，總時間 O(n)、額外空間 O(1)。這裡容許正負數；視窗何時移動由固定長度決定。

def max_fixed_window_sum(nums: list[int], k: int) -> int:
    if not 1 <= k <= len(nums):
        raise ValueError("k 必須介於 1 與陣列長度之間")
    current = sum(nums[i] for i in range(k))
    best = current
    for right in range(k, len(nums)):
        current += nums[right] - nums[right - k]
        best = max(best, current)
    return best
nums = [4,−2,5,1]，k = 2

k 等於陣列長度時，會比較幾個完整視窗？

看推理

預算超過時，從左端縮回來

每天消耗 [2, 1, 3, 1, 1, 2]，預算 5，要找最長連續天數。右端納入 3 後總和成為 6，就移出左端的 2；總和回到 4，接著繼續擴張。

元素都是非負數時，加入新一天只會增加或維持消耗。某個起點已經超標，之後繼續往右延伸也會超標，所以 left 可以向右移動並永久排除舊起點。縮完後的視窗，是目前右端所能得到的最長合法區間。

left 與 right 都只向右走，各最多 n 次，所以 for 裡有 while 的整體成本仍是 O(n)。同長時保留較早的一段；空輸入或沒有非空解時回傳 (0, 0)。

若資料含負數，例如 [4, −3, 2]、預算 3，整段總和剛好為 3；起初的 4 會被後續負數抵銷。處理這種總和限制，要根據目標改用前綴和與有序查詢；精確等於某值的題目可用下一章的前綴字典。

def longest_budget_window(nums: list[int], budget: int) -> tuple[int, int]:
    """回傳最長合法半開區間；同長時取最早者。僅接受非負整數。"""
    if budget < 0 or any(value < 0 for value in nums):
        raise ValueError("budget 與元素必須非負")
    left = 0
    total = 0
    best = (0, 0)
    for right, value in enumerate(nums):
        total += value
        while total > budget:
            total -= nums[left]
            left += 1
        if right + 1 - left > best[1] - best[0]:
            best = (left, right + 1)
    return best

視窗長度最長與總和最小，能使用相同的 best 更新式嗎？

看推理

best 要直接對應目標。求最長時比較 right+1−left；求總和則比較目前 total。更新狀態與評分方式分別由限制和目標決定。

同一份資料被問很多次

資料不變，卻一直有人問不同區間的總和，就先建立前綴陣列。對 [3, −2, 5, 1]，P=[0,3,1,6,7]；P[i] 是前 i 個元素的總和。

想求 [1,4)，從前四項的 7 扣掉前一項的 3，得到 4。公式 P[right]−P[left] 同時處理整段、單點與空區間，負數也照常相消。

建表 O(n) 時間與空間，m 次查詢再花 O(m)，總計 O(n+m)。若資料改動，後面的前綴值需要更新；頻繁修改與查詢可改選 Fenwick tree 或 segment tree。

加總有可逆運算，區間最大值需要另一種資料結構。例如前 3 項最大值與前 10 項最大值都是 100，後 7 項的最大值可能是 8，也可能是 100，這兩個前綴最大值沒有保存足夠資訊。

def build_prefix(nums: list[int]) -> list[int]:
    prefix = [0]
    for value in nums:
        prefix.append(prefix[-1] + value)
    return prefix


def range_sum(prefix: list[int], left: int, right: int) -> int:
    if not 0 <= left <= right < len(prefix):
        raise ValueError("區間必須符合 0 <= left <= right <= n")
    return prefix[right] - prefix[left]

最短達標區間，更新時機換在哪裡

現在改找總和至少 target 的最短非空區間，資料仍為非負數。當 total 達標，立刻把目前長度當候選，再移出左端，試著縮得更短；一旦不足 target，才等待右端加入新值。

對 [2,1,3,1]、target=4，走到 3 時，總和 6，先記長度 3；移出 2 後總和 4，再記長度 2；接著移出 1 就不達標。答案為 2。

同一個起點一旦已找到達標區間，未來把右端延得更遠只會更長，因此可以繼續丟掉左端。下方實作以 target>0、元素非負為輸入條件，無解回傳 0，時間 O(n)、額外空間 O(1)。

Python · min_length_at_least
def min_length_at_least(nums: list[int], target: int) -> int:
    """最短非空區間：元素非負、target > 0；無解回傳 0。"""
    if target <= 0 or any(value < 0 for value in nums):
        raise ValueError("target 必須為正，元素必須非負")
    left, total = 0, 0
    best = len(nums) + 1
    for right, value in enumerate(nums):
        total += value
        while total >= target:
            best = min(best, right - left + 1)
            total -= nums[left]
            left += 1
    return 0 if best == len(nums) + 1 else best

若等 while 結束後才更新最短長度，會拿到什麼視窗？

看推理

while 是在 total≥target 時縮小，結束時留下的視窗總和已不足 target。有效候選應在每次縮小之前更新。

依重複工作選方法

有序陣列找兩數配對，用左右端點排除一整批候選；保序刪除元素，用 read/write；相鄰固定區間只差兩端，用固定視窗；非負消耗限制下找最長區間，用可變視窗。

資料靜態而區間查詢很多，前綴和把成本搬到第一次建表。選法時就看題目反覆做哪件事，以及哪些資訊可以沿用。

拿全負數測固定視窗、拿零測可變視窗、拿重複值測雙指標，再用空區間檢查前綴和邊界——這些小例子挑的都是會直接改寫更新條件的邊界情境。
