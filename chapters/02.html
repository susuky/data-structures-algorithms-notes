02｜陣列與字串：用邊界減少重複掃描

本章的範例數據與練習敘述為自編。相關 LeetCode 題目列在對應段落旁，標為「相近題型」或「延伸練習」；規格不同處會另行說明。可先依本章題意完成，再開連結練習。

陣列題最常見的浪費，是對重疊區間重複掃描。雙指標把可排除的候選丟掉，滑動視窗把相鄰區間的共同資訊留住，前綴和則先算好各個前綴的總和，再以相減回答區間查詢。這三種方法各有適用前提，不能只因題目提到「連續」就套同一個模板。

本章目標：能證明指標為什麼可以前進、辨認負數何時破壞視窗條件，並用半開區間避免索引錯位。範例的加減、索引與整數比較採固定成本模型。所有「區間」預設連續；子序列可以跳過元素，兩者不同。

1. 先約定索引與區間

長度 n 的 Python list，合法索引是 0 到 n − 1；負索引是語言的便利功能，卻可能掩蓋越界的邏輯錯誤。list 可修改，字串不可修改。Python str 的索引依 Unicode 碼位，不等於使用者眼中的完整字形；組合重音與某些 emoji 可能包含多個碼位。若題目關心「看起來一個字」，需要另外定義文字分割方式。

本章以 [left, right) 表示含左、不含右的半開區間。長度直接是 right − left；空區間可寫成 [i,i)；相鄰的 [a,b) 與 [b,c) 合起來剛好是 [a,c)。注意：程式中兩端夾逼的 two_sum_sorted 使用兩個包含端點的索引，回傳也是元素索引；其餘回傳區間的函式會明寫半開區間，不能混用。

Python 的 nums[left:right] 會建立新 list，長度 k 就需 O(k) 時間與空間。維護一對邊界則只需 O(1) 空間。想驗證目前視窗，可以在小測試中印出切片；正式迴圈若每輪都切片或重新 sum，就可能把線性演算法變回平方級。

2. 左右夾逼：用排序證明整批排除

相近題型：LeetCode 167 · Two Sum II - Input Array Is Sorted。原題也在已排序陣列中找兩數和，但索引從 1 開始且保證恰有一組解。本章索引從 0 開始，允許無解並回傳 None；找到任意一組即可。

問題：給定已依非遞減順序排序的整數陣列，找兩個不同位置使其和為 target；任意一組即可，無解回傳 None。用 left 指向最小、right 指向最大。若兩者和太小，連目前最大的搭檔都不夠，left 不可能和剩餘任何元素成功，因此可以丟掉；太大則對稱地丟掉 right。

def two_sum_sorted(nums: list[int], target: int):
    """前置條件：nums 已依非遞減順序排序。回傳兩個不同索引或 None。"""
    left, right = 0, len(nums) - 1
    while left < right:
        current = nums[left] + nums[right]
        if current == target:
            return left, right
        if current < target:
            left += 1
        else:
            right -= 1
    return None

逐步範例 A：nums = [−6, −2, 1, 5, 9]，target = 6。

left、right相加動作與理由
0、4−6 + 9 = 3太小，排除 left = 0
1、4−2 + 9 = 7太大，排除 right = 4
1、3−2 + 5 = 3太小，排除 left = 1
2、31 + 5 = 6回傳 (2,3)

不變量：如果答案存在，至少有一組完整位於目前的 [left,right] 中。每次排除端點都有上述大小關係支持，所以不會丟掉全部答案。停止於 left ≥ right，表示已沒有兩個不同位置。每輪至少縮短一格，故必定終止。

已排序前提下，時間 O(n)、額外空間 O(1)。負數與重複值都允許。若輸入未排序，不能直接套用；先排序需 O(n log n)，若還要原始索引，就要保留值與索引的配對。第 03 章會用雜湊解未排序版本。

3. 同向雙指標：讀取與寫入分開

相近題型：LeetCode 27 · Remove Element。原題只要求回傳保留元素個數，並把它們放在陣列前端，允許改變順序。本章另要求保留相對順序，使用讀寫指標做穩定壓縮。

問題：原地刪去所有 unwanted，保留其他元素的相對順序，回傳有效長度。read 逐一讀原位置，write 指向下一個可寫位置；遇到要保留的值才寫入並前進。此合約不要求真的縮短 list，因此尾端的舊值不算答案。

def remove_value(nums: list[int], unwanted: int) -> int:
    """原地穩定壓縮；僅前 write 個元素是有效輸出。"""
    write = 0
    for read in range(len(nums)):
        if nums[read] != unwanted:
            nums[write] = nums[read]
            write += 1
    return write

不變量：每輪開始時，nums[:write] 等於原輸入中 read 之前所有應保留的元素，且 write ≤ read。這個不等式保證寫入不會破壞尚未讀取的區域。例如 [5,2,5,8] 刪除 5，最後前兩格是 [2,8]，回傳 2，尾端可能仍有殘值。

時間 O(n)，額外空間 O(1)。若題目要求縮短容器，可另做 del nums[write:]，但要把那一步的工作量算入。直接在 for 迴圈中 remove 元素會移位，也容易跳過相鄰重複值；讀寫指標分別標記「已完成、待處理」的邊界，方便檢查寫入是否安全。

4. 可變視窗：把單調性寫成前提

相近題型：LeetCode 1208 · Get Equal Substrings Within Budget。原題把兩個等長字串各位置的字元碼差絕對值當成成本，求總成本不超過 maxCost 的最長連續子字串長度。本章直接提供非負成本陣列，回傳區間邊界，並額外指定平手取最早。

問題：每天消耗量都是非負整數，找總消耗不超過 budget 的最長連續時段。回傳半開區間，平手選最早；空輸入或沒有非空合法時段回傳 (0,0)。右端加入一天後若超過預算，左端持續移出，直到再次合法。非負性確保：往右加入不會降低總和，從左移出不會增加總和。

def longest_budget_window(nums: list[int], budget: int) -> tuple[int, int]:
    """回傳最長合法半開區間；同長時取最早者。僅接受非負整數。"""
    if budget < 0 or any(value < 0 for value in nums):
        raise ValueError("budget 與元素必須非負")
    left = 0
    total = 0
    best = (0, 0)
    for right, value in enumerate(nums):
        total += value
        while total > budget:
            total -= nums[left]
            left += 1
        if right + 1 - left > best[1] - best[0]:
            best = (left, right + 1)
    return best

逐步範例 B：nums = [2,1,3,1,1,2]，budget = 5。表格記錄縮完後的狀態；right 是本輪剛加入的元素索引。

right加入後總和移出left、剩餘總和目前最優區間
02無0、2[0,1)
13無0、3[0,2)
2621、4[0,2)，平手不更新
35無1、5[1,4)
4612、5[1,4)
5733、4[1,4)

不變量：縮完後 total 等於 nums[left:right+1] 的總和且不超標；所有比 left 更早的起點對目前右端都已知不合法。當某個左端因超標被丟掉，未來再加非負數也無法讓從它開始的區間重新合法。因此目前視窗是以這個右端結尾的最長合法候選，逐輪比較便得到全域最長。

雖然 for 內有 while，left 與 right 都只前進、各最多 n 次，所以總時間 O(n)，空間 O(1)。前面的非負檢查另掃一次，也仍為 O(n)。只保存邊界，沒有複製最長區間；若最終要回傳內容，另計輸出長度。

負數反例：[4,−3,2]，budget = 3。若套同一規則，讀到 4 就將它丟掉，最後只找到長度 2；但整段總和是 3，正解長度 3。負數讓已超標區間可能重新合法，破壞了永久排除的證明。本函式會拒絕負數；混合正負數的精確區間和可改看前綴和與第 03 章的雜湊。

滑動視窗不一定依賴數值非負；例如「不重複字元」可以用集合或計數維護。這些視窗方法都需要確認：擴張造成的違規，能藉單向收縮修復，而且已丟棄的邊界不必回頭。使用前，要先證明這些條件成立。

5. 前綴和：把一段相加換成兩點相減

相近題型：LeetCode 303 · Range Sum Query - Immutable。原題對固定陣列反覆查詢區間總和，sumRange 的左右端點都包含在內。本章使用半開區間。把原題 sumRange(left,right) 的輸入交給本章 range_sum 時，右端點要往後移一格。

若資料固定卻有許多區間加總查詢，預先建 P，令 P[0] = 0，P[i+1] = P[i] + nums[i]。P[i] 表示前 i 個元素的總和，因此 nums[left:right] 的總和恰好是 P[right] − P[left]。負數不會破壞此等式；需要的是加法與減法，而不是單調性。

def build_prefix(nums: list[int]) -> list[int]:
    prefix = [0]
    for value in nums:
        prefix.append(prefix[-1] + value)
    return prefix


def range_sum(prefix: list[int], left: int, right: int) -> int:
    if not 0 <= left <= right < len(prefix):
        raise ValueError("區間必須符合 0 <= left <= right <= n")
    return prefix[right] - prefix[left]

逐步範例 C：輸入 [3,−2,5,1]。

讀入元素目前前綴新增意義
尚未讀入[0]前 0 個元素總和
3[0,3]P[1] = 3
−2[0,3,1]P[2] = 1
5[0,3,1,6]P[3] = 6
1[0,3,1,6,7]P[4] = 7

查 [1,4) 得 7 − 3 = 4；查整段 [0,4) 得 7；查空段 [2,2) 得 0。統一公式不需替 left = 0 寫特例。

不變量：建立到第 i 個邊界時，prefix[i] 正好是原陣列 [0,i) 的和。查詢時共同前綴相消，即得到目標區間。建表 O(n) 時間與空間，m 次查詢 O(m)，合計 O(n + m)。原資料若更新，舊前綴會失效；別把「靜態快速查詢」誤認成「動態更新也快速」。

前綴最大值不能像總和一樣相減：左邊曾出現的最大值，並沒有一個減法可以從全段最大值中移除。決定保存哪種摘要前，先確認能否用它還原所需的區間資訊。二維前綴和則再用容斥扣除重疊，但仍應先把一維的邊界模型練熟。

6. 自編練習與解答

延伸練習：LeetCode 643 · Maximum Average Subarray I。原題求固定長度區間的最大平均值；下方自編練習求最大總和。長度固定時，找到最大總和後除以 k，就得到原題要求的平均值。

練習 1：固定長度時段。給定可含負數的日收益，求長度恰好為 k 的最大連續總和。k 不合法時拋出 ValueError。為什麼這裡負數沒有問題？

參考解答

固定視窗每次移出一個、移入一個，不做「超標就永久排除起點」的推論，所以不需要非負性。初始 best 必須是第一個視窗的和，不能設為 0，否則全負數會出錯。時間 O(n)、額外空間 O(1)；用 generator 建第一個和，避免切片。

def max_fixed_window_sum(nums: list[int], k: int) -> int:
    if not 1 <= k <= len(nums):
        raise ValueError("k 必須介於 1 與陣列長度之間")
    current = sum(nums[i] for i in range(k))
    best = current
    for right in range(k, len(nums)):
        current += nums[right] - nums[right - k]
        best = max(best, current)
    return best

例如 [−5,−2,−4]，k = 2，兩段為 −7 與 −6，應回傳 −6。

延伸練習：LeetCode 209 · Minimum Size Subarray Sum。原題要求正整數陣列中，總和至少 target 的最短連續區間長度，無解回傳 0。下方練習沿用這個目標，但允許元素為零，並檢查不合法輸入。

練習 2：最短達標時段。元素非負、target > 0，求總和至少 target 的最短非空連續長度；無解回傳 0。與最長不超標的更新時機有何不同？

參考解答

目前一旦達標，就先記錄候選，再縮左端，嘗試更短答案；縮到不達標才等待下一個元素。若等縮完才記錄，留下的反而是不合法視窗。每個右端的合法候選在收縮時被檢查；已經記錄並丟掉的左端，未來只會形成更長區間，不可能改進最短答案。

def min_length_at_least(nums: list[int], target: int) -> int:
    """最短非空區間：元素非負、target > 0；無解回傳 0。"""
    if target <= 0 or any(value < 0 for value in nums):
        raise ValueError("target 必須為正，元素必須非負")
    left, total = 0, 0
    best = len(nums) + 1
    for right, value in enumerate(nums):
        total += value
        while total >= target:
            best = min(best, right - left + 1)
            total -= nums[left]
            left += 1
    return 0 if best == len(nums) + 1 else best

[2,1,3,1]、target = 4 的答案是 2。時間 O(n)、空間 O(1)。允許零，但 target 必須為正，避免空區間與收縮條件混淆。

延伸練習：LeetCode 303 · Range Sum Query - Immutable。這題自編練習專門處理原題的包含式端點，與本章半開區間之間的轉換。

練習 3：查詢索引轉換。原始陣列 [3,−2,5,1] 的查詢介面使用「包含左右端點」的 [1,3]。如何呼叫 range_sum？若 left = right 又如何？

參考解答

先建 prefix，再呼叫 range_sum(prefix, 1, 4)，答案 4。包含式 [i,i] 是單一元素，必須轉成半開 [i,i+1)，而不是 [i,i)。最好在介面邊界只轉換一次，內部統一使用同一區間約定。

延伸練習：LeetCode 27 · Remove Element。這題用自編輸入練習原地移除；本章仍比原題多要求保留順序。

練習 4：原地壓縮。對 [7,7,1,7,2] 刪除 7，請手算每一輪 read、write，並說明為什麼不用把被刪元素挪到尾端。

參考解答

處理各位置後的 write 依序是 0、0、1、1、2；前兩格最後為 [1,2]。合約只承諾前 write 格有效，尾端沒有規定。多做交換或尾端整理只會增加不必要工作，甚至破壞穩定性。

7. 邊界測試與章末決策

本章可執行測試窮舉長度 0 至 5、元素取自 {0,1,3} 的 364 組陣列，將可變視窗、前綴查詢、最短達標與壓縮結果對照暴力答案；另用含負數的小陣列驗證已排序配對和固定視窗。負數視窗、負預算、k = 0 與越界查詢皆檢查會被拒絕。這些測試會核對輸出是否符合合約，也會檢查應該拋錯的情況。

資料與問題特徵優先考慮必須能回答
有序資料，找一對或排除端點左右雙指標排除某端點為何不漏解？
原地保序篩選讀／寫指標寫入是否會蓋掉未讀資料？
連續區間，可單向修復限制滑動視窗起點丟掉後為何不用回頭？
固定長度區間統計固定視窗資訊能否移出一項、加入一項？
靜態資料，多次區間加總前綴和摘要能否用相減還原區間？
