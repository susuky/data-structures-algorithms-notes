10．回溯法：選擇、限制與撤銷

在現實開發與演算法挑戰中，我們經常面臨需要連續做出一連串決策的問題：例如為研討會挑選議程組合、為複雜排班規劃順序，或是在字元矩陣中搜尋是否存在某條合法單字路徑。這類問題通常不存在直接套用的數學閉式解，也無法只靠貪心法一步到位。回溯法（Backtracking）將「大膽嘗試一個選擇、走不通就退回原處換個方向再試」的直覺思維，落實為一套具備嚴格不變量與狀態復原機制的樹狀搜尋演算法。我們在遞迴深入時逐步擴充局部候選解，在遭遇死胡同時精準回滾狀態，進而系統性地探索整座決策空間。

撰寫回溯函式的黃金法則，在於每次進入遞迴時明確界定三件事：當前的局部狀態是什麼？當前層級有哪些合法候選決策？何時達到遞迴邊界並記錄解答？而最核心的工程細節，則是在子呼叫返回時完全恢復當前層級所做的所有可變修改，並在保存答案時進行深層或獨立拷貝。

典型適用信號：需要窮舉列出所有符合條件的子集合、排列或多約束棋盤配置；問題規模較小（通常 $n \le 20$），允許指數級別的搜尋複雜度。若問題只要求「可行解的數量」或「全域極值」，且不同決策路徑抵達同一狀態後「未來的子問題完全重疊」，那麼下一章的動態規劃（DP）會是效率高出數個量級的解法。

10.1 把候選答案畫成決策樹

LeetCode 78．Subsets。元素互異時，每組索引對應唯一的值子集合。

理解回溯法的最佳視角，是將潛在的搜尋空間具象化為一棵「隱式決策樹（Implicit Decision Tree）」：樹上的每個節點代表當前已構造出的局部解；從節點延伸出的每一條分支邊，代表在此刻做出的一個具體選擇；而整棵樹的所有葉節點，則對應到一個個完整走訪完畢的候選結果。以子集合問題為例，每個位置只有「選」與「不選」兩條分支；排列問題每層則從剩餘未使用的元素中挑選一個；網格搜尋則是向上下左右的未走訪鄰居推進。回溯法本質上就是用深度優先搜尋（DFS）在這棵隱含樹上穿梭，完全不需要在記憶體中真正建構出整棵樹的實體結構。

以兩張不同卡片 A、B 為例，針對每個元素逐一做出選或不選的二元決策，整棵樹恰好有 $2^2 = 4$ 個葉節點，分別對映到一個子集合。演算法的核心不變量是：當進入 dfs(i) 時，前 i 個元素的取捨決策已全數拍板定案，path 清單忠實記錄了其中被選中的所有元素，且元素相對次序與原始輸入完全一致。當索引 $i$ 推進到陣列長度時，遞迴必然抵達葉節點邊界並保存結果。

def subsets(items):
    """items 中的位置視為不同選項；若值相同，輸出可能值相同。"""
    answer, path = [], []

    def dfs(i):
        if i == len(items):
            answer.append(path.copy())
            return
        dfs(i + 1)                 # 不選第 i 個
        path.append(items[i])      # 選擇
        dfs(i + 1)                 # 探索
        path.pop()                 # 撤銷

    dfs(0)
    return answer

逐步例子一：從 [] 到 [A,B]，再回到 []

步驟目前呼叫／動作path已儲存答案
1不選 A，不選 B，到 i=2[][[]]
2回到 i=1，選 B[B][[],[B]]
3撤銷 B，回到 i=0，選 A[A]不變
4不選 B，到 i=2[A]再加入 [A]
5回到 i=1，選 B，到 i=2[A,B]再加入 [A,B]
6先撤銷 B，再撤銷 A[]四份獨立的答案保留下來

為何既不重複也不遺漏？因為長度為 $n$ 的集合中的任意子集，在數學上都唯一對應到一串長度為 $n$ 的 0/1 決策序列。程式完整走遍了二元樹的所有分支，因此必然覆蓋全域；而任何兩個不同葉節點的路徑，至少在某個索引位置的決策截然不同，因此產生的索引集合絕對互不相同。需要注意的是：若輸入原本就帶有重複元素（例如 [A, A]），分別挑選第一個 A 與第二個 A 會產生數值相同的 [A]；若要做到數值組合的唯一性，就必須配合預先排序與同層剪枝技巧。

複雜度分析：$n$ 個互異元素共產生 $2^n$ 個子集合。雖然走訪整棵決策樹僅需 $O(2^n)$ 次遞迴呼叫，但將每個長度平均為 n/2 的 path 拷貝存入 answer 清單，總共需要 O(n \cdot 2^n) 的時間與輸出空間！遞迴呼叫堆疊的最大深度為 $n$，因此輔助空間僅需極度精簡的 $O(n)$。若輸入為空清單，函式亦能正確回傳 [[]]。

10.2 返回上一層時，恢復原狀

在回溯演算法中，為了避免在每一層遞迴都耗費高昂代價去拷貝全新的清單或狀態物件，我們通常會讓所有分支「共享同一份可變狀態（Mutable State）」。共享帶來的極致記憶體效益背後，必須嚴格遵守一項鐵律：函式在進入某一分支前所做的任何狀態變更，在該分支執行完畢返回時，必須百分之百精確復原！具體在程式碼中表現為完美的鏡像對稱：append 必定配對 pop()、集合的 add() 必定配對 remove()、布林旗標的 used[j] = True 必定配對 used[j] = False。只有當現場被乾淨復原，下一個平行的兄弟分支才能在不受任何污染的基準狀態下展開探索。

請務必警惕「物件參考共享」的經典新手 Bug：在終止條件處，若寫成 answer.append(path)，存入清單的只是指向這份全域 path 的記憶體指標！當後續回溯執行 path.pop() 時，先前儲存在 answer 裡的所有歷史紀錄都會跟著一起被清空，最終回傳一大串空清單。使用 path.copy() 建立當前時間點的淺拷貝快照是不可或缺的防護。雖然有些開發者偏好在傳參時寫成 dfs(path + [x]) 來規避手動撤銷，但每次串列拼接都會額外配置記憶體並耗時 $O(\text{len})$，在遞迴深度深時會造成巨大的效能浪費。

提早返回的撤銷黑洞：在某些「只需尋找單一合法解」的題目中，如果一找到答案就衝動地直接 return True，往往會直接跳過後續的狀態撤銷程式碼！這會導致全域共用的 used 集合遺留髒資料。若要實作短路提早返回，務必將結果暫存並執行撤銷後再 return，或是利用 try ... finally 結構強制保證現場復原。

10.3 組合與排列：下一層可以選誰？

LeetCode 47．Permutations II。列出不重複的完整排列。

搞清楚「組合（Combination）」與「排列（Permutation）」在回溯狀態轉移上的本質差異，是演算法進階的分水嶺：

  • 組合問題（順序無關）：例如 [2, 5] 與 [5, 2] 被視為完全相同的解。為了防止重複計算，我們透過傳遞 start 索引，硬性規定後續只能從當前索引更右邊的位置挑選元素。若每個元素限用一次，子呼叫傳入 j + 1；若允許同一元素重複取用（如零錢兌換），則傳入 j。
  • 排列問題（順序有關）：下一層遞迴可以挑選陣列中「任何一個之前尚未被使用的元素」。因為挑選方向不再限於往右，我們無法使用 start 指標，必須引入一個全長為 $n$ 的布林陣列 used 來精確追蹤各個位置的佔用狀況。

當輸入陣列包含重複元素時，排列的去重是一大難點。先對陣列進行遞增排序，讓相同數值緊密聚集在一起。接著引入關鍵的同層剪枝不變量：在同一層遞迴中，只有當位於前方的相同數值已經被納入 path 使用時，後方的相同數值才被允許使用。若前一個相同數值依然處於 used[j - 1] == False 的閒置狀態，代表當前分支正試圖開啟一個「以相同數值作為該位置選擇」的平行分支，此時果斷 continue 跳過，即可完美斬斷所有重複排列！

def unique_permutations(items):
    values = sorted(items)
    used = [False] * len(values)
    answer, path = [], []

    def dfs():
        if len(path) == len(values):
            answer.append(path.copy())
            return
        for j, value in enumerate(values):
            if used[j]:
                continue
            # 同層中，先使用前一個相同值，固定相同值的相對次序。
            if j > 0 and values[j] == values[j - 1] and not used[j - 1]:
                continue
            used[j] = True
            path.append(value)
            dfs()
            path.pop()
            used[j] = False

    dfs()
    return answer

數學上，若各相異數值的重複頻率分別為 $c_1, c_2, \dots$，其理論相異排列數為多項係數 $n! / (c_1! c_2! \dots)$。上述程式保證了每個合法相異排列被且僅被生成一次。演算法的時間複雜度上限為 $O(n \cdot n!)$，輔助空間為 $O(n)$，精準實現了非重複排列的窮舉。

10.4 剪枝必須有證明：正值包裹挑選

LeetCode 40．Combination Sum II 的延伸：增加「恰好挑 k 件」的限制。

「剪枝（Pruning）」是回溯法能在嚴苛測資下生存的靈魂。如果我們能在走到葉節點之前，就透過數學論證提前斷言「當前子樹絕不可能誕生任何可行解」，那我們就可以毫不猶豫地砍掉這整條分支。然而請牢記：任何剪枝條件都必須具備無懈可擊的邏輯證明，絕不能憑僥倖心理隨意截斷。

考慮問題：從一批正整數重量中「恰好挑選 k 件」使得總重等於 target，每個位置至多用一次，且結果不得重複。我們在先排序的基礎上，維護狀態三元組 (start, need, remain)，並建立前綴和陣列以實現 $O(1)$ 的極限剪枝：

  1. 數量剩餘不足：若當前剩餘的可用元素總數小於尚需挑選的件數（即 $n - start < need$），件數根本湊不齊，立即返回。
  2. 最小理論總和超標（下界剪枝）：若哪怕挑選接下來最輕的 need 件物品，其重量總和 smallest 依然嚴格大於 remain，那後面更重的組合絕不可能達標，立即返回。
  3. 最大理論總和不足（上界剪枝）：若哪怕挑選全域最重的 need 件物品，其重量總和 largest 依然小於 remain，說明再怎麼湊也湊不到目標重量，立即返回。
  4. 單調跳轉：因為陣列已經由小到大排序且全為正數，在迴圈中一旦遇到 values[j] > remain，後續所有的元素只會更大，此處可直接使用 break 徹底中斷當層搜尋！
def choose_k_sum(numbers, k, target):
    """恰選 k 個位置、每個至多一次；回傳不重複的值組合。"""
    if k < 0 or any(x <= 0 for x in numbers):
        raise ValueError("k 必須非負，數值必須為正整數")
    values = sorted(numbers)
    n = len(values)
    prefix = [0]
    for x in values:
        prefix.append(prefix[-1] + x)
    answer, path = [], []

    def dfs(start, need, remain):
        if need == 0:
            if remain == 0:
                answer.append(path.copy())
            return
        if n - start < need:
            return
        smallest = prefix[start + need] - prefix[start]
        largest = prefix[n] - prefix[n - need]
        if remain < smallest or remain > largest:
            return
        for j in range(start, n - need + 1):
            if j > start and values[j] == values[j - 1]:
                continue
            if values[j] > remain:
                break
            path.append(values[j])
            dfs(j + 1, need - 1, remain - values[j])
            path.pop()

    dfs(0, k, target)
    return answer

請特別注意剪枝成立的前提邊界：values[j] > remain 之所以能大膽 break，是百分之百依賴「所有數值均為正整數」且「已排序」的假設！如果題目允許負數（例如 [-3, -2] 湊 -5），第一個候選 $-3 > -5$，若按此規則 break 就會當場把正確解答誤殺。面對含有負數的場景，必須拔除這個局部大小判斷，轉而完全依賴剩餘項目的上下界區間來做剪枝判定。

10.5 多重限制：一列一列放皇后

LeetCode 51．N-Queens。這裡以每列皇后的欄索引回傳配置；原題回傳棋盤字串。

在 $n \times n$ 的國際象棋棋盤上擺放 $n$ 個皇后，使其互不攻擊（即任意兩個皇后不可處於同一行、同一欄、或同一正反對角線上）。面對這種多重交互約束問題，聰明的狀態建模能讓搜尋難度大幅降低：

我們將「每一列恰好放置一個皇后」直接內化為搜尋樹的遞迴深度。也就是說，dfs(row) 天生就保證了列與列之間絕不衝突，我們完全不需要額外追蹤列的狀態！對於其餘的三大幾何限制，我們利用代數幾何性質以三個集合（Set）在 $O(1)$ 內判定：

  • 直行衝突：位於同一欄的格子，其 col 座標必相等。使用 columns 集合記錄。
  • 主對角線衝突（左上至右下）：沿著斜率為 1 的對角線移動時，列座標與欄座標同增同減，因此常數特徵為 row - col 恆定。使用 diagonal_down 集合記錄。
  • 副對角線衝突（右上至左下）：沿著斜率為 -1 的對角線移動時，列增則欄減，因此常數特徵為 row + col 恆定。使用 diagonal_up 集合記錄。
def queens_columns(n):
    """每個解是一串欄編號，第 r 個值表示第 r 列皇后的欄。"""
    if n < 0:
        raise ValueError("n 必須非負")
    columns, diagonal_down, diagonal_up = set(), set(), set()
    path, answer = [], []

    def dfs(row):
        if row == n:
            answer.append(path.copy())
            return
        for col in range(n):
            if (col in columns or row - col in diagonal_down
                    or row + col in diagonal_up):
                continue
            columns.add(col)
            diagonal_down.add(row - col)
            diagonal_up.add(row + col)
            path.append(col)
            dfs(row + 1)
            path.pop()
            columns.remove(col)
            diagonal_down.remove(row - col)
            diagonal_up.remove(row + col)

    dfs(0)
    return answer

這段實作的對稱美感極高：進入 dfs(row) 時，不變量保證前 row 行的皇后皆已安頓且互不攻擊；在子呼叫結束後，透過三組 remove() 與 path.pop() 乾淨還原集合。得益於對角線的強大剪枝，實際探索的節點數遠小於 $O(n!)$，輔助空間僅需線性的 $O(n)$。

10.6 回溯、DFS 與記憶化的分界

在技術交流中，「DFS」與「回溯」經常被混為一談。嚴格來說：DFS 是一種走訪圖或樹的遍歷拓撲策略；而回溯法則是特指在 DFS 的基礎上，引入「主動做出假設、深入探查、隨後完全復原狀態」的決策架構。在標準的圖形 DFS 中，全域的 visited 陣列一旦標記為 True 就永遠不會取消，目的是防止無向環引發無窮迴圈；但在回溯演算法中，used 標記僅代表當前探查路徑上的局部佔用，一旦退回父節點就必須立刻解除標記。若把回溯當成純 DFS 而忘記清理，就會把其他方向合法的解永久封殺。

另一個常見的迷思是「能不能給回溯法隨手掛上 @lru_cache 進行記憶化？」。請記住：只有當狀態鍵值完全封裝了未來所有決策所需的所有資訊時，記憶化才合法。在網格搜尋單字問題中，很多初學者試圖用 (r, c, i) 作為快取 key，這是一個嚴重的邏輯錯誤！因為即便兩次呼叫都處於相同的座標 $(r, c)$ 且比對到相同的單字索引 $i$，但兩次抵達該處時「歷史路徑已經踩過哪些格子（即 used 集合）」可能截然不同，這會導致後續能走的剩餘鄰居完全不同。如果貿然快取布林值，先前失敗的路徑會把後續原本能成功的其他路徑一併扼殺。若要正確記憶化，key 必須包含 used 狀態，但這會讓狀態空間直接爆炸，失去記憶化的意義。

在編號 0 到 n−1 的時段中，可以自由挑選任意多個時段，但限制「不可挑選相鄰時段」。請列出所有合法的時段編號組合（含空組合）。先手算 n=3，再實作不重複的回溯搜尋。

參考解答

在每個位置 $i$，我們面臨兩難決策：若「不選 $i$」，則下一層可考慮 $i + 1$；若「選擇 $i$」，則下一個合法候選時段必須跳至 $i + 2$！手算 $n=3$ 的合法組合共 5 種：[]、[2]、[1]、[0]、[0, 2]。程式碼如下：

def nonadjacent_slots(n):
    if n < 0:
        raise ValueError("n 必須非負")
    answer, path = [], []

    def dfs(i):
        if i >= n:
            answer.append(path.copy())
            return
        dfs(i + 1)
        path.append(i)
        dfs(i + 2)  # 下一格不能選
        path.pop()

    dfs(0)
    return answer

令合法解數量為 $R(n)$，其遞迴關係恰好滿足費氏數列：$R(n) = R(n - 1) + R(n - 2)$，總解數呈指數級增長。含解答拷貝的總時間為 $O(n R)$，空間複雜度為 $O(n)$。

練習二：合法的巢狀括號

LeetCode 22．Generate Parentheses。n=2 的答案是 ["(())","()()"]。

給定正整數 $n$，產生所有由 $n$ 對括號組成的合法閉合字串。如何從前綴不變量出發直接剪枝，而不需要先暴力生成 $2^{2n}$ 個字串再去過濾？

參考解答

維護兩個計數器：已使用的左括號數 opened 與右括號數 closed。核心不變量是：在任何合法前綴中，右括號數量絕不能超過左括號數量。因此生成規則非常單純：只要 opened < n，就允許嘗試放入 (；只要 closed < opened，就允許嘗試放入 )。當 closed == n 時收斂儲存。程式實作：

def balanced_parentheses(n):
    if n < 0:
        raise ValueError("n 必須非負")
    answer, path = [], []

    def dfs(opened, closed):
        if closed == n:
            answer.append("".join(path))
            return
        if opened < n:
            path.append("(")
            dfs(opened + 1, closed)
            path.pop()
        if closed < opened:
            path.append(")")
            dfs(opened, closed + 1)
            path.pop()

    dfs(0, 0)
    return answer

合法解的數量嚴格等於第 $n$ 個卡塔蘭數（Catalan Number）$C_n = \frac{1}{n+1}\binom{2n}{n}$，總運算時間與輸出空間皆為 $O(n C_n)$，無任何無效分支浪費。

練習三：字卡格子尋路

LeetCode 79．Word Search。空 word 回傳 True；空棋盤搭配非空 word 回傳 False。

在二維字元矩陣中搜尋是否存在某條相鄰路徑能拼出單字 word，路徑不可重複踏足同一個格子。若字串在深層搜尋提早成功返回，如何確保全域狀態依然被安全清理？

參考解答

利用 try ... finally 機制：無論子遞迴是提早返回 True 還是遍歷失敗返回 False，finally 區塊中的 used.remove((r, c)) 都享有最高保證必定會被執行，徹底杜絕狀態殘留。實作範式：

def word_exists(board, word):
    """矩形字元格；上下左右相鄰，同一次路徑不得重複使用格子。"""
    if not word:
        return True
    if not board:
        return False
    rows, cols = len(board), len(board[0])
    if any(len(row) != cols for row in board):
        raise ValueError("board 必須為矩形")
    if cols == 0 or len(word) > rows * cols:
        return False
    used = set()

    def dfs(r, c, i):
        if (r < 0 or r >= rows or c < 0 or c >= cols
                or (r, c) in used or board[r][c] != word[i]):
            return False
        used.add((r, c))
        try:
            if i == len(word) - 1:
                return True
            return any(dfs(r + dr, c + dc, i + 1)
                       for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)))
        finally:
            used.remove((r, c))  # 成功提早回傳時也必定撤銷

    return any(dfs(r, c, 0) for r in range(rows) for c in range(cols))

設網格總格數為 $RC$，單字長度為 $L$。因為每一步不能立即折返走上一格，單一搜尋分支度至多為 3，時間複雜度上界為 $O(RC \cdot 3^L)$，呼叫堆疊輔助空間僅為 $O(L)$。

  • 需求是列舉全量答案：先估算答案總數的理論規模；若解答本身高達數百萬，那是天生輸出的物理限制，換任何演算法都省不掉。
  • 組合與排列的核心分流：組合靠 start 鎖定單向遞增；排列靠 used 追蹤佔用狀態並在同層跳過未啟動的前一相同元素。
