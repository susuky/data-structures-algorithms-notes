12．面試工具箱：把懂的演算法變成可檢查的解答

辨認出演算法後，還要能說清楚解法。面試時，你要把含糊的題意整理成明確介面，說明為什麼方法適用，寫出能維護的不變量，最後用測試與成本分析驗證。本章提供一份可調整的流程、Python 速查及兩個完整原創模擬題，可直接用於計時練習與解題檢討。

練習方式：先遮住解答，給自己 35–45 分鐘完成其中一題。把口頭解釋寫成三句話：輸入保證什麼、每一步維護什麼、為什麼不漏掉答案。可依自己的練習進度調整計時長度。

1. 面試六階段：每一階段都要有可確認的結果

  1. 澄清契約：輸入型別及範圍、空輸入、重複值、負值、是否有序、可否改動輸入、無解回傳值、平手規則。只問會改變演算法或輸出的問題。
  2. 建立基準解：先說最直接的正確作法與成本。例如枚舉所有子陣列，再檢查條件。它可以當作小輸入的測試 oracle。
  3. 找可改進的地方：重複計算的總和能否用前綴和處理？重複查找能否用 hashing？移動邊界是否有單調性？套用模板前，先確認這些條件是否成立。
  4. 實作：先說不變量與資料結構，再寫主迴圈。變數名稱能反映意義；先完成清楚的解法，再考慮微調。
  5. 驗證：手追一個一般案例、一個邊界、一個容易破壞直覺的反例；解釋每個索引的範圍。
  6. 收尾與延伸：時間、輔助空間、輸出空間分開說；限制改變時，要重新檢查原本的證明。

卡住時可說：「暴力法會重複檢查相同的區間，我正在找能增量更新的狀態。」這比長時間沉默更具體。如果還沒確定怎麼改進，先保留可驗證的基準解。程式寫完後，也要檢查空輸入，才算完成。

4. 原創模擬一：挑一段監測紀錄

LeetCode 904．Fruit Into Baskets 的延伸：種類上限改成 k，回傳半開索引，同長取最早。

題目：感測系統依時間留下標籤序列 labels。分析畫面一次最多能顯示 k 種不同標籤。請找最長的一段連續紀錄，使其中標籤種類數至多為 k，回傳半開索引 (left, right)。同長選最早開始；空輸入或 k=0 回傳 (0,0)。本題假設 0≤n≤200,000，k 是非負整數，標籤為可雜湊字串，不可修改輸入。

範例 labels=[A,B,A,C,C,B,B]、k=2，答案 (3,7)，對應 C,C,B,B。

基準解：枚舉 O(n²) 個區間，每次重建 set 最壞 O(n)，總 O(n³)。若每個左端固定後漸進擴張並更新 set，可降到 O(n²)，仍不適合本題設定。進一步觀察：右端每加入一個標籤，只需更新一次計數；若種類太多，左端一直移到合法為止。

def longest_label_window(labels, k):
    """回傳至多 k 種標籤的最長半開區間；同長時選最早。"""
    if k < 0:
        raise ValueError("k 不可為負")
    counts = {}
    left = 0
    best = (0, 0)
    for right, label in enumerate(labels):
        counts[label] = counts.get(label, 0) + 1
        while len(counts) > k:
            old = labels[left]
            counts[old] -= 1
            if counts[old] == 0:
                del counts[old]
            left += 1
        if right + 1 - left > best[1] - best[0]:
            best = (left, right + 1)
    return best

正確性：while 結束後，counts 正好記錄 [left,right+1) 內的正次數標籤，種類數不超過 k。左端只在不合法時移動；較早被排除的左端，在增加更多右端元素後仍不可能重新合法。因此當前 left 是這個 right 下能保留的最早合法左端，所得視窗是以 right 結尾的最長合法視窗。遍歷所有 right，就覆蓋了全域最優解。同長不更新，保留最早找到的答案；同長區間依 right 增加，left 也增加，所以符合最早規則。

逐步追蹤

right / 新標籤收縮後 left有效計數本輪長度最佳 [L,R)
0 / A0A:11[0,1)
1 / B0A:1,B:12[0,2)
2 / A0A:2,B:13[0,3)
3 / C2A:1,C:12[0,3)
4 / C2A:1,C:23[0,3)
5 / B3C:2,B:13[0,3)
6 / B3C:2,B:24[3,7)

加入第一個 C 時，不是左端移一次就好：移除第一個 A 仍有 A、B、C 三種，必須再移除 B。因此這裡必須用 while，不能用 if。

兩個指標各最多移動 n 次，雜湊平均 O(1) 的假設下總時間 O(n)。計數表穩定時至多 k 種，加入新值瞬間至多 k+1 種，因此額外空間 O(min(n,k+1))；k=0 仍可能短暫存一個鍵。回傳索引為 O(1) 輸出；若回傳整段 labels[L:R]，還要 O(答案長度) 複製。

面試延伸：如果資料是無法回頭讀的串流，移除左端仍要知道舊標籤，就需保留視窗中的資料或其他足夠資訊。若保存整個視窗，空間會隨視窗長度成長。

5. 原創模擬二：園區接駁轉乘

題目：園區站點用非空字串命名，graph[u] 是可直接從 u 前往的站點，路線有方向，每搭一段都算一次。給起點 start 與終點 goal，回傳搭乘段數最少的站點路徑；無法抵達回傳 []，起終點相同回傳 [start]。鄰接表沒出現的站點視為沒有出邊；可能有環與重複邊。同長路徑任取，這份實作按鄰接順序選。

本例：S→A、B；A→C；B→C、T；C→S、T；T 沒有出邊。求 S 到 T。

這是無權最短路徑，BFS 佇列按距離層次處理。用 parent 同時記錄「已發現集合」與「路徑來源」：在節點入列時就記錄它，而非出列時才標記，可避免多個來源反覆加入同一節點。起點以 None 作父節點哨兵，因此此介面禁止節點本身為 None。

from collections import deque

def shortest_route(graph, start, goal):
    """無權有向圖；鄰接順序決定同長路徑的選擇。"""
    parent = {start: None}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        if node == goal:
            path = []
            while node is not None:
                path.append(node)
                node = parent[node]
            return path[::-1]
        for neighbor in graph.get(node, ()):
            if neighbor not in parent:
                parent[neighbor] = node
                queue.append(neighbor)
    return []

正確性：佇列中節點按起點距離不減排列。從距離 d 的節點第一次發現鄰居時，距離為 d+1；若存在更短的路，該更短路的前一個節點應更早出列並先發現它，矛盾。因此第一次記錄的父節點鏈即為最短路徑，遇到終點後逆向追 parent 並反轉即可。

逐步追蹤

本輪出列新增 parent處理後 queue說明
初始化S:None[S]起點已發現
SA:S、B:S[A,B]距離 1
AC:A[B,C]C 距離 2
BT:B[C,T]C 已發現，不再入列
C無[T]S、T 都已發現
T無[]反向 T→B→S，輸出 S→B→T

設可達區域有 V 個節點、E 筆鄰接項，最壞時間 O(V+E)，額外空間 O(V)。重建長度 L 的路徑需 O(L) 時間與輸出空間；path[::-1] 也建立新串列，仍在 O(V) 總界內。若邊有不同非負耗時，改用 Dijkstra 求最短時間；BFS 求的是最少邊數。

6. 常用模板與不變量

上面兩題已提供視窗與 BFS 模板。這裡再補上兩個短模板，方便搭配前章的方法使用。使用每份模板前，都要確認輸入契約；修改條件後，先重新讀一遍註解與不變量。

模板 A：有序序列中的第一個不小於目標的位置

LeetCode 35．Search Insert Position。本模板也接受重複值與空陣列。

def first_at_least(values, target):
    lo, hi = 0, len(values)
    while lo < hi:
        mid = (lo + hi) // 2
        if values[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

前提是非遞減且支援隨機存取；[0,lo) 都小於 target，[hi,n) 都不小於 target，返回值可能為 n。O(log(n+1)) 時間，O(1) 額外空間。若題目允許標準庫，可用 bisect_left，但仍要能解釋回傳語意。

模板 B：含負數也能計數的前綴和

LeetCode 560．Subarray Sum Equals K。計算總和等於目標的非空子陣列數量。

def count_target_sum(values, target):
    """連續非空子陣列總和；支援負值。"""
    seen = {0: 1}
    total = answer = 0
    for value in values:
        total += value
        answer += seen.get(total - target, 0)
        seen[total] = seen.get(total, 0) + 1
    return answer

在目前前綴 total，若某個更早前綴等於 total−target，兩者之間的非空子陣列和就是 target。seen={0:1} 代表空前綴，讓從索引 0 開始的答案被計入；一定要先查再加入當前前綴，避免 target=0 時把長度零的區間算進去。在雜湊平均常數時間下，時間 O(n)、空間 O(n)。

測 [2,−2,2]、target=2：三個答案是索引 [0,1)、[2,3)、[0,3)。這個模板數的是「有幾個」，不是回傳所有區間；若要列舉，需儲存前綴出現的索引，還要算輸出量。

7. 驗證清單：不用大量例子，也要命中風險

  • 形狀：空、一個元素、全部相同、嚴格遞增或遞減、極端偏斜的樹、稠密或不連通的圖。
  • 邊界：k=0、k≥n、答案在第一格或最後一格、完全無解、起終點相同。
  • 狀態：計數降到零有沒有刪鍵？visited 是否在入列標記？回溯離開前是否撤銷？前綴和先查還是先記錄？
  • 回傳契約：半開還是閉區間？回傳值、索引、數量還是路徑？平手結果是否確定？
  • 成本：雙層迴圈是否真是平方，還是每個指標只移一次？是否在迴圈中反覆切片或排序？

把最佳化版與基準解放在同一份小規模測試裡，用窮舉或固定種子的亂數比較。若有多個合法答案，驗證條件與最優值，不要只比某一條路徑。為了讓示範結果一致，這份教材已明訂同長視窗的選法及 BFS 鄰接順序。

8. 練習與面試追問

練習一：忘記刪除零次數的鍵

視窗程式把 counts[old] 減到零，但沒有 del。對 [A,B]、k=1，可能發生什麼事？

參考解答

加入 B 後字典有 A、B 兩鍵。移除 A 後 A:0 還在，len(counts) 仍是 2，所以 while 繼續收縮，甚至移到陣列範圍外。字典長度要代表種類數，就必須只保留正次數；另一種做法是另存 distinct 計數並正確維護。

練習二：BFS 能處理不同票價嗎？

S→T 票價 20；S→A、A→T 各 3。想找最低總票價，原模板會錯在哪裡？

參考解答

BFS 會偏好一段的 S→T，但兩段 S→A→T 只要 6。模板的不變量是最少邊數，不是最低總成本。非負票價可用 Dijkstra；最小堆積應按累積成本取出下一個狀態。

練習三：前綴和加入順序

對 values=[0,0]、target=0，正確有幾個非空子陣列？如果先增加 seen[total] 再查會多算什麼？

參考解答

正確三個：[0,1)、[1,2)、[0,2)。先更新會在每輪把當前前綴與自己配對，各多算一個空區間，兩輪後錯得 5。先查歷史、再登記現在，就只配對嚴格較早的前綴。

練習四：口頭複雜度修正

「我用 sorted 找中位數，只保留一個答案，所以空間 O(1)。」如何修正？

參考解答

sorted 會建立 n 個元素的新串列，排序本身也有工作記憶體，總額外空間 O(n)；輸出雖只有一個值，不能忽略中間資料。時間最壞 O(n log n)。若討論其他選擇演算法，需另說實作、是否改動原陣列與最壞成本。

9. 自評與下一輪練習

每題用五項各 0–2 分自評：契約是否明確、方法是否有理由、程式是否完整、測試是否命中邊界、成本是否包含隱藏工作。用這份練習量表追蹤不同面向的進步。依照低分項目安排下一次練習，例如「寫迴圈前先口述不變量」，才知道要改進哪裡；只多刷題還不夠。
