12 · 把解題方法接成完整答案

這章用兩個小型模擬題串起前面的工具：一題追蹤連續資料，一題規劃轉乘路線。從輸出規格一路走到實作、推理與測試。

把思路變成一條可追蹤的過程

拿到題目，把一組小輸入與預期輸出寫出來。例如標籤 [A,B,A,C]、最多兩種，應回傳哪個區間？同長時選哪段？這些決定會直接落在比較式與回傳值。

先走一遍最直接的解法，找出重複工作。枚舉每個起點再往右掃會重算很多區間；頻率與左右邊界能把相鄰區間接起來。

實作時保持一條連續說明：目前狀態代表什麼、下一步為何可行、何時更新答案、每項資料共處理幾次。這樣程式與理由會使用同一組變數。

「同長取最早」會讓更新最佳答案的比較用 > 還是 ≥？

看推理

用 >。只有嚴格更長才更新，後面同長的候選就不會覆蓋較早答案。

從限制找出能沿用的資訊

題目給排序資料，可試整批排除候選的雙指標或二分；要求連續區間，可看相鄰視窗是否能增量更新；要向過去找值或次數，可設計雜湊鍵。

每次只取目前最重要候選，用堆積；所有邊等成本的最短路徑，用 BFS；選擇互相影響且需列舉，畫回溯樹；不同路徑反覆遇到相同子問題，試記憶化或 DP。

限制可以幫你排除無效方法。負數會改變部分視窗的單調性，邊權會改變最短路徑順序，原索引要求會影響是否可直接排序。

把每一行背後的工作補上

外層迴圈 n 次，裡面若呼叫 list.count、list.index 或建立長切片，總成本就需要乘上該次掃描或複製量。程式行數少，工作量仍可能很大。

用 deque 做 FIFO，避免反覆 pop(0)；字串片段使用 join；比較長字串鍵時，計入鍵生成與相等性成本。排序的 key 通常每項計算一次，重複二分的 key 則可能反覆計算。

時間統計整個過程，空間看同時保留的峰值。輸出答案的清單、遞迴路徑、候選容器，各自依實際大小計算。

最多 k 種標籤，保留最長一段

監測紀錄是 [A,B,A,C,C,B,B]，要選至多兩種標籤的最長連續區間。右端加入新標籤，頻率加一；種類超過 k，就從左端移出直到重新合法。

最多 k 種標籤

每一步維持的關係

頻率字典只保存視窗內的種類；數量歸零就刪除該鍵。

平均 O(n) 時間、O(min(n,k+1)) 額外空間。

頻率歸零時刪掉鍵，讓 len(counts) 正好表示視窗內種類。每輪縮完得到以目前 right 結尾的最長合法區間，再與 best 比較。此例最佳 [3,7) 是 C,C,B,B，長度 4。

回傳半開區間，同長取較早。k=0 與空輸入回傳 (0,0)，k<0 回報 ValueError。左右端各前進至多 n 次，平均時間 O(n)，頻率字典大小受目前種類數限制。

def longest_label_window(labels, k):
    """回傳至多 k 種標籤的最長半開區間；同長時選最早。"""
    if k < 0:
        raise ValueError("k 不可為負")
    counts = {}
    left = 0
    best = (0, 0)
    for right, label in enumerate(labels):
        counts[label] = counts.get(label, 0) + 1
        while len(counts) > k:
            old = labels[left]
            counts[old] -= 1
            if counts[old] == 0:
                del counts[old]
            left += 1
        if right + 1 - left > best[1] - best[0]:
            best = (left, right + 1)
    return best

園區接駁，找最少搭車次數

每一站是一個節點，有向邊表示可直接搭到另一站，每搭一段算一次。用 BFS 找最少邊數，再由 parent 回推出完整站點路徑。

起點先加入 parent，值為 None。首次發現鄰站時保存前一站；若有多條同長路徑，鄰接清單的順序決定先找到哪條。

shortest_route 的起終點相同時回傳 [start]，不可達回傳 []。時間 O(V+E)、空間 O(V)。若改成總行車時間最少，就把每條邊的時間納入權重並使用相應最短路徑方法。

from collections import deque

def shortest_route(graph, start, goal):
    """無權有向圖；鄰接順序決定同長路徑的選擇。"""
    parent = {start: None}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        if node == goal:
            path = []
            while node is not None:
                path.append(node)
                node = parent[node]
            return path[::-1]
        for neighbor in graph.get(node, ()):
            if neighbor not in parent:
                parent[neighbor] = node
                queue.append(neighbor)
    return []

最少轉乘與最短時間，對同一張交通網可能給出不同路線嗎？

看推理

會。一段直達可能耗時 40 分鐘，兩段各 10 分鐘只花 20 分鐘。前者邊數較少，後者總時間較短。

模板保留的是關係，不是變數名字

first_at_least 保留「lo 左側太小、hi 起的右側夠大」；count_target_sum 保留「字典只包含目前右端之前的前綴頻率」。兩個模板的分支與更新時機都來自這些關係。

把 target 換成其他判斷時，同時檢查相等分支如何歸類。把區間個數換成最長區間時，同時把字典 value 換成最早位置。

下方兩段實作可以拿來對照新題。每次套用時，讓變數的含義與當前輸出要求保持一致。

def first_at_least(values, target):
    lo, hi = 0, len(values)
    while lo < hi:
        mid = (lo + hi) // 2
        if values[mid] < target:
            lo = mid + 1
        else:
            hi = mid
    return lo

def count_target_sum(values, target):
    """連續非空子陣列總和；支援負值。"""
    seen = {0: 1}
    total = answer = 0
    for value in values:
        total += value
        answer += seen.get(total - target, 0)
        seen[total] = seen.get(total, 0) + 1
    return answer

一個例子只測一種容易出錯的決定

挑例子時，讓預期結果能指出某一條分支是否寫對。全負數檢查最大值初始化；重複值檢查嚴格比較；空陣列檢查邊界；無解檢查回傳規格。

對優化後的程式，用很小的輸入與枚舉解比較。最長區間可以列出所有 (left,right)，Top K 可以排序比較，圖最短路徑可用另一種小規模計算方式對照。

找到錯誤時，把輸入縮到仍會失敗的最小版本。兩三個元素通常就能看出更新前後哪一個狀態不符合原本定義。

同一題改一個條件，再推一次

標籤視窗若由「至多 k 種」改成「恰好 k 種」，擴張與收縮仍可維持至多 k 種，但只有目前種類數等於 k 時才更新候選。

接駁問題若允許最多一次免費轉乘，狀態加入是否已用優惠；若限制最多 K 次中停，狀態加入已用邊數。到同一站的路徑，可能保留不同後續資格。

先修改狀態與評分，再調整程式。這樣每個新條件都能在一個具體欄位或分支裡找到位置。

若要數出恰好 k 種標籤的子陣列數，有什麼可重用的關係？

看推理

恰好 k 種的數量等於至多 k 種減去至多 k−1 種。每個右端縮成合法視窗後，可累加 right−left+1 個以它為終點的區間。

關掉程式，還能把過程說回來嗎

重做一題時，先用小輸入畫出狀態。若能說出某個候選為何排除、某格 dp 依賴誰、某個節點何時標記，就已抓住可遷移的部分。

卡在語法就查 API，卡在狀態就回到具體例子，卡在正確性就找反例。每次修正一個明確的判斷，下一次題目改變時才知道哪裡要重推。
