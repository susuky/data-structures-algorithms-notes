16 · 字串比對與索引

字串比對怕的就是每次失敗都退回原點重頭掃。KMP 把剛比對過的資訊留成前綴表，滾動雜湊讓視窗往右一格就能算出新指紋，後綴陣列則乾脆把所有尾巴排好讓查詢變二分。

比對失敗後，已經相同的字可以留下多少？

在長文字裡找出所有 ababaca。遇到失敗時，KMP 讓文字指標繼續向前，從已比對字串的相同字首與字尾找下一個起點。

pi[i] 是 pattern[0:i+1] 的最長真字首、且同時也是字尾的長度。「真字首」的長度嚴格小於整段。例如 ababa 的共同字首字尾是 aba，所以 pi[4]=3。若下一字元比對失敗，已匹配長度 j 改為 pi[j−1]，先沿用這 3 個字。

建立 pi 本身也會沿失敗鏈回退。模式 ababaca 處理索引 5 的 c 時，先試已知的長度 3，預期 b；退到 pi[2]=1，預期仍是 b；再退到 pi[0]=0，c 與開頭 a 也不同，所以 pi[5]=0。同一個 c 留在原位，候選長度依序從 3→1→0。

建立 pi 花 O(m)，掃描文字花 O(n)，總時間 O(n+m)、空間 O(m)，另計輸出。j 每次增加都伴隨一個新字元，回退次數受先前增加量限制。找到完整模式後也回到 pi[j−1]，所以重疊匹配會保留：在 aaaa 找 aa，可回傳 [0,1,2]。如果搜尋空字串，這個函式會回傳每個字元間隙 0…n。

def prefix_function(pattern):
    pi = [0] * len(pattern)
    for i in range(1, len(pattern)):
        j = pi[i - 1]
        while j and pattern[i] != pattern[j]:
            j = pi[j - 1]
        if pattern[i] == pattern[j]:
            j += 1
        pi[i] = j
    return pi

def kmp_find_all(text, pattern):
    if not pattern:
        return list(range(len(text) + 1))
    pi = prefix_function(pattern)
    matches = []
    j = 0
    for i, char in enumerate(text):
        while j and char != pattern[j]:
            j = pi[j - 1]
        if char == pattern[j]:
            j += 1
        if j == len(pattern):
            matches.append(i - len(pattern) + 1)
            j = pi[j - 1]
    return matches

模式 aaa 的 pi 是多少？找到一次 aaa 之後，j 應回到幾？

看推理

pi=[0,1,2]，找到完整匹配後 j 回到 2，保留末尾的 aa；下一個 a 抵達就能再找到一次重疊匹配。

延伸閱讀：Princeton．Substring Search

每個字元都參與計算，最後再找槽位

要把字串鍵分散到雜湊表的槽位，可以把字元依序帶入 h=(h×base+字元值) mod modulus。base 讓同樣字母、不同順序得到不同的計算路徑。

以 base=31、modulus=101 計算 cat，Unicode 碼點依序是 99、97、116。每加入一字，舊內容乘上 31，再加上新字。最後要放進大小 M 的表，可以使用 h%M 找槽位，再在槽位內比對原始鍵。

長度 m 的鍵需要 O(m) 時間、O(1) 工作空間，以固定大小整數算術計。modulus 個結果要容納任意多字串，碰撞會自然出現；查詢時沿著相同槽位尋找、再比較原始鍵，就能得到正確結果。教材用小 modulus 讓計算清楚，實際選參數時會依鍵的分布與表格大小安排。

def polynomial_hash(text, base=257, modulus=1_000_000_007):
    if base < 1 or modulus < 2:
        raise ValueError('base >= 1 and modulus >= 2 required')
    value = 0
    for char in text:
        value = (value * base + ord(char)) % modulus
    return value

base=1、modulus=7 時，ab 與 ba 的值是多少？這會讓哪一個步驟變重要？

看推理

兩者都是 (97+98)%7=6。同一槽位內的原始鍵比較會分辨 ab 與 ba；base=1 讓字元順序完全消失，字母排列相同的鍵會大量集中。

延伸閱讀：Princeton．Hash Tables

視窗往右一格，扣掉最左字元再接上新字

每個長度 m 的子字串都重算雜湊，需要 O(nm) 次字元處理。視窗只移動一格時，可以沿用中間 m−1 個字元。

若 h 表示目前視窗，先扣掉左端字元的 ord(left)×base^(m−1)，接著整體乘 base，最後加上新右端字元並取餘數。前方扣除以模數正規化，讓 h 維持在 0…modulus−1。

下方 Rabin–Karp 在雜湊相等時比較原字串，精確回傳所有匹配起點。建立與滾動部分花 O(n+m)；若有 v 次雜湊相等，完整成本為 O(n+m+vm)，最壞 O(nm)。工作空間 O(m) 包含 Python 切片，另計答案；大量重複字串會增加確認工作。需要確定的 O(n+m) 比對時間時，可用前一節 KMP。

def polynomial_hash(text, base=257, modulus=1_000_000_007):
    if base < 1 or modulus < 2:
        raise ValueError('base >= 1 and modulus >= 2 required')
    value = 0
    for char in text:
        value = (value * base + ord(char)) % modulus
    return value

def rabin_karp(text, pattern, base=257, modulus=1_000_000_007):
    if base < 1 or modulus < 2:
        raise ValueError('base >= 1 and modulus >= 2 required')
    n, m = len(text), len(pattern)
    if m == 0:
        return list(range(n + 1))
    if m > n:
        return []
    high = pow(base, m - 1, modulus)
    target = polynomial_hash(pattern, base, modulus)
    value = polynomial_hash(text[:m], base, modulus)
    matches = []
    for left in range(n - m + 1):
        if value == target and text[left:left + m] == pattern:
            matches.append(left)
        if left + m < n:
            value = (value - ord(text[left]) * high) % modulus
            value = (value * base + ord(text[left + m])) % modulus
    return matches

模式長度是 1，最高位權重 base^(m−1) 變成多少？

看推理

變成 1。扣除唯一的舊字後，視窗的剩餘值為 0，再加入新字即可，更新公式沿用原式。

延伸閱讀：Princeton．Substring Search

把所有後綴排好，共同字首就靠在一起

banana 裡重複最長的片段是 ana。將每個起點的後綴依字典序排列，相近的後綴會相鄰，共同字首就容易比較。

直接建立每個後綴字串會複製 O(n²) 個字元。倍增法用 rank 表示長度 w 的片段排名，再以 (rank[i], rank[i+w]) 排長度 2w 的片段。超過字尾的排名設為 −1，讓短字串排在相同字首的長字串前面。每輪把相同的 pair 壓成相同新排名，w 依序變成 1、2、4、8。

這份實作用比較排序處理 pair，每輪 O(n log n)、共 O(log n) 輪，建置時間 O(n log² n)、額外空間 O(n)。排名全部不同時，後綴順序已確定，可提早停止。建好後能用二分搜尋找模式的後綴區間，基本比較版每次查詢 O(m log n)；相鄰後綴的最長共同字首長度可再用 LCP 陣列加速相關問題。

def suffix_array(text):
    n = len(text)
    suffixes = list(range(n))
    rank = [ord(char) for char in text]
    width = 1
    while width < n:
        key = lambda i: (rank[i], rank[i + width] if i + width < n else -1)
        suffixes.sort(key=key)
        updated = [0] * n
        for j in range(1, n):
            updated[suffixes[j]] = updated[suffixes[j - 1]] + (key(suffixes[j]) != key(suffixes[j - 1]))
        rank = updated
        if rank[suffixes[-1]] == n - 1:
            break
        width *= 2
    return suffixes

為什麼只檢查排序後相鄰的後綴，就能找到最長重複片段？

看推理

所有以同一個片段開頭的後綴會形成連續區塊。只要該片段出現兩次，這個區塊至少有一對相鄰後綴；它們的共同字首至少包含這段片段。

延伸閱讀：Princeton．Suffix Arrays
